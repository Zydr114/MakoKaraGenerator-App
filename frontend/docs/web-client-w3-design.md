## 2. 结构调整

### 2.1 页面与导航

`App` 的页面加上 `appearance`、`library`。样式库是应用级资源，没有工程也能进。外观页依赖当前工程。离开有未保存草稿的样式库时先确认；外观页本身没有草稿。

### 2.2 共享底部区

W2 的 `AudioController` 由歌词页 `Workspace` 创建。W3 把它提到“工程舞台”这一层：有工程时，由它创建播放器并加载波形，歌词页和外观页都从这里拿。
- 播放条和时间轴的组件不变。
- 时间轴加只读模式：外观页上点选或框选行只改变目标选择，不能拖动时间。
- 模板名标在目标浏览器的行上；时间轴行块是画布绘制，暂不标模板名。

### 2.3 协议与客户端

- `src/protocol/templates.ts`：
  - 模板库描述、摘要、详情。
  - 静态定义：`TemplateLibraryStyle` 及其文字、填充、材质（纯色／渐变）、描边、阴影。
  - 21 个 `TemplateProperty`，`TemplateKind`（`line`／`token`／`composite`）。
  - 五种库命令及其响应。
- `src/protocol/style.ts` 补 `GET .../style` 的响应类型。
- `MakoClient.templates`：
  - `libraries()`。
  - `list(libraryId, { offset, limit, expectedRevision })`。
  - `listAll(libraryId)`：首次读取得到修订，再用同一修订翻页；中途修订变化就从头重读。
  - `detail(libraryId, templateId, expectedRevision)`。
  - `command(libraryId, expectedRevision, command)`：沿用客户端回执，同一意图重试时请求 ID 和截止时间保持不变。
- `MakoClient.projects.style(projectSessionId, target, expectedRevision)`。
- 修订都是不透明字符串：个人库没有入口时修订为 `missing`，第一次新建时 `expectedRevision` 就写 `missing`。

### 2.4 样式库状态（无 DOM）

`TemplateLibraryStore`：
- **缓存**：两个库的完整摘要列表和已读详情。详情按 `(libraryId, templateId, templateRevision)` 缓存。
- **草稿**：选中模板后从详情复制一份到本地，编辑只改草稿，草稿有自己的撤销／重做栈；连续拖动滑块只记一步。
- **脏标记**：比较草稿与原定义的规范化 JSON。
- **保存**：
  - 已有的个人模板发 `replace`，新草稿发 `create`。
  - 409 时重读列表，草稿保留，提示“模板库已被修改，已重新读取；你的修改仍在，可再次保存”。
  - 422 `LibraryInvalid` 时只报错，不覆盖原库。
- **新建**：用内置“经典整行”的定义作起点，名称改为“新模板”，未保存，不能凭空构造定义。
- **复制**：发服务端 `copy`，参数是来源库、来源修订和新名称，返回新 ID 后选中新模板。

### 2.5 属性分组

模板的 `properties` 决定它控制哪些属性，没列出的属性由目标继承。界面按组开关，每组对应的属性如下。实际属性语义以后端 `StyleBatchEditor` 为准，分组已在 G15 邮件里请 Codex 确认：

| 组 | 属性 | 文本单元用途可用 |
|---|---|---|
| 字体 | `fontFamilyName`、`fallbackFamilyNames` | 否 |
| 字号 | `fontSizePx` | 否 |
| 字重与字形 | `fontWeight`、`isBold`、`isItalic` | 否 |
| 字距 | `letterSpacingPx` | 否 |
| 位置 | `verticalCenterRatio`、`horizontalAlignment` | 否；组合用途也不可用 |
| 未唱填充 | `unsungColor`、`unsungGradientSpec` | 是 |
| 已唱填充 | `sungColor`、`sungGradientSpec` | 是 |
| 描边 | `strokeColor`、`strokeWidthPx`、`strokeSpec` | 是 |
| 阴影 | `shadowColor`、`shadowBlurPx`、`shadowSpec` | 是 |
| 透明度 | `opacity` | 是 |
| 缩放 | `scale` | 否 |

- 读取时，组内任一属性在 `properties` 里，就显示为“包含”。
- 保存时：
  - 原来就包含的组，保留原有的属性子集，例如内置“逐字强调”只列 `unsungColor`／`sungColor`。
  - 新打开的组写入整组属性。
  - 关掉的组移除整组属性。
- 至少要包含一组，否则禁用“保存”并说明原因。
- 描边、阴影的“开／关”是样式值（`null` 表示明确关闭），和“包含在模板中”是两件事。界面上分开放：组标题是“包含”开关，组内第一项是“描边：开／关”。

### 2.6 外观目标与适用规则

- **目标**：`project`、`branch`、`line`、`token`，与命令的四类目标同形。多选只在同一层级内进行（多行，或多个文本单元），不混选。
- **适用规则**，对照后端 `PresetApplicationTargets.CanApply`：
  1. 用途为“文本单元”的模板只能用于文本单元。
  2. 目标是文本单元时，模板的属性必须都在上表“文本单元用途可用”的范围内。
  3. 含包或配方的高级模板不在 W3 的应用范围内，选择器里灰显，写明“含效果，暂不支持”。
- 不满足规则的模板仍然列出，但灰显并写明原因；最终以后端 422 为准，界面显示后端给的原因。
- **应用**：发一条 `presetApplications.apply`。参数是 `templateLibraryId`、`templateId`、`templateRevision`，以及全部选中目标（最多 1000 个）。`templateRevision` 填的是列表读到的**库修订**（`LibraryList.revision`），不是摘要里的模板修订（2026-10-17 实测，对照后端实现）。`branchInputs` 不发，静态模板没有具名输入。目标原有分配时由后端替换：同一模板保留应用身份，相当于更新。
- **库修订过期**：库在读取之后又被修改，或模板已被删除时，后端回 404 `resourceNotFound`（字段 `command.templateRevision`）。界面重读两个库后提示“模板库已更新，已重新读取。请确认后再应用。”

### 2.7 外观页预览

- 复用 W1 的 `PreviewController`：每个工程一条预览会话，只保留最新的“时刻＋修订”。
- **尺寸**：工程画布按比例缩到不超过 1280×720。
- **重新请求帧**：播放头变化，或工程修订变化时请求新帧；修订变化先换输入。
- **能力检查**：工程含预设分配时，需要 `runtime-info.sourceProfiles` 里有 `static-lyrics-scene-presets-v1`。没有就显示“后端预览不支持模板分配”。
- 预览失败时保留上一帧，并标出是哪个修订的画面。
- 画面上方显示“成片 · 修订 N · 时刻”（§5.4）。

### 3.1 G15 需求草案

- **场景**：外观页选中“主歌词 / 第 2 行”，需要显示“经典整行 · 本行直接分配”，并能停用、移除，或在库里有新版本时更新。
- **现有缺口**：
  - 合同里只有四个写命令；`GET .../style` 只有一个 `hasPresetApplications` 布尔值。
  - 命令响应也不返回新分配的 ID。
- **请求**：`GET /api/v1/project-sessions/{id}/preset-applications?expectedRevision=…`，与 S1 读模型同样的精确修订门禁，返回当前修订下的全部分配。
- **每项需要的字段**：
  - `applicationId`。
  - 目标：六类 binding 照实返回；node／clips 只读，前端显示为“编排对象”。
  - `targetValid`：目标已失效时为 false。
  - `enabled`。
  - 模板快照摘要：`templateId`、名称、`kind`、`properties`、高级标志，以及与库里 `templateRevision` 可比较的快照修订。前端靠比较这个修订判断“有新版本”。
  - `branchInputs`。
- **ID 与 Int64**：ID 保持原字符串；修订是字符串。
- **其他**：
  - 读取不改变历史。
  - 条目数量大时用分页或预算，由 Codex 决定。
  - 四个写命令的 changeSet 加一个可识别的 area（例如 `presetApplications`），前端收到后只重读分配，不必整体重读歌词。
- **验收场景**：
  1. 应用到两行后读到两条、ID 不同。
  2. 停用后 `enabled=false`。
  3. 移除后消失。
  4. 撤销后恢复原 ID。
  5. 库里替换模板后，快照修订与库修订不同。
  6. 删除目标行后 `targetValid=false`，仍可移除。

### 3.2 G16、G17 需求草案

- **G16**：预览会话可以接受“当前修订＋一份候选分配”的输入。候选的形状与 `presetApplications.apply` 相同。
  - 不写工程，不产生历史；工程修订变化后候选作废。
  - 一个会话同一时间只有一份候选，换候选不累积。
  - 结束试看就回到普通输入。
  - 验收：试看帧与真正应用后同一时刻的帧 SHA 相同；结束试看后帧与应用前相同。
- **G17**：用固定试样场景渲染一份静态模板定义，可以是库里的模板，也可以是未保存的草稿。
  - 试样至少要有：整句、多行、注音、文本单元强调；时刻可选；背景深色、浅色、透明三种。
  - 输出 PNG，复用预览帧的鉴权读取与过期规则。
  - 缩略图可以就是同一接口的小尺寸输出。
  - 验收：改草稿的颜色后帧变化；同一定义渲染两次 SHA 相同。

### 3.3 R2：个人库写入能接受、读取却拒绝的渐变取值（2026-10-17 发现）

**已修复**（后端 `1272a8c`，含在合同 1.13.0／产品 0.87.0 里；2026-10-17 前端实测三种取值都能写入、读回、应用、保存重开）。前端在 W4 第 2 步恢复了三个选项，注明后端渲染器暂时按纯色基色绘制这些组合（后端 `GradientSupport`）。

- **现象**：`create`（推测 `replace` 同理）接受一份静态定义并写入个人库，但之后个人库的**每一次**读取（列表、详情）都返回 422 `commandRejected`／`LibraryInvalid`；写命令也同样被拒绝（按库文件实际 SHA-256 作 `expectedRevision` 发 `delete` 仍是 `LibraryInvalid`）。用户无法经 HTTP 恢复，只能手动删除 profile 里的库文件。
- **触发取值**（以内置“经典整行”为底，只改 `sungFill.material` 为渐变，其余参数取后端 `GradientSpec` 默认值，每个变体前清空个人库）：

  | 变体 | create | 之后读取 |
  |---|---|---|
  | `colorSpace: oklch`（`huePath` 为 `shorter` 或 `longer`） | 成功 | `LibraryInvalid` |
  | `coordinateSpace: glyph` | 成功 | `LibraryInvalid` |
  | `coordinateSpace: progress` | 成功 | `LibraryInvalid` |
  | 线性两色标、末色标半透明、三色标、径向（含 `radiusX` 0.8）、`hsv`、`canvas`、角度 30°、描边材质为渐变 | 成功 | 正常，详情与提交的定义一致 |

- **期望**：同一份定义要么在 `create`／`replace` 时就被 422 拒绝（并写明原因），要么能正常读回；任何情况下都不应把个人库变成不可读、不可经接口修复的状态。
- **前端临时处理**：渐变编辑里 OKLCH、单个字形、演唱进度三个选项暂时禁用并注明“后端缺陷 R2”，修复后恢复。已有模板里出现这些取值时照常显示。

### 3.4 R3：分配读模型 `source` 的空值与 OpenAPI 不符（2026-10-17 发现，**已修复**）

> 后端 `1d49778`（合同 1.14.0，产品 0.87.1）修复：OpenAPI 改为 `string|null`／`boolean|null` 并列为必返；能力列表新增 `project-sessions.preset-applications.read`。前端在 W4 期间同步（W4 设计 §6），集成测试已去掉放行。

- **现象**：`GET .../preset-applications` 的每一项 `source` 实际返回 `{"libraryId": null, "revision": null, "comparable": false, "newVersionAvailable": null}`，行为正文 §13.4 也这样写；但 OpenAPI 的 `ProjectPresetApplicationSourceDto` 把这三个字段写成 `string`／`string`／`boolean`，不允许 null。按冻结 OpenAPI 校验真实响应会报三处类型不符。
- **期望**：OpenAPI 与实际一致：三个字段允许 null（例如 `type: ["string", "null"]`），或改为省略。
- **前端临时处理**：类型按可空处理；集成测试的 OpenAPI 校验只放过这三处，修复后去掉。

## 4. 实施步骤

每步单独提交：
1. 外壳：导航加“外观”“样式库”；播放器和底部区提升为工程级共享；时间轴只读模式。
2. 协议与客户端：模板库四个路由、静态定义类型、`GET .../style`；单元测试。
3. 样式库（一）：列表（内置／我的、搜索、按用途筛选）、详情只读查看、复制、改名、删除、新建。
4. 样式库（二）：外观页签编辑（除渐变外的各组）、包含开关与用途限制、草稿撤销／重做、保存、离开确认、冲突处理；高级页签。
5. 样式库（三）：渐变编辑（线性／径向、角度、中心与半径、色标、色彩空间与色相路径），旁边用 CSS 渐变条显示色标。这只是控件，不是渲染。
6. 外观（一）：目标浏览器、时间轴联动、真实预览画布、检查器（目标路径、本层直接覆盖只读）。
7. 外观（二）：模板选择器（适用性灰显与原因）、多目标一次应用、“已应用 · 撤销”、模板修订过期处理。
8. 集成测试与浏览器冒烟补齐，联调回执。
9. G15 交付后：分配读取、目标浏览器显示模板名、停用／移除／更新、有新版本提示。

6. **测试**：单元、集成、`smoke:browser`、`smoke:editor`、`smoke:appearance` 全部通过。
