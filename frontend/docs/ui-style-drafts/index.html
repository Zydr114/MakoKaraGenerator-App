MakoKara 界面风格稿

三份方向不同的风格稿，覆盖开屏、新建工程、歌词、编排、导出五个画面。页面分区、交互和用词都沿用已确认的《Web 前端设计稿》，这里只改视觉和布局。请从三份里选一份，细节可以从其他稿里借。

  • 密度：比 mdui 默认紧，比视频剪辑软件松；控件统一 24～30px 高。
  • 秩序：底部只留一条播放条加时间轴；所选单元的起止固定在编辑区底部。
  • 常驻提示收进“快捷键”入口；状态只在一处显示。
  • 三稿共用同一个记号：卡拉 OK 的逐字填充（标志、文本单元、波形、预览）。

A 暗场深色，像剪辑软件

整块石墨灰，面板之间只留 1px 缝。琥珀色只给“已唱、当前、主操作”。页签放在 40px 标题栏正中，去掉左侧导航栏，底部 24px 状态栏放连接、修订和快捷键。

三稿共同的布局改动

底部只剩一块

现在底部叠着 4～5 条横栏。改成一条播放条（播放、速度、循环、本页开关、缩放、吸附）加时间轴；歌词分配移到编排页的左栏或画布下方。

时间字段固定

所选文本单元的起、止、±1 帧、整行平移，固定在行编辑区底部，编辑区怎么滚动都不会被挤走。

一套控件尺寸

输入框、下拉、按钮统一 28px 左右，不再出现 56px 描边输入框挨着原生下拉框的情况。快捷键说明收进一个入口。

组件库与许可

仓库计划以 GPLv3 开源。MIT、ISC、BSD 可以并入 GPLv2 和 GPLv3；Apache-2.0 只能并入 GPLv3（与 GPLv2 不兼容），所以本仓库应写 GPLv3 或“GPLv3 或更新版本”。字体用 OFL，可以随软件一起分发，字体本身仍按 OFL。

库许可与 GPLv3说明
React Aria ComponentsApache-2.0兼容无样式。列表多选、拖放排序、树、带单位的数字字段、键盘操作都很完整，正好对应行列表、文本单元、槽位、画面结构树和属性面板。
Base UIMIT兼容无样式，MUI 团队维护，已到 1.x，shadcn 的默认底座。组件更轻；拖放和树要另配。
Radix PrimitivesMIT兼容无样式，生态最大；与 Base UI 同类。
Ark UIMIT兼容无样式，基于状态机，多框架通用。
MantineMIT兼容自带样式和大量组件，上手最快；要做成这三稿的样子，需要覆盖它的大部分样式。
BlueprintApache-2.0兼容为高密度桌面界面设计，但自身风格很强，改主题成本高。
Semi DesignMIT兼容组件全；React 19 需要用单独的包。
Fluent UI v9MIT（代码）代码兼容字体和图标资产另有许可，不宜随 GPL 软件分发。
react-resizable-panelsMIT兼容可拖动的分栏和底部区高度，三稿都需要。
dockviewMIT（核心）核心兼容可停靠面板。8.0 起另有商业许可的 Enterprise 附加包，不要引入。
Lucide／Phosphor／TablerISC／MIT／MIT兼容线性图标，24 网格，和稿里手绘的图标风格一致。
Inter、Noto Sans CJKOFL-1.1可随附界面字体。MiSans、HarmonyOS Sans 是专有许可，不要打包。
mdui（现用）MIT兼容可以逐页替换，不必一次推倒。

建议：交互层用 React Aria Components，分栏用 react-resizable-panels，图标用 Lucide，外观全部由自己的 CSS 变量决定。三份稿都是自定义外观，带样式的库（Mantine、Blueprint、Semi）反而要花力气去掉原样式。

风格上我推荐 C 台前幕后：这个软件一半时间在读写日文和注音，一半时间在看画面和时间轴，C 让两件事各在最合适的底色上；也是三份里最不像通用模板的一份。想要最“专业剪辑软件”的观感就选 A，想要最好上手就选 B。

稿件是手写的 HTML 与 CSS，用来定方向，不是组件库的实际渲染；图标是为稿件手绘的占位。说明和来源见 README.md。
