# 固定字形部件分区合同

2026-10-03；按 R0 §6.3／ADR-0081：捕获排除的部件继续绘制。
这是正式父子协调器的前置实现，不新增数据格式或脚本权限。

## 1. 分区和目标

基础文字和注音分别提供 Fill／Stroke／Shadow 六类真实彩色部件。
它们复用整行固定 glyph、当前已唱／未唱裁切、源覆盖／脚本样式和最终矩阵；不是白色 Coverage。
Stroke 使用生产外部轮廓，Shadow 使用相同源字形／渐变／alpha 的 shadow-only 滤镜。
不以整体图片减去填充猜测半透明阴影，也不修改原样式的透明度、装饰边界或源数据。

仅真实 Line／TokenFamily／TextMark 具有自己的部件；组由其实际孩子合成，不制造组填充。
Line 的部件不含附着标记或后代组；Mark 独立提供基础文字部件，不能请求注音部件。
不存在的装饰或合法没有注音可返回空部件，失效装载／不独立 glyph 分区仍失败。

## 2. 共同透明度

部件颜色保留各自的基础外观 alpha，但不分别应用同对象的共同合成透明度。
Line／Token 提取整行入场 alpha；Mark 提取入场附着 alpha × 标记样式 opacity。
返回对象同时保存原共同值和生产 ToOpacityByte 量化后的值；重组完成后只应用一次量化值。
静态元素样式 opacity 和注音关联仍按原规则烘入部件，不伪造重排或新的样式字段。
附着标记的共同值由它自身返回，父子协调器必须明确处理附着入场的继承，不能再次相乘。

## 3. 所有权及验证

彩色部件明确 sRGB、实际 Canvas 框／密度，共享捕获构建和帧账；彩色输出和临时图层计费。
调用者拥有返回部件及表面；共同值是不可变元数据，不持有作者脚本或源可写对象。
失败／取消不返回半个部件，不能把失败当作没有描边／阴影。
AssembleSceneColorParts 仅接受调用者显式顺序的同一快照／准备帧／时刻／输出／质量／目标部件，
禁止重复部件和裁掉输入框；返回独立颜色图及尚未应用的共同 alpha。释放输入不会使重组图失效。
输入与独立输出在分配前检查固定和共享预算。它不决定排除部件与效果的叠放，也不自行应用共同 alpha。
显式临时层按既有账本计费，阴影内部 scratch／上游终结器仍不是完整 native RSS 验证。
旧正常 Render 与完整 TargetColor 捕获保持原路径及像素，分区仅用于新协调器。
显式重组验证的是指定顺序：基础外描边→阴影→填充，再叠注音部件；这不宣称任意相互重叠的多源绘制单元都与旧逐单元交错绘制逐像素相同。正式协调器须明确其部件／效果顺序并记录差异。

验证应包含部件真实颜色／渐变、逐字裁切、缺时间元素、静态／脚本族样式与变换、注音和前奏，
以及共同透明度一次重组与逐部件 alpha 的差异、实际密度／预算／失败／取消及像素回归。

## 4. 仍须完成

未纳入部件与整张效果结果的叠放顺序已询问用户，答复前不默认决定。
本合同实现部件生产；混合配方重组、子图到父图、真实下层快照及正式 Render 调度仍是必需工作。
部件 API 已实施不意味着包材质／完整 R2～R8／工作区已经完成。
