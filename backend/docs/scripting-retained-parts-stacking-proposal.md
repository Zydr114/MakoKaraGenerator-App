# 图效果与保留部件的叠放规则（已确认，0.12.1 字形目标已实施）

2026-10-03；接续 ADR-0081／0082。用户已确认未纳入捕获的注音、描边、阴影继续原样显示；本合同补充它们与图效果产物的先后关系。用户本轮明确选择**放在所处理部件的最高层**，0.12.1 已接入元素／行／标记协调；完整组隔离继续后续。

## 1. 当前限制

生产捕获已能分别得到基础文字／注音的填充、外描边和阴影，保留共同透明度供最终合成一次使用。图效果会把选中的多个部件融合成一张图片，融合后不能再把这张图片拆成原来的六个图层。例如，图同时处理基础填充与注音填充，却排除两套描边时，无法把注音描边插回融合图片内部。

当前无图效果的原绘制路径保留原行为；现有独立部件验证使用从下到上的顺序：基础外描边、基础阴影、基础填充、注音外描边、注音阴影、注音填充。任意元素局部变换下的字形交错仍由生产绘制负责，不能将这六张独立图片宣称为所有情况下与原路径逐像素相同。

## 2. 三个可选规则

| 规则 | 处理方式 | 基础填充 glitch、排除注音／描边／阴影时 |
|---|---|---|
| **放在所处理部件的最高层（建议）** | 将选中的部件整体替换为效果图片，放在其中原本最高的部件位置；其他部件保留相对顺序 | 基础描边／阴影在效果下方，注音在效果上方 |
| 效果永远在保留部件上方 | 原样绘制全部保留部件，再画效果图片 | 效果可能遮住注音和描边 |
| 效果永远在保留部件下方 | 先画效果图片，再原样绘制全部保留部件 | 描边和阴影也可能覆盖故障画面 |

建议第一项，因为只处理基础文字时仍能保留注音的清晰度。若同时处理基础填充与注音填充，效果图片位于注音填充的位置，两套保留描边／阴影在它下方；这可能改变部件重叠处的外观，须接受这个明确结果，不能悄悄还原或重复画基础字。

## 3. 与已有合同的关系

- 叠放顺序不改变字形布局、源歌词、绑定范围、图采样框或入场透明度。
- 半透明部件按原 alpha 合成，共同入场 alpha 在对象重组后应用一次。
- 后续图仍按实例顺序接续，保留全部已生效的替换范围；不能把融合图片冒充每一种捕获配方。不同配方的重组必须保存实际部件及效果产物的来源，未实现的组合继续明确报错。
- 透明导出跳过背景依赖图后恢复其指定原输入；跳过的图不制造新图层或替换范围，也不改变保留部件的相对顺序。
- 父组捕获应读取孩子已经完成效果与部件重组的结果；不将孩子再画一次。真实下层输入从目标绘制之前的合成结果读取。

## 4. 实施和验收

按已确认规则接到主画布父子协调器。验证基础填充 glitch 排除注音、只纳入描边、混合基础／注音部件、重叠及半透明部件、两次不同配方的效果、透明旁路与父组捕获。用明确颜色和重叠区域的像素断言证明顺序；真实预览／导出使用同一协调器。

本次先独立修复真实控制器包对已实现组仿射的旧能力门禁；该修复不依赖本提案，也不改变材质／图的未确认编码。

## 5. 0.12.1 接续边界

用户随后确认：部分切分已有融合图片须拒绝并提示调整效果顺序／范围；没有目标输入的图替换绑定目标全部部件。真实每输入部件来源、最高层重组、元素到整行、真实下层、一次共同 alpha、透明跳过／缓存／导出报告已接主 Render。组隔离与跨行父组、自身粒子排除和 owned overlay 仍需实施，详见[主画布合同](scripting-main-canvas-composition-contract.md)／roadmap §18.59。
