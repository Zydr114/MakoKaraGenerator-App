**不做**：
- **导出范围**：后端只导出 0 到输出时长这一段。原设计稿的范围栏是为了 10 秒上限，现在没有上限了，去掉。只想导出一部分，就改输出时长。
- **“版本不兼容”标记**：目录条目里没有工程版本（G26，§3）。打开不兼容的工程时，后端的打开任务会失败，失败原因写在首页。
- **清理恢复候选**：后端没有接口（G27，§3）。
- **重开后显示原文件名**：资源清单没有显示名（G28，§3）。本次会话里上传的文件，名称记在内存里。
- **视频背景的缩略图**：需要下载整段视频；只显示类型和大小。
- **上次运行留下的任务**：`recovery-jobs` 能读出 Server 重启前留下的导出成片和验证报告，W5 不做这个入口。
- **歌词页导入对话框改用导入规划**：属于 W6。W5 只在新建工程对话框里用导入规划显示识别结果和改选候选。

## 2. 结构调整

### 2.1 页面、顶栏与导航

- `App` 的页面加 `export`。它不在导航栏里：导航栏没有选中项，顶栏有工程时显示“导出视频”按钮。离开导出页时导出任务不停，回来时仍能看到任务。
- 顶栏的更多菜单改为四项：另存为…、导出歌词文件…、关闭工程、协议控制台。
- 关闭工程或连接重置时，在导出页的话也回到首页。

### 2.2 协议与客户端

所有新类型都手写，形状以 `docs/backend/contract/openapi.json` 为准；集成测试用冻结 OpenAPI 校验每个真实响应。Int64 保持字符串（例如 `resources[].sizeBytes`、进度里的 `timeUs`）。

- `src/protocol/jobs.ts`：
  - 目录条目：`ProjectDirectoryEntriesResponse`、`ProjectDirectoryEntry`。
  - 恢复：`RecoveryCandidate`、`RecoverProjectInput`。
  - `JobResponse` 里 validation 和 export 的专用字段改为有类型：`input`、`validationResult`、`exportInput`、`exportResult`、`failureReportRef`。
- 新文件 `src/protocol/render-jobs.ts`：
  - 能力：`ValidationCapabilities`、`ExportCapabilities`。
  - 请求：`ValidationJobInput`、`ExportJobInput`（格式、质量、含音轨）。
  - 结果：`ValidationReport`（issues、diagnostics）、`ExportReport`、`ExportFailureReport`（`kind: "exportFailure"`）。
  - 诊断分页：`JobDiagnosticsPage`。
- 新文件 `src/protocol/lyrics-export.ts`：评估请求与响应、导出请求与响应、损失、问题、报告。
- `src/protocol/project.ts`：
  - 资源清单：`ProjectResource`、`ProjectResourcesResponse`。
  - `ProjectSettings.background`。
  - 命令：`project.rename`、`audio.replaceAsset`、`audio.clear`、`composition.setBackgroundAsset`、`composition.clearBackground`、`composition.setBackgroundFit`、`composition.setBackgroundPlayback`。
  - 歌词导入规划：`LyricsImportPlan`。
- `MakoClient`：
  - `files.entries(rootGrantId, relativePath, { offset, limit })`；`files.listAll(rootGrantId, relativePath)` 读出全部页。翻页过程中 `totalCount` 变了（目录被改动），就从第一页重读，最多重试两次。
  - `recovery.candidates()`；`projects.recover({ recoveryId })`，返回 202 任务。
  - `projects.resources(id, expectedRevision, page)` 和 `projects.resourcesAll(id, expectedRevision)`。
  - `lyrics.importPlan(assetId, options?)`。
  - `projects.lyricsExportPlan(id, input)`、`projects.lyricsExport(id, input)`、`lyricsExports.content(exportId)`（二进制）。
  - `validation.capabilities()`；`projects.validate(id, { expectedRevision, framesPerOutput })`；`jobs.validationResult(jobId)`；`jobs.validationDiagnostics(jobId, cursor?)`。
  - `exports.capabilities()`；`projects.export(id, { expectedRevision, format, quality, includeAudio })`；`jobs.exportResult(jobId)`；`jobs.exportContent(jobId)`（二进制，返回 Blob 和响应里的文件名）；`jobs.exportDiagnostics(jobId, cursor?)`。
  - 新建工程的 `audioAssetId`、`lyricsAssetId` 改为可选，并加上可选的 `importerId`、`encodingName`。
- 有副作用的请求都沿用客户端回执：同一意图重试时请求 ID 和截止时间不变。

### 2.3 页面模型（无 DOM）

- `model/project-directory.ts`：
  - 路径导航的各段；按名称搜索（不分大小写，只搜已读到的这一层）。
  - 拼出目标路径；按后端规则做客户端预检（沿用 `checkRelativePath`）。
  - 保存目标是否已经存在：已有同名工程、已有同名普通目录、可以新建。后端保存到已有别的工程的目录时会直接覆盖（集成测试实测），所以“已有同名工程”必须先确认“覆盖”。
- `model/recovery.ts`：候选按保存时间倒序；时间显示为本地时间，“今天 14:20”“10月17日 18:26”这样。
- `model/export-readiness.ts`：由设置、摘要、资源和导出能力算出准备检查项。每项是 `{ id, level: ok | info | warning | block, text, fix? }`，`fix` 指向设置面板里的某一组。检查项：
  - **导出可用**：`enabled` 为 false 时阻断，原因用 `disabledReason`。
  - **格式可用**：所选格式不在 `formats` 里时阻断。
  - **输出时长**：未确定时阻断，修复入口是“去设置”。
  - **歌词时间**：导出要求每句、每个字都有时间，空字也不行（后端领域检查 MissingTime、EmptyText 在导出时是错误）。由已读的全部歌词算出“N 句还有字没打轴”，阻断，修复入口是“去歌词页”。后端拒绝时只说“存在阻断导出的领域错误”（G29），前端这一项是唯一能告诉用户原因的地方。
  - **画布**：MP4 要求宽高都是偶数，否则阻断，写明“MOV 透明不受这个限制”。
  - **部署限制**：帧数、时长、帧率、画布大小，只检查能力里给了值的项；超出时阻断并写明限制。
  - **音轨**：要含音轨但工程没有音频时，提示“没有音频，只导出画面”，并自动取消“含音轨”。音频还没准备好时阻断。
  - **背景媒体**：资源状态不是 `available` 时阻断。
  - **正式验证**：没做过时为提示；当前修订验证通过为通过；未通过为警告（不阻断导出，后端导出自己会检查）。
  - 同一模块算总帧数，规则与后端相同：`max(1, round(outputDurationUs / 1e6 × fps))`，远离零取整。也算正式验证默认检查多少帧：`min(总帧数, maxFramesPerOutput)`。
- `model/render-job.ts`：
  - 阶段文字：validating 验证输入、probing 读取音频、rendering 渲染、muxing 合成、verifying 校验成片、preparing-result／prepared 整理结果、committing 发布。
  - 进度比例、报告摘要、失败代码的说明。
- `model/lyrics-export.ts`：格式选项与说明、文件扩展名、损失与问题的文字。

### 2.4 导出页状态

`ExportStore`（每个工程一个，与 `OrchestrationStore` 一样由 `App` 持有，切换页面时保留）：
- 能力只读一次，失败时可以重试。
- 正式验证任务、导出任务各最多一个在跑，各自记录：任务 ID、固定的源修订、进度、终态、结果。
- 等终态用 `jobs.waitForTerminal`；SSE 的 `job.progress` 只用来刷新进度。
- 取消：发出请求后显示“正在取消”，一直到真正的终态。任务已经进入 committing 时 `canCancel` 为 false，取消按钮停用。
- 下载：用认证 fetch 取 `export-content`，转成 Blob 后用 `a[download]` 保存，文件名优先用响应头里的。成片保留 1 小时，过期后提示重新导出。
- 任务固定在接受时的修订上。之后又编辑了，任务卡片上写明“导出的是修订 R，之后又有修改”。

### 2.5 工程设置

- **工程组**：名称。按 Enter 或离开输入框时提交；去掉首尾空白后为空或超过 256 个字符时就地提示。
- **背景组**：
  - 底色不变；有媒体时写明“底色在媒体透明处或留白处可见”。
  - “选择图片或视频…”：上传后发 `composition.setBackgroundAsset`，`kind` 按文件的 MIME 判断。有媒体时这个按钮变成“替换…”，旁边是“移除”（`composition.clearBackground`）。
  - 适配方式：完整显示、铺满、原始大小。原设计稿只给视频显示，但图片同样需要适配，所以都显示。
  - 播放策略：循环、停在最后一帧，只有视频显示。
  - 媒体信息取自资源清单：类型、大小、状态。图片显示缩略图（认证读取 `contentUrl`，转成对象 URL）。
  - 失败时保留原来的媒体，原因写在这一组里（§5.6）。
- **音频组**：
  - 显示文件名（只有本次会话上传的才知道，见 G28）、时长、准备状态（资源清单的 `preparationStatus`、`waveformStatus`）。
  - “替换音频…”：上传后发 `audio.replaceAsset`。后端要同步准备音频，可能要几十秒，按钮显示进行中。成功后的提示写明“已清除音频分析；输出时长没有变”。
  - “移除音频”：确认后发 `audio.clear`。
  - 换了音频后，播放器和波形随 `audioAssetId` 重建，这一点已有。
- **输出时长组**：不变。导出页的“去设置”会打开设置面板并滚动到这一组。

### 2.6 首页

- **继续工作**：已打开的工程做成卡片，沿用 W1 的数据，加上“正在编辑”标记。
- **工程目录**：
  - 进入首页时读根目录的全部页。上限 4096 项，超过时后端返回 429，就写明“目录里的项目太多”。
  - 路径导航：工程目录 / a / b，点哪一段就回到哪一层。
  - 搜索框只过滤当前这一层。
  - 工程行显示目录名和“打开”，溢出菜单里是“只读打开”；普通目录点进去。
  - 打开失败（例如版本不兼容、正在被别的会话写）时，原因写在列表上方，不会自动消失。
  - “刷新”从第一页重读。
- **最近打开**：沿用 `localStorage` 里的相对目录名（不含凭证），显示在目录列表上方，点一下直接打开。
- **新建工程对话框**：
  - 选歌词文件时就上传，并调用导入规划。歌词资源 600 秒没被引用就过期；对话框开太久导致创建时资源过期，就自动重新上传一次。
  - 识别结果和预览行数显示在文件选择下面。格式或编码不确定时显示候选，创建时把选中的 `importerId`／`encodingName` 一起提交。
  - 规划失败时显示 `preparationError` 的原因，不能进入下一步。
  - 名称：不填时依次用音频文件名、歌词文件名、“新工程”。
  - 两项都不选时，第二步说明“会创建一个空工程，之后可以在歌词页导入歌词、在设置里选择音频”。
- **恢复对话框**：候选按时间倒序，选一项后“恢复”，恢复任务的进度显示在对话框里。恢复成功后进入歌词页；恢复出的工程是否记得原位置，由摘要的 `hasPath` 决定，下一次保存就按它走。

需求草案：
- **G26**：每个 `isProject:true` 的条目加可选的 `project`：`{ name, savedAtUtc, productVersion, compatible, incompatibleReason? }`。只读入口文件的元数据，不加载工程，不探测媒体。读不出来时省略并给一个状态。验收：
  1. 保存后列表里有名称和时间。

## 8. 已知限制

- **G26～G29、R9 未交付**（§3）：
  - 工程目录只显示目录名，不显示工程名、时间和版本；版本不兼容要打开时才知道。
  - 恢复候选清不掉，本机已经积到 117 份。
  - 重开工程后，设置里显示不出音频和背景的原文件名。
  - R9：集成测试的合同核对暂时放过 validation-capabilities 的 `sourceProfiles`。
- **“歌词时间”检查是前端重算的**（G29）：规则取自后端现在的领域检查（字缺时间、空字）。后端规则变了，前端可能放行一个会被 422 拒绝的导出，这时只能显示一句笼统的说明。
- **下载文件名用工程名**：同一个工程导出两次，浏览器会自己加“ (1)”这类后缀；文件名里不带格式、质量或修订。
- **视频背景没有缩略图**，只显示类型和大小（§1“不做”）。
- **上次运行留下的任务没有入口**：Server 重启前完成的导出成片和验证报告，W5 读不到（§1“不做”）。
- **开发环境的客户端数量**：同一个 Server 上累计登记的客户端太多时会返回 429。冒烟反复跑时遇到过，重启 Server 就好；正常使用碰不到。
- 都只在无头 Chrome、1440×900 下检查过；窄屏下导出页和各对话框的布局没有专门检查。请在日常使用的浏览器里实际走一遍新建、保存、导出。
