# 普通入口新建工程与不可读字体（0.49.6，2026-10-09）

用户要求原代码审查goal继续暂停，另行报告0.49.5普通启动脚本的问题：填写新建对话框并确认后，首页停留不动；先进入模板制作再新建则程序退出。用户素材位于仓库示例目录。该问题单独修复，不恢复原goal、全量测试、性能任务或此前暂缓的未知导出提示。依据ADR-0185。

## 已确认的故障链

保留用户日志显示 `SKTypeface.OpenStream()` 返回空值，`SKShaper` 在 `ToHarfBuzzBlob` 抛出 `ArgumentNullException("asset")`。发生于 `RefreshShapingDiagnostics → Reload → ReplaceProject → StartPreparedProject → NewProjectAsync`。旧实现已经 `Workspace.StartNew` 且取走候选播放器后才整形，故会部分替换工程，并使准备结果失去候选播放器的释放责任。

首页以丢弃Task调用同一工程操作，异常没有界面反馈；菜单是 `async void`，未处理异常进入Dispatcher导致退出。0.49.5实际普通执行体在受控注入同一异常后，首页检测到部分发布，模板菜单退出-6；不只是静态阅读或Gallery结果。

**用户进程中字体流为什么为空尚未确认。** 健康文件系统的普通进程可读取默认Noto Sans及CJK字体，中文和日语示例均可正常新建。隔离的无字体进程复现了真实SKShaper空流异常，证明异常机制，不能将该环境当成用户环境。没有证明某个歌词字符、字体文件、NTFS或启动脚本是空流的根因。

## 修复行为

整形引擎使用当前Skia字体管理器匹配请求族／字重／斜体，在构造SKShaper前检查原生句柄及字体流。主字体不可读时尝试系统默认族及既有CJK回退；显式／自动回退同样拒绝不可读条目。全部不可读时抛出中文可重试错误，不把空流交给SKShaper。合法字体的字形、诊断与像素在现有真实字重、字号、斜体及回退用例中保持。未将工程默认字体改成某个固定CJK族；有界回退缓存、输出格式、固定依赖与公开签名保持。

新建发布前先执行与Reload实际选中行、字体和字号一致的整形诊断。失败不取走候选播放器，不更换工作区／工程引用、撤销历史或旧音频播放；候选仍由调用方的准备结果释放。本次覆盖已报告的字体失败边界，不声称所有后续UI事件的任意异常都有原子回滚。

工程操作统一捕获IO、访问、参数、不支持及状态错误，写日志并更新首页反馈及状态栏。操作门禁在finally恢复，两入口都可以再次新建。保留原异常信息；真实引擎无可读字体时使用中文字体错误。未屏蔽内存耗尽等不可恢复异常。
