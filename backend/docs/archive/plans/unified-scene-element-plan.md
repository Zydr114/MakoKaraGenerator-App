# 统一场景元素与歌词布局重构方案

> 状态：S0～S3 已在 0.6.0 实现；自动验证通过，用户确认双行与内部槽位位置生效。其他验收细项未逐项反馈，S4 脚本尚未开工。
> 日期：2026-09-30；设计基线：0.5.0；本文保留 0.6.0 批次设计和验收。0.7.0 已按 ADR-0063 将持久化与运行层级升级为原生通用容器树，见 [完整案例方案](lyric-exclusive-display-case-plan.md) 和 [当前架构](../history/current-architecture.md)；0.8.0 的通用片段／局部微调及编辑器见 [实施合同](../legacy-ui/scene-editor-implementation-contract.md) §8；下文旧 branches JSON 仅属历史批次。

## 1. 设计结论

画布对象统一使用 `SceneElement`，节点类型只有组和文本。**每个歌词分支拥有一个稳定的显示容器**，普通模式和双行模式共用它的外层位置；模式只改变内部布局策略。渲染器不再通过 `ignoreLinePlacement` 选择位置来源。

```text
场景根
  ├─ 主歌词显示容器（稳定 ID、共用位置、固定参考矩形）
  │   └─ FreeLine 或 DualSlots（内部布局策略）
  │       └─ 文本节点（普通行，或槽位一／二绑定的行）
  │           └─ 注音节点（联合测量，跟随基础字）
  └─ 翻译显示容器（独立位置、TranslationFlow 布局）
```

这解决的是“布局和动画如何共存”：布局负责静态几何，动画只改变容器或子布局的时间通道；两者通过固定的变换顺序组合，而不是互相覆盖。

## 2. 三层模型

### 2.1 源模型：歌词是什么

继续使用现有 `LyricBranch`、`LyricLine`、`LyricToken` 和注音关联，保存文字、时间、样式覆盖和稳定关联。

另设 `LyricPresentationDefinition`，保存每个分支的容器位置、固定参考矩形、内部策略、逐行局部覆盖和内置动画配置。展示定义集中到 `project.json.lyricPresentation`，通过稳定源 ID 关联歌词；修改走工作区命令和撤销栈，位置不进入样式模板。

正式断代时，歌词模型中的旧 `LyricLine.Placement`、分支 `DefaultPlacement`／`DualLineGroupTransform` 等展示字段退出，不在两份文件重复保存。不保存某一帧的矩形或渲染缓存。

### 2.2 场景定义：如何组成画布对象

首期采用不可变的场景定义投影。它是从工程源数据和分支配置重建的运行时对象，不直接作为一帧几何保存：

```text
SceneElementDefinition
  Id                   // 画布节点稳定 ID
  ParentId             // 场景树父节点，可为空
  Kind                 // Group / Text；单行、双行不作为节点类型
  SourceBinding        // BranchId / LineId / TokenId / 注音 ID 的只读关联
  Placement            // 父参考坐标内的位置、锚点、旋转、缩放
  ReferenceRect        // 组的固定局部参考矩形，规定尺寸与枢轴
  LocalLayout          // FreeLine / DualSlots / TranslationFlow / Ruby
  Order                // 从分支顺序和局部绘制顺序生成
```

`SceneElementId` 是画布节点身份；`LineId`／`TokenId` 是源数据身份。容器 ID 从 `BranchId + display` 派生，槽位 ID 从容器 ID 和槽位角色派生，换歌词不换容器／槽位 ID。普通文本节点由分支与 `LineId` 派生，注音由稳定注音 ID 派生；不使用两句歌词的配对首行作为组 ID。

`BindingId` 属于采样结果，表示槽位这次装载哪句：由容器 ID、槽位 ID、`LineId` 和调度装载区间确定。可见区间、逐字状态、动画通道和当前绑定也属于帧结果，不能成为定义对象中随当前时刻反复改变的字段。

### 2.3 帧模型：这一帧画什么

采样器根据 `ProjectSnapshot + timeUs + SceneDefinition` 产生 `SceneFrame`。它包含已经测量的元素树、局部几何、外层世界变换、可见／进入／退出进度和逐字进度。脚本只读 `FrameContext`，返回经过校验的 `FramePlan`；`SceneFrame` 和 `FramePlan` 都是临时值，不写回歌词源数据。

## 3. 位置与变换合同

### 3.1 唯一外层位置

分支显示容器的外层 `Placement` 在普通／双行模式下都生效，画布拖动、位置输入、旋转和缩放默认操作当前容器；双行启用后同一入口继续可用。

内部配置明确分开：`FreeLine` 保存默认局部位置和按 `LineId` 的局部覆盖；`DualSlots` 保存两个稳定槽位的局部位置和文本锚点；`TranslationFlow` 保存翻译安全区及流式排布；`Ruby` 联合测量基础字和注音。界面显示当前策略的局部参数，共用外层位置不会被禁用。源行位置不能成为槽位的隐藏覆盖。

节点位置归一化到父节点固定的 `ReferenceRect`；场景根使用画布宽高。容器枢轴固定在参考矩形中，不随歌词长度或当前两句的包围盒变化；测量包围盒只用于命中、吸附提示和可见边框。允许有限的画布外位置并由画布裁切，不把无效值夹紧。

### 3.2 固定变换顺序

```text
世界矩阵 = 父世界矩阵 × 节点静态 Placement × 节点局部动画矩阵

源文本与解析样式 -> 整形与局部排版 -> 世界几何
  -> 脚本样式调制 -> 最终绘制
```

首版脚本只允许针对容器或其子元素返回主机校验的样式调制，不允许任意重排局部布局、改变可见性或写回 `Placement`。若未来开放脚本变换，必须明确它作用在容器外层还是子元素局部层，并在预览与导出使用同一顺序。

### 3.3 动画不夺取布局所有权

进入／保持／退出只产生进度或临时变换，不能换掉 `SceneElement.Placement`。双行槽位动画在容器局部坐标解释，随外层旋转／缩放；显示容器的枢轴保持固定。样式不透明度与动画不透明度分开组合，脚本结果不修改节点矩阵或文本排版。

## 4. 单行与双行的统一实例

| 场景 | `SceneElement.Kind` | 子内容 | 外层位置 | 内部策略 |
|---|---|---|---|---|
| 普通主歌词 | `Group` + `Text` | 当前行 | 共用分支容器位置 | `FreeLine`，逐行局部覆盖 |
| 动态双行 | 同一个 `Group` + 槽位子节点 | 交替装载的两行 | 同一共用位置 | `DualSlots`，相对锚点与进出场 |
| 关联翻译 | 独立 `Group` + `Text` | 关联或独立的翻译 | 翻译容器位置 | `TranslationFlow`，安全区与测量 |
| 注音 | 文本子节点 | 基础字、注音 | 继承父文本变换 | `Ruby`，联合测量，基础字时间不变 |

翻译和注音使用同一树节点合同。脚本可读取其源关联和几何；翻译按源行／元素调制样式，注音继续跟随基础字，不单独开放注音写权。

## 5. 选择、命中与脚本目标

- 编辑器选择优先选择 `SceneElementId`，再显示其源 `LineId`／`TokenId`。
- 双行点击槽位时，命中结果包含容器 ID、`BindingId` 和槽位 ID；拖动容器修改外层位置，拖动槽位只修改内部布局参数。
- 样式套用仍按行模板／元素模板作用于源对象，不把模板写入 `SceneElement` 临时结果。
- 脚本回调携带 `SceneElementId` 与源 ID；首期样式目标是源行／元素，可只读查询其显示容器和绑定。

## 6. 迁移步骤

### S0：冻结现有行为

用现有采样／几何／像素入口固定普通行、双行、翻译、注音和分支整体变换的时序、锚点与画面。当前尚无 `SceneFrame`；先记录现有结果，再与新投影比对。

### S1：建立适配器

新增场景定义构建器，先生成与现有画面等价的容器树。当前双行是“画布坐标槽位 → 绕画布中心的整体变换”，正常采样不把 `branch.DefaultPlacement` 当作组合位置，因此不能把两个旧字段相加。

适配期根容器参考矩形取画布大小、枢轴取画布中心，槽位画布坐标转换为局部坐标，整体变换作为容器外层变换；普通行位置进入 `FreeLine` 局部配置，根先保持恒等变换。这个适配只服务当前内存对象和测试，不读旧工程，不是格式迁移。

### S2：统一几何与渲染

让静态试样、布局编辑、命中测试、预览和导出都消费同一个 `SceneFrame` 几何。删除 `ignoreLinePlacement` 参数和 `slotOwnsLayout` 的几何分支；保留它们仅作为适配器内部的短期诊断，直到测试证明可以移除。

### S3：统一编辑入口

持久化统一展示定义，退出旧展示字段。布局编辑器显示“当前场景容器位置”和“内部布局”两组属性。外层拖动、方向键、预演和撤销提交同一容器位置命令；局部编辑显示本行或槽位目标。切换模式保留并消费同一个外层位置。

### S4：接入脚本

脚本 SDK 只读取稳定的 `SceneFrame` 和事件 ID，返回填充／渐变、描边、阴影和不透明度等样式调制。不开放容器级变换、可见性、额外对象或场景树写入；不让脚本绑定当前渲染器的私有几何类型。

## 7. 数据与兼容边界

S3 已正式断代：程序 0.6.0、工程 v18、歌词 v15、模板库 v3。只保存统一展示结构，不给旧工程追加迁移，继续执行精确程序版本门禁。§6 描述实施顺序；旧模式适配字段已退出最终代码。

`SceneElement`、`SceneFrame` 和几何缓存不应直接写入 `project.json`。若用户需要保存自定义组合，应保存可重建的场景定义和绑定，而不是某次预览的矩形。

## 8. 验收标准

1. 普通行与双行容器使用同一套外层位置编辑、撤销、命中和画布坐标。
2. 改变双行槽位只改变两句的相对位置；移动容器整体不改变槽位相对关系。
3. 切换普通／双行时共用外层位置和枢轴保持；更换歌词内容时容器／槽位 ID 和旋转中心不变。
4. 静态试样与时间帧共用容器矩阵和布局测量；试样去除时间动画。相同时间的正常预览与导出得到相同世界几何，跳转纯时间重建。
5. 脚本 callback 能同时指向源行／元素和画布容器；未定时元素仍只触发可见事件，不伪造逐字开始事件。
6. 删除旧的模式旗标后，普通、双行、翻译和注音的像素回归仍通过。

## 9. 首期边界与后续扩展

- 共用容器位置编辑属于 S3 验收；任意组创建、任意文本框和通用媒体多轨后置。
- 脚本容器变换、粒子、额外对象和播放操作录制另立协议；首期只调制样式，不作为当前开发前提。


## 10. 0.6.0 实施记录

S0 先运行全部原有 1376 项测试，保留普通行、双行、翻译、注音及成片像素检查。S1/S2 建立场景定义、采样绑定与共同测量入口；S3 随本次程序交付进行结构断代。工程不再保存两套位置来源。

### 10.1 现行展示数据

`LyricPresentationDefinition.Branches` 按 BranchId 关联源分支，`LyricLinePresentation` 按 LineId 关联源行。容器默认位置 (0.5, 0.5)、Center、0°、1 倍，参考尺寸默认画布大小。工程级进入动画保持在 project.json 顶层；源行动画、分支动画策略与其他展示配置集中到新定义。

```json
{
  "lyricPresentation": {
    "branches": [
      {
        "branchId": "primary",
        "placement": { "x": 0.57, "y": 0.45, "anchor": "Center", "rotationDegrees": 12, "scale": 0.85 },
        "referenceWidthRatio": 1,
        "referenceHeightRatio": 1,
        "maxWidthRatio": 0.9,
        "lines": [
          { "lineId": "line-001", "placement": { "x": 0.3, "y": 0.6, "anchor": "Center", "scale": 1 } }
        ]
      }
    ]
  }
}
```

这是片段；真实保存还包含安全区及启用时的完整双行配置。SourceBinding、BindingId、SceneDefinition、SceneFrame 与测量矩形均不写盘。动画策略缺省按主歌词 Karaoke／其他 Static 解释，显式值保存在展示定义。

### 10.2 代码入口

- Core：`LyricPresentationDefinition`、`PresentationEditor`、`LinePlacementEditor`、展示 DTO 和关联校验。
- Rendering.Abstractions：`SceneDefinitionBuilder`、`SceneMatrix`、`LyricSceneSampler.SampleFrame`、`SceneElementFrame`、共用几何接口。
- Skia：`GetSceneFrame` 完成翻译流式排布、文本／注音联合测量、节点树和世界变换；实际绘制直接使用该帧几何。
- 编辑器：位置目标选择默认容器；内部拖动按父矩阵逆变换；复制／删除同步关联，预演隔离，撤销统一发布位置和动画通知。

`ignoreLinePlacement`、`slotOwnsLayout`、旧 DualLineGroupTransform 类型及源展示字段均已移除。模板保持只写行／元素样式。

### 10.3 用户验收路线

1. 演示工程开启布局编辑，默认「当前分支 · 整体容器」，拖动、输入 X/Y、旋转／缩放，两句共同变化。
2. 切槽位一修改位置，槽位二和整体参数保持；切槽位二独立调整。Esc 取消拖动，松开一步撤销。
3. 在分支设置关闭双行，再打开，整体参数不丢失；普通模式可编辑本行内部位置，双行模式只有槽位内部目标。
4. 换句时容器整体位置与旋转中心保持；保存新工程并重开，布局与撤销反馈一致。
5. 翻译分支可独立移动整体；查看注音跟随与预览／导出画面。

本批未接入脚本 SDK、Roslyn、音频输入、粒子或通用组创建。人工结果记录到 roadmap §18.17，不以自动测试替代用户验收。

### 10.4 用户反馈与容器编排讨论

用户确认双行分支和内部槽位位置生效，进一步提出同一源分支中的某句脱离双行独立居中，以及槽位增减；明确特殊句出现时双行暂时退出。本计划首期仍是按分支生成的固定容器结构，尚无通用成员分配和互斥展示片段。现状证据与下一阶段建议见[容器编排能力复盘](../research/scene-container-composition-review.md)，该讨论尚未实施，不替代当前 ADR-0062。
