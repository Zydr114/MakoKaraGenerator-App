# 导出音频归一化修复（2026-11-17）

分支：`fix/export-audio-normalization`；开发基线：`2552df3`；交付产品 `0.114.1`，合同 `1.55.1`。独立分支交付 AppImage，不合并主分支。

## 原因

本机 nayuta 工程的音频完整解码为 48 kHz、12,231,628 个每声道样本帧，源时长 254,825,583 微秒。原视频计划按 30 fps 四舍五入得到 7645 帧、254,833,333 微秒；源比计划少 372 个样本帧，即 7.75 ms。原执行器要求源音频覆盖派生视频时长，渲染前以 `WorkerExportAudioTooShort` 失败。局部正式验证只验证采样画面，不执行整曲音频编码，故成功不代表可以导出。

## 已确定的行为

- 保留 `CompositionFramePlan` 的帧数、帧时刻和有理时长。
- 受管导出有音频时统一重编码：短源通过 `apad` 补静音，长源按计划 `-t` 截断，不使用 `-shortest` 缩短画面。普通 MP4 使用 AAC，透明 MOV 使用 PCM16。
- 工程既无音频声明也无受管音频时，无论请求 `includeAudio` 为何，固定有效选项为 false，输出纯视频。声明音频但授权缺失仍失败。
- 保留来源授权、SHA、大小、封闭格式、完整严格解码、资源预算、取消、成片帧数和实际音轨时长校验；取消源长度不足这一项阻断。
- `audioDurationUs` 记录真实源时长，`actualAudioDurationUs` 记录实际成片音轨时长，后者与计划相差最多 50 ms。报告和界面说明补静音、截断、无音频与局部验证范围。
- 补静音仅发生在编码阶段。分析不延长、不伪造，效果沿用现有缺失分析／范围外语义；显式必需分析的原诊断保留。
- 工程格式未变，0.114.1 仅额外允许读取 0.114.0 工程，读取不改写原文件；其他版本与 schema 保护保留。用户显式保存时按当前版本写盘。

## 验证与交付

新增用例先在旧实现失败，再验证修复后的短源、长源、无音频、损坏及报告拒绝规则。执行后端完整构建、相关回归、前端类型与单元测试，生成 metadata 合同并同步双端。发布同源 Server/Worker 后进行隔离 profile 的真实 HTTP 导出，核验下载 SHA、实际帧数、完整解码和尾部静音；真实工程使用副本，原工程保持不变。最后打包、验证 AppImage 并替换本机安装与启动器。

具体执行结果在完成验收后追加；静态合同、测试、HTTP、桌面启动与完整工程导出分别记录。
