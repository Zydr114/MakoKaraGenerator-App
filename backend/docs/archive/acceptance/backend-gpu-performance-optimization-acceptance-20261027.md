本批遵循[调研报告](../research/backend-gpu-performance-optimization-research-20261027.md)的优先级，完成三项内部优化：

1. **成功预乘验证去重。** 内部拥有的不可变 `SKImage` 及其非拥有别名共享成功事实，仅同设备可以复用。外部 `Borrow`、跨设备消费和新图像仍检查；像素验证失败或验证阶段取消不登记成功，验证完成后的其他阶段失败不撤销该成功事实。拥有者释放使事实永久失效，别名不延长图像、设备租约或预算生命周期。结构、句柄、kind、几何、密度、sRGB、尺寸和预算检查仍执行。
2. **无 ruby 的判空读回。** `RubyAnnotations.IsEmpty` 可证明 ruby 原始颜色部件没有绘制内容时，只省略捕获后的 alpha 读回。`CaptureColorPart`、几何／透明度检查、实际表面创建、绘制、预算预留及原顺序保留。没有省略作者材质执行，也没有减少捕获表面数。被省略的读回本身不再执行，不能宣称其设备故障仍会出现。
3. **有界临时数组复用。** 原始部件在单对象状态内保留一个最多 16 MiB 的数组，超限使用临时数组并释放旧引用。图像验证和 masked 覆盖使用独立进程级池，最多保留 3 个数组、单个不超过 16 MiB、合计不超过 32 MiB；租约释放幂等，异常和取消归还，超限不入池，扫描只访问有效像素长度。这两个上限独立，不是总进程或 GPU 内存上限。

公开端点、DTO、CPU/GPU 选择及失败不回落、项目格式和依赖版本保持。完整图域的非法预乘及 masked 越界检查保留；未实施同帧作者图共享、验证与 masked 读回复用、GPU 小结果归约、同步边界调整或 ROI。
