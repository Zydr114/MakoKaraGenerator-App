# 作者草稿替换包内素材：设计

日期：2026-11-08。阶段一遗留项“资源导入事务”的收窄版本，范围由用户 2026-11-08 确认：
在作者草稿里替换已有 `.mkfx` 包内的图片、字体和 SVG，不做别的。验收按 M10／M11 的放宽口径。

## 1. 范围

**做：**
- 作者草稿的包文件列表里，图片、字体、SVG 文件各有一个「替换…」，选本机文件整份换掉。
- 换完与改文本一样算一处改动，「保存修订」时和文本一起生成新的源码修订；SDK v2 草稿照旧要编译通过再采用。
- 修订历史、撤销采用、`.mkfx` 下载都沿用现有流程。

**不做：**
- 不能新增、删除、改名文件，不改文件用途（role），清单不暴露给这项功能编辑；
- 视频（`video`）和其他二进制（`asset` 等）不能替换；
- 不在工程里已安装的效果上直接替换；
- 不做完整的 `.mkfx` 编辑器。

## 2. 现状

- `PUT /api/v1/drafts/{id}/package-files` 保存清单和全部可编辑文本。SVG（role `svg`）本来就是可编辑文本；
  图片、字体等二进制要求 path、role、sha256 都不变，字节取自最新源码修订（`ProjectSessionRegistry.AuthorPackageFiles.cs`）。
- `POST /api/v1/assets` 已能上传图片和任意二进制（字体按 `application/octet-stream`），导入 `.mkfx` 就走这条路。
- 包内字体按家族名参与匹配（`SkiaTextLayoutEngine` 固定字体目录）：文字样式写的家族名和字体文件里的不一致时，
  这份字体只在按字符回退时才可能用到。
- 草稿每个源码修订各存一份完整包，按客户端 256 MiB 计配额；单文件上限 64 MiB，整包 256 MiB。

## 3. 后端

### 3.1 保存请求加替换列表

`AuthorPackageFilesRequest` 新增两个可选字段：

| 字段 | 含义 |
|---|---|
| `replacedFiles` | `[{ path, assetId }]`，省略或 null 表示不替换。每个 path 只能出现一次 |
| `baseSourceRevision` | 编辑器所看的源码修订，必须在草稿保留历史里。不可编辑的文件从这个修订取；省略时取最新修订（原行为） |

`baseSourceRevision` 是必须一起补的：替换以后，不同修订的图片可能不同。作者查看旧修订、改了文本再保存时，
清单里写的是旧修订的哈希，如果仍按最新修订核对就会被拒绝。

替换的规则：
1. path 必须是基准修订里已有的文件，role 只能是 `image` 或 `font`。SVG 走文本，不进这个列表。
2. 清单里这个文件的 path、role 不变，sha256 仍写基准修订的值（证明客户端是在看到的版本上替换的）；后端用新字节重算。
3. 资源须属于本客户端、未过期；大小不超过包单文件预算。
4. 新文件的格式必须和原文件相同：
   - 图片按 Skia 实际识别的编码格式比较（PNG 只能换 PNG，JPEG 只能换 JPEG）；
   - 字体按文件头分为 TrueType、OpenType（CFF）、字体集合三类比较。
5. 新文件必须通过和渲染相同的检查：
   - 图片用 `PackageImageValidator` 完整解码，受同一尺寸预算限制；
   - 字体用固定字体目录的同一套加载代码读出每个字形的家族名。
6. 尺寸不同、家族名不同都只提醒，不拒绝（§3.2）。

失败时不生成新修订，错误带 `field`（`replacedFiles[i]`）和具名 `failureCode`：
- `AuthorReplacementTargetInvalid`：路径不存在、重复或 role 不能替换；
- `AuthorReplacementFormatMismatch`：格式和原文件不同；
- `AuthorReplacementFontInvalid`：字体读不出；
- 图片解码和预算沿用 `PackageImageDecodeFailed`、`PackageImageBudgetExceeded`；
- 资源不存在、无权访问沿用资源库的错误。

### 3.2 只读检查

`POST /api/v1/drafts/{id}/package-file-replacement-inspection`，请求为
`{ expectedDraftRevision, sourceRevision, path, assetId }`，不改变草稿，也没有回执。

返回原文件和新文件各自的信息：
- 格式、字节数、sha256；
- 图片的宽高，字体的家族名。

另返回提醒列表 `warnings[{ code, message }]`：
- `imageSizeChanged`：图片尺寸变了。按像素裁切或假定尺寸的效果可能要调整。
- `fontFamilyChanged`：家族名集合变了。工程、模板里按旧名字引用的文字不会用到新字体。

检查和保存走同一套校验，所以检查能通过的文件，保存时不会因格式被拒绝；保存时仍会重新校验。

### 3.3 版本

新增接口和可选字段都是加法：HTTP 合同升到 1.49.0，产品版本升到 0.112.39。

## 4. 前端

- 包文件列表里，图片、字体文件的只读详情区增加「替换…」。
- **选择文件后**：先上传，再调用检查。详情区写出原文件和新文件的格式、大小、尺寸或家族名，提醒用醒目样式显示；
  文件列表标上改动点，「保存修订」可用。可以「撤销替换」。
- **SVG**：编辑器工具栏增加「用文件替换…」。按 UTF-8 严格解码后放进编辑器，跟手改一样，不经过新接口。
- **保存修订**：一次提交文本、`replacedFiles` 和 `baseSourceRevision`。成功后清掉待保存的替换，按新修订重读文件列表。
- **丢弃改动**：查看别的修订会丢掉待保存的替换，沿用现有的确认对话框。
- 不在前端解析图片或字体；格式、尺寸、家族名都以后端检查为准。

## 5. 验收

- **后端定向测试**：
  - 替换图片生成新修订，清单哈希已重算；替换字体同理；
  - 格式不同、role 不支持、路径重复或不存在、解码失败都被拒绝且不生成修订；
  - 按 `baseSourceRevision` 保存旧修订；
  - 检查接口返回尺寸和家族名提醒。
- **合同**：新元数据生成并校验 1.49.0，前端同步。
- **真实 Server**：上传 PNG，检查，保存，下载 `.mkfx` 核对新字节；字体家族名不同时检查返回提醒。
- **真实 Chrome**：导入 SDK2 样例 SpriteTrail，替换 `assets/spark.png`，保存、编译、采用，试样画面随之改变。

## 6. 已知限制

- 每个修订存一份完整包，反复替换大字体会较快用满客户端 256 MiB 作者存储；超出时沿用现有的配额拒绝。
- 只比较格式，不检查新图片是否满足效果对尺寸的假设；尺寸变化只提醒。
- 字体只读第一层信息（家族名），不检查是否覆盖工程里实际用到的字。
