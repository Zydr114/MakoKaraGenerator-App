## 0. 2026-10-29 实测

动手设计前，用临时集成测试在真实 Server（0.107.0）上核对了合同没写细的行为。效果包用后端仓库 `samples/ScriptEffects` 的示例打成 `.mkfx`；曲线参数没有现成示例，另做了一个带两个曲线参数的 WordEmphasis 变体。

**草稿**
- 用上传的 `.mkfx` 建草稿（资源 ID、导出、名称）约 50 毫秒。初始配置：
  - 参数 `{}`，作用于“整个分配”（`application`），读取范围“绑定的来源”，叠放层“随包”；
  - 读回时，为空的 `branchInput`、`fixedSeed` 直接省略，不写成 null。
- `kind` 是领域分类：控制器和图导出都是 `Effect`，材质导出是 `Material`。注意首字母大写，与包导出的 `controller`／`material`／`graph` 不同。`bindingKinds` 取自导出，材质为空。
- 草稿只有一个名称：改配置里的名称，草稿名称跟着变。
- 导出不存在时返回 422 `commandRejected`，`field` 是 `exports.<导出>`，`failureCode` 是 `PackageExportMissing`。
- 草稿响应不记录它是从哪个配置建的。
- **归属**（§3 的 G33）：
  - 草稿只属于创建它的客户端。另一个客户端列表为空，读取返回 401 `resourceUnauthorized`（“作者草稿不属于当前客户端”）。
  - Server 重启后要登记新客户端，原来的草稿同样看不到、读不了。
  - 浏览器每个标签页是独立客户端（身份存在 sessionStorage），所以草稿只在本标签页里有效：刷新后能续接，换标签页或 Server 重启就找不回来。
  - 个人配置库属于 profile，不受影响。
- **配额**：每个客户端最多 16 个草稿，第 17 个返回 429 `requestQuotaExceeded`（`field: drafts`）。
- 删除要带精确草稿修订，修订过期返回 409；删除后读取返回 404。

**源码**
- `sources` 只返回 C# 文件，例如 WordEmphasis 只有 `src/WordEmphasis.cs`；`manifest.json`、README、着色器和图片都不返回。
- 保存源码必须一次提交“全部且仅全部”的现有 C# 文件。多一个文件、少一个文件、带上 `manifest.json`，都返回 400 `invalidRequest`（`field: files`）。所以不能加文件、删文件、改 manifest（§3 的 G34）。
- 修订按内容计算：
  - 内容相同时再保存是 no-op，草稿修订不变；
  - 改回原内容后，修订号和原包完全相同。
- 保存后，配置的 `packageRevision`、`sourceRevision` 都换成新修订；包 ID 和版本号不变。
- 旧修订还能按修订号读源码（例如原包的 `baseSourceRevision`）。但后端没有接口列出草稿保留了哪些修订（§3 的 G35）。
- **材质包和图包没有 C# 源码**（CustomInk、GlassInk、LineGlitch，内容是 `.sksl` 和图 JSON）：
  - 读源码返回 404“源码修订不包含 C# 文件”；
  - 编译返回失败，诊断是 `PackageCSharpMissing`；
  - 但草稿的 `canCompile` 仍然是 true（§3 的 R10）。

**编译**
- 同步编译第一次约 650 毫秒（冷启动），之后 13～35 毫秒。
- 异步编译返回 202，任务 `kind` 是 `author-compilation`，约 40 毫秒完成。任务里有 `authorCompilationInput`，结果从 `/jobs/{id}/compilation-result` 读。
- 编译只针对“最新修订”（`currentSourceRevision`），不一定是试样在用的那份。
- 编译失败时 `succeeded: false`。诊断包括编码（例如 `CS0103`）、编译器原文（英文）、是否错误、路径、行和列；行和列从 1 开始。
- 没编译过时，`GET .../compilation` 返回 404。草稿的 `lastCompilation` 是最近一次的摘要（含 `stale`）；保存新源码后摘要清空。

**草稿里的四个修订**
- `baseSourceRevision`：导入时的原包。
- `currentSourceRevision`：最近一次保存的修订。
- `adoptedSourceRevision`：最近一次“采用”的修订，开始时没有。
- `configuration.sourceRevision`：试样、验证和存进组件库时实际用的修订（下面称“在用修订”）。

实测：
- 保存源码后，在用修订只在它原来就是最新修订时跟着换成新修订；在用的是别的修订（例如采用了原包）时不变（2026-10-30 实施步骤 6 时发现，后端 `SaveAuthorSourceRevisionAsync` 也是这样写的；这里原先写成“不管之前采用过哪一份都立即换”，有误）。内容和最新修订相同时不新建修订。
- 采用某个修订 X 后，在用修订和采用标记都变成 X。采用不要求编译通过，编译失败的修订也能采用。
- 改配置时也可以直接指定在用修订（任一保留的修订），这时采用标记不变。

所以后端的“采用”实际是“改用某个已保存的修订”，常见用途是退回原包或退回更早的一版。

**配置**
- 改配置要提交完整配置，内容相同时是 no-op。
- 出错时会指出字段和原因，比模板校验（G31）好：
  - 参数越界：400，`field: parameters.peakScale`，`PackageParameterOutOfRange`；
  - 包里没有的参数：`field: parameters.nope`，`PackageSemanticUnknownField`；
  - 曲线、图片参数的错误也带字段（见下文）。
- 最大种子 18446744073709551615 原样保留。
- 可以换成同一个包里的另一个导出（GlassInk 的 `glass-media` 换成 `glass-backdrop`），草稿的 `exportId` 跟着变。
- 作用于改成“整行”后，试样目标里不再有 `token`。
- 材质只有参数：作用于必须是“整个分配”，不能设种子和叠放层。违反时返回 400 `AuthorConfigurationInvalid`（“源材质不创建控制器实例，也不保存事件订阅、种子或图元层。”），`field` 只写 `configuration`。
- 没有图元输出的效果，叠放层只能“随包”（“非图元效果不能覆盖图元层。”），与 W7 的本地规则一致。

**试样**
- 建 `authorDraft` 预览要写明 `previewKind: authorDraft`、`committable: false`。`authorSourceRevision` 必须等于在用修订，否则返回 409（`field: source.authorSourceRevision`）。
- 一次性取一帧（建会话、取帧、关闭）要 1.9～3.6 秒。
- 已开的会话可以 `PUT input` 换成同一草稿的新修订，约 0.5 秒，代次加一。换成工程来源返回 422 `commandNotSupported`。
- 画面与等价的模板试样相同：逐字、放大比例 3、第 3 秒，草稿试样和含同样配方的完整模板试样，帧 SHA 相同。参数改动能看出来：放大比例 1.25 和 3 的帧不同。
- 材质草稿必须指定材质部位：不指定返回 400（“材质配置必须提供合法材质槽位”）；三个部位的帧各不相同。效果草稿的 `sampleOptions.materialSlots` 为空。
- 两点观察（模板试样也一样，不是缺陷）：
  - 第 3 秒时单行样本与多行样本的帧相同；
  - 目标选“文本单元”时，逐字强调看不出变化。
- **失败**：
  - 源码编译不过：会话进入 `failed`，`renderFailureCode` 是 `WorkerPackageCompilationFailed`。预览诊断里有编译诊断（编码、路径、行、列，`originKind: compileSource`），每个效果实例重复一条。
  - 运行时抛异常：抛出之前的时刻照常出帧，之后是 `ScriptExecutionFailed`。
  - 死循环：约 26 秒后报 `WorkerPackageTimedOut`。

**作者验证**
- 创建返回 202，任务 `kind` 是 `validation`。输入里有 `sourceKind: authorDraft`、`sourceProfile: author-script-sample-v1`，以及固定规格：640×360、30 fps、12 秒、每个输出 360 帧，还有渲染设备。
- 正常的包约 2.9 秒跑完 720 帧（不透明和透明两个输出）。报告包括是否通过、不透明帧数、透明帧数、问题、诊断和渲染设备。
- 源码编译不过：任务失败，0 帧。编译诊断在报告的 `issues` 里，`validation-diagnostics` 接口返回空列表。
- 运行时抛异常：在 2.008 秒失败，61 帧。问题的编码是 `ScriptExecutionFailed`，消息里有包、修订、导出和异常原文，诊断接口也列出了它。

**个人配置库**（下文叫“组件库”）
- 初始修订是 `missing`，之后是 64 位十六进制。
- 命令有五种：新建、替换、复制、改名、删除。复制允许重名。
- 新建和替换有三种来源：草稿的某个修订、库里的另一个配置、包引用（例如刚上传的 asset 引用）。
- 列表的摘要有名称、`kind`、包 ID、包修订、导出和 `bindingKinds`，没有包的名称和版本号。
- 详情要带精确库修订，过期返回 409。详情给出完整配置和完整包检查结果；包引用是 `configuration` 引用，其中 `configurationRevision` 就是库修订。
- 从草稿存进库的配置，在草稿删除和 Server 重启之后都还在，别的客户端也看得到。
- 后端没有接口把组件或草稿导出成 `.mkfx`（§3 的 G36）。

**用到模板里**
- 把配置详情的包引用放进 `packages`，再加一个带 `configurationId` 的配方：试样选项和保存都正常。读回后，包引用变成 `library` 引用，配方保留 `configurationId`。
- `configuration` 引用钉在库修订上：组件库改名后，旧引用返回 409（`field: reference.configurationRevision`），与 W7 的 `library` 引用一样。
- 组件删除后，已保存的模板照常出试样（包已经复制进模板）。
- `configurationId` 只记录来源：
  - 配置引用加 `configurationId: null` 可以；
  - asset 引用加 `configurationId` 也可以；
  - 配方参数与配置不同也可以。
- 同一包 ID 的两个修订（原包和改过源码的）可以放进同一个模板。
- 同一个包（ID 和修订都相同）写两个引用（asset 和 configuration 各一个）时被拒绝，消息只有“完整草稿未通过模板校验”，没说原因（又是 G31）。
- 材质配置可以作为模板的包材质。

**曲线与图片参数**
- 曲线有三种形式（后端 `EffectPackageParameterParser`，求值见 `CurveValue`）：
  - 缓动：`{"easing":"linear|easeOut|easeInOut","kind":"easing"}`。easeOut 是 1−(1−p)³，easeInOut 是 3p²−2p³。
  - 贝塞尔：`{"first":[x,y],"kind":"cubicBezier","second":[x,y]}`。x 在 [0,1]，y 可以过冲：(0.3,−0.5)、(0.7,1.6) 都接受。
  - 折线：`{"kind":"controlPoints","points":[[0,0],…,[1,1]]}`。首尾固定，x 严格递增，y 可以不单调。
- 检查结果里的默认值是键按名称排序的规范形式。
- 曲线不合法时返回 400 `PackageCurveInvalid`，`field` 指到参数或 `.points`，消息是中文，例如：
  - “折线须有首尾 (0,0)、(1,1) 且 X 严格递增。”
  - “曲线进度必须在 [0,1]。”
  - “未知缓动。”
- 图片参数的取值是包内路径，指向的文件必须是 `role: image`。SpriteTrail 只有一张 `assets/spark.png`（123 字节）；写 `README.md` 返回 `PackageParameterImageMissing`。后端没有读取包内图片字节的接口。

**能力**：`features` 里有 `author.drafts.*`（新建、列表、读取、源码、配置、编译、读取编译结果、保存源码、采用、删除）和 `script-configurations.*`（读取、详情、五种命令）；作者验证和作者预览没有单独的能力名。

## 2. 结构调整

### 2.1 协议与客户端

- 新文件 `src/protocol/author.ts`：
  - 草稿：`AuthorDraft`；读到的配置 `AuthorDraftConfiguration`（`branchInput`、`fixedSeed` 可省略）；写入用的 `AuthorDraftConfigurationInput`（可空字段显式写 null）；试样选项 `AuthorSampleOptions`；
  - 编译：`AuthorCompilation`、`AuthorCompilationSummary`、`AuthorCompilationDiagnostic`；
  - 源码与采用：`AuthorSourceFile`、`AuthorSourceRevisionResponse`、`AuthorAdoptResponse`；
  - 删除与验证：`AuthorDraftDeleteResponse`、`AuthorValidationJobInput`。
- 新文件 `src/protocol/script-configurations.ts`：摘要、详情、配置写入（来源三选一）、五种命令和命令回执。
- 修订都是字符串：
  - 草稿和源码修订是 `sha256:<64 位>`；
  - 组件库修订是 `missing` 或 64 位十六进制。
  - `fixedSeed` 沿用 W7 的原文处理（`model/json-text.ts`）。
- 补充已有类型：
  - `PreviewSource` 加 `authorDraft` 分支（`sourceId`、`sourceRevision`、`authorSourceRevision`、`templateSample`）；
  - 建会话和换输入的请求加 `previewKind`、`committable`；
  - 任务 `kind` 加 `author-compilation`，任务响应加 `authorCompilationInput`、`authorCompilationResult`、`authorValidationInput`。
- `MakoClient`：
  - `drafts.create`、`list`、`get`、`sources`、`setConfiguration`、`saveSources`、`compile`（异步，返回任务）、`compilation`、`compilationResult`、`validate`、`adopt`、`delete`；
  - `scriptConfigurations.list`、`detail`、`command`；
  - `preview.createAuthorDraft`：沿用名额满时退避重试（`withPreviewQuota`）。
  有副作用的请求沿用客户端回执。
- 能力判断：
  - 组件库看 `script-configurations.read`；
  - 编辑看 `author.drafts.create`；
  - 没有时，左栏“效果组件”页签写明“后端没有开放效果组件”。

```text
└──────┴───────────────────────────┴──────────────────────────────────────────────────────────────────────┘
```

- 左栏顶部两个页签：“模板”（W3、W7 原样）和“效果组件”。页签只是界面状态，在本标签页里记住上次选的。
- 效果组件页签分两组：
  - **草稿 · 本标签页**：本客户端的草稿，写明个数和上限（N/16）。有没保存到组件库的改动时，后面带一个点。
  - **我的效果组件**：组件库里的配置。每项写名称和类别（效果、材质），副标题写包 ID 和导出。摘要里没有包的名称和版本号，选中后在详情里显示。
- 搜索同时筛两组的名称。空态写“还没有效果组件 · [导入效果包…]”。
- 从模板页签切过来、或在两组之间切换时，模板草稿的未保存确认沿用 W7 的 `confirmDiscardTemplate`。作者草稿在后端，切走不会丢，不用确认。

### 2.3 组件库

新增 `ComponentLibraryStore`（不依赖 React），保存组件库修订、摘要列表和当前选中项。

**导入效果包**
1. 选 `.mkfx`，上传后检查（W7 的 `effectPackages.inspect`）。列出包名、版本、各导出（类别、名称）和诊断；结构无效时不能导入。
2. 每个导出前有勾选框，默认全选。每个勾选的导出在组件库里新建一项：
   - 名称：只有一个导出时用导出名；有多个导出时用“包名 · 导出名”；
   - 来源：上传得到的 asset 引用；
   - 参数 `{}`，读取范围“绑定的来源”，叠放层“随包”，种子不固定；
   - 作用于：效果按 W7 的默认规则（只写文本单元族的导出取“逐字”，否则“整行”），材质取“整个分配”。
3. 依次提交新建命令，用上一条的修订接下一条；完成后选中第一个新组件。

导入不建草稿（§9 决定 3）：组件库长期保存，草稿换标签页或 Server 重启就找不回来（G33）。

**选中一个组件**（没有在编辑）
- 详情区显示组件的名称、类别、包（名称、版本、包 ID、修订前 12 位）、导出、作用于、读取范围、叠放层、种子和参数摘要。这些都从详情读取。
- 试样：用内置“经典整行”做底，临时拼一个完整模板草稿，走 W7 的工坊试样：
  - 效果组件是一个配方，`configurationId` 填这个组件；
  - 材质组件放进“未唱填充”，材质焦点也是它。
  不写库。
- 操作：“编辑”（§2.4）、“复制…”、“改名…”、“删除…”。删除时写明“已经用在模板里的不受影响”。
- 组件库修订过期（409）时重读列表；当前项还在就重读详情，然后让用户再点一次。不自动重放命令。

### 2.4 作者草稿

**生命周期**
- 草稿是一个组件在后端的工作副本：包的副本加上配置。
- 草稿属于本标签页的客户端：刷新页面能续接；关闭标签页或 Server 重启后找不回来（G33）。草稿详情区顶部常驻一行说明：“草稿只在这个标签页里保留，保存到组件库才会长期保留。”
- **编辑**：组件上点“编辑”，就以组件为来源新建草稿（组件 ID、库修订、导出、名称）。
  - 后端不记录草稿来自哪个组件，前端把“草稿 → 组件”的对应记在 sessionStorage（`mako.author-draft-origins`），按客户端 ID 区分。
  - 本标签页里已经有这个组件的草稿时，直接打开它。
- **上限**：草稿已有 16 个时，“编辑”停用，写明“草稿已有 16 个，先关闭不用的草稿”。
- **关闭草稿**：删除草稿。有没保存到组件库的改动时先确认：“草稿里的修改没有保存到组件库，关闭后找不回来。”
- **离开**：
  - 在应用里切页面不提示，草稿还在。
  - 关闭或刷新标签页时，如果有草稿没保存到组件库，或者源码编辑器里有没保存成修订的改动，用浏览器的离开提示。
  - 刷新本身能续接草稿，但编辑器里没保存成修订的文字会丢。
- **Server 重启**：连接层报告 `hostRestarted` 后，草稿组清空，并说明当前页面尚未提供草稿恢复，已保存的组件仍可使用。后端持久草稿并未因此删除。

**是否已保存到组件库**
- 有来源组件时，比较草稿配置和组件详情：名称、导出、参数、作用于、读取范围、输入名、种子、叠放层和在用修订。不一样就标“未保存到组件库”，一样就标“已保存”。
- 来源组件已删除，或者对应关系丢了：只能“另存为新组件”。

**保存**
- 有来源组件：主按钮“保存到“X””，用替换命令，来源是“草稿 + 草稿修订 + 在用修订”。
- 任何时候都可以用“⋯ → 另存为新组件…”，输入名称后新建，并把对应关系改成新组件。
- 保存前检查两件事：
  - 源码编辑器里有没保存成修订的改动：提示“编辑器里的改动还没保存成修订，组件会用在用修订 xxxxxxxx”，可以“先保存修订”或“仍然保存”。
  - 在用修订没有编译通过（失败，或者没编译过）：提示“这个修订还没有编译通过，用到它的模板可能出不了画面。仍要保存吗？”。后端不要求编译通过。
- 组件库修订过期：重读列表后重试一次（替换是整份写入，重试是安全的）。

### 2.5 配置页签

- 字段：
  - 名称（也是草稿名称）；
  - 导出：同一个包里同类别的导出（效果是控制器和图，材质是材质）。换导出后参数清空，有改过的参数时先确认；
  - 作用于：整行、逐字、整个分配；
  - 叠放层：导出没有图元输出时只能“随包”，沿用 W7 的 `hasOverlay`；
  - 读取范围与输入名；
  - 固定随机种子；
  - 参数（§2.9 和 W7 的 `ParameterFields`）。
- 材质组件只有名称、导出和参数，其余字段不显示，并写一行“材质组件只有参数；作用于和叠放层由使用它的模板决定”（§0）。
- 作用于的可选项按导出判断：只沿用 W7 里与模板用途无关的规则（导出的 `bindingKinds`、输出）。和模板用途有关的限制，到“从效果组件选”时再判断（§2.10）。
- **提交**：
  - 控件提交（失焦、回车、滑块松手）后，停 300 毫秒合并成一次 `PUT`；
  - 同一时刻只有一条在途，用返回的草稿修订接下一条；
  - 期间又有新的改动时，只提交最新的一份。
- **校验**：
  - 提交前按 W7 的规则在本地校验：参数类型、范围、种子、读取范围要有输入名。有问题就写在控件旁，不提交。
  - 后端拒绝时，`field` 是 `parameters.<参数>` 的写在对应参数下，其他写在页签顶部。材质的 `AuthorConfigurationInvalid` 只有 `configuration`，直接显示后端原话。
- **撤销与重做**：
  - 页面内保留配置快照栈。撤销就是把上一份快照再 `PUT` 一次；
  - 后端没有草稿历史，离开页面后撤销栈不保留；
  - 快捷键是 Ctrl+Z、Ctrl+Shift+Z，焦点在源码编辑器里时归编辑器。

```text
│ [配置] [源码] [验证]                                                                                 │
│ 文件                         │  1  using MakoKaraGenerator.Scripting;                                │
│ ● src/WordEmphasis.cs        │  2                                                                    │
│                              │  …（CodeMirror：C# 高亮、行号、括号匹配、诊断波浪线）               │
│ 修订                         │ 10      peak = contxt.Parameters.GetNumber("peakScale");             │
│  a071466d 最新 · 在用        │                ~~~~~~                                                 │

│ [保存修订 Ctrl+S] [编译]     │  ✕ CS0103  src/WordEmphasis.cs:10:16  The name 'contxt' does not …   │
```

**编辑器**（§9 决定 1）
- CodeMirror 6，只装这几个包：
  - `@codemirror/state`、`@codemirror/view`；
  - `@codemirror/commands`：撤销历史、默认按键、Tab 缩进；
  - `@codemirror/language`：高亮、括号匹配；
  - `@codemirror/legacy-modes`：`clike` 里的 `csharp`；
  - `@codemirror/lint`：诊断标记。
- 不带补全、搜索面板和格式化。
- 新文件 `library/SourceEditor.tsx` 只是一层 React 包装。第一次打开源码页签时才动态 `import`，打成单独的分块，不增加首屏体积。配色跟随 mdui 的浅色和深色主题。
- 打开的是**在用修订**的文件。左侧是文件列表，改过的文件前面带点。每个文件的编辑内容、撤销历史和光标留在页面内存里，切文件不丢。

**没有 C# 源码的包**：读源码返回 404 时，页签说明当前编辑器只支持 C#，材质和图的包文本编辑尚未接入，不显示编译。读取的在用修订与 `canCompile` 判断的最新修订可能不同，仍以源码读取结果判断编辑能力。

**保存修订**（Ctrl+S）
- 一次提交全部 C# 文件。成功后写“已保存为修订 xxxxxxxx，试样已改用它”。后端只在在用修订原来就是最新修订时让它跟着换（§0）；不是时，前端再提交一次配置，只把在用修订换成新修订（采用标记不变）。
- 内容没变化时写“内容没有变化”。

**编译**
- 用异步编译，沿用任务进度与取消；完成后读编译结果。
- 编译的是**最新修订**（§0）：
  - 按钮写“编译最新修订（xxxxxxxx）”；
  - 编辑器有改动时，按钮变成“保存并编译”；
  - 在用修订不是最新修订时，再写一行“试样在用的是 yyyyyyyy”。
- 诊断列表：错误、警告，`路径:行:列`，编译器原文。点一项就跳到对应文件和行；当前文件的诊断同时以波浪线和行号旁的标记显示。
- 编译结果标明对应的修订。源码再保存后，结果标“已过期，需要重新编译”。

**修订**
- 列出已知的修订，每行写修订号前 8 位和标签：原包、本页保存、最新、已采用、在用。
- 当前页尚未接入 1.40.0 的修订列表（G35）。“本页保存”是前端从保存回执里记下来的，记在 sessionStorage，按草稿区分；换标签页或丢失后只剩原包、最新、已采用、在用四个。
- 每行有两个操作：
  - “查看”：把这个修订读进编辑器。在它上面改完再保存，就成为新修订。编辑器有没保存的改动时先确认。
  - “改用此修订”：调采用接口，在用修订换成它，试样跟着变。

### 2.7 验证页签

- 运行条件：
  - 默认用试样画布当前的样本、目标和材质焦点，也可以在页签里改；
  - 渲染设备按顶栏偏好传 `renderBackend`，规则同渲染设备批次。
  - 写明固定规格：640×360、30 fps、12 秒，不透明和透明各 360 帧。
- 运行中显示进度（已完成帧数／总帧数、阶段），可以取消。
- **报告**：
  - 结论：通过或失败，不透明和透明各完成多少帧，实际用的设备。
  - 问题列表：时刻（m:ss.mmm）、编码、消息（`message` 为空时取 `diagnostic.message`）、来源（编译或运行）。有路径和行的，点击后跳到源码页签的对应行。
  - 诊断分页沿用 W5 导出页的读取方式。编译失败时诊断接口是空的，问题全在 `issues` 里（§0）。
- **需重新验证**：报告记着草稿修订和在用修订。草稿再改（配置或源码）后，结果上方写“草稿已经改过，结果对应旧版本，需要重新验证”。
- 最近一次验证的任务 ID 按草稿记在 sessionStorage，刷新后在任务保留期内能重读报告。

### 2.8 试样画布

- 沿用 W7 的 `TemplateWorkshop` 界面：样本、目标、材质焦点、时刻、试播与循环。来源新增“作者草稿”：
  - 每个草稿保持一个预览会话；
  - 草稿修订、样本、目标或材质焦点变了，用 `PUT input` 换输入，不像模板试样那样关掉重建（§0）；
  - 目标和材质部位取草稿的 `sampleOptions`；
  - 材质草稿必须选部位，默认“未唱填充”；效果草稿不显示材质焦点。
- 失败时显示的文字：
  - `WorkerPackageCompilationFailed`：“脚本编译失败”，并列出预览诊断里的前几条（编码、路径和行列相同的只算一条），加“在源码页签查看”；
  - `ScriptExecutionFailed`：“脚本运行出错”，后面跟诊断的消息；后端没有返回详细诊断时，指引到验证页签运行检查（R11）；
  - `WorkerPackageTimedOut`：“脚本运行超时（约 25 秒没有返回）”；
  - 其他沿用 `errorText`。
- 换草稿、离开样式库、草稿关闭时都要关闭会话（W7 的教训，`a99423a`）。

### 2.9 曲线与图片参数（§9 决定 2）

W7 的 `ParameterFields` 由材质页签、效果页签和草稿的配置页签共用。两类参数从“只读 JSON 原文”改成图形控件，模板里的材质和效果同样能编辑。

**曲线**（新文件 `library/CurveField.tsx`，纯函数在 `model/curves.ts`）
- 一个约 160×160 的 SVG 图：横轴是进度 0～1，纵轴范围自动包住曲线，至少是 −0.25～1.25。上方选类型：缓动、贝塞尔、折线。
- **缓动**：下拉选线性、减速（easeOut）、先加速后减速（easeInOut），画出对应曲线。公式见 §0。
- **贝塞尔**：
  - 两个控制点可以拖。x 限制在 [0,1]，y 不限（允许过冲）；
  - 下面有 x1、y1、x2、y2 四个数字框；
  - 曲线用与后端相同的二分法求值（56 次迭代）来画。
- **折线**：
  - 首尾两点固定在 (0,0)、(1,1)；中间的点可以拖，x 限制在左右邻点之间（至少相差 0.001）；
  - 在空白处双击加一个点；选中一个点后按 Delete 删掉。
- **换类型**时按近似转换：
  - 缓动转贝塞尔取常用预设：线性 (0,0)(1,1)，减速 (0,0)(0.58,1)，先加速后减速 (0.42,0)(0.58,1)；
  - 贝塞尔转折线取 5 个采样点；
  - 折线转缓动取“减速”。
- 拖动中只更新画面，松手才提交。数值保留 4 位小数，写出时键按名称排序（与后端的规范形式一致）。
- 本地校验与后端一致（§0）。图形控件本身不会产生不合法的曲线；原文不合法时显示原文和“恢复默认”。

**图片**（新文件 `library/AssetField.tsx`）
- 下拉列出包里 `role: image` 的文件，写路径和大小。当前取值不在列表里时，显示为“（包里没有这个图片）”。
- 后端没有读取包内图片的接口，所以不显示缩略图（§8 写进已知限制）。

### 2.10 模板里“从效果组件选”

**效果页签**
- 效果页签保留 W7 原有的包导出列表，另加“从效果组件选…”按钮，打开只列效果类别的选择器；材质页签复用同一轻量选择器。
- 选一个组件后，新配方按组件填写：
  - 名称、作用于、包 ID 和修订、导出、参数、叠放层、读取范围与输入名、种子都取组件的；
  - 启用；`configurationId` 填这个组件。
- 配方之后照常可以改，改了不影响组件。组件库以后更新，模板也不跟着变（整体设计 §5.5.2）。
- 与模板用途不合的组件列出但不能选，并写明原因，规则同 W7 的 `targetProblem`、`exportProblem`。例如文本单元模板不能用作用于“整行”的组件。

**材质页签**：包材质区加“从效果组件选…”，列出类别是材质的组件。选中后，这个部位改成组件的包材质：包 ID、修订、导出和参数。材质没有 `configurationId` 字段，所以不显示来源。

**包引用**
- 模板的 `packages` 里已经有同一个包（ID 和修订都相同）时，沿用原来的引用，不再加一个（§0：后端不接受重复）。
- 没有时，加入组件详情给的 `configuration` 引用，并把详情里的包检查结果放进 W7 的包目录。

**来源显示**：W7 写的“来自效果组件 {ID}（W8）”，改成按组件库列表找名称，写“来自效果组件“X””；找不到时写“来自效果组件（已删除）”。

**引用过期**
- `configuration` 引用钉在组件库修订上（§0）。模板草稿还没保存时，如果组件库变了，按 W7 的包引用重定位办法，重读涉及的组件详情，换成新引用。
- 组件已删除时没法重定位，写明“效果组件“X”已经删除，请移除这个效果后重新添加”。
- 模板保存后，引用变成 `library` 引用，由 W7 的逻辑接手。
