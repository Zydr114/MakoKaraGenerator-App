# 通用容器与歌词编排编辑器：现状复核及设计建议

> 日期：2026-10-01；审查基线：0.7.0，注音修订交付为 0.7.1。
> 状态：**原合同已批准，0.8.0 G1～G4 完成且基本编排流程已获人工确认；0.8.1 已按批准方案优化体验，待人工验收**。[实施合同](scene-editor-implementation-contract.md) §8 保留 0.8.0 证据，最新 [UI 优化方案](scene-editor-ux-optimization-plan.md) §13 记录 0.8.1 代码、真实控件验证及验收路线。本文 §1～7 保留 0.7.0／0.7.1 调研及方案形成过程，不代表当前代码仍有这些限制。树中拖动槽位改变轮换顺序已实施（ADR-0066）。
> 依据：ADR-0063、[当前架构](../history/current-architecture.md)、[完整案例](../plans/lyric-exclusive-display-case-plan.md)及用户要求“提供全面的编辑功能，不把双行布局特殊化”。

## 1. 结论

**0.7.0 已将持久化容器和父子变换统一；下一步要统一编辑目标与展示编排。**

双行可以准确理解为“通用歌词容器采用两个槽位的轮换预设”。源歌词继续保存文字、演唱时间与样式；容器承载位置和内部布局；显示程序把源内容装入容器。单槽、双槽、三槽及更多槽位沿用同一机制。

用户提出的高度自定义方向符合现有数据模型的演进方向。当前仍有明确边界：树节点通用，歌词装载规则和界面入口尚未全部通用；不能据此声称已经提供完整场景编辑器。

## 2. 0.7.0 审查基线的实现与局限

| 层面 | 当前代码事实 | 后续缺口 |
|---|---|---|
| 容器存储 | `SceneContainerDefinition` 保存 Id、ParentId、Placement、ReferenceRect、可选 Layout；纯组、常规容器、独立容器和槽位共用该类型 | 缺少用户可编辑的名称与结构管理入口 |
| 位置与层级 | `SceneContainerGeometryResolver` 按真实父链计算矩阵；父组变换自动影响子节点 | 缺少任意节点选择、父级重挂及坐标解释界面 |
| 槽位 | `LyricContainerLayout.SlotIds` 是有序节点 ID 列表；位置只保存在节点；校验允许一个或多个槽位 | 缺少增删、复制、重排、数量与容量预演 |
| 调度 | 按 `ordinal % Slots.Length` 分配，已有单槽／三槽回归测试 | `DualLineAnimationProfile`、`DualLineAnimationScheduler`、`SceneLocalLayout.DualSlots` 等名称仍沿用旧双行口径；三槽不等于自动同时显示三句，还要设置同屏上限和触发规则 |
| 位置编辑 | `ScenePlacementTarget` 仍列举 Container、Line、SlotOne、SlotTwo；VM 列表最多暴露前两个槽位 | 第三个槽位、常规子容器及独立容器尚不能统一从画布或列表选择编辑 |
| 显示程序 | 每个源分支一个程序、一个常规容器、若干单句独占片段；独占可复用不同独立容器 | 无法直接编辑“前段双槽、后段三槽”等多个常规展示片段 |
| 独占归属 | 已能绑定源 LineId 与独立容器，严格按源行时间切换 | 新建、修改、恢复常规显示和影响预演没有 UI |
| 槽位内单句位置 | 运行时使用槽位参考锚点；旧 Line Placement 在槽位模式不生效 | 用户已确认开放明确的单句局部微调；具体合同已批准，不能直接启用过去被忽略的行位置 |
| 文字与注音 | 从源行／元素生成运行 Text 节点；注音绑定 BaseTokenId，继承基础文字最终矩阵和进度 | 全面注音编辑入口未开发；同一源行多个同时活动实例也未开放 |
| 绘制 | 当前绘制仍以歌词 SceneFrame.Lines 为入口，世界几何统一 | 任意图像、媒体、粒子叶节点不属于当前已实现能力 |

证据入口：Core 的 `SceneContainerDefinition.cs`、`LyricPresentationDefinition.Tree.cs`、`PresentationEditor.cs`、`Validation/PresentationValidator.cs`；Rendering.Abstractions 的 `SceneDefinition.cs`、`LyricSceneSampler.cs`；App 的 `EditorViewModel.Placement.cs`、`BranchSettingsWindow.axaml.cs`。

## 3. 统一的用户概念

编辑器围绕三个对象组织：

1. **源歌词**：文字、行／元素时间、翻译关联、注音和样式模板应用。沿用歌词行编辑器。
2. **容器树**：共同父组、内部布局、槽位及其位置。位置修改通过选中的稳定 NodeId 发起。
3. **展示编排**：哪些源行在哪个片段交给哪个容器、如何轮换和交接。源时间只有一份。

双行和三行作为可修改的布局预设出现。预设负责创建初始节点及参数，创建之后用户可继续修改槽位数量、次序、位置和容量。任何预设都不引入专用歌词子类型。

```text
主歌词展示组
  ├─ 前段布局容器（槽位序列）
  │   ├─ 槽位 A → 本次装载的歌词 → 该句注音
  │   └─ 槽位 B → 本次装载的歌词 → 该句注音
  ├─ 副歌布局容器（自由定位）
  │   └─ 本片段的歌词 → 该句注音
  └─ 后段布局容器（槽位序列）
      ├─ 槽位 C
      ├─ 槽位 D
      └─ 槽位 E

展示片段：前段 → 副歌 → 后段
源歌词：持续保留原 LineId、TokenId、文字、时间、翻译关联和样式
```

此图描述目标编辑能力；当前程序存储仍只有一个常规容器和单句独占列表。

## 4. 建议的编辑界面

### 4.1 在现有布局模式形成同一工作区

建议复用主窗口画布，左侧为窄容器树，右侧为所选对象属性，下方为紧凑的展示片段列表。顶栏明确当前选中的对象、父级、作用范围与预演状态。显示位置和文字打轴保留各自入口。

- 容器树展示持久化节点；本帧歌词与注音显示为源关联内容，附当前 LineId 和槽位装载状态。
- 单击选择节点，画布与属性面板同步；提供“选择父组”“进入子项”，重叠对象可用候选列表选择。
- 原先“容器／槽位一／槽位二”下拉改为动态 NodeId 选择。节点数量增加时自然扩展。
- 节点创建、复制、删除在树顶部或右键第一层展示；次要操作直接可见，避免堆叠底部按钮及多级“更多操作”。
- 属性面板按“位置／内部布局／展示关联”分组；名称、父组、参考尺寸、锚点、位置、旋转、缩放直接显示。自动布局的控制对象和影响范围必须可读。
- 片段选择可跳到区间试样；同时列出首／末源行、容器、布局和冲突。波形与行时间编辑仍沿用已有歌词编辑区。

具体窗口组织、1400×880／940×640 稿及原型检查见[实施合同 §5](scene-editor-implementation-contract.md#5-ui-合同)，尚未转化为程序界面。

### 4.2 通用容器与槽位操作

创建纯组、歌词容器或槽位时采用同一节点位置合同；角色由父关系、布局引用和显示绑定解释。复制容器需先显示子树和关联范围，不自动复制源歌词或展示片段。

槽位序列采用可重排列表：用户可增加、删除、复制、拖动排序，也能逐项选择画布对象。列表顺序是轮换顺序，树排列和绘制顺序另行表达，避免一处拖动改变两种含义。

更改数量、顺序、触发与容量时，预演显示受影响的歌词分配、可见区间及冲突。明确区分“槽位数量”和“最大同屏句数”；三槽预设应同时给出相应容量和时序参数。

删除受引用节点时先给出影响清单。仍被片段引用或会使布局无有效槽位的操作必须阻断，用户先解除或调整关联；不能静默丢失歌词显示。

### 4.3 歌词归属与片段操作

在歌词行编辑器显示当前展示归属，并提供进入编排对象的快捷入口。创建独立居中显示时选择已有容器或新建容器，预演源区间、共同父组和冲突；样式继续在歌词行编辑器套用。

用户已确认通用片段方向：选一段源歌词创建片段，为其选择布局容器；前段双槽、副歌自由定位、后段三槽均使用同一操作。普通片段和单句片段共用片段选择、修改和删除流程。多句区间已确认由首句行起点至末句行终点并随源时间更新；连续成员、缺失时间及删除后归属的具体规则见已批准合同。

移除片段前须说明成员接下来交给哪个片段／容器。未定时成员不能猜展示区间。直接跳转与播放、预览与导出共用片段解析和时间采样。

### 4.4 单句与槽位的关系

槽位位置定义所有装入该槽位歌词的参考位置。建议另设“本句局部微调”对象，明确只作用于当前源行在该展示归属中的文字；更改该对象无需移动槽位或其他句。

建议变换顺序：父容器世界矩阵 × 槽位静态变换 × 文字参考锚点／单句局部微调 × 本句动画。注音继承文字最终矩阵，翻译继续遵循自身展示归属。

用户已确认开放这项能力；它涉及现有“槽位模式禁用行位置”语义及数据合同，具体字段与编辑命令需另行设计批准。旧 Line Placement、局部偏移与自动布局求解结果不得相互充当隐含替代值。

## 5. 数据和用例改造建议

以下均为下一阶段候选合同，本轮未修改 schema。

- 保留 nodes 为唯一容器位置来源；增加用户名称时写入节点，显示标签与稳定 ID 分开。
- 用基于 NodeId 的纯命令编辑节点位置、参考尺寸、父级和布局。位置编辑无需选中某句才能操作纯组；TrySetTree 继续作为整体校验接缝。
- 将固定 SlotOne／SlotTwo 目标替换为节点引用；把调度器及运行枚举名称收口到 SlotSequence，内部算法按实际槽位列表求值。
- 按已确认的分段编排方向，建议将程序的 RegularContainerId／ExclusiveClips 演进为有稳定身份、源成员集合、目标容器及区间依据的片段集合。首期维持每句一个活动归属，避免顺带引入多实例样式优先级。
- 源歌词负责演唱时间；展示片段解析负责可见区间与切换；局部布局负责文字如何放入容器。显示区间不得靠修改源时间实现。
- 稳定节点 ID、片段 ID、源 ID 与本次 BindingId 分开；重排和改名不重新生成 ID，运行帧不写盘。
- 必要 JSON 改动提升程序 MINOR 及对应 schema，按既有版本门禁拒绝旧工程，不追加旧格式兼容。

全部用例先形成不可变草稿，预演完整影响，提交后一步撤销；取消和无变化不增加历史。源时间、树结构、片段归属及删除造成的失效引用使用统一校验。预演期间若工程改变，拒绝过期草稿。

## 6. 必须明确的产品决策

| 事项 | 本轮建议 | 状态 |
|---|---|---|
| 是否支持前段双槽／后段三槽等通用片段 | 支持同一分支分段选择容器和布局 | 用户已确认 |
| 槽位轮换中的单句局部微调 | 开放明确的局部变换，影响范围为该句 | 用户已确认 |
| 重挂父级后的坐标 | 保持画布位置、旋转和大小，换算局部参数 | 用户已确认；矩阵和参考尺寸转换见实施合同 |
| 多句片段的区间依据、间隙及边界 | 首句行起点至末句行终点，随源时间更新；边界直接切换 | 用户已确认区间；内部采样及阻断规则见实施合同 |
| 插入／删除／重排槽位后如何调度 | 暂停布局编辑播放，预演整段分配；按新顺序从第一个槽位重新分配 | 用户已确认整段重新分配 |
| 默认归属、删除片段与节点复制 | 默认容器接收未分配成员；删除片段回默认；复制子树不复制绑定 | 实施合同中具体化，用户已批准 |
| 在模板工坊制作布局预设 | 首期给内置可修改预设，样式工坊继续制作样式 | 若需要用户可保存的布局预设，应另定存储和编辑入口 |

## 7. 推荐实施顺序与出口

1. **固定合同与交互稿（G0 审阅稿已完成）**：五项方向已确认并记录 ADR-0065；具体数据、删除／绑定规则及两尺寸 UI 见实施合同，批准后进入 G1～G4。
2. **原生节点编辑闭环**：动态 NodeId 选择、任意容器／槽位位置、纯组操作、命中与属性联动；保存重开、取消与一步撤销通过。新命令直接编辑原生树。
3. **槽位与布局闭环**：一／二／三／更多槽位增删复制重排、容量与时序预演；所有槽位均可选中、拖动、数值编辑，现有两槽用例作为其中一个验收样例。
4. **归属与片段闭环**：用户从源行选择容器、创建独立显示及批准的多句片段；同分支双槽→居中→三槽案例由用户完整制作，验证边界与冲突。
5. **单句局部编辑及清理旧适配**：按批准合同完成局部微调、重挂与删除；位置编辑不再依赖临时分支视图，清理双行专用名称和固定目标。模板应用仍保持既有责任边界。
6. **冻结脚本只读 SDK**：在容器、片段与绑定身份稳定后发布版本化只读投影；继续遵守主进程串行、仅样式调制、导出遇错阻止等 ADR-0061 合同。

验收必须包含由用户新建的结构，而非仅加载内置演示；包含三槽实际同时可见、深层父组、独立句、单句微调、翻译／注音、重挂、删除影响、撤销、保存重开、随机跳转及成片抽帧。新 UI 的自动探针与渲染像素证据都不能替代人工操作验收。

## 8. 本轮注音修订与验收记录

用户确认 0.7.0 双行布局正常显示，布局编辑中移动整体会带动组合变化。其余完整案例的细项没有逐项反馈；注音按截图反馈需修订。

原演示把 `qǐng zhào` 全部关联到「请」，定位因此围绕单字中心。用户明确选择按元素注音：请→`qǐng`，照亮→`zhào liàng`。0.7.1 按该选择构造两个注音，显式比例 0.4 避免相邻注音交叠，保留原源元素与时间；预览、导出、联合占用测量及注音进度沿用同一现行路径。

2026-10-01 用户确认注音恢复正常。验证以 roadmap §18.19 为准。该修订更新演示源数据；用户已保存的错误注音配置仍按原始数据读取，不静默改写。
