## 0. 2026-10-27 实测

动手设计前，用临时集成测试在真实 Server（0.106.0）上核对了几处合同没写细的行为。

**`project.applyEdits`**
- N 条修改只记一条历史，历史名是 `project.applyEdits`。一次撤销就全部还原。
- `editResults` 逐条返回原来的反馈，例如删除行的 `feedback.selection`。
- `changeSet` 总是 `requiresFullRefresh`。
- **数量有上限**：上限来自回执预算（64 KiB），不是条数。删除行 300 条可以，400 条返回 `413 resourceTooLarge`（`field: command.edits`，“完整编辑反馈超过命令回执预算”）；改正文 300 条可以，1000 条也是 413。

**注音片段**
- `lyrics.setRubyText` 新建的注音只有一个片段，没有时间，ID 是 `<rubyId>-segment-1`。
- 注音有多个片段，或者有片段带时间时，`setRubyText` 无论改字还是清空都会被拒绝（`RubySegmentsRequireExplicitEdit`）。这时只能用片段命令修改，或者逐个删掉片段（删除最后一个片段时整组注音一起删除）。
- `addRubySegment` 的 `rubyResult` 带 `createdSegmentId`，并且 `selectionChanged: true`。
- 片段时间可以超出基础文本单元，后端不会夹紧。
- 七条片段命令的 `changeSet` 都是 `requiresFullRefresh: true`，只改时间也不例外，所以每次都会整体重读（见 §3 的 G30）。

**翻译来源**
- 粘贴新建的翻译来源是“跟随主歌词”，行本身没有时间（`time: {}`），显示时用关联主歌词行的时间。
- 改成“独立计时”后，这些行仍然没有时间，要自己打轴。

**TTML**
- W5 导出的“TTML（整个工程）”带有 `mkg:profile="ttml.project"`。
- **用它新建工程会恢复全部来源**：ID、时间策略、注音片段和时间都在。
- 对它做导入规划时，`sourceBranches` 列出全部来源，`selectedSourceBranchId` 默认是主来源；带上 `sourceBranchId` 后，预览行换成该来源的行。
- 往已有工程里再次导入时，多来源的文件必须指定 `sourceBranchId`，否则拒绝（`SourceBranchRequired`）。指定以后，一次只导入一个来源。

**发现的 W5 文案错误**：新建工程对话框遇到多来源文件时写的是“新建时导入‘主歌词’，其余来源可以之后在歌词页添加”，实际上会恢复全部来源。W6 第 2 步改正。

## 2. 结构调整

### 2.1 选择

`Selection` 增加可选的 `segmentId`：

```ts
interface Selection { lineId: string; tokenId?: string; segmentId?: string }
```

- `segmentId` 一定属于 `tokenId` 那个文本单元的注音组，组 ID 从行的 `ruby` 里查。
- `reconcileSelection` 在片段不存在时去掉 `segmentId`，保留文本单元。
- 再点一次已选中的片段，回到文本单元。
- 命令建议的选择（`selectionHint`）：
  - `rubyResult.selectionChanged` 为真时（加、删片段），选中 `selectedSegmentId`；没有这个 ID，就只清掉片段。
  - `selectionChanged` 为假但带 `selectedSegmentId` 时（改字、改时间、清除时间，后端带回被修改的片段），也选中它。
  - `project.applyEdits` 取最后一条带建议的结果。

### 2.2 一条历史的批量操作（G13、G14）

- `EditorSession` 加 `applyEdits(edits, options)`：按 200 条一批，每批发一次 `project.applyEdits`。
  - 某一批被拒绝就停下，并写明已完成几批。
  - 分批的纯函数放在 `model/edit-batches.ts`。
  - 200 条的依据是 §0 的实测：删除行 300 条可以、400 条超出回执预算。留了余量。
- **多选删除**：确认框写“删除 N 行？记一条历史，可以一次撤销”；超过 200 行时写“将分 K 批删除，每批一条历史”。完成后提示带“撤销”。
- **翻译关联对话框**：只发有变化的行。说明文字改为“提交记一条历史”。

### 2.3 导入对话框（导入规划）

流程：选文件 → 上传 → 导入规划 → 显示识别结果 → 选目标与选项 → 导入。

- **识别结果**沿用新建工程对话框的纯函数（`planSummary`、`planNotes`、`formatChoices`、`encodingChoices`、`planErrorText`）。这些函数从 `model/new-project.ts` 挪到 `model/lyrics-import.ts`，两个对话框共用。
- 改选格式、编码或来源时，用同一个资源重新请求规划，不重新上传。
- **预览**：前 5 行，显示正文和是否有逐字时间。有注音时，在正文后面用括号写出注音。
- **来源选择**：只在 `sourceBranches.length > 1` 时显示，默认是规划选中的来源。改选后预览随之变化。导入命令带上 `options.sourceBranchId`。
- 解析失败时，写明原因，“导入”按钮禁用。
- 原来的“格式”“编码”下拉框由候选替代；拆分规则、估算逐字时间保留。
- 导入报告对话框不变。
- **新建工程对话框的多来源提示**改为“这是 MakoKara 工程 TTML，新建时会恢复全部 N 个来源”。
- 实施时补充的几处（第 2 步）：
  - 规划的钩子和识别结果面板放在 `lyrics/LyricsPlanPanel.tsx`，两个对话框共用。重新规划期间仍显示同一文件上一次的结果，改选用的下拉框不会消失（否则 mdui-select 在值变化后被卸载会抛错），这期间“导入”禁用。
  - 只有工程 TTML 会有多个来源（AMLL 的翻译旁轨被丢弃，见后端 `TtmlImporter`），所以 `sourceBranches.length > 1` 就判定为工程 TTML。多来源时概要写“N 个来源共 M 行”。
  - 预览行就是所选来源的全部行。目标是主歌词、所选来源的行又关联着主歌词时，提前写明不能导入（后端会拒绝）。
  - 作为新来源导入多来源文件时，新来源的名称和角色默认跟随所选来源。
  - TTML 解析出错时后端不报解析失败，而是得到空文档、报 `EmptyImport`；这时用报告里第一条错误说明原因（“文件解析失败：…”）。

### 2.4 注音片段（行编辑区）

选中文本单元后，“注音”一节：

```text
注音（所选「朝」）                                  [按字拆开] [删除注音]
 [あ ●] [さ ○] [＋ 加片段]
 所选片段「あ」  文字 [あ        ]   [← 左移] [右移 →] [删除片段]
```

- **整段文字**：
  - 没有注音时，显示原来的“注音”输入框（`setRubyText` 新建一个片段）。
  - 只有一个没有时间的片段时，也可以直接改整段（`setRubyText`）。
  - 其他情况下输入框只读，下面写“注音已分成几个片段或已有时间，请逐个片段修改”。
- **片段**：用一排小按钮显示，文字加时间状态图标（与行列表相同：✓ 已确认／已修改，◐ 估算或导入，○ 没有时间）。
  - 点选片段就选中它（§2.1），时间栏和时间轴跟着变。
- **所选片段**：
  - 改字：`setRubySegmentText`。不能改成空，要删除就用“删除片段”。
  - 左移、右移：`reorderRubySegments`，传完整的新顺序。
  - 删除片段：`removeRubySegment`。删除最后一个片段时整组注音一起删除，按钮文字改为“删除注音”。
- **“＋ 加片段”**：在所选片段后面加，没选片段时加在最后（`addRubySegment`）。
  - 先弹出一个小输入框填文字，提交后选中新片段。
- **按字拆开**：把没有时间的、两个字以上的片段拆成每字一段，用一次 `applyEdits`。
  - 做法：其余的字倒序加在原片段后面（`addRubySegment`，`afterSegmentId` 都是原片段），这样结果的顺序正好；最后把原片段改成第一个字（`setRubySegmentText`）。改字放在最后，它的结果带回原片段，拆开后选中的就是原片段。
  - 没有可拆的片段时按钮禁用，写明原因。
  - 有时间的片段不拆：拆开后时间怎么分没有依据。
- **删除注音**：一次 `applyEdits`，删除全部片段。

### 2.5 时间栏与逐字预览

**时间栏**：选中片段时，左边一组改为“注音片段「あ」”。
- 起止：`setRubySegmentTime`，格式与现有的相同。
- ±1 帧：用 `setRubySegmentTime` 把起止一起移一帧。后端没有片段的 nudge 命令，所以在本地算好再发。
- 清除时间：`clearRubySegmentTime`。
- **起点取播放头**：起点设为当前播放头。原终点晚于播放头时保留原终点，否则终点设为播放头后一帧。
- **终点取播放头**：终点设为当前播放头。要求已经有早于播放头的起点，否则按钮禁用并写明原因。
- 都按帧吸附，与时间轴一致。

**逐字预览**：
- 注音按片段渲染，每个片段是一个带填充的 `span`。
- 有时间的片段按自己的半开区间算进度，与后端规则一致。没有时间的片段用它的文本单元的进度。
- 纯函数加在 `model/word-preview.ts`。

### 2.6 时间轴扩展（2026-10-27 用户审阅通过）

现在的轨道从上到下是：标尺 22 / 波形 72 / 元素轨 34 / 行轨 22，编排页在下面再加片段轨、前奏轨。扩展后，歌词页的轨道是：

```text
标尺      22
波形      72
注音轨    22   ← 新：当前来源有注音时才显示
元素轨    34
行轨      22
翻译行轨  22 × N   ← 新：看主歌词时，每个翻译来源一条
主歌词参考 22      ← 新：看其他来源时，只读的主歌词行轨
```

两条新轨只在歌词页出现，外观页、编排页的时间轴不变（由 `Timeline` 的新 props 控制）。

#### 注音轨

- **画什么**：
  - 有时间的片段画成色块，标上片段文字；估算或导入的片段颜色浅一些，选中的片段高亮。与元素轨相同。
  - 一组注音里所有片段都没有时间时，在它的文本单元的位置画一个虚线框，标上整段注音，表示“跟随文本单元”。
  - 部分片段有时间时，只画有时间的片段。
- **点选**：
  - 点色块，选中这个片段（同时选中它的文本单元）；行编辑区和时间栏跟着变。
  - 点虚线框，选中文本单元和它的第一个片段。
- **拖动边界**：与元素轨的规则相同。
  - 按帧吸附，按住 Alt 不吸附。
  - 共用同一边界的相邻片段一起移动，包括相邻文本单元的注音。
  - 松手提交一次 `setRubySegmentTimes`，记一条历史。
  - 可以拖到文本单元范围外面，因为后端允许。

#### 翻译行轨

- **什么时候显示**：当前来源是主歌词时，在行轨下面为每个翻译来源（角色为“翻译”）加一条轨。注释、自定义来源不画。
  - 轨道左端用浅色小字写来源名，例如“中文”。
  - 没有可画的行时，写“这个来源还没有时间”；来源不计时时写“这个来源不计时”。
- **画什么**（按来源的时间策略）：
  - 独立计时的来源：有时间的行画实心色块，标上翻译正文；没有时间的行不画。
  - 跟随主歌词的来源：已关联、且关联的主歌词行有时间的行，在主歌词行的位置画虚线框，标上翻译正文，只显示；后端保留的原时间不画（显示时不用它）。
  - 不计时的来源：不画。
- **拖动边界**：只对独立计时的行有效。松手提交一次 `setTimeRange`（目标是翻译来源的那一行），记一条历史。跟随主歌词的虚线框不能拖。
- **点选**：双击色块或虚线框，就切到那个翻译来源并选中这一行。单击没有动作，以免拖边界时误切来源。

#### 主歌词参考轨

- **什么时候显示**：当前来源不是主歌词时，在行轨下面加一条只读的主歌词行轨，左端写“主歌词”。
- **画什么**：主歌词有时间的行，画法与行轨相同，不能拖。
- **点选**：与翻译行轨一致，双击切回主歌词并选中这一行；单击没有动作。
- 同时，当前来源跟随主歌词时，行轨里已关联的行在关联主歌词行的位置画虚线框，标上正文，不能拖；单击照常选中这一行。没有关联的行照旧按自己的时间画。

#### 用户的决定（2026-10-27）

1. 翻译色块的点选方式：**双击**切到那个来源并选中这一行；单击没有动作。
2. 看翻译等其他来源时，**加**只读的主歌词参考轨；行轨里跟随主歌词的行画虚线框。
3. 注音轨放在**元素轨上方**。
4. 翻译行轨**只包括角色为“翻译”的来源**。

## 3. 后端缺口

都不阻断 W6，只登记。后端已宣布收口，由用户决定是否转达。

| 编号 | 缺口 | 现状 | 前端做法 |
|---|---|---|---|
| **G30** | 注音片段的时间命令总要整体重读 | `setRubySegmentTime(s)`、`clearRubySegmentTime` 的 `changeSet` 带了 `lineIds`，却总是 `requiresFullRefresh: true`（§0）。元素时间命令只重读受影响的行，片段时间每次都要重读全部来源 | 照常整体重读；歌词多时拖动片段后会慢一些。希望只改时间的片段命令像元素时间命令一样不要求整体刷新 |

编号已核对：W5 用到 G29、R9；本仓库与后端仓库的文档里都没有 G30。

另外两点不算缺口：
- `applyEdits` 的条数受回执预算限制，这是合同写明的预算，前端按 200 条分批（§2.2）。
- 多来源 TTML 不能一次导入全部来源：导入命令按目标逐个写入，这是合同的设计（§18.2）。

## 8. 已知限制

- **G30 未交付**（§3）：注音片段的时间命令总要整体重读。歌词多时，拖片段边界、改片段时间后会慢一些。
- 注音片段没有打点模式，用时间栏的“起点取播放头”“终点取播放头”，或者在注音轨上拖（§1 不做）。
- 工程 TTML 在歌词页一次只能导入一个来源；要恢复全部来源，就用它新建工程（§1 不做）。
- 拖行的边界时，行不能缩到把自己的元素挤出去：起点拖过第一个元素、终点拖过最后一个元素，后端会拒绝，界面回弹并提示原因。这是领域规则，要先改元素的时间。
- 翻译行轨只拖边界，不能整行平移；不显示翻译的文本单元和注音。注释、自定义来源不画轨。跟随主歌词的来源里，后端保留的原时间不画。
- 视口缩得很小时，窄的色块不写文字（注音轨、翻译行轨与原有的轨一样）。
- 开发环境：后端默认最多 16 个客户端，没关的工程会让客户端身份一直有效，不会被回收（后端 `backend-api.md` §G1 配额按需回收）。冒烟会留下打开的工程，同一个 `pnpm dev:backend` 上连续跑十几次冒烟后，新页面登记客户端会得到 429，页面显示“连接失败，正在重试”。重启 `pnpm dev:backend` 即可。这是合同写明的配额，不算缺陷。
