# Hosting 预览会话注册表

本切片新增 `BackendPreviewSessionRegistry`，以注入的真实 `IRenderFrameSessionFactory` 和 `IBackendPreviewPngEncoder` 建立像素→PNG→帧句柄／诊断存储的生产者。未新增公共Server创建／请求路由，也不宣称HTTP成功预览或跨进程运行已在本切片验收。

## 所有权与调用合同

- `BackendPreviewPinnedInput`来自可信组合根，包含完整固定 `ProjectSnapshot`、来源ID／修订和工厂；客户端不能提交裸工作区或用布尔开关绕过脚本门禁。
- `ProjectSession.CapturePreviewInputAsync(clientId, expectedProjectRevision, factory)`在原会话唯一 `Writer` 闸门内检查客户端、关闭状态和精确修订，捕获不可变快照。后续编辑产生新数据，不改变已捕获快照。调用方仍负责授予媒体／固定输入租约；此方法不取得文件权限或创建第二个写者。
- `Create(clientId, PreviewSessionRequest, pinnedInput)`要求请求来源完全等于固定输入来源，并检查会话数量、输出尺寸及透明模式。
- `Update`、`RequestFrame`、`CloseAsync`都要求clientId、当前代次和当前来源修订；更新还要求新来源匹配新的固定输入。`Read`按客户端隔离。
- 代次由服务分配为单调的规范十进制字符串。`seek`原子产生新代次，接受响应返回新代次；旧代次请求拒绝。请求序号在同一会话全生命周期单调递增，重复／倒退直接拒绝；上层命令回执另行负责重试去重。
- 同代次`playback`只允许时间不倒退；请求时间不能超过固定工程时长。同一时间的新序号可以刷新，执行中的请求继续完成，待处理请求只保留最新一个。

## 排队、编码和发布

注册表复用 `BackendPreviewCoordinator`，没有第二套渲染队列。协调器新增可选服务请求序号及 `Invalidate`：更新输入时立即使旧输入失效，取消在途渲染，并在同一执行者上释放旧会话；不要求调用方先提交新帧才能清理。

协调器先复制像素并释放原生帧，再在锁外回调。注册表在自己的闸门内检查当前输入，锁外编码PNG和投影诊断，随后再次检查会话仍开放、代次／来源／快照相同、序号和实际帧时间不倒退。存储再次核对已激活的代次，旧编码／渲染结果不能复活被更新或关闭的会话。

编码器必须编码收到的真实帧；注册表检查输出尺寸／格式／时间／像素长度，随后由存储检查PNG结构／尺寸、SHA-256、大小及TTL。编码异常、空内容、非法PNG、渲染失败及诊断预算溢出都进入当前`failed`状态并产生安全的诊断，不把原始异常路径／堆栈输出给客户端。每次成功发布以 `PublishBatch`原子替换完整诊断页链，旧游标失效；首页至末页最多32页。

当前注册表严格拒绝效果指纹、效果包／实例、直接预设应用及包材质引用；即使伪造空指纹也不能绕过。它允许音频描述随固定快照保留，但不自行读取／播放文件。实际工厂支持范围和媒体权限仍由组合根及后续静态codec合同约束。

## 关闭与排水

`CloseAsync`立即关闭帧／诊断存储并停止新请求，等待协调器真实排水后返回`closed`。排水前会话仍占配额；多个关闭调用等待同一个任务。已取得的HTTP读取流租约可以读完，未取得租约的旧帧不能再读取。关闭返回后会话从注册表移除，后续读取返回会话不存在，不无限保留关闭墓碑。

`DrainClientAsync`是宿主在客户端租约结束时的清理入口；`DisposeAsync`停止接受新操作并等待全部会话关闭。重复释放调用等待同一任务。协调器在排水完成后清除请求、工厂／快照、运行任务和订阅引用，避免消费者继续持有已释放协调器时保留旧输入。可信工厂必须响应取消或由其Worker超时／进程回收机制收敛；编码器必须有界完成，注册表不会在实际工作未退出时虚报排水完成。
