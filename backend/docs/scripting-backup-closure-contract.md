# 统一工程闭包的自动备份发布合同

> 0.25.6，2026-10-05。属于 R4 备份事务接续；固定 DLL／工作区、R5～R8 和最终人工验收继续按后续计划实施。

## 1. 完整闭包与发布点

`AutoSaveStore.Save` 从同一个不可变 `Project` 快照调用 `ProjectStore.Save`，发布歌词、音频／背景媒体、已接受音频分析、效果包及源材质引用。每份备份拥有独立字节；目录搬移后可重开、另存为，删除原始外部媒体不影响恢复。

完整闭包先写到备份根内唯一的 `.autosave-<guid>.tmp` 目录。`ProjectStore` 仍以根入口最后发布，所有资源保留现有 hash、profile、路径和版本门禁。该暂存目录始终不进入备份列表；写入全部成功后，使用同一父目录下的目录移动发布完整备份。恢复现场标记由 `ProjectAutoSave` 在保存返回后更新，已发布目录的相对资源路径无需改写。

## 2. 同秒身份与保留顺序

首份备份保持 `autosave-yyyyMMdd-HHmmssZ` 名称。同一秒已有文件或目录占用时，追加二十位十进制递增序号，例如 `autosave-20261005-120000Z-00000000000000000001`。序号取仍存在的同秒名称最大值再递增；已有文件、目录及已发布入口不会被覆盖。已裁剪的序号空位不复用，保证本批备份按名称降序仍是发布顺序。

同一进程的目录发布与裁剪串行进行，完整闭包写入可独立完成。跨进程同名目录先被发布时，目录移动失败后重新选择序号；其他 IO 失败继续向调用方报告。序号溢出明确失败，不回绕到旧路径。

保存成功后才裁剪旧备份，始终保留本次发布；时钟回拨时也不能返回一个已被裁剪的恢复目录。其余份数按现有 UTC 名称顺序保留。独立调用 `Prune` 继续按列表顺序保留指定份数。列表只包含名称前缀正确且具有 `project.json` 的目录；缺入口的半成品或被占用路径不参与保留数量，也不由裁剪删除。已发布入口损坏或版本不符仍由正常加载诊断报告。

## 3. 失败与恢复

媒体发布后分析失败、包发布失败或入口写入失败均不会公开新备份，也不会裁剪旧备份。本次唯一暂存目录由调用方独占，失败时清理其全部未发布内容；已有工程和已发布备份的历史内容沿原合同保留。

失败不更新 `ProjectAutoSave` 的恢复现场标记或“已备份实例”引用，不更新工作区 saved reference。外部资源恢复后，同一编辑实例可以直接重试，仍属于未保存编辑。进程被强制终止留下的暂存目录不会出现在列表中；本批不增加启动磁盘回收或历史资源 GC。

## 4. 格式与运行边界

本批只改变自动备份目录的发布方式；工程／歌词／模板 schema 26／16／5、包 profile2、Shader ABI、公开 SDK、程序集与依赖不变，不迁移旧工程。源码编译失败的工程仍能保存和备份；编译与正式会话门禁继续在运行前执行。本机 DLL 缓存不进入工程备份语义，固定修订的离线编译／复用由后续 R4 接续验证。
