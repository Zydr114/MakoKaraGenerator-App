# 样式编辑器前端体验重构方案

> **历史实施文档**：本页的固定应用栏、真实目标预览和目标筛选描述当前窗口；新版本将依据 [ADR-0050](../decisions/decisions.md#adr-0050模板工坊歌词行编辑器与程序版本边界) 改为“模板工坊设计、歌词行编辑器套用”。

- **文档状态**：已实施；最小窗口、键盘与窗口管理器交互已人工验收
- **日期**：2026-09-27
- **适用范围**：`StyleEditorWindow`、样式选择器、样式预览、草稿属性编辑和固定应用区
- **关联文档**：[`style-animation-system-plan.md`](../plans/style-animation-system-plan.md)、[`decisions.md`](../decisions/decisions.md) ADR-0044/0045
- **参考截图**：[主界面.png](../../../主界面.png)、[样式编辑器.png](../../../样式编辑器.png)

## 0. 结论摘要

样式编辑器需要重新设计信息架构，不再继续在当前三栏上增加按钮或压缩间距。当前窗口把样式库、试样、草稿属性和应用目标同时放在一个滚动区域里，用户很难判断“正在看什么、改了什么、最后会写到哪里”。

下一版采用“**选择 → 预览 → 编辑 → 应用**”四步工作流：

1. 左侧只负责找到样式和确认来源；
2. 中央只负责确认画面是否真的变化；
3. 右侧只负责编辑草稿和查看继承来源；
4. 底部固定应用栏只负责目标、写入内容和提交。

样式预览改为编辑器的中心状态。预览必须使用当前目标的真实文本和真实生效样式，并明确显示“当前效果”“候选效果”“草稿效果”三个状态；播放头、未唱/进行中/已唱状态和暂停按钮统一放在预览头部。用户不需要根据一串属性文字推断画面是否生效。

窗口仍保持 Material You 风格，但减少无意义的边框和嵌套圆角，改用色调层级、选中容器、清晰的标题和一个固定主操作建立层次。

## 1. 本次审查的依据

### 1.1 截图

- [主界面.png](../../../主界面.png)：2542×1382。主窗口已经形成“歌词栏—画布—检查器—时间轴”的清楚骨架，画布是视觉中心，右侧检查器承担工程设置。
- [样式编辑器.png](../../../样式编辑器.png)：1426×990。样式窗口处于最小可用宽度附近，能暴露独立窗口的实际拥挤问题。

### 1.2 改造前代码

- `StyleEditorWindow.axaml` 仍用顶层“样式设计／动画”页签承载两个完整工作区，窗口标题区只有标题、说明和关闭按钮。
- `StyleDesignerPanel.axaml` 将库、预览、草稿属性和应用区放入同一个控件；左右列各自滚动，底部应用区固定但高度随说明文本增长。
- `StyleDesignerPanel.axaml.cs` 通过 `BuildFields()` 动态创建大量属性控件，属性选择、参数编辑和效果开关在同一层级展开。
- `StyleWorkspaceViewModel` 已经提供候选样式、草稿、目标、批量目标、前后快照、搜索和筛选能力，但这些状态在界面上没有形成清晰的状态模型。
- 预览控件当前固定使用较小的高度；样式库预览、草稿预览和当前样式预览没有共享一个明确的“当前预览状态”标题。

## 2. 截图中暴露的问题

| 观察 | 用户实际感受 | 根因 |
|---|---|---|
| 样式库、候选预览、草稿编辑和应用区都在首屏出现 | 页面看起来像设置面板集合，无法形成操作顺序 | 信息架构按实现模块排列，没有按用户任务排列 |
| 左、中、右三列同时滚动，底部应用区再次出现目标和属性摘要 | 需要在多个滚动容器中找按钮；应用目标容易被忽略 | 工作区和提交区没有明确分层 |
| 中央两个预览区域很暗，文字很小，画面变化不明显 | 用户无法确认样式是否真正生效 | 预览尺寸、预览内容和状态标签都不够明确；候选、草稿、工程结果的关系不直观 |
| 右侧属性区显示 18 项长摘要，元素目标时再显示一整段不支持属性 | 错误信息压过了操作本身；用户不知道该怎么处理 | 应用前没有结构化的“将写入／将跳过”摘要，所有属性都以文本堆叠 |
| 每个属性前都有勾选框，效果开关、属性写入和继承语义混在一起 | 用户不清楚勾选是“修改这个值”还是“启用这个效果” | 设计字段的三种状态没有用不同的视觉控件表示 |
| 内置样式列表主要显示名称和 ID | 样式之间难以比较，库像一份调试列表 | 缺少缩略图、类别、来源、支持范围和选中态信息 |
| “读取工程当前样式”“读取当前对象”“设计稿来源”同时出现 | 来源和草稿替换关系需要靠阅读说明理解 | 来源入口没有收敛成一个可追踪的来源链 |
| 应用按钮在大量说明之后才出现，元素目标时可能处于禁用状态 | 用户无法快速完成一次应用 | 目标选择、能力过滤和提交动作没有在同一个固定区域闭环 |
| 外层样式页签和动画页签都拥有自己的预览逻辑 | 切换页签时不容易判断播放的是哪个状态 | 预览状态没有统一的会话模型 |

## 3. 设计目标与不变约束

### 3.1 目标

1. 用户在 3 秒内知道当前编辑对象、当前候选样式和应用目标。
2. 用户在不滚动的情况下看到候选效果和主操作。
3. 修改属性后，预览立即显示草稿结果，并同时保留应用前结果用于比较。
4. 不支持的元素属性以结构化列表显示，并提供自动只应用可用属性的动作。
5. 样式库、草稿和工程结果始终保持隔离；选择和预览不修改工程。
6. 最小窗口仍可通过折叠侧栏完成完整操作，不能依赖悬停才能发现关键动作。
7. 所有颜色、表面、文字和状态都使用 Material You 资源，不在界面 XAML 中写新颜色。

### 3.2 不变约束

- 草稿只有“应用”才进入工程和撤销栈。
- 工程、行、元素三个目标层级继续保留；恢复继承和显式关闭仍是两个动作。
- 预览和导出继续消费同一 `ProjectSnapshot`/渲染管线，不在控件里复制渲染规则。
- 文案继续集中在 `Resources/Strings.axaml`。
- `Core`、`Application`、`Rendering` 不因前端重构引用 Avalonia。

## 4. 新的信息架构

### 4.1 窗口骨架

```text
┌────────────────────────────────────────────────────────────────────┐
│ 样式设计      当前对象：第 1 行第 1 个元素   草稿状态   关闭        │
│ [样式] [动画]                                                     │
├───────────────┬────────────────────────────────┬───────────────────┤
│ 样式库         │ 预览                             │ 草稿与属性        │
│               │                                  │                   │
│ 搜索/筛选      │ 当前效果  ↔  候选效果             │ 来源链            │
│ 当前工程样式   │                                  │ 属性分组          │
│ 内置样式       │ 实际歌词文本                     │ 效果开关          │
│ 我的样式       │ 未唱 / 进行中 / 已唱             │ 参数编辑          │
│ 最近/收藏      │ 播放、暂停、时间和缩放           │ 继承/覆盖来源      │
│               │                                  │ 保存为我的样式    │
├───────────────┴────────────────────────────────┴───────────────────┤
│ 目标：当前元素  ·  将写入 4 项  ·  将跳过 2 项   恢复继承  应用    │
└────────────────────────────────────────────────────────────────────┘
```

窗口保留“样式／动画”一级切换。样式页不再有“样式库／草稿编辑”二级页签；库、预览和草稿同时可见，用户不需要在两个页签之间记忆状态。动画页沿用独立的动画模型，但使用同样的窗口头、预览头和底部应用栏。

### 4.2 顶部窗口头

左侧显示标题“样式设计”和当前会话状态；中间显示当前目标面包屑；右侧是关闭按钮。

状态显示使用一个小型状态标签：

- `已应用`：草稿与最近一次应用相同；
- `有未应用改动`：草稿已变化；
- `目标未选择`：当前目标不可用；
- `存在校验错误`：属性输入需要处理。

状态标签必须是文字加色调容器，不能只依赖颜色。

### 4.3 左侧样式库

左侧宽度在宽窗口下约 280 logical px。内容从上到下固定为：

1. 搜索框：匹配名称、类别、字体、颜色、效果和来源；
2. 筛选按钮：打开筛选浮层，筛选项包括类别、收藏、最近使用、当前目标可用；
3. “当前工程”分组：当前工程样式和当前对象生效样式各一张置顶卡片；
4. “样式库”分组：内置、我的、最近使用、收藏通过分组标题或切换条选择；
5. 样式卡片列表；
6. 库管理入口。

样式卡片不再显示调试 ID 作为主要信息。每张卡片包含：

- 96×56 左右的真实歌词缩略图；
- 样式名；
- 类别标签，例如“字体”“渐变”“描边”；
- 来源标签，例如“内置”“我的”“当前工程”；
- 支持范围，例如“工程／行”“元素仅颜色”；
- 收藏按钮和更多操作按钮。

点击卡片只切换候选预览。点击“编辑草稿”才会把候选复制进草稿；草稿有未应用改动时，弹出“保留草稿／替换草稿／取消”三选一确认。

### 4.4 中央预览区

中央区域是窗口视觉中心，不再使用多个小型黑色画布堆叠。建议使用一个统一的 `StylePreviewStage`：

```text
┌────────────────────────────────────────┐
│ 候选：描边阴影    [当前] [对比] [草稿]  │
│                                    ⋮   │
│          夜空中最亮的星                 │
│       真实样式效果与进度状态             │
│                                        │
│ 未唱 ───────●────── 已唱                │
│ 00:01.500   ▶/Ⅱ   适配画布 100%          │
└────────────────────────────────────────┘
```

预览区必须提供以下状态：

- **当前**：当前目标在工程中的生效样式；
- **候选**：样式库卡片的效果；
- **草稿**：右侧属性正在编辑的效果；
- **对比**：左右或滑块对比当前与草稿，不能用两个无标题的小画布代替。

预览内容默认取当前选中的实际歌词行或元素，使用真实文本、真实字数、真实时间和真实工程画布比例。没有选中对象时才使用“示例歌词”，并明确标注“示例”。

预览头部显示当前来源和状态，画布内部显示可见的进度标记。预览底部统一放置播放/暂停、进度滑块、未唱/进行中/已唱三态切换和适配比例。三个预览状态共享时间采样，切换状态不会出现某一块停在旧时间的情况。

预览画布采用“适配画布”模式，保持歌词的可读最小字号；窗口变窄时优先缩小画布周围留白，不缩小文字到无法辨认。没有歌词时显示原因和操作入口，而不是只显示黑色空画布。

### 4.5 右侧草稿与属性

右侧宽度在宽窗口下约 340–380 logical px。右侧第一屏只显示三件事：草稿状态、来源链、当前修改摘要。

#### 来源链

用一条紧凑的来源链替代多个“读取”按钮：

```text
工程默认  →  当前行  →  当前元素  →  当前草稿
```

每一层显示“继承”或“有覆盖”。点击某层的“读取”才将该层生效值载入草稿；读取操作仍需要替换草稿确认。

#### 属性分组

属性按用户理解分组，而不是按枚举顺序全部展开：

1. 字体与排版；
2. 填充与渐变；
3. 描边；
4. 阴影；
5. 变换与透明度；
6. 布局位置。

每组默认折叠，当前草稿有改动的组自动展开。组标题显示“已改 2 项／继承 4 项”。“全部静态样式／清空应用内容”改为组标题右侧的次级操作，不再占据属性区首屏。

#### 属性行

每行拆成三个明确区域：

```text
[写入开关]  未唱颜色                 [色块] #4A5060   [恢复]
             来源：工程默认 · 当前值
```

- 写入开关表示“本次应用是否写入这一项”；
- 效果开关表示“描边/阴影/渐变是否启用”；
- 恢复按钮表示“清除本层覆盖，恢复继承”；
- 输入值只展示当前草稿值，来源单独展示。

元素目标不支持的属性使用禁用状态和“仅工程/行”标签，不能把所有 18 项放进一段红色长句。右侧顶部显示结构化摘要：

```text
将写入 4 项
将跳过 2 项（字体、字号；元素不支持）
[只应用可用属性]
```

## 5. 固定应用栏

应用栏高度目标为 72–88 logical px，始终贴在窗口底部，不随属性内容滚动。它只承载提交相关信息：

```text
目标 [当前元素 ▾]  [选择多个目标]
写入 4 项 · 跳过 2 项 · 应用后可撤销
[恢复继承] [应用到当前元素]
```

规则：

- `应用` 是唯一的高强调主按钮，按钮文字包含目标，例如“应用到当前元素”；
- 目标缺失时主按钮禁用，同时显示一行可操作的原因；
- 有不支持属性时默认保留可用属性并允许直接应用；“只应用可用属性”是显式选项，不需要先点击一个隐藏的解锁按钮；
- 没有任何改动时主按钮显示“已应用”，而不是灰色空白按钮；
- 恢复继承是次级按钮，必须明确显示作用层级；
- 应用成功后在应用栏短暂显示结果和“撤销”动作，随后恢复正常状态；
- 批量目标在应用栏展开目标摘要，详细勾选进入目标选择器，不把几十个目标塞入窗口底部。

## 6. Material You 视觉规范

### 6.1 表面层级

继续使用 `Theme/Colors.axaml` 和 `Theme/MaterialYou.axaml` 中的动态资源。建议将样式窗口的表面分成四层：

| 层级 | 用途 | 资源方向 |
|---|---|---|
| Window surface | 窗口背景和大面积预览周围 | `UiSurfaceBrush` |
| Surface container low | 左侧样式库和右侧属性背景 | `UiSurfaceContainerLowBrush` |
| Surface container | 来源链、属性组和预览控制条 | `UiSurfaceContainerBrush` |
| Surface container high | 选中卡片、输入区、应用栏 | `UiSurfaceContainerHighBrush` |

不要让每一个 `Border` 都有边框和阴影。结构分隔优先使用表面色差和 1px 的 `UiOutlineVariantBrush` 分割线；预览舞台只保留一层边界。

### 6.2 选中和状态

- 选中样式卡片：`UiPrimaryContainerBrush` + `UiOnPrimaryContainerBrush`，配一条窄的强调色边缘或明确的选中图标；
- 主按钮：`UiPrimaryBrush` / `UiOnPrimaryBrush`；
- 次级操作：透明或低色调容器，不与主按钮抢视觉重量；
- 警告：`UiErrorContainerBrush` 只用于需要处理的错误，不把“元素不支持”当成致命错误；
- 未应用改动：使用 `UiTertiaryContainerBrush` 或项目已有的状态资源，配文字“有未应用改动”；
- 禁用控件仍保留文字和原因，不只降低透明度。

### 6.3 密度、文字和形状

- 采用 8 logical px 间距基线，常用间距为 8、12、16、24；
- 窗口标题 20–22，区域标题 16，正文 14，辅助文字不低于 12；当前大量 11px 辅助文字需要减少；
- 普通输入控件高度 40–44，按钮触达区域不低于 40；
- 大型容器圆角 20–24，控件圆角 12–16，避免卡片套卡片；
- 保持 `Noto Sans CJK SC`，数字和时间使用等宽或表格数字风格；
- 所有新增文案进入 `Strings.axaml`，颜色进入主题资源，不能在窗口 XAML 中直接写颜色值。

## 7. 响应式窗口布局

当前窗口最小尺寸接近截图中的 1426×990 物理像素，但逻辑宽度受缩放影响，必须按 logical px 设计。

### 7.1 宽窗口（≥1280 logical px）

- 左侧 280；中央自适应；右侧 360；
- 应用栏固定；三列只各自滚动内容，不滚动标题和应用栏；
- 预览舞台至少占中央区域的 55% 高度。

### 7.2 中等窗口（960–1279 logical px）

- 左侧改为可折叠抽屉，默认打开；
- 中央预览和右侧属性保留；
- 搜索和筛选留在抽屉顶部，关闭抽屉后预览获得全部宽度；
- 应用栏仍固定。

### 7.3 小窗口（<960 logical px）

- 不强行保留三列；切换为“库／预览／属性”三段式页签；
- 预览页保留底部应用栏；
- 任何关键操作都不能只出现在悬停菜单中；
- 目标和主应用按钮固定在底部，属性输入在属性页滚动。

窗口最小值建议调整为 880×620 logical px，并在小窗口下自动使用单列模式。需要通过真机键盘验证焦点顺序、回车提交和 Esc 关闭行为。

## 8. 交互状态和流程

### 8.1 选择样式

```text
浏览卡片 → 单击卡片查看候选 → 预览确认 → 编辑草稿 → 修改属性 → 应用
```

浏览和候选预览不改变草稿。进入“编辑草稿”时才发生候选到草稿的复制，并在草稿有改动时进行替换确认。

### 8.2 修改属性

属性输入后立即更新草稿预览，但不改工程。错误显示在属性行下方，应用栏同步显示“有校验错误”。输入框失焦、回车和点击应用都走同一个提交逻辑，避免预览值与应用值不同步。

### 8.3 恢复继承

恢复继承必须从“关闭效果”中分离出来：

- 关闭效果：在当前层写入明确关闭；
- 恢复继承：清除当前层覆盖，回到上一层来源。

两者都显示在属性行和应用栏中，并各自进入撤销栈。

### 8.4 预览暂停与页签切换

- 样式预览和动画预览有独立播放状态，但共用统一的预览头布局；
- 切换一级页签时停止当前页播放，并保留时间位置；
- 关闭窗口时停止计时器；
- 预览时间跳转后，当前、候选和草稿三种状态必须同步刷新。

## 9. 代码结构调整建议

当前逻辑可以保留 `StyleWorkspaceViewModel` 作为协调器，但前端状态需要拆成清晰的子模型：

```text
StyleEditorViewModel
├─ StyleLibraryViewModel       搜索、分组、卡片、收藏、最近使用
├─ StylePreviewViewModel       当前/候选/草稿、对比模式、时间、播放
├─ StyleInspectorViewModel     来源链、属性组、效果开关、校验
└─ StyleApplyBarViewModel      目标、批量选择、写入摘要、应用/恢复继承
```

建议的职责调整：

1. `StyleWorkspaceViewModel` 保留工程状态、候选来源和应用命令，不再承担所有展示筛选状态。
2. `StyleDesignerPanel.axaml.cs` 只负责窗口生命周期、预览计时和对话框调用。
3. `BuildFields()` 生成的控件逐步替换成 XAML `DataTemplate`，属性组和属性行由视图模型提供；这样可以统一选中态、来源、禁用原因和键盘焦点。
4. 新增 `StyleCardView`、`StylePreviewStage`、`StyleApplyBar`、`StylePropertyGroup` 四个独立视图，避免一个 XAML 文件继续承载整个窗口。
5. 预览状态命名统一为 `Current`、`Candidate`、`Draft`、`Compare`，禁止继续使用“库样例”“当前样例”这类难以区分的名称。
6. 应用摘要由 `StyleApplySummary` 产生结构化数据：`WritableProperties`、`SkippedProperties`、`RestoreProperties`、`Target`，视图只负责展示。

## 10. 实施顺序

### 阶段 1：状态和预览先行

- 增加统一 `StylePreviewViewModel`；
- 让预览使用当前目标真实歌词；
- 实现当前／候选／草稿／对比四态；
- 统一播放、暂停、时间和画布适配；
- 先做预览快照一致性测试。

**出口**：改任意颜色、渐变、描边或阴影后，草稿预览立即可见；当前和草稿对比不会混淆。

### 阶段 2：窗口壳和响应式布局

- 重写 `StyleEditorWindow.axaml` 和样式页根布局；
- 移除样式页内部的库/草稿二级页签；
- 实现宽、中、小三档布局；
- 应用栏改成固定高度。

**出口**：窗口缩到最小尺寸仍能看到预览、目标和主应用按钮。

### 阶段 3：样式库卡片

- 引入卡片模型和缩略图快照；
- 增加来源、类别、支持范围和收藏状态；
- 将搜索/筛选收敛成一个筛选浮层；
- 加入工程当前样式和当前对象样式置顶卡片。

**出口**：用户不打开属性区也能区分样式来源、类别和可用范围。

### 阶段 4：属性检查器

- 将属性分组和属性行迁移到数据模板；
- 分离写入开关、效果开关、继承来源和恢复动作；
- 支持渐变方向/停止点、字体参数、描边和阴影的渐进式展开；
- 结构化展示元素目标的跳过项。

**出口**：属性区首屏不超过一个屏幕高度；每项都能回答“当前值、来源、本次是否写入”。

### 阶段 5：应用闭环和动画页

- 重写应用摘要和主按钮状态；
- 自动提供“只应用可用属性”；
- 应用成功后显示撤销动作；
- 动画页复用预览头和应用栏视觉结构。

**出口**：一次应用不需要在多个区域之间来回确认；撤销和恢复继承语义清楚。

### 阶段 6：验收与清理

- 最小窗口、键盘焦点、Esc/Enter、Tab 顺序真机验收；
- 预览和导出同快照/同时间回归；
- 删除旧的重复布局和旧入口临时显示逻辑；
- 更新截图和文档。
