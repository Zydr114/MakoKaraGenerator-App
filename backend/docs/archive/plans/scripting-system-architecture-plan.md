## 2. 全局上下文的定义

脚本可以保存变量、对象、订阅和计算结果，但“全局”指**一个工程的一次执行会话内共享**，不使用全应用唯一的静态对象。

建议分成三个生命周期：

| 层 | 内容 | 生命周期 |
|---|---|---|
| ProjectContext | 完整歌词/分支只读目录、场景定义、参数、资源目录、音频特征 | 工程快照和资源修订期间 |
| ScriptSessionContext | 当前时刻、事件游标、已出现内容索引、状态变量、随机数状态、脚本回调订阅 | 一个预览或导出会话 |
| FrameContext | 当前帧场景、有效样式、几何、目标时刻 | 一次帧求值 |

预览与导出共享编译结果和只读数据，各自持有独立 `ScriptSessionContext`。不能让导出继承用户拖动播放头后残留的状态，也不能让模板试样修改主画布的脚本状态。

工程关闭、脚本卸载、参数更改或代码代次替换后，旧会话释放订阅和资源。脚本自有状态不写入 project.json；只有源码、声明参数、绑定和启用状态是工程数据。

## 3. 时间线历史与播放控制历史

### 3.1 歌曲时间线历史

指歌曲从时间原点到目标时刻经历的歌词事件、可见内容和音频分析数据。即使没有实时听过这段，也能离线重建：

- 某字何时开始、结束；
- 某行何时进入、离开显示容器；
- 某段音量、频谱和能量变化；
- 脚本累计的高潮估计、已出现字集合和计数。

这是首期状态脚本的推荐基础，也是预览／导出一致性的输入。

### 3.2 播放控制历史（本轮不进入成片视觉）

这里的“真实播放操作”不是预览界面绘制的帧，也不是脚本收到的歌词事件，而是用户对播放器做过的控制：点击播放／暂停、拖动播放头、循环选区、跳转或改变播放速度。它描述的是一次编辑会话里用户实际听过什么，并不属于歌曲本身的时间线。

本轮决定不把这类控制历史作为脚本视觉输入。脚本需要的是可重建的歌曲时间线历史：同一个 `timeUs` 从头重放时，预览和导出得到相同的“已经出现的字”、逐字进度和音频特征。这样用户是否先试听过某一段，不会改变导出结果。

未来若要制作“按用户试听过程变化”的作品，另行增加播放会话录制功能，把控制日志作为明确的导出输入；当前不引入这条路径，也不让 `TransportChanged` 改变默认成片状态。

## 4. 回调和事件规则

建议提供主机生成的类型化事件，而不是监听播放器或 ViewModel：

- LineBecameVisible / LineBecameHidden：由场景采样和布局绑定决定；
- TokenBecameVisible：该 token 所属内容首次出现在本次绑定中，包含没有逐字时间的字；
- TokenStarted / TokenCompleted：仅针对有效逐字区间；
- AudioFeatureTick：音频特征时间序列的分析时刻；
- Advance：脚本状态的固定模拟步；

首期视觉 SDK 不提供播放控制回调；编辑器诊断需要的播放状态由宿主处理。这样不需要再建立会影响视觉状态的 `TransportChanged` 通道。

“已经出现”和“已经唱完”分开。双行提前显示会先出现后开始唱；未定时字可以出现但没有 TokenStarted/Completed。callback 可查询截至事件时刻的内容，也可在这一时刻重新处理此前出现的字。

事件记录至少含 EventId、SourceId、SceneElementId（适用时）、BindingId、TimeUs 和 ReplayReason。相同微秒按固定次序分派：结束／退出 → 开始／进入 → 固定模拟步；同类按稳定 ID 排序。

连续前进消费 (previousTimeUs, targetTimeUs] 内事件；初始时刻的事件单独初始化一次。暂停重绘和缓存命中不再触发同一事件。循环返回和向后跳转创建新的重建区间；事件允许重放，回调可读 IsReplaying，不把一次订阅误当作一生只触发一次。

## 5. 有状态，但可重建

推荐把模拟和绘制分开：

```text
Initialize(ProjectContext)
  -> Advance / OnTimelineEvent（可以改变脚本会话状态）
  -> EvaluateFrame(FrameContext)（读取状态，输出本帧效果）
  -> Dispose
```

模拟使用工程时间和固定时间步，不依赖 UI 刷新频率或导出帧率；事件位于固定步之间时按事件时间拆分推进。EvaluateFrame 对相同会话状态和时刻不得再次累加计数，避免暂停重绘、缩略图或缓存改变后续动画。

允许持有普通 C# 对象和累计状态；重建路径是：

- 首版：创建新会话，从原点重放到目标时刻；
- 后续：脚本可实现 CaptureState/RestoreState，从检查点继续重放；
- 跳转、循环、参数撤销、源码替换按同一路径重建；
- 暂停期间调换模板也会产生新快照，失效依赖旧样式／几何的检查点；
- 导出从新会话开始。截取中段时也先构建该起点所需历史；
- 随机数以显式种子和固定事件次序推进。

不强行自动序列化任意 C# 对象图。没有检查点接口的脚本仍可工作，代价是重新执行历史；可显示重建进度并支持协作取消。检查点是派生缓存，不是源数据。

## 6. 首批音频输入：节奏与低频

当前 Media 已有音频探测、PCM 解码和波形，尚无脚本用的离线节奏／低频分析服务。首期不暴露完整 FFT、高频频谱或通用高潮探测器。

`AudioAnalysisService` 基于源音频离线生成可重现的数据：低频带 RMS／能量（首期默认 20～250 Hz）、低频包络、短时能量变化和节奏脉冲；能估计稳定拍点时再提供拍点相位／序号／置信度，以及 BPM 元数据。低频脉冲不等于准确拍点；弱节奏或无节奏片段返回节奏不可用／低置信度，不伪造 BPM。归一化和包络时间常量固定在 `AnalysisConfig`，不按某次试听片段的最大值重新缩放。

分析采样率、窗口、hop、低频范围和分析版本进入 `AnalysisConfig`。首期不追求通用精准节拍识别，低频量和可视化脉冲是基本验收入口；昂贵的特征计算在离线分析阶段完成。

`ProjectContext.Audio` 提供 `GetAt(timeUs)` 与 `GetRange(startUs, endUs)`；脚本在 `Advance` 或音频事件中自行累计高潮估计。预览与导出读取同一离线数据，不从实时音频设备采样。音频内容哈希、`AnalysisConfig` 和分析器版本是缓存及检查点输入。

## 7. Roslyn 热编译与状态交接

热编译采用编译出新代次后替换：

```text
源码变化
  -> Roslyn 编译、文件／行／列诊断
  -> 创建新代次并初始化
  -> 重放到当前工程时间
  -> 试运行成功后在会话边界原子替换
  -> 释放旧实例、回调和加载上下文
```

这不等于把任意正在执行的函数或对象就地改写。首版入口按 §11 使用实现 SDK 的普通 C# 类型，由 Roslyn 编译；早期比较的 .csx／globals facade 保留为后续扩展方向，不再并列成首版未裁决事项。

默认不把旧代次的任意对象直接交给新代次。只有脚本明确提供带 StateSchemaVersion 的状态交接且验证成功时才恢复；否则重放。

编译失败时预览可继续使用旧代次，但必须显示“源码尚未生效”。导出不能静默使用旧代次：只要工程当前启用源码编译失败，就阻止导出。导出开始固定源码代次、参数和音频数据，中途预览热替换不改变该导出。

Roslyn 官方提供 globals、编译诊断和连续执行示例；产品需要的代次交接、订阅释放和会话重建由本项目实现，不能把示例 API 当作完整热重载产品。[Roslyn 官方示例](https://github.com/dotnet/roslyn/blob/main/docs/wiki/Scripting-API-Samples.md)

## 8. 受信执行、线程和异常

已决定应用内受信执行，恶意脚本、权限沙箱、独立 worker 和脚本市场不进入当前任务。保留源码、运行代次、启用状态和诊断，便于理解实际执行的版本；不追加反复权限确认。

脚本不运行在 Avalonia UI 线程，而是在主程序进程内按会话使用专用串行调度器：同一会话的回调、历史推进和状态更新不并发；只有诊断、进度和用户可见状态回到 Avalonia dispatcher。这样既保留脚本可持有的全局会话上下文，也不会用历史重放或 Roslyn 编译阻塞界面。多个预览／导出会话是否并行属于性能议题，首版可先限制为每会话串行、跨会话按资源预算调度。

普通编译／运行异常捕获并报告；协作取消和慢回调诊断可以实现。不能承诺在同进程强制终止任意不响应的死循环。CancellationToken 是协作机制，AssemblyLoadContext 卸载同样需要线程退出、订阅和对象引用释放。[.NET 取消规则](https://learn.microsoft.com/en-us/dotnet/standard/threading/cancellation-in-managed-threads)、[加载上下文卸载规则](https://learn.microsoft.com/en-us/dotnet/standard/assembly/unloadability)

该限制影响取消和热编译可靠性，属于当前运行模式的实际语义；不是另行引入恶意脚本防护任务。

## 9. 与统一场景元素的关系

0.6.0 建立 [统一场景元素](unified-scene-element-plan.md)，0.7.0 改为原生树，0.8.0 已接通 [通用编排编辑器](../legacy-ui/scene-editor-implementation-contract.md)；以下 ScriptSession／FramePlan 仍是待实现设计：

```text
工程源数据 + 场景定义
  -> 内容绑定与时间线事件
  -> 样式解析、文本测量、局部布局、世界变换
  -> SceneFrame
  -> ScriptSession（历史推进 + 当前帧效果）
  -> 校验后的 FramePlan
  -> Skia／预览／导出
```

脚本 ProjectContext 可访问完整的只读内容目录，不再只收到当前可见几行。FrameContext 则读当前场景树和几何。SceneElementId 指画布实例，LineId/TokenId 指源内容，BindingId 指槽位本次装载；callback 和效果目标必须说明使用哪个 ID。

0.9.0 验收前拟定的首期输出为主机校验的填充／渐变、描边、阴影、不透明度调制，排版变换和粒子原拟后置。本轮用户新增需求按 §16 扩展为独立视觉缩放及临时粒子输出；字体／字号／字距排版、持久布局／源时序改写仍不开放，具体输出协议先审阅。不能把新提案当成已有 TransformEffect／OverlayElement 实现。

FramePlan 是临时结果，不回写源模型。场景树统一为将来开放受控变换、额外对象提供入口。

0.8.0 的 NodeId／ProgramId／ClipId 与源 BranchId／LineId／TokenId 已分别稳定；BindingId 使用程序、片段或默认成员首末身份、实际槽位和源行，不混入起止时间数值。槽位重排改变装载身份，源时间修改仍使会话和采样结果失效重建。这些是 SDK 的当前依据，不代表 SDK 已冻结；需结合编辑器人工反馈，再固定只读公开合同。Roslyn、ScriptSession、节奏／低频分析、脚本参数与 DLL 持久化仍未实现。

## 10. 分层与依赖建议

```text
Core：歌词源数据、场景定义、参数值、纯校验和编辑命令
Text：后端无关的测量数据
Rendering.Abstractions：SceneFrame / FramePlan / 渲染合同
Rendering.Skia：整形适配与执行 FramePlan
Scripting.Abstractions：稳定 SDK 视图、事件、上下文和效果合同
Scripting：Roslyn、代次、会话状态和脚本运行
Media：音频解码、特征提供器
Application：工作区、历史和预览／导出会话编排
App：编辑器、脚本诊断、组合根
Export：消费会话帧提供接口、编码、取消和结果报告
```

Export 不反向依赖 Application；通过中立抽象取得已评估帧，避免上一版“Export 调 Application”引入依赖环。SDK 不公开 Avalonia、Skia、ViewModel 或可写 Core 工程对象。

无需立即拆出所有这些项目。先落稳接口再按 ADR-0003 增量创建，脚本 SDK 不直接复制全部 Core 类型。

## 11. 持久化和缓存

工程保存源码、脚本清单、绑定、启用状态、SDK API 版本、源代码哈希、种子和声明参数；源码放在工程 `scripts/` 目录，参数编辑走工作区命令和撤销栈。

成功编译的 DLL 是可重建、同时持久化的本地产物。采用应用数据目录，Linux 为 `$XDG_DATA_HOME/MakoKaraGenerator/scripts/<artifactHash>/`；未设置时根目录使用 `~/.local/share`。保存 `effect.dll`、诊断符号 PDB 和构建清单，随程序退出保留，不使用临时目录，也不作为一般帧缓存随手清空。清单记录源码、SDK、编译器版本及选项、全部引用程序集、目标框架／运行时的指纹，工程只关联内容哈希和入口类型，不保存本机绝对 DLL 路径。

先在同一目录树内写完整临时代次、校验后原子发布；编译失败保留此前成功产物，当前启用源码失败仍阻止导出。DLL 缺失或指纹不一致时从工程 `scripts/` 源码重编译；当前已启用产物和正在导出的代次不得清理。源码导入时复制到工程，不依赖原外部目录。首版入口采用实现 SDK 的普通 C# 类型并由 Roslyn 编译；现成 DLL 导入和第三方依赖包管理后置。

复制工程到另一台机器携带源码、清单和参数，目标机器按自己的运行时生成本地 DLL；本地二进制失效不造成源码丢失。只清理不再引用的旧代次，并提供显式重建入口。脚本运行时状态和任意 C# 对象不序列化进 DLL。

脚本状态、检查点、音频特征和临时 `SceneFrame` 仍是可重建缓存，不成为项目唯一源数据。新 JSON 等合同确定后再递增对应 schema，不兼容旧工程。

最终帧缓存必须含：
源快照修订、场景修订、源码代次、参数、音频分析修订、目标时间、模拟合同版本和种子；
帧结果首期不依赖播放控制日志；若未来另立录制模式，再增加该日志修订。

缓存命中只能免掉绘制／求值，不得让脚本会话漏掉历史事件。事件推进发生在有状态会话层，像素缓存是其后层。DLL 构建指纹、音频特征指纹与场景修订各自独立，不把参数变化误判成必须重新编译。

3. **脚本与音频合同**：上下文、事件历史、音频特征查询、模拟步和失败策略。
4. **Roslyn 纵向切片**：热编译、有状态会话、回调释放、重放；先做累计演唱字数／历史能量调色示例。
5. **工程与 UI**：工程源码／参数与本地 DLL 保存、撤销、诊断、启用和实际运行代次。
6. **导出接入**：新会话、独立历史重建、固定代次、异常阻止。
7. **验收后性能基准**：包含状态重放、音频特征、脚本执行和渲染；独立 worker 不作为本轮门槛。

粒子和额外对象协议在单独确认后加入。

§12 保留此前总体顺序；0.9.0 验收后建议将预览／导出的一致性验证前移到最小案例，当前批次划分以 §15 的未实施建议为准。

## 13. 验收必须覆盖

- 主进程受信运行，Roslyn 成功／失败代次切换；
- 首次出现、开始唱、唱完三种 callback 的不同语义；
- 后一个字唱起来时未定时字的状态不被推算；
- 跳转到中段与从头播放到中段得到同一状态和画面；
- 暂停多次重绘不增加计数，30/60 fps 不改变历史模拟结果；
- 循环、参数撤销和热编译后重建正确；
- 低频量／节奏脉冲按源数据可重现；弱节奏不伪造拍点，无音频有明确不可用状态；
- 应用退出重开复用有效的本地 DLL；缺失／指纹失配重编译，失败保留旧产物并阻止导出；
- 字体／字号／位置等越界脚本结果明确拒绝，不以“只管样式”放开布局写权；
- 预览和导出独立状态、相同合同；启用源码错误阻止导出；
- 旧代次回调／定时器／引用释放，不重复执行；
- 像素缓存不跳过历史推进，历史记录不无限保留帧数据。

## 14. 首期决定与后续扩展

已确认的运行信任、主进程内串行调度、热编译、允许历史／全局状态、导出失败阻止和参数撤销不再重复询问。
统一容器字段、脚本源码存储、首批音频输入和首期样式调制范围也已收口；实际播放操作录制、容器变换、粒子／额外对象和更丰富的音频分析属于未来扩展，不阻塞首期实现。脚本提案继续和已实现的场景批次分开记录。

## 15. 0.9.0 验收后的下一步方向（2026-10-02）

> 上一轮推荐范围。用户随后明确逐字放大、跨行粒子及重复文本 callback，当前设计及实施建议按 §16 和新方案 E0～E5；本节不作为粒子继续后置的理由。

### 15.1 当前基础与真正的缺口

用户已确认 0.9.0 功能全部正常，前奏作为真实容器绑定目标句符合预期。规范样式、通用树／片段／槽位／局部微调、文字标记和准备显示已经有实施及验收证据。下一步可以转入脚本系统；本节是方向建议，不是 SDK 已冻结或代码已开工的声明。

当前代码可复用 `ProjectSnapshot`、`SceneDefinition`／`SceneFrame`、`LyricSceneSampler`、源身份与装载身份，以及预览／导出共享的 Skia 管线。仍缺公开 SDK、Roslyn 编译与代次加载、串行会话和历史重放、音频特征、效果帧计划、脚本工程数据及诊断 UI。

代码核对显示以下接缝必须在实施合同中明确：

1. **公开视图**：当前帧分别保存歌词、文字标记和元素，整形后的几何及歌词有效样式由渲染流程生成。SDK 需要后端无关的只读内容／场景／有效外观视图，不能直接公开可写工程、ViewModel、Skia 对象，也不能把内部 `SceneFrame` 全部字段直接当作稳定 API。
2. **身份与事件**：区分持久 NodeId、源 LineId／TokenId、运行时 BindingId，以及提示 CueId；文字标记没有源歌词 TokenId，不伪造源身份。区分持久父组与运行时跟随目标的附着关系。`Preparation`／`Performance` 是展示阶段，后者不等于当前有字正在演唱；可见、首字起唱及各元素演唱事件分别由时间合同决定。
3. **外观组合**：工程基线／行与元素覆盖、原入场动画、提示样式和脚本输出必须有明确的解析顺序。动画不透明度与样式不透明度各自只计算一次；明确脚本读的是哪一阶段的有效值、输出覆盖值还是调制量，以及多脚本顺序。脚本帧效果不写回模板、歌词或工程基线。
4. **共享求值与缓存**：目前 `CachedRenderPipeline.Render` 可在命中时直接返回像素。脚本历史推进必须在像素缓存之前，几何查询和实际绘制不能重复派发同一事件；缓存增加源码代次、参数、音频分析及模拟合同等修订。预览和导出消费共同的已校验效果帧计划，各自建立会话。

这些是增加有状态脚本时需要完成的设计，不作为当前无脚本 0.9.0 的功能缺陷。
