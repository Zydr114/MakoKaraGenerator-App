# 模板目录快照与后台复核

F6b／R13／A03在0.45.4实施，依据[修复计划 §9](archive/plans/code-review-remediation-plan.md)、ADR-0174及[修复验收](archive/acceptance/code-review-remediation-acceptance.md)。本合同只改变目录读取与新应用入口，不升级工程中的固定PresetApplication或工坊作者草稿。

## 所有者与读取

组合根持有一个Application层TemplateLibraryCatalogue，通过ITemplateLibrarySource接受模板仓储。MainWindow向AppearanceWorkspaceView显式注入目录。构造目录及隐藏画面工作区不触发库读取；歌词编辑、工程变化和对象选择在只读内存快照上过滤。工坊自身建立作者草稿时的仓储读取保持独立，不把其来源修订替换成目录缓存。

进入画面任务获得租约，并后台检查真实索引字节修订。首次加载、索引改变、错误重试、用户完整刷新或资源失效才展开闭包。一个后台读取者合并失效请求；每次结果对照索引字节和请求代次。最后租约释放后不启动新读取，已开始的只读操作安全完成并丢弃迟到结果；再进入重新复核。窗口关闭释放租约与订阅，共享目录由应用拥有。

文件通知只提示失效。存在库时监视索引及包资源；缺失库时监视最近存在的上级目录，目录创建后在后台调整监视位置，不创建库目录或递归监视整个仓库。包资源、目录和监视错误要求完整校验，即使索引字节没改变也检查闭包。隐藏期间仅积累失效标记。

本进程保存、删除、导入沿用F3仓储，成功通知携带本次固定发布内容。提交通知可能在释放写入锁后乱序：目录显示发布快照但先标过期，在后台对照实际字节后才允许新应用。旧读取不能覆盖新发布；旧通知也不能将旧修订误认成当前。UI通知合并，视图重新取得最新快照，不重放旧目录对象。

## 错误与操作边界

读取失败或任何库诊断均保留上次成功目录并显示错误／过期状态，不能报告空个人库。加载、过期和错误阶段禁用新应用及更新；路由调用也检查有效性、所选固定模板和确认前后目录代次。用户可明确刷新；成功后清理错误并恢复入口。

已有工程应用继续使用固定快照，可启停、移除或复制自己的快照；库刷新不修改工程数据、实例ID、种子、dirty或撤销历史。工坊的作者来源修订、非法文本和F3冲突门禁保持独立。

## 画面区展示与精确分段（0.49.3）

依据ADR-0182，预设、应用对象和分段端点的展示模板在控件构造时建立一次。对象绑定、名称、详情、启用和缺失状态都相同时保留实际项目及多选集合；任何展示内容改变仍替换项目。预设候选按目录对象引用比较，即使完整刷新后的内容相同，也采用新目录的实际对象，保持新应用的引用门禁。

分段端点持有上一份歌词行展示快照。领域编辑清空／重建行集合时，先保留原端点ID，再映射到当前行对象和文字；删除端点时回退到当前所选行。换工程明确重置两个端点，不能继承旧工程的选区。普通选择不重建相同的项目来源，仍刷新实际目标、输入映射、继承和动作可用性；已有固定应用及保存／撤销语义保持。

## 可重复验证

- Application的TemplateLibraryCatalogueTests与LibraryRepositoryTests.Catalogue验证单读取、合并、激活／隐藏、乱序通知、迟到读取、错误保留、完整资源及另一个真实进程更新。
- `bash tools/ui-suki-compatibility/layout-check.sh --catalogue`通过实际编辑、选择、预设确认、失效入口、已有应用及关闭路由；不连接桌面。
- `--appearance-refresh`使用实际控件验证多选、编辑／撤销／重做、端点删除、换工程和同内容目录完整刷新，覆盖深浅主题及760／1440宽度。
- `--catalogue-benchmark`使用MAKO_PERSISTENCE_FIXTURE指定的固定300秒音频／60秒视频，三个固定包和100个含材质包模板，记录目录读取次数及输入优先级任务排队分位数。普通编辑／选择零全库和索引读取、所有目录IO不在dispatcher为硬断言。

带窗口绘制的Headless目录基准与F6a保存基准不同，不能沿用其50ms检查或宣称物理输入／绘制验收。当前仍记录其他UI工作的剩余排队延迟，实际数字与线程证据见修复验收；不以缓存完成代替全部交互性能已解决。文件通知不是外部写入事务：任意编辑器不参与协作锁，持续改变索引会显示错误并等待再次刷新；不保证网络文件系统通知或Windows实机行为。格式28／16／6、配置1、profile2、作者SDK与固定生产依赖保持。
