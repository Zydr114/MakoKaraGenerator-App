# 自然引导修订：让操作说明自己

日期：2026-10-10。范围：[新版 UI 设计稿](ui-0496-prototype.html)及其配套规范；不修改桌面产品。

用户已确认本次自然引导版可作为重构基线。后续实施统一参见 [UI 重构规划](../archive/legacy-ui/ui-0496-refactoring-plan.md)，保持当前全部功能及原生 SukiUI 风格。

用户认可上一版布局，本次保留工作区、三栏关系、画布、检查器和时间轴的位置。仍遵守“先制作外观预设，再应用到对象”。这次纠正的是设计稿自身的说明负担，原始截图与代码审查的 36 项问题保留为历史依据。

## 1. 问题重新判断

上一稿试图通过写清所有边界来消除歧义，但把设计规范当成了页面内容：标题解释流程、面板解释职责、提示框解释提交、底栏再解释一次。用户每次工作都要掠过相同文字，真正变化的目标、草稿、错误反而不突出。

新的要求不是单纯缩短句子。任何一个动作如果需要先读一段话才敢操作，先检查动作名称、前置条件、结果预览和返回路径是否清楚，再判断是否确实需要说明。

## 2. 信息何时出现

| 信息 | 呈现时机 | 例子 |
|---|---|---|
| 当前目标、选择、值 | 始终可见，各占一个位置 | `主歌词 / 第 1、4 行 · 2 行`；字段旁的单位 |
| 会改变用户判断的状态 | 状态所在对象旁，保持到状态改变 | `未保存`、`继承自工程默认`、`试看`、`脚本关闭` |
| 可执行的下一步 | 使用具体动作名称，随条件变化 | `复制并编辑` → `保存并试用` → `应用到 2 行` |
| 必填项、非法输入 | 需要用户解决时，就地呈现 | 未映射来源时显示来源字段；非法结束时间在该字段下显示原因 |
| 成功反馈 | 操作后短暂显示 | `预设已保存`；底栏反馈约 4.5 秒后恢复“就绪”，撤销入口持续可用 |
| 不可逆或有损后果 | 提交前说明具体对象和后果 | 丢弃哪个未保存草稿、覆盖哪个文件；不用泛化警告 |
| 继承细节、版本等低频信息 | 用户打开该对象详情 | `外观来源`、`库版本与更新` |
| 教程、算法、架构合同 | 帮助文档 | 不分散成十几个常驻提示，也不整段塞进悬浮提示 |

“就地呈现”不能退化为只给一个红框或不可点击按钮：必要原因必须可见且有修复入口。错误不能用会自动消失的底栏消息代替。空态只保留状态和一个能启动任务的动作。

## 3. 按页面调整

| 页面 | 删除或降级的信息 | 自然引导方式 |
|---|---|---|
| 全局 | 每次切页重放职责说明；每次保存解释其他保存层级 | `保存工程/保存预设/保存组件`明确对象；状态留在对应标题；底栏只反馈刚完成的动作 |
| 歌词与打轴 | “播放与选择独立”、输入提交规则、单字不可拆分等常驻说明 | 标题标编辑行，预览标当前时刻，按钮直接写“定位到此行/试听此行”；时间字段保留单位、选中单元和局部错误 |
| 画面与编排 | “选择对象→核对→应用”流程文字；每行重复“继承 Test”；先做预设的常驻教学 | 左侧可见多选模式；右侧只显示一次应用对象、当前预设与来源；`更换预设/复制到工坊编辑`表达两条路径 |
| 预设选择 | “工程尚未改变”“可一次撤销”和目标范围的多重提示框 | 画布一个`试看`标记，检查器一个精确目标，按钮`应用到 N 行`；取消直接回原画面 |
| 预设来源映射 | 中央警告与侧栏错误重复 | 缺来源时保留原工程画面；只有来源字段旁显示`选择来源后可试看`，补齐后自动更新候选画面并启用应用 |
| 基础布局 | 范围高亮教程、当前到候选的重复说明、泛化继承警告 | 选区高亮对应范围字段；画布从`当前布局`切换为`试看`；应用按钮写入具体范围。真正的继承变化须在提交差异中列实际影响 |
| 预设工坊 | 内置只读教学横幅、个人库与工程区别、固定试样解释 | 只读状态旁直接提供`复制并编辑`；编辑后显示`未保存`；从工程进入保留返回对象和`保存并试用` |
| 效果组件空态 | 首次使用三步教学及无内容表单 | `还没有效果包` + `导入效果包…`；导入后出现当前效果所需字段 |
| 效果配置 | 固定包、未保存、未验证组合成的大提示框 | 包版本是字段值；未保存只在标题；验证状态在验证页；父预设只读时给`复制预设并加入`直接解决阻碍 |
| 源码 | 常驻解释保存、编译、采用的区别 | 主操作依次为`保存修订`→`编译`→`采用修订`→`验证此修订`；不具备前提的动作禁用；当前状态紧邻文件名 |
| 自定义布局 | 上下各一段“草稿不改工程/不运行脚本” | 标题显示`未应用`，画布一个`布局预览 · 脚本关闭`，提交写`应用并返回`；真正存在冲突再就地解释 |
| 工程设置 | 画布与缩放、音频归属、关闭保存、计算一次的常驻说明 | 分组与字段单位表达含义；`按当前音频计算`是取值动作；字段提交后脏状态/撤销更新 |
| 导出 | 原型免责声明占据产品面板 | 输出路径与摘要直接可读；交互预览的模拟范围统一在产品外标记一次 |

## 4. 三条完整路径

### 给两行更换外观

左侧“多选” → 勾选第 1、4 行 → 右侧显示这两行 → 更换预设 → 点击候选后画布变为“试看” → “应用到 2 行” → 返回并短暂反馈已应用，撤销可用。

必要信息来自选择、预览、按钮范围和结果。没有一段话要求用户先理解完整预设架构。

### 改出自己的预设

当前对象“复制到工坊编辑” → 名称和可编辑字段 → 修改后“未保存” → “保存并试用” → 回到原对象试看 → 明确应用。

直接进入内置预设时，“复制并编辑”是首个主动作。只有从工程带入了返回对象，才出现“保存并试用”；独立制作则是“保存预设”。保存到库与应用到工程由实际步骤区分。

### 修改源码并用于当前组件

源码修改后：`未保存 / 保存修订`；保存后：`待编译 / 编译`；成功后：`编译通过 / 采用修订`；采用后：`已采用新修订 / 验证此修订`。参数或采用版本变化后，旧报告显示“需重新验证”。

这不是自动替用户执行后续动作。保存、编译、采用、验证仍各有边界，但用户不用对照一段流程说明寻找按钮。正式实现还须把编译/运行失败、取消和诊断定位接进同一条状态路径。

## 5. 不应因删字丢失的内容

- 多选必须展示具体目标，不只给数量；保留局部预设、范围扩大、映射变化等真实后果在确认前可判断。
- 不能把“未保存、试看、脚本关闭、需重新验证”都删除成一个绿点。用简短文字和控件状态共同表达。
- 输入错误保留输入和原因，修正后消失；不要默默纠正、静默失败或只显示禁用。
- 删除、覆盖、丢弃仍按真实后果确认；普通可撤销应用不增设一道“你是否理解”确认。
- 窄窗口和键盘操作仍可找到多选、主提交、错误及取消；不能靠悬停发现关键功能。
