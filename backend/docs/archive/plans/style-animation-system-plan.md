## 0. 当前状态与下一步

- 线性、行坐标的多停止点渐变、RGB／HSV 插值及行／元素覆盖已贯通；径向、Oklch 和其他坐标空间仍未接入。
- 完整 `StrokeSpec` 已在 0.2.7 接入模板属性、行／元素覆盖、读取、持久化和 Skia。透明填充的外部描边已改为字形遮罩求差，见 §13。
- 方向阴影、字重／粗体／斜体／字距和字体诊断已有实现；不重复开发这些参数。
- `FillSpec`、独立 `TypographySpec` 和现有双重字段的统一表达仍待独立模型批次完成。
- `LinePlacement` 的行编辑已在 0.2.8 验收；0.3.0 补齐分支默认与跨分支批量。`LyricBranch`、`RubyAnnotation`、`DualLineAnimationProfile` 已贯通当前格式、编辑和渲染，见 §15。

描边与独立行位置已验收；翻译、注音、分支切换和双行整体变换已获用户确认。0.3.1 收紧双行模式的位置所有权，0.3.2 增加分支级双行整体变换。下一步推进样式模型统一与高级渐变；脚本阶段仍须先决定运行进程。

每批通过 Core、当前格式往返、视图模型和像素断言；全量构建与测试通过后启动正式窗口验收。改 JSON 结构时提升对应 schema，按 ADR-0050 不追加旧工程自动迁移；普通收尾递增 PATCH，不兼容模型重构递增 MINOR。

## 1. 这轮要解决的问题

下一轮需要同时解决四件相互影响的事：

1. **样式编辑要像编辑设计稿**：用户能快速找到样式、看懂样式包含的属性、在独立窗口中修改和预览，最后明确应用到工程、行或元素。
2. **布局要能直接在画布上操作**：每一句歌词可以拖动，位置在画布下方显示精确数值，可以将位置批量应用到选中的行或某个歌词分支。
3. **动画要能编排多句歌词**：动画不能只挂在一行上；最基本的双行交错显示必须由统一采样器计算，预览和导出走同一份结果。
4. **歌词要能有多个分支**：逐字歌词、翻译、注音等分支有各自的显示策略、样式和布局；翻译分支默认只做简洁的静态显示，不参加逐字动画。

### 1.1 这轮不做的事

- 不把脚本扩展成动画、时间轴、分支或粒子系统；脚本只处理样式结果，具体限制见第 7 节。
- 不要求本轮自带更多中文字体文件；先建立字体发现、回退和诊断接口，使用本机可发现的字体。
- 不先做任意节点式关键帧编辑器；先用可组合的内置动画配置覆盖真实的双行需求。
- 新建工程默认提供主歌词分支；新增分支和布局必须显式配置。旧程序版本工程按 ADR-0050 的门禁拒绝加载，不做自动转换。

## 2. 分层原则

以后渲染一帧时，数据和职责固定按下面的顺序流动：

```text
工程快照
  -> 分支与行时间采样（哪些行在当前时刻可见）
  -> 布局求解（槽位、位置、注音占用和碰撞）
  -> 样式解析（工程 -> 分支 -> 行 -> 元素）
  -> 动画求值（进入、保持、退出、逐字进度）
  -> 脚本样式调制（只改变允许的样式通道）
  -> 画布合成
```

需要坚持的约束：

- 分支采样器、布局求解器、样式解析器和动画求值器都放在 UI 之外的纯逻辑层；
- 预览和最终导出都消费同一份 `RenderScene` 或等价的场景快照，不在 Avalonia 控件里重新推导时序；
- 渲染器只读快照，不把拖动结果、动画进度或脚本临时值写回项目源数据；
- 所有新增属性都必须有校验、当前格式持久化往返、视图模型测试和至少一条渲染断言。

## 3. 样式系统的下一版模型

### 3.1 从一组颜色字段升级为可组合的绘制描述

当前 `LyricStyle` 中的四个渐变端点、描边和阴影字段足以覆盖首期，但无法表达多色停止点、方向和色相插值。下一版建议将绘制属性拆成以下值对象，并收敛基础字段与完整对象的双重表达；新格式按程序版本断代，不追加旧字段迁移：

| 值对象 | 主要内容 | 首期用途 |
|---|---|---|
| `FillSpec` | 纯色或渐变、停止点、坐标空间、角度 | 未唱／已唱填充、单字多色 |
| `GradientSpec` | 线性／径向、方向角、停止点、插值空间、色相路径 | 可调方向和色相的渐变 |
| `StrokeSpec` | 颜色、宽度、连接方式、位置 | 外部描边 |
| `ShadowSpec` | 颜色、不透明度、方向、距离、模糊半径 | 可调方向和模糊的阴影 |
| `TypographySpec` | 字族、回退族、字重、斜体、字距、字号 | 字体和字形参数 |
| `LinePlacement` | 锚点、X/Y、坐标空间、旋转和缩放基线 | 逐句位置 |

解析优先级从低到高固定为：

```text
工程默认样式
  -> 分支样式覆盖
  -> 行样式覆盖
  -> 元素样式覆盖
  -> 当前帧的动画变换
  -> 脚本允许的样式调制
```

样式库的“类别”是编辑器组织信息，不新增继承层。建议首期类别为：**字体、填充、渐变、描边、阴影、布局、动画外观**；一个样式可以带多个类别标签，选择器按标签筛选。

### 3.2 渐变、色相和逐字多色

- 全局未唱／已唱分别拥有 `FillSpec`，可以是纯色或多个停止点的渐变；至少支持线性渐变，径向渐变留在同一接口的后续实现位。
- 渐变方向使用角度和可视化方向手柄双向编辑；角度以画布坐标定义，避免预览窗口大小变化导致方向改变。
- 渐变坐标空间明确区分**画布、行、字形、逐字进度**。默认使用行空间，逐字多色使用字形空间，时间推进只由逐字进度负责。
- 颜色插值必须记录插值空间和色相路径，不能把 RGB、HSV 和感知色空间混成一个未命名的“色相”。默认采用线性 RGB 和短色相路径；编辑器提供方向、色相路径和插值方式选项，感知色空间作为可选扩展。
- 一个元素可以拥有多停止点填充，因而支持单字渐变和单字多色；元素覆盖只写填充属性，不复制整份行样式。
- 渐变采样由渲染层统一实现，逐字裁切只改变可见区域，不重新排版，保证进度线推进时字形边界不跳动。

### 3.3 描边和阴影

- 描边语义固定为“外部”：描边像素不能侵入字形填充区域。Skia 实现应使用字形遮罩或等价的外扩路径，不能仅依靠居中的 `StrokeWidth`。
- 描边的颜色可以是纯色或与填充相同坐标的渐变；第一阶段先实现纯色，数据结构预留渐变。
- 阴影由颜色、透明度、方向角、距离和模糊半径组成；方向与距离分开编辑，预览中提供方向手柄。
- 元素覆盖关闭描边或阴影时，渲染器只画一次最终区域，不能留下整行样式的外沿。这延续 ADR-0044 的“每个区域只画一次”约束。

### 3.4 字体、字重和回退

- `TypographySpec` 增加可序列化的字重（100–900）、粗体、斜体和字距；粗体／斜体是字形请求，不在 UI 中偷偷拼接字体名称。
- 字体选择器显示字体族、可用字重、斜体支持和缺字诊断。字体来源使用系统字体发现和现有 `ITextLayoutEngine`，本轮不捆绑中文字体。
- 同一行缺字时，布局结果记录每个字形实际使用的字体，检查器可指出回退发生的位置；预览和导出必须使用相同的字体发现结果或明确报告环境差异。
- 字重和斜体属于整行排版属性，元素级仍然禁用；元素级可以覆盖填充、描边、阴影和不透明度。

## 4. 更人性化的样式选择器与独立编辑器（历史设计）

> 本节的目标应用区、旧样式窗口及工程上下文设计已由 ADR-0050/0051 取代。当前制作和套用交互见模板优化与套用体验方案，不再作为待实施窗口任务。

### 4.1 独立窗口

新增 `StyleEditorWindow`，首期作为独立窗口而不是模态对话框，打开后可在主画布和编辑器之间切换。当前窗口关闭只隐藏窗口，草稿由会话状态保留；工程保存不保存未应用草稿。

推荐布局：

```text
┌────────────┬──────────────────────────┬──────────────────────┐
│ 类别/筛选   │ 试样预览、前后对比、画布   │ 属性编辑与来源        │
│ 内置/我的    │ 可切换未唱/进行中/已唱     │ 渐变、字体、描边、阴影 │
│ 最近/收藏    │ 可拖拽渐变和阴影方向       │ 草稿状态、继承状态     │
├────────────┴──────────────────────────┴──────────────────────┤
│ 目标：工程 / 当前行 / 当前元素 / 已选行 │ 选择属性 │ 应用 / 恢复继承 │
└───────────────────────────────────────────────────────────────┘
```

### 4.2 选择器行为

- 内置、我的、工程当前样式和草稿分组显示；每张卡片显示缩略试样、类别标签、支持范围、来源和最近使用时间。
- 搜索同时匹配名称、标签、字体、颜色和效果；支持收藏、最近使用和“只看当前目标可用”。
- 单击卡片只换试样和草稿来源，不改工程；切换会提示“草稿有未应用改动”并提供保留、丢弃、取消。
- 预览提供前后对比和动画暂停按钮，样式编辑器的预览计时器独立于动画页签和主画布。
- 应用区在提交前列出目标、将写入的属性、被元素能力限制排除的属性和撤销提示；一次应用仍是一条撤销记录。
- 个人样式的保存、更新、重命名和删除继续只操作应用级样式库；已经应用到工程的值不建立动态链接。

### 4.3 可选效果的开关交互

渐变、描边和阴影都采用“开关先于参数”的界面契约：

- 效果没有有效参数时，效果复选框未选中，参数区完全隐藏；效果是否启用、涉及哪些属性以及开启/关闭时的初始值由 Core 的 `LyricStyleEffects` 统一提供，界面不再自行复制这套判断；
- 选中复选框后才显示颜色、停止点、方向、宽度、偏移和模糊等调节菜单，并填入可编辑的初始值；
- 关闭复选框会清除该效果的参数并把相关属性加入本次应用，写入“明确关闭”；
- 参数区内部仍可逐属性取消勾选，用于批量应用时保留其他层的值；
- “关闭效果”和“恢复继承”是两个动作：前者写入本层的显式关闭，后者清除本层覆盖；两者都可撤销。

## 5. 画布位置编辑和批量应用

### 5.1 位置语义

`LinePlacement` 采用画布归一化坐标保存（0–1），同时保留画布像素换算结果供界面显示。锚点默认是行的几何中心，后续可扩展到左上、基线中心等锚点。归一化坐标使工程在改变输出分辨率后保持相对位置；用户仍能在画布下方输入像素值。

位置所有权按布局模式决定。手动模式使用：行显式位置 → 分支默认位置 → 样式默认位置。双行模式使用槽位位置 → 分支默认位置 → 样式默认位置；行显式位置保留在工程中，但不参与双行渲染。动态模式下编辑器禁用逐行拖动、位置输入、恢复默认和批量位置入口，用户应在分支设置中编辑槽位。

### 5.2 交互

- 画布进入“布局选择”后，点击行显示边界、锚点和对齐辅助线；拖动整句移动，不改变文字时间。
- 画布下方固定显示 X、Y、锚点、旋转和缩放；支持像素与百分比切换、方向键微调、恢复分支默认。
- 拖动时显示与画布边缘、中心线和其他选中行的吸附提示；吸附只影响本次编辑值，不静默修改其他行。
- 选中多行或一个分支后可“应用当前行位置”“平均分布”“恢复分支默认”；批量操作必须预览目标和冲突，一次写入一条撤销记录。
- 位置编辑不改 `LyricStyle` 的字体和填充字段，避免“移动一句歌词”把视觉样式固化到行覆盖。

## 6. 歌词分支、注音和动态布局

### 6.1 分支模型

将 `LyricsDocument` 扩展为包含多个 `LyricBranch`：

```text
LyricsDocument
  ├─ Branch: 主歌词（逐字、Karaoke）
  │    └─ LyricLine[]
  ├─ Branch: 翻译（静态、跟随主歌词）
  │    └─ LyricLine[]
  └─ Branch: 注音（预留、跟随基础文本）
       └─ LyricLine[] / RubyAnnotation[]
```

每个分支至少包含稳定 ID、显示名称、角色、语言、默认样式、布局配置、时间策略和动画策略。角色建议为 `Primary`、`Translation`、`Annotation` 和可扩展的 `Custom`。

- 主歌词分支默认拥有逐字时间和卡拉 OK 动画。
- 翻译分支默认以静态文本显示，默认跟随关联主歌词的可见区间，不参与逐字填充、进入、退出或槽位轮换动画。
- 行之间用稳定的关联键配对，而不是用数组下标；主歌词增删、重排时，无法匹配的翻译行必须在诊断中提示。
- 新格式歌词文档显式保存主歌词分支；稳定行／元素 ID、样式覆盖及进入动画进入当前格式往返测试，不为旧工程建立自动转换。

### 6.2 注音预留

注音先建立数据和布局接口，不要求本轮完成导入器和完整编辑 UI。建议 `RubyAnnotation` 关联基础文本元素，包含注音文本、语言、相对字号、对齐方式和间距。

- 注音的时间默认跟随基础元素，不建立第二套逐字时间。
- 布局器把“基础字 + 注音”视为一个占用组，先测量注音再求基础行的位置，避免注音覆盖上一行。
- 注音不得改变基础歌词的逐字进度边界；渲染可以分别裁切，但进度只由基础元素决定。
- 后续如果需要日文汉字的多种读法，数据结构支持一个基础范围挂多个注音候选，但界面一次只激活一个。

## 7. 动画系统改造

### 7.1 动画和样式分开

引入 `AnimationProfile` 与 `LayoutProfile`。样式描述“长什么样”，布局描述“放在哪里”，动画描述“何时出现、怎样过渡”。新模型用行进入配置表达现有进入动画能力；新采样器稳定后清理旧字段，不保留旧工程兼容输入。

动画采样器的输出应至少包含：分支 ID、行 ID、槽位 ID、可见性、行进度、逐字进度、进入/保持/退出进度和几何变换。它不返回颜色；颜色由样式解析器和脚本样式调制决定。

### 7.2 双行布局的完整时序

内置 `DualLineStaggered` 配置提供两个交替槽位：默认一左上、一右下。双行模式下槽位是主歌词位置的唯一来源，行显式位置不覆盖槽位。阈值、槽位、过渡、保留和冲突处理都不是写死的动画分支，而是配置的一部分。默认规则：

1. 第 `n` 行进入第一个槽位并开始逐字播放；
2. 当第 `n` 行逐字进度达到 `RevealProgress`（默认 0.5，可改为时间、百分比或跟随下一行的提前量）且第 `n+1` 行有有效时间时，第 `n+1` 行进入第二个槽位并开始播放；
3. 当第 `n+1` 行达到同一触发条件时，调度器准备第 `n+2` 行进入第一个槽位；
4. 默认的保留策略是旧行保留到自身行结束。若目标槽位仍被旧行占用，默认排队等待槽位释放；用户可以改为允许临时显示第三行、提前退出旧行或跳过本次触发；
5. 槽位替换使用独立的进入／保持／退出配置，后续行按槽位交替轮换。每个配置都能单独选择曲线、时长、位移、缩放、透明度和触发条件。

### 7.3 双行动画的自定义空间

动画编辑器需要把“双行模板”展示为一组可编辑参数，而不是一个不可解释的开关：

- **槽位**：名称、顺序、归一化位置、锚点、安全区、最大宽度和对齐；
- **触发**：当前行进度百分比、绝对时间、下一行提前量、行结束前时间，以及是否要求下一行有完整时间；
- **可见行数**：最大同时显示行数、槽位占用冲突策略（排队／允许额外行／提前退出／跳过）；
- **进入**：起始透明度、缩放、位移、方向、缓动和是否从槽位外开始；
- **保持**：静态、轻微强调、逐字填充和样式脉动；
- **退出**：保持到行结束、淡出、滑出、缩放退出、退出时长和缓动；
- **分支过滤**：哪些歌词分支使用该布局，翻译分支使用的独立安全区和显示条件；
- **继承与覆盖**：工程默认、分支覆盖、行覆盖，恢复继承只清当前层选择的属性。

编辑器提供预设模板（例如“左上/右下双行”），模板只是初始参数集合，用户可复制为个人动画配置再逐项修改。渲染器只消费解析后的配置，不根据模板名称写特殊分支。

采样器必须处理行时间缺失、行过短、首尾行和播放头跳跃：缺失时间的行不能凭空参与时序，跳转后应从当前时刻重建同一场景，而不是依赖逐帧累积状态。

### 7.4 其他内置动画规划

按实现顺序分为四组：

1. **行过渡**：淡入、滑入、缩放、淡出，支持线性和常用缓动；
2. **逐字反馈**：填充推进、当前字轻微强调、完成后的短暂高亮；
3. **布局编排**：双行交替、翻译跟随、三行安全区、按分支设置显示区域；
4. **样式脉动**：颜色、渐变停止点、描边亮度和阴影强度的受限变化。

旋转、任意路径、粒子和场景对象先不放进内置动画系统；它们若未来需要，必须另立场景动画契约，不通过样式脚本偷偷实现。

### 7.5 翻译分支的显示策略

翻译默认使用独立的静态样式和固定安全区，可以在主歌词行出现后显示，直到关联主歌词行离开。翻译行可以拥有自己的行级起止时间，不要求逐字切分；没有关联键时也可以按自己的时间独立显示。它不参与逐字进度，不进入双行槽位轮换，也不继承主歌词的进入动画。后续可增加一个简单的“跟随主歌词整体淡入”开关，但那属于分支布局过渡，不是逐字动画。

## 8. 脚本系统边界

本计划把脚本限制在**样式层**：脚本可以读取已布局的字形边界、分支和逐字进度，并返回填充颜色／渐变停止点、描边、阴影、样式不透明度等允许的样式调制；脚本不能改变：

- 行或分支的显示时序、逐字时间和关联关系；
- 行的位置、槽位、旋转、缩放和碰撞结果；
- 进入／保持／退出动画曲线；
- 分支的角色、布局策略和翻译静态策略；
- 新建动画对象、粒子或改变背景场景。

因此动画采样器先完成，脚本只接收其输出。脚本的每帧结果仍必须是纯样式值，预览和导出使用相同输入；脚本异常只影响该样式调制，不得让 UI 线程崩溃或写出半截视频。

- `LyricsDocument.primaryBranchId/branches` 是磁盘真值；`Lines/Language` 是主分支的便捷访问，不在歌词根对象另存副本。

- 主窗口歌词栏上方选择分支；切换只重建编辑视图、不写工程。文字、时间和模板继续由现有歌词行编辑器编辑，导入替换当前分支并重新分配全局唯一 ID，其他分支保留。
- 分支设置负责创建／删除翻译、名称／语言、时间策略、关联和布局配置；编辑先写设置草稿，保存一步撤销，取消无写入。主分支不能删除；工程变化后旧设置草稿拒绝保存。
- 翻译默认静态、字号为工程基线的 65%、底部安全区。行通过 `primaryLineId` 关联主行；重排不改变关联，失效关联报告诊断。关联行跟随主行实际可见区间，包括双行提前显示；没有关联的行可使用自身时间。
- 关联模式下，行编辑器明确提示时间来源、禁用独立行时间写入，波形聚焦关联主行的源时间。解除关联或改为独立策略后可编辑本行时间。
- 模板「全部」覆盖所有分支的同类对象；位置批量按分支分组勾选全工程行，保持原有预演／确认／一步撤销。渲染和保存始终使用实际主分支；编辑投影只供现有单分支行命令使用，不写盘、不参与渲染。

### 15.2 统一场景和动态布局

`LyricSceneSampler` 输出分支、行、槽位、逐字状态、位置及进入／退出进度与几何通道；
逐字时间仍由 `LyricSampler.SampleLine` 解释。普通预览和导出共同消费它，不依赖逐帧累积状态。

- 双行按有效时间行的文档顺序交替槽位；未定时行不占槽位。默认行时间进度 50% 时提前显示下一行，预显行在自身演唱前保持未唱外观。
- 可选上一行开始后固定延迟、下一行开始前提前量；槽位冲突可排队、允许额外行、提前退场旧行或跳过。跳过行不会在旧行结束后意外复活；旧行默认留至自身结束。
- 分支设置提供触发、最大可见数、冲突／保留策略、槽位位置／锚点／旋转／缩放，以及进入／保持／退出的不透明度、缩放、横纵偏移、旋转和独立进入／退出缓动。
- 进入和退出时长超出可见区间时按比例压缩，不扩大或改写源行时间。本行已有进入覆盖优先于分支进入通道；保持和退出仍采用分支配置。
- 翻译默认不进入槽位、不逐字变色，也不继承进入动画；可显式选「跟随主行整体动画」，只跟随整体通道，不复制逐字高亮。
- 同时出现的静态关联翻译先测量占用，再在安全区内分行，必要时适配尺寸；占用包含注音和装饰外扩。显式行位置优先，不自动挪动用户单独定位的行。最大宽度可限制最终布局缩放。
- 画布布局试样与命中几何采用所属分支的默认位置或当前双行槽位。双行模式下只允许查看当前槽位，逐行手动位置控件停用；关闭双行后恢复本行位置。辅助线和试样请求仍不进入成片。

### 15.3 注音

`LyricLine.rubyAnnotations` 保存 `id/baseTokenId/text/language/relativeScale/gapPx/alignment`。
先整形基础行与注音，测量联合字形占用，再定位整个组；基础字的横向进度边界不重切。
注音跟随基础元素的时间进度与样式，缺失时间保持未唱外观；基础字失效、重复活动注音和非法参数有诊断。
复制行会重建注音 ID 与基础字关联。本批不提供完整注音导入器或编辑 UI，符合阶段 G 约定；演示工程的「夜」附带 `yè`，可直接核对画面。

### 15.6 0.3.1：双行布局所有权收紧

0.3.0 实窗验收中确认翻译、注音和分支切换无问题；双行位置暴露出槽位与本行显式位置同时拥有布局的问题。
本版采用明确的模式所有权；用户已确认双行布局和非双行布局均正常：

- 普通模式由 `LyricLine.Placement` 负责逐行位置。
- 双行模式由 `DualLineAnimationProfile.Slots` 负责主歌词位置；场景采样输出的槽位位置传给渲染和几何命中。
- 双行模式下保留工程中的本行位置，不删除、不改写，但渲染、画布试样、命中测试和布局编辑均忽略它。
- 动态模式下禁用逐行拖动、位置输入、恢复默认和批量位置；切回普通模式后原位置恢复。
- 进入／保持／退出动画只作用于已解析的槽位布局，不重新决定布局位置。

槽位坐标是其锚点在画布中的归一化坐标。分支级整体变换包住槽位布局：以画布中心为轴，使用归一化横／纵偏移、旋转和缩放，保持两槽位的相对关系。普通模式不读取该变换。

本版构建无警告、无错误，1365 项测试通过；新增槽位覆盖像素断言和动态模式逐行编辑拒绝断言。用户已确认双行布局和非双行布局正常工作。

### 15.7 0.3.2：分支级双行整体变换（2026-09-30，用户验收通过）

0.3.1 的实窗验证确认双行模式和普通模式的位置规则均可用。为避免用户只能同时修改两个槽位，0.3.2 在歌词 schema v12 增加可选的 `DualLineGroupTransform`：

- `OffsetXRatio`／`OffsetYRatio` 表示相对画布宽高的整体横／纵偏移；`RotationDegrees` 与 `Scale` 以画布中心为共同变换轴。
- 变换在槽位位置解析之后、行进入／保持／退出动画之前生效。槽位一和槽位二使用同一个外层变换，因此相对方向与间距只随整体缩放／旋转改变，不会被分别重排。
- 双行关闭时保留变换数据但不消费；分支设置的开关关闭会清空本次草稿中的变换，保存后恢复槽位原始位置。普通模式仍由 `LyricLine.Placement` 负责。
- 保存／重开、统一场景采样、画布几何和实际 Skia 绘制共享同一变换函数；整体变换不进入样式模板，也不复用逐行位置。

自动证据包括歌词 v12 结构往返、槽位位置的相对距离和旋转／缩放后的几何、实际画面差异；当前全量测试为 1367 项。用户已确认整体横移、纵移、旋转、缩放、关闭恢复、普通模式恢复及保存／取消／撤销全部正常。下一步是否增加可视化拖动手柄，留待整体样式模型批次之后再评估。
