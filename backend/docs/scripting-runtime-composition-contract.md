# 脚本工作区运行装配合同

2026-10-04；按R0已接受的异步会话／共享画布／独立导出及当前脚本目标授权实施。M3／R7依次完成运行装配、材质编辑和完整包／实例工作区，不以其中一步代替完整交付。

## 1. 本批U0（0.20.0）

Rendering.Abstractions新增中立IRenderFrameSessionFactory／IRenderFrameSession，固定ProjectSnapshot，异步RenderAsync返回正式像素帧。会话承担准备与绘制装配，底层Skia不回调脚本；Export只认识中立接口，不引用Application或Scripting实现。组合根使用既有Scripting／Skia程序集，无新第三方依赖。旧静态IRenderPipeline接缝保持用于基础几何与无效果测试。

完整快照编译入口固定全部源包、实例、分析及指纹。快照补齐实际AudioPath语义，保留未分析／无音频区别，不重建不完整Project或伪造媒体。编译器可由宿主指定本机产物根，指纹仍覆盖真实源码／入口／SDK／分发参考／选项；复用前完整校验DLL／PDB及指纹。失败／损坏缓存不回退旧代次，不改源工程。

实际运行会话帧外固定全包native图／材质／图片资源，以画布逻辑框作为显式捕获框；包图片使用原始像素尺寸、1像素／逻辑单位及声明空间，位置／适配由图Transform节点负责，不默认拉伸。材质与图保留原写权／区域／透明协议、未接通能力和预算门禁。几何实例、图资源、预算及脚本对象由会话独立持有；序列化求值和绘制，取消／失败／正常退出按会话→渲染器→借用入口／图片表面→包native→预算释放，不与预览或别的导出共用可变对象。

主画布异步后台编译／准备／绘制，UI只复制完成像素和显示状态。每画布保留一个串行工作器、一份最新待请求，不堆逐帧任务；播放推进时合并待请求而不反复取消当前帧，快照或工厂变更／关闭取消旧工作。完成结果必须仍属于当前输入，旧请求不能覆盖新画面。失败保留上一成功画面并一级显示“上一成功画面／当前效果失败／不能导出”和真实原因，重新请求不伪装成功。尺寸／时间变化重新求值，快照修改建立新独立会话。资源和脚本不在UI线程执行。

正常工程画布及编排按时间预览使用同一工厂；导出每次建立独立会话，在编码器创建前完成编译门禁，逐帧await准备和绘制。效果／源材质异常继续阻止成片并保护旧产物；视图模型捕获这些真实失败，错误不逃出async事件。普通渲染占位策略只保留在非效果错误。当前编译／求值错误显示可见导出阻止状态，编辑产生新输入后重新验证。

0.44.0导出事务按ADR-0163扩展：编码完成仅交出独有暂存产物，验证读取暂存路径，报告使用最终路径；正式脚本／native渲染会话及编码会话必须在发布前释放成功。验证及释放期间取消仍保护旧输出；最后取消检查后进入短暂Committing，发布成功后返回成功，不因迟到取消或通知失败谎报旧输出未改变。Error门禁、透明回退、探测告警严重性及每次独立会话保持，实际证据见[修复验收F1](archive/acceptance/code-review-remediation-acceptance.md#f1--r01导出事务04402026-10-08)。

0.45.0背景视频宿主取消协议按[进程合同](background-video-process-contract.md)／ADR-0170扩展：正式请求令牌传到背景resolver、打开与逐帧读取，捕获使用同一入口；调用者取消抛出并保持F1旧输出保护，不按缺失背景继续。生产旧同步入口有有限期限，第三方默认桥只检查旧调用前后，不能宣称其中的阻塞IO可被打断。每个正式会话继续独立持有来源及像素缓冲，帧号／播放映射、作者SDK和数据格式保持。

## 2. 布局试样边界

现有任意时刻强制显示某行的LayoutLineId不是歌曲真实显示计划，与准备帧互斥。有脚本／源包材质时编排明确使用按时间预览，不将伪装试样帧送给脚本；暂停时仍允许修改基础布局，取真实源坐标而非把脚本变换写回工程。界面说明这一规则，静态工程的布局试样与既有交互保持。完整效果最终几何的编辑辅助按R7接续，不能静默忽略效果。

## 3. U1：材质工坊接续（0.21.0）

U1 已接通工坊未唱／已唱／描边三个独立材质槽位。每个槽位在同一个选择器中提供当前纯色、当前渐变和当前草稿包闭包中的合法材质导出；切换来源是完整 MaterialSpec 替换，不能把包材质悄悄降级为旧颜色。包导出按实际 `regions` 过滤，填充与描边不会误用不支持的区域。

包参数面板读取导出引用的九类清单参数，文本、数值、布尔、枚举、颜色、曲线和图片值均先按声明类型编码，再通过唯一 `EffectPackageDefinition.ResolveParameters` 校验；无效输入只保留编辑文本和字段错误，不污染样式草稿。参数修改、材质切换、导入包都属于个人模板草稿，只有保存才发布模板库；放弃仍回到保存版本，完整包闭包和模板复制／删除语义不变。当前已支持目录与 `.mkfx` 导入，导入后必须显式选择材质导出。

中央固定试样和模板卡现在将模板包放入 `ProjectSnapshot.Effects.Packages`，并统一使用 `App.PreviewSessions` 的异步会话。含源材质的试样会真实编译固定包、建立准备帧并走正式区域材质 Render；失败状态交给画布显示上一成功画面和导出阻止提示，不再留空画布冒充预览成功。模板工坊不把目标歌词、工程实例或运行时历史写入模板。

U1 仍不开放效果实例／控制器绑定、直接图跨输出配方、父组捕获图编辑或歌词行编辑器大画布；这些保持 U2／R3～R8 的后续范围。

## 4. U2：效果实例工作区基础（0.22.0）

U2 的基础切片已经实施。工程实例与不可变源码包在界面上分栏；实例列表直接表达执行顺序，并提供新建、复制、删除、上移、下移。实例属性面板编辑名称、启用状态、包修订、导出入口、写入绑定、节点后代开关、订阅范围、随机种子和清单参数。参数仍通过包定义的 `ResolveParameters` 校验，绑定类型仍由导出清单限制；Core 的 `ProjectEffectsEditor` 对新增、替换、删除和重排提供同一语义校验。工作区可导入已校验的目录／`.mkfx` 闭包，包分享使用当前修订并原子写出，不把外部路径保存进工程。

工作区所有改动先留在草稿中。0.22.0 的基础实现曾在保存前运行 `ProjectValidator` 的导出校验和正式会话验证，成功后由一个 `SetProjectEffectsCommand` 写入工程历史；放弃草稿不会改工程。主窗口“视图”菜单提供入口。此保存前编译门禁只是该批历史行为：它不能满足 R0 已接受的“失败源码仍可保存”，已在下述 0.24.0 作者闭环中改为保存与编译分开。

### 4.1 0.24.0 作者闭环的实施合同

本批先依据[源码编辑合同](archive/legacy-ui/scripting-workspace-source-editing-contract.md)明确职责和数据状态，再实现界面。编辑文本按 `(packageId, revision, path)` 保存跨文件／跨包选择草稿；源码区“保存修订并编译”合并其全部脏源文件，更新相应摘要并构造新内容修订，不覆盖原包，然后独立编译当前包。诊断保留包修订、文件和行列，能够定位源码；失败源码已经保存，不回滚新修订。显式“应用此修订到所选实例”只替换当前实例的包修订，保留入口、身份、参数、绑定、订阅、seed、启用状态及顺序；其他实例和源材质继续使用原修订。

工程效果草稿、源码草稿和编译状态相互独立。新建实例初始禁用；“保存工程改动”把全部未发布源码修订与实例草稿通过同一个历史命令提交，不把 Roslyn 编译成功当作保存前提，保存后窗口留在原处。“验证工程效果”独立走正式会话，不把未引用包伪装成编译成功。失败源码也可保存和备份；当前启用实例或真实源材质引用失败包时，预览／导出仍使用正式运行门禁并报告错误，不退回旧 DLL。工作区关闭的保存／放弃／取消必须考虑全部源码脏状态，保存包含未发布的源码修订。主窗口的工程磁盘保存仍是独立操作。

编译／保存异步任务固定输入，期间冻结可变编辑和选择；取消／关闭要取消任务并释放其编译包或运行资源，不发布过期结果。真实编译失败与取消分开显示，不改写源码以获取成功。细项、后续边界和验证矩阵见源码编辑合同；本节为 0.24.0 已实施合同，实际自动验证证据见 roadmap §18.76。
