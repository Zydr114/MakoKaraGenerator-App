# M11 完整作者工作流与样例：功能证据

日期：2026-11-07。按 2026-11-07 用户指示，M10／M11 功能优先，回归与性能不作门槛，
只排除极端性能崩坏。本文只记录已经实跑的功能证据和尚未完成的部分，不关闭完整 D8。
验收要求见[验收表 M11](script-sdk-v2-render-acceptance.md)。

## 1. 样例重写（产品 0.112.36）

`backend/samples/ScriptEffectsV2/` 现有 13 个 v2 包：原九样例（WordEmphasis、RepeatEmphasis、
CursorTrail、VectorTrail、SpriteTrail、EventBurst、CustomInk、LineGlitch、GlassInk），
以及附加的 ClusterExit、AdaptiveStroke、StarSweep 和 WaveWarp。

- `a48c608`：CustomInk、LineGlitch、GlassInk 改为 package3／SDK v2 的无 DLL 资源包，
  图、程序与 SkSL 不变。测试覆盖了无 DLL 准入、全部图导出的原生编译，以及 LineGlitch 的
  分片位移（强度为 0 时与无效果像素一致）。
- `3c32fc3`：SpriteTrail 由宿主解析播放头粒子，纯视觉阶段绘制包内图片星芒和拖尾。
  近端、三分钟、十分钟各点在乱序、重复和重开后结果一致。
- `609465d`：StarSweep 用 SVG 矢量星沿真实播放头扫句；WaveWarp 对正在唱的字族
  （含注音）施加 6×1 正弦网格。

## 2. 目标复杂样式

- `bced791`：同一工程里叠加 ClusterExit、WaveWarp、StarSweep、CursorTrail、AdaptiveStroke
  和 Ruby。已确认的结果：
  - 退场与演唱可以同帧共存。
  - 星芒中心与最终播放头重合，且随 Warp 移动。
  - 媒体不可用时只撤回描边。
  - 透明输出可以准备。
  - 乱序、重复和重开得到同一个准备帧。
- `1132072`：`m11_complex_style_probe.py` 走真实 HTTP 和 Vulkan，步骤如下：
  - 五个包经作者草稿导入，组成同一行模板，应用到两行歌词和图片背景。
  - 在三个时刻取实帧：首行演唱、首行退场与次行演唱并存、次行演唱。
  - 背景分析事件到达后，用同一修订重新固定输入，三帧都因自适应描边而改变。

## 3. 透明输出的媒体输入（产品 0.112.37，`140affd`）

问题：固定媒体输入的输出模式属于输入本身。依赖媒体特征的包在正式验证的透明半程和透明预览里
都以 `MediaFeatureOutputMismatch` 失败（AdaptiveStroke 的作者验证首轮就因此失败）。

修复：
- `ProjectRuntimeMediaOutputs`（Backend.Rendering）统一提供背景声明、解析纯色档案和
  透明无媒体输入，Host 与 Worker 从同一快照得到同一个固定输入。
- `RuntimeFrameValidator` 可以为透明半程接收独立的快照和会话工厂。Worker 为普通输出的
  媒体输入另建一份透明无媒体绑定。
- 透明预览（straight）捕获运行输入时按透明输出固定，与透明导出一致。

## 5. 前端作者流程（`70d1c55`）

接入合同里已有、但界面一直没有用到的三项能力：

- **完整修订历史**：源码页签按页读取 `source-revisions`，最多 20 页。历史修订排在已知身份行
  之后、原包之前。读取失败时写明原因并可以重试。
- **`.mkfx` 下载**：每个修订行都能按固定的草稿修订和源码修订下载包。
- **草稿恢复**：左栏新增“可恢复的草稿”，列出本 profile 下其他客户端拥有的草稿
  （active、dormant、orphaned 三种状态）。认领时同时校验草稿修订和所有权修订；
  遇到 409 会提示并重读列表。换身份后会重新读取。

检查：`pnpm typecheck` 通过，4060 项单元测试通过，`pnpm build` 通过；新增的
`author-history-client.test.ts` 按 OpenAPI 校验了请求与响应形状。真实浏览器冒烟未跑。

## 6. 失败旧帧与诊断读全（`ba285e0`）

- **试样失败保留旧帧**：试样工坊记住同一画布范围内上一张成功的帧（画面、时刻和作者源码修订）。
  失败时状态仍是 error，画布变淡显示旧帧并叠上失败原因，画布下方写明“这次没有新画面”和旧帧
  身份。成功的帧也写明修订和时刻。换草稿或模板时清掉旧帧。
- **诊断读全**：试样失败时按页读完预览诊断（最多 8 页）。验证页的问题和其他诊断先显示 50 条，
  可以逐批展开；报告本身就是完整列表。

检查：
- 单元测试 4062 项通过，新增两项覆盖旧帧携带与清除、诊断分页。
- 真实 Chrome 加 0.112.37 后端：拦截帧下载使试样失败，画布保留旧帧并标明；恢复后新帧不再带
  旧帧标记，页面没有异常。
- 作者冒烟 6 步通过，720 帧验证在 CPU 上完成（`101881d` 修正了冒烟脚本的选文件步骤）。

说明：前端启动器按合同清单把产品版本固定为 0.112.15，而 M10／M11 的补丁版本没有同步合同清单，
所以本次用临时脚本直接调用 `host.py run`，使用隔离 profile、只绑定 loopback。

## 8. 用户手测结论（2026-11-07）

2026-11-07，用户在桌面版 App（后端 0.112.37，Electron GPU 共享纹理预览）中导入 13 个 SDK v2
样例包做了部分手测。样例包与 M11 全样例验证使用同一打包规则，manifest 中每个文件的 sha256 都已核对。
用户结论：**SDK v2 没有破坏性的性能问题，实现均符合预期。**

按 2026-11-07 的放宽口径（没有极端性能崩坏即视为阶段性完成），M10、M11 记为**功能阶段性完成**，
阶段一（M07–M11）的功能交付随之完成。这不等于验收表中节点的严格关闭，以下各项转入后续，
不写成通过：
- 资源导入事务；
- 调试叠加层与成本视图；
- 作者草稿试样的透明输出与宿主分析；
- 完整 D8 的 E/A/X/D/T 逐项映射；
- 正式性能矩阵与门槛。

2026-11-08 补记：调试叠加层与成本视图已经补齐，见[检查投影设计 §8～§10](script-sdk-v2-inspection-cost-design.md)。
同日用户实测结论：**叠加层和成本视图均测试无问题，验收通过**（[检查投影设计 §11](script-sdk-v2-inspection-cost-design.md)）。
