# GPU 结构性能优化与统一监控计划（2026-10-28）

> **后续集成（2026-10-28）：** 本文对应成果已随 `dev/performance-optimization` 的 `77643f8` 快进纳入 `main`，见[合入记录](../history/backend-main-integration-20261028.md)。下文保留实施／验收时的分支、版本、来源和范围，合入不表示重新运行这些验收。

> 工作分支：`dev/performance-optimization`。基线：`10bad12`（二次结构调研收口）。本计划依据 [GPU 结构与读回路径二次调研](../research/backend-gpu-structural-performance-research-20261028.md) 制定。本文先冻结实施边界；后续代码、回归、性能和发布证据不得把探索性数字直接当作交付验收。

## 目标和证据边界

本批目标是降低 Vulkan 图／材质／组合场景的单帧 wall 时间，同时让 Runtime、Rendering、Worker 和 Hosting 使用同一种结构化性能事件记录性能消耗。性能结论仍限定在固定本机、固定字体、固定 fixture 和短批次；代码存在、定向回归、同设备像素/诊断一致、匹配发布、fresh HTTP、浏览器/平台和完整工程性能分别登记。

二次调研给出的直接读回候选在三轮隔离实验中使 graph、material、combined 中位数分别下降 66.80%、70.72%、67.92%，但候选只覆盖了 161 对有效 BGRA 与诊断一致，尚未覆盖全部错误边界。组合最大值仍为 506.331 ms，不能承诺达到 500 ms。

## 实施顺序

### A. 同设备颜色匹配的直接图像读回

将内部 BGRA8888／Premul 读回从无颜色空间目标改为与源 `SKImage.ColorSpace` 匹配的直接 `SKImage.ReadPixels`。保留显式 Flush／Submit、BottomLeft 原点、完整像素检查、预乘检查、masked 检查、取消、预算和首错顺序。

生产实现必须满足以下准入条件：调用者明确要求 BGRA8888／Premul；源图和目标属于同一仍存活的 Ganesh 设备；目标颜色空间可由源图明确取得并与调用者语义一致；尺寸、stride、有效长度、alpha 类型和设备租约检查通过。外借图像、跨设备、失效 context、未知颜色空间、需要实际色域转换的调用继续走原有安全路径。不得全局改用 TopLeft，也不得把直接读回描述成零拷贝。

回归覆盖 CPU 与 Vulkan、sRGB 与无颜色空间、BottomLeft、透明／不透明、外借／跨设备／失效资源、非法像素、取消、预算和异常释放。性能验收使用新的同设备旧／新 A/B，完整 BGRA 和规范化诊断逐帧一致。

### B. 同帧相同无输入作者图共享

只缓存可证明相同的作者图执行结果。共享键至少包含包身份／修订、图身份、设备、时间和离散参数、完整画布 bounds、像素格式／颜色空间、变换和所有会影响输出的输入依赖。只有无图像输入、无 TargetColor／背景依赖、无随机或可变外部状态、无作者错误待归属差异的图才进入共享路径。

共享只覆盖作者图结果；每个目标仍独立执行 coverage、透明度、绘制顺序、目标绑定、预算记账、诊断归属、取消和资源租约。失败、取消、超预算、设备释放和 session 结束不得留下可复用结果。若源码审查无法证明这些条件，则只交付键/探针/回归基础，不扩大到生产共享。

### C. 统一性能监控

在共享的 `Rendering.Abstractions` 层定义低开销性能事件和 scope 计时器，供 Runtime、Rendering、Worker、Hosting 记录：request/session/task、backend、scene、frame 序号、总 wall、脚本宿主准备及实际作者调用、图执行、image readback 次数与请求字节、GC／托管分配和错误/取消状态。现有 `Scripting.Abstractions/PerformanceSample` 表示歌词演唱进度，不能复用为性能指标。阶段依据真实入口逐项登记，不能把未插入的阶段列为已支持。

事件默认结构化写入现有后端日志，标识采用短生命周期 request/session ID 或哈希，不写入歌词正文、源码、路径、token 或凭证。支持环境变量配置采样率、详细模式、周期摘要间隔和最大事件速率；关闭详细模式时保留帧及阶段聚合摘要。计时器必须支持嵌套 scope、异步传播、取消和异常收口，且不能改变业务错误顺序或阻塞渲染主路径。Worker stderr/stdout 与 Hosting 日志合并时保持可关联但不要求公开 HTTP 字段变化。

监控自身增加事件丢弃计数、采样率和版本字段；日志记录失败不能使渲染失败。周期摘要还须覆盖尚未完成帧的窗口，记录进程 CPU／工作集与进行中的帧数。详细模式按数量上限汇总包／修订／实例／调用阶段的不可逆身份摘要，便于区分多个脚本；阶段时间有嵌套，进程分配和 GC 不能声称为单脚本独占成本。Worker 来源的日志标为不可信遥测，不能冒充安全审计。为防止高负载放大，默认不采集逐像素数据、不记录完整诊断正文、不为每次像素读回分配字符串。

## 验收门禁

1. 生产源码与文档分步提交；每个提交只做一个切片，保留无关未跟踪 `tools/backend-project-image-export-probe/`。
2. 定向构建和相关测试零警告、全绿；新增回归须至少做一次 mutation red／restore green。
3. 直接读回与作者图共享都要有 CPU／Vulkan 负例和资源生命周期验证；所有有效同后端 BGRA、诊断、错误码、取消和预算结果一致。
4. 使用匹配源码的 Server／Worker 发布和新 HTTP 证据验证监控不会改变协议和排水语义；`202` 只记为 accepted，不记为完成。
5. 运行新的同设备旧／新性能矩阵：普通场景 5 轮 `8+24`，材质／组合 5 轮 `4+8`，另列 transparent、seek、instrumented trace 和创建／首帧；插桩 wall 与未插桩 wall 分开。
6. 报告中分别记录 median／P95／max、读回计数和请求字节、托管分配／GC、进程设备证据、源码／工具／发布指纹、进程自然退出和凭证扫描。不能把读回请求字节当作物理总线流量，不能把单机短批次外推为跨平台或长片性能。

本批交付计划版本为 **0.107.0**，公开合同 **1.39.0**／HTTP 协议 **1** 保持。主 wall 矩阵显式关闭监控，隔离生产优化本身；在相同新版执行体中另做 `off`／`summary`／`detailed` 开销与像素／诊断对照，其中 `summary` 为后端默认运行模式。二者分别统计，不用监控关闭的结果替代默认日志开销。

## 已实施边界与验收进度

生产基线固定为 `5802ac1`（0.107.0）。直接读回、同对象作者图共享与统一监控已分步提交；进一步审查修复了图像首次并发借用的预算登记及错误字段，以及极低日志速率下的后端摘要饥饿。缓存的有效变异实际执行 CPU/Vulkan 两例，禁用共享后创建次数由预期 17 变为 32、两例均失败，恢复原字节后的关联 145 项通过；早期仅触发 CS1061 的尝试不计为有效变异。

监控实现以 Worker 内的 Runtime 为采集边界，Server 转发校验后的有界不可信日志；不采集 Server HTTP 请求自身指标。使用 request/session 哈希、Worker pid、frame sequence 关联操作，本版没有独立 task/scene 字段。`summary` 聚合真实阶段和计数，`detailed` 额外采样逐帧与脚本身份；所有阶段均为包含嵌套工作的宿主 wall，不能相加。帧外初始化仅由进程心跳观察。完整配置与字段口径见[监控说明](../../backend-performance-monitoring.md)。

最终零警告构建、4045次相关测试执行、合同冻结、匹配`103ba2c`发布以及默认摘要2032请求／13313断言、详细模式304请求／3951断言的fresh HTTP已通过，详见[验收记录](../acceptance/backend-gpu-structural-performance-optimization-acceptance-20261028.md)。性能曾因CS2负载按用户选择延期；用户随后授权恢复，七标签及两组原版／插桩对照全部通过，246进程／4560项目帧，图／材质／组合Vulkan中位降低64.89%／73.82%／73.61%。材质／组合主矩阵最大346.453／373.706ms低于500ms，首帧和独立监控对照仍有超限。默认summary在Vulkan组合样本观测中位开销35.053ms（10.70%），详细模式限速丢弃27条但摘要覆盖全部帧。完整性能、开销与边界见验收记录§5。
