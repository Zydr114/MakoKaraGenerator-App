  按路径暂存，保留其他 worktree 和既有未跟踪 `.VSCodeCounter/`。
- 源码复核：产品 `0.110.2`、HTTP 合同 `1.42.2`、协议 `1`；工程／歌词 schema `29/18`、
  模板库／脚本配置库 `7/1`；效果合同 `1`、包 `2`、SDK `1.0.0`、

## 2. 每个节点的共同门禁

1. **先建立可比较基线。** M00 记录当前构建、测试、已知失败、环境和场景。
   后续节点对同一输入保留应保持的行为，新增功能补正例、反例和边界测试。
   修复新发现缺陷时，先证明对应旧实现或可逆变异会失败，再证明修复后通过。
2. **每步先验证再提交。** 后端代码阶段运行解决方案构建，要求零警告、零错误；
   运行受影响模块和相邻调用链的回归。前端／desktop 改动运行各自相应检查。
   每个节点关闭前汇总本节点全部改动的测试结果，不能以最后一个小提交的检查代替。
3. **关键阶段扩大回归。** M00 建立全量后端测试基线；M07、M13、M14 运行全量后端回归。
   其他节点运行定向回归和已建立的共同协议／渲染回归集；共享语义改动扩大到全部消费者。
   涉及 HTTP 的功能在当节点使用匹配 Server／Worker 做真实请求和终态验证，不拖到 M14。
4. **结果分层登记。** 构建、单元／集成、静态合同、实际 HTTP、浏览器、桌面、像素与性能
   分开记录。`202` 只表示接受；必须继续观察生效、成功／失败／取消终态及资源归还。
   跳过、环境不可用和未执行均不算通过；不得以历史结果代替当前提交。
5. **出现回归就停止依赖它的工作。** 不带着新增错误进入后续依赖节点，不删除断言、吞掉诊断
   或放宽阈值换取通过。可独立切片允许继续，但未完成项必须留在清单并保持阻塞关系。
   “无新增错误、无回归”限于记录的验证矩阵；未覆盖项明确列出。
6. **运行与证据隔离。** 仅用本仓库构建、隔离 profile、loopback 服务；凭证不进入 URL、日志
   或提交。清理按本次拥有的 PID 与进程身份执行。性能采样独占设备，和构建／测试串行。
   报告保存源码 SHA、生产输入／制品摘要、命令、环境、通过／失败／跳过数和证据路径。

具体实现可继续拆成独立提交，接口、格式和依赖必须先稳定再开展其消费者工作。

## 5. 不能提前放行的决定

- **性能阈值**：计划 §8.2 的 50／150／200 ms、1.5 s 和 16 ms 等数值是候选；M00 用同场景、
  硬件、模式和统计口径提出正式值后确认。用户操作→请求、请求→正确帧、接受／生效→正确帧、
  用户操作→可见分别记录，不能扣除 UI 合并／轮询等待后称为端到端。
- **像素容差**：1x 阈值已明确；缩放／倾斜／Warp 的阈值在 M12 测量后确认。
  容差不允许掩盖顺序、裁剪或诊断变化。
- **持久化门禁**：M07 起的开发并存必须使用明确实验输入／隔离 profile，或同步版本与读写门禁。
  隔离 profile 本身不允许把未声明 v2 数据写入 schema 29；不能等 M13 才补数据格式身份。
- **能力缺口**：九样例通过不能替代 D8。无法纯化的实际能力列具体场景和替代方案，未解决不进入 M14。
- **专项范围**：真正 GPU 异步回读、NV12、桌面零 CPU 等待和自研 Vulkan 独立研究；
  改动交接或错误检测合同需单独审查。优化受阻时保留正确行为，并保留未完成项。
