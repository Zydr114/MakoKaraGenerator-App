# 样式引擎下一阶段计划：高级渐变、规范模型收尾与字体回退

> **状态：0.5.0 已实施**
> **日期：2026-09-30**
> **适用版本：当前程序 0.5.0**
> **前置决策：ADR-0057（统一样式数据模型）**

## 1. 目标

0.4.1 已把工程、歌词和模板的持久化样式统一为嵌套规范对象。0.5.0 已把仍然“模型声明了、后端没有完整实现”的能力补成真实闭环，并删除规范模型上的临时源码外观。

本阶段按以下顺序完成：

1. 固化高级渐变的几何、坐标空间和能力矩阵；
2. 接通采样器、Skia、编辑器、预览和导出的高级渐变；
3. 清理平面样式访问器和旧渐变端点路径；
4. 建立可持久化的字体回退链，并让预览与导出共用解析结果。

性能基准暂不属于本阶段，待脚本系统完成后再做。

## 2. 当前代码审查结论

`GradientSpec` 已声明线性／径向类型、画布／行／字形／进度坐标和 RGB／HSV／Oklch 插值，但当前 `GradientSampler` 只实现线性 RGB／HSV，Skia 只接入线性行坐标。编辑器也会把未接入的选项标为不可用，说明这些选项不能继续作为“已经支持”的正常路径。

当前统一样式模型已删除渐变起止色和阴影 XY 的平面编辑地址；渲染器直接读取 FillSpec、StrokeSpec 和 ShadowSpec。字体与纯色等便捷属性仍只是直接委托到规范对象，不持有第二份值。

## 3. 高级渐变契约

### 3.1 第一批支持矩阵

| 类型 | 画布坐标 | 行坐标 | 字形坐标 | 进度坐标 |
|---|---:|---:|---:|---:|
| 线性 | 支持 | 支持 | 后续批次 | 后续批次 |
| 径向 | 支持 | 支持 | 后续批次 | 后续批次 |
| Oklch | 后续批次 | 后续批次 | 后续批次 | 后续批次 |

第一批只新增径向几何和画布坐标，不同时引入字形局部坐标、逐字进度映射和 Oklch，避免几何语义与色彩空间语义互相掩盖问题。

### 3.2 径向几何

径向渐变使用归一化二维坐标：

- `centerX`、`centerY`：中心点，范围 `0..1`；
- `radiusX`、`radiusY`：横向和纵向半径，范围 `> 0`；
- 行坐标以整行布局矩形为基准；画布坐标以合成画布为基准；
- 半径不做静默收缩，非法值在校验和编辑器中报告；
- 线性渐变的 `angleDegrees` 对径向结果没有作用，但仍保留字段以保持描述对象统一。

### 3.3 不支持组合的处理

不支持的组合不得静默回退成端点颜色。编辑器禁用对应选择并给出原因；手工 JSON 或未来版本产生的无效组合进入诊断，渲染器拒绝使用该渐变并保留纯色基色，不能把它伪装成另一种渐变。

## 4. 规范模型收尾

- `LyricStyle`、`LyricStyleOverride`、模板编辑器和渲染器直接消费规范嵌套对象；
- 删除渐变起止色和阴影 XY 的源码访问器及其编辑地址；
- `LyricStyleProperty` 只保留规范对象的编辑地址；
- DTO 继续只写规范嵌套结构；本阶段不添加旧格式迁移。

## 5. 字体回退链

### 5.1 数据合同

TypographySpec 已增加有序的 fallbackFamilyNames。空列表表示使用渲染后端的系统回退；非空列表按用户顺序尝试，系统自动匹配只作为链尾兜底。

回退链属于整行排版属性，元素级覆盖继续拒绝。回退族名按原样保存；空白和重复名称在读取时报告，无法使用的名称由 Skia 字体诊断保留为链上的失败候选，不静默改写用户输入。

### 5.2 渲染与诊断

`TextLayoutOptions` 将回退链传给布局引擎。Skia 为每组字号／字重／斜体创建主字体和有序回退字体集合；`ShapedTextElement.FamilyName` 与 `IsFallback` 继续作为预览、导出和诊断的共同结果。

预览和导出必须使用同一份字体解析规则。缺字仍然报告为缺字，不把缺字标记误认为成功回退。

## 6. 版本策略

本阶段交付程序版本 **0.5.0**。工程 schema 为 **v17**、歌词 schema 为 **v14**、模板库为 **v3**。当前程序不读取、不迁移旧格式。

## 7. 验收门槛

+ Core：径向投影、画布／行坐标、范围校验、能力矩阵诊断、渐变往返和字体回退链往返；
+ Rendering：线性／径向、多停止点、RGB／HSV、元素覆盖、显式回退链和缺字诊断像素断言；
- App：渐变不可用组合明确禁用，字体回退链可编辑并显示诊断；
- 预览／导出：相同快照和时刻得到相同渐变及字体解析结果；
- 全量构建 0 警告、全量测试通过，启动窗口后进行实机验收。

## 8. 与脚本系统的关系

当前仓库已有可复用的脚本接缝：不可变 `ProjectSnapshot`、统一 `LyricSceneSampler`、规范样式解析器和预览／导出共享的 `IRenderPipeline`。这些保证脚本将来可以读取稳定的场景结果。

当前没有脚本 SDK 程序集、`ILyricEffect`、Roslyn 编译服务、`AssemblyLoadContext` 管理器、脚本持久化或脚本 UI。`SPIKE-07` 和 `SCRIPT-01`～`09` 仍未开工。脚本阶段开始前仍需单独决定受信任脚本采用主进程还是独立进程；本阶段不提前决定，也不实现脚本。
