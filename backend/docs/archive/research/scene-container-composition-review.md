# 容器编排能力复盘与下一阶段建议

> 日期：2026-10-01；审查代码：0.6.0 / `49a231a`。
> 本文保留 0.6.0 的调研结论；后续用户确认方案后，0.7.0 已按 ADR-0063 实施原生通用树与完整独占案例，见 [实施方案](../plans/lyric-exclusive-display-case-plan.md)。下文代码局限属于审查时点，编辑功能仍待设计。
> 用户已确认双行分支及内部槽位位置编辑生效，并明确：特殊歌词独立居中时，双行暂时退出，只显示居中那句。

## 1. 当前是否已经是容器与子容器

**渲染定义和帧结果已经表达真实父子关系；工程可编辑的结构仍限定为按分支生成的歌词显示结构。**

当前双行帧的关系是：

```text
主歌词分支的显示容器 Group
  ├─ 槽位一 Group → 本次绑定的歌词 Text → 注音 Text
  └─ 槽位二 Group → 本次绑定的歌词 Text → 注音 Text
```

代码没有 `Children` 集合，而是平面不可变节点数组加 `ParentId`，同样可以表示树。定义中的源文本先关联分支容器；帧采样根据槽位绑定给出实际父节点。位置、世界矩阵、稳定节点 ID、源 ID 和绑定 ID 已分开。

工程保存的是 `LyricPresentationDefinition.Branches`：每个分支一份外层位置、内部布局配置和逐行覆盖；`SceneDefinition` 由这些配置重新生成。用户还不能保存任意的容器树、成员分配和展示片段。

依据：`SceneDefinition.cs:36`、`:74`、`:130`；`LyricSceneSampler.cs:16`；`LyricPresentationDefinition.cs:29`、`:79`。路径分别位于 Rendering.Abstractions 与 Core/Projects。

## 2. 现行局限及证据

| 局限 | 当前实现 | 对新需求的影响 |
|---|---|---|
| 分支与显示容器一对一 | `SceneDefinitionBuilder.Build` 每个 BranchId 生成一个根容器，布局由分支展示配置决定 | 同一主歌词分支不能直接配置双行、居中等多个显示容器 |
| 所有定时行进入同一调度 | `LyricSceneSampler.cs:94` 把 `branch.Lines` 整体传给槽位调度器 | 缺少“此句交给独立容器显示”的绑定或成员规则 |
| 双行时单句位置不可编辑 | `PresentationEditor.cs:33` 拒绝双行的 Line 目标；采样在 `LyricSceneSampler.cs:117` 使用槽位位置 | 调槽位会改变以后装入该槽位的歌词，不能只移动某一句 |
| 槽位数量未贯通编辑器 | Profile 接受至少两个槽位；调度按 `ordinal % Slots.Length` 轮换；位置目标枚举只有 SlotOne/SlotTwo，静态试样按两句分组 | 已有多槽轮换基础，但新增、删除、一槽模式和任意槽位的画布编辑仍缺失 |
| 缺少互斥的展示片段 | 当前按各分支独立采样，没有“居中片段暂停双行”的编排层 | 单纯移走一行仍可能留下提前显示的下一句或尚未退出的上一句 |
| 几何仍了解固定层级 | `SkiaRenderPipeline.SceneFrame.cs:15` 直接找分支根；Geometry 按容器加局部文本计算；绘制遍历 `SceneFrame.Lines` | 有 ParentId 尚不足以让任意嵌套组自动参与递归布局、动画和绘制 |
| 文本实例身份仍从源身份派生 | TextId 使用 BranchId + LineId | 同一句未来要同时出现多次，需要独立的显示实例 ID；本次互斥需求首期可限制每句只有一个活动实例 |

槽位数组、分支设置中的槽位参数循环并非写死两个。真正写死的是部分编辑目标、最少数量约束及静态编辑试样。因此可复用现有调度算法，但不能只增加第三个按钮就宣称已支持通用容器。

### 已经可以单独修改什么

某句的文字、时间、行模板、元素覆盖与进入动画覆盖仍能独立修改。行样式解析继续读取源行覆盖，并不因进入双行而失效。当前缺口是单句显示归属与独立位置。

还需区分：槽位是反复装载歌词的显示位置；歌词是槽位本次装载的内容。修改槽位的位置天然会影响多个绑定时刻。新增槽位也会改变分配次序、容量和提前显示规则，需要调度预演。

## 3. 建议的结构

### 3.1 分支管理内容，容器管理显示

保留源分支的文字、时间、角色、语言与主歌词／翻译关联。同一个分支的行可以绑定到多个显示容器，不必复制、移动源歌词或破坏翻译关联。

工程持久化独立的展示结构，包含稳定的容器节点、槽位节点、父子关系、固定参考矩形及显示绑定。双行成为槽位布局的一个预设：两个槽位、既定位置、轮换和进入／退出参数。单槽、三槽或四槽沿用同一合同。

```text
主歌词展示组（可整体移动）
  ├─ 常规歌词容器：自动轮换的槽位列表
  │   ├─ 槽位 A
  │   └─ 槽位 B
  └─ 特殊歌词容器：独立居中位置

同一份主歌词源数据 → 显示绑定 → 上述容器
```

外层公共组允许整套画面整体移动；常规与特殊容器分别保存布局。仅在槽位内部微调一句时，还可提供明确的“本次歌词局部位置”目标：父组变换 × 槽位变换 × 文本局部变换 × 局部动画。默认文本局部变换不改变槽位排布，不能重新引入隐藏的旧行位置覆盖。

### 3.2 明确每句的显示归属

建议首期提供：默认交给常规容器；用户选中某句或连续多句后，显式改为交给特殊容器。绑定保存稳定 LineId，界面明确显示当前归属。

常规容器的成员由绑定解析后再传入调度器。首期同一句在同一展示通道中只允许一个活动归属，冲突报告给用户。副歌仍使用原 LineId、TokenId 和时间，不复制成第二份歌词。

模板工坊继续只制作样式模板；独立居中那句可直接套用已有行模板。首批沿用现有工程→分支→行→元素样式解析；未来如果需要同一句多个显示实例的不同样式，再设计实例覆盖的优先级。

### 3.3 用展示片段表达切换

用户已经明确特殊句要独占主歌词显示。需要显式表示：常规片段→特殊片段→恢复常规片段，作用范围限定主歌词展示通道；翻译、注音是否跟随由各自关联规则解释。

建议普通交互为“独立显示本句”，软件预演其显示区间与切换结果；初始区间关联该行时间，允许明确的展示偏移或转场参数。源行／元素时间不被改写，未定时行必须先指定可用的展示依据，不能猜时间。

边界需在实施设计中固定：

- 特殊片段内常规容器不可见，提前出现的下一句也不能穿过该片段。
- 进入／退出效果不能突破已确认的互斥显示边界；需要交叠时由用户显式选择转场。
- 恢复常规时重新开始该片段的槽位轮换，推荐从第一个槽位进入，避免移除特殊句后奇偶序号改变产生意外。
- 直接跳到任意时间，结果与从头播放一致；用绝对时间与绑定重建，无须依赖真实暂停／恢复历史。
- 显示区间与演唱区间继续分开，均采用整数微秒和半开区间。

### 3.4 通用组与自动槽位布局的边界

Group 可以包含自由定位的文本、子组和自动调度槽位。一个子节点必须明确由手工局部位置还是布局策略定位；手动微调采用明确的子节点变换层，不让两个系统同时覆盖同一个位置值。

槽位列表应按稳定 SlotId 编辑，数量与顺序可变；一个槽位也应合法。空组可以用于组织对象，自动槽位布局启用时需要至少一个可用槽位。删除槽位或容器前展示受影响绑定和分配预演，不静默重挂父节点。

建议把持久化节点定义与临时帧测量继续分开；递归测量和变换真正按 ParentId 工作，校验循环、孤立节点、重复 ID、失效源关联和相互冲突的绑定。

## 4. 推荐落地顺序

1. **先补实施设计**：持久化容器／绑定／片段、ID、位置所有权、区间边界、恢复调度与撤销规则。沿用当前无旧工程兼容要求；批准实施后再确定版本与 schema。
2. **打通核心案例**：同一主歌词分支，常规双行→一句独立居中并套行模板→恢复双行；能保存、重开、取消和一步撤销，边界帧及直接跳转一致。
3. **泛化槽位编辑**：动态目标列表、增删重排、稳定槽位 ID、一槽／多槽、静态试样和分配预演；同时验证所有槽位的命中与实际画面。
4. **完成树编辑与递归几何**：公共父组、明确重挂归属、容器独立选择、父参考坐标与世界位置保持。首次重挂建议默认保持画布位置，并展示转换结果。
5. **再冻结脚本 SDK**：区分容器节点、文本显示实例、源行／元素和绑定身份；可见事件依据展示片段，逐字事件依据源时间。首期脚本仍只调制样式，不能写树、绑定、位置或显示区间。

上一轮已经完成的只读快照、时间采样、样式解析、稳定身份、矩阵运算和工作区撤销链可继续复用。需扩展的是可编辑展示定义和调度边界；本讨论不代表已经批准或实现通用场景编辑器。
