## 2. R3 重新划分

### 2.1 R3 Core

R3 Core 只处理实际渲染目标：

```text
Token
Line
Mark
```

必须交付：

- 填充、已唱填充、描边、注音的区域捕获；
- 一个字符对象或整行的完整目标捕获；
- `TargetColor`、`Coverage`、`BackdropBelow`、`BackgroundMedia`；
- Runtime Shader、Blur、Mask、Transform、Blend；
- 字符内部材质、描边材质、字符整体 Glitch、整行 Glitch；
- 毛玻璃、液态玻璃、色散和色差；
- 输出外扩、覆盖裁切、透明背景回退；
- 预览和导出使用同一目标、同一图链结果。

`GroupTarget` 和父合成原语保留为扩展接口，但 R3 Core 不开放父组图像效果。首版遇到组图绑定必须给出明确的“不支持父组图像效果”诊断，不能静默忽略。

### 2.2 R3.1 高级合成

只有在需要把双行、三行或整个容器作为一张图处理时，才实施：

- 父组捕获和嵌套容器合成；
- 子组与粒子归属；
- 注音／描边／阴影保留部件重组；
- owned overlay；
- 跨输出依赖和复杂映射。

本计划不引入 GPU，也不展开 CPU／GPU 性能优化。

## 4. 验收方式

以下保留既定验收判据；本轮已结合自动证据与用户总体实测反馈收口，准确反馈范围见§1.2与[R8验收记录](../acceptance/scripting-r8-acceptance.md)，不追加未提供的逐项人工记录。

### R3 Core

- 无效果画面与当前基线一致；字符整体 Glitch 不分离填充／描边／注音；整行 Glitch 保持注音一致。
- 毛玻璃读取真实下层且不读取自身；液态玻璃／色散在透明输出时使用包内基础外观并提示。
- 1×／2× 密度、旋转、父组位置和槽位布局一致。
- 预览、CPU 离屏帧、MP4、Alpha 在同一时刻一致。
- 预算超限、资源缺失、Shader 错误和取消均释放全部中间表面。

### R4／R5

- 包离开原目录后仍可编译和运行；工程重开得到相同包修订、参数和 seed。
- 逐字放大、重复文本计数和音频输入在 24／30／60 FPS 下保持相同语义。
- 重绘、跳转、导出和取消不重复计数、不污染历史。
- Error 阻止导出并保留源码定位。

### R6

- 连续发射速率、Burst 数量、出生顺序和多播放头结果可复现。
- 无空档跨行直接换点，有空档时按配置桥接。
- 粒子预算超限报告错误，不静默裁剪。
- 粒子预览与导出逐帧一致。

### R7／R8

- 新建、复制、删除、排序、绑定、调参、保存和撤销可用。
- 编译失败时旧预览可见，导出明确禁用。
- 工程重开后效果实例和包资源完整。
- 普通视频、透明视频、失败中止和旧输出保护通过人工验收。

统一验证命令：

```bash
dotnet build MakoKaraGenerator.slnx --no-restore -m:1
dotnet test MakoKaraGenerator.slnx --no-build -m:1
```

每个代码批次同步更新 `docs/roadmap.md`、`AGENTS.md`、对应合同和程序版本，并使用独立 Git 提交。

## 5. 固定约束

- 不增加旧工程兼容层；数据格式按当前合同继续断代。
- CPU Skia 是 R3 Core 的唯一权威渲染后端。
- 父组图像效果不删除，只从 R3 Core 延后到 R3.1。
- 脚本仍在主进程内按会话串行执行。
- 脚本不能修改歌词源文本、时间、排版或容器树。
- 预览和导出必须消费同一份准备帧和同一套时间语义。
