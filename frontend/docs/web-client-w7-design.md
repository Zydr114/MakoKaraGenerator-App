## 0. 2026-10-27 实测

动手设计前，用临时集成测试在真实 Server（0.106.0）上核对了合同没写细的行为。效果包用后端仓库 `samples/ScriptEffects` 的示例打成 `.mkfx`（ZIP，根目录是 `manifest.json`）。

**内置库与完整定义**
- 内置库只有两个静态模板：“经典整行”（整行，21 个属性）和“逐字强调”（文本单元，2 个属性），都不含效果。
- `definitionFormat=full` 对静态模板也能用，返回 `fullAvailable`，`packages`、`effectRecipes` 是空数组。所以编辑器可以统一按完整定义读写。
- 含效果的模板不带 `definitionFormat` 读取时，返回 `advancedRuntimeAvailable` 和 `definition: null`；带上才有完整定义。

**效果包**
- `effect-packages/inspect` 很快（6～35 毫秒），返回名称、版本、导出（材质、控制器、图三类，以及各自的 `bindingKinds`）、参数表、文件清单和结构诊断。坏 ZIP 返回 422 `PackageArchiveInvalid`。
- 参数类型有九种。颜色参数的取值是 `{"r":…,"g":…,"b":…,"a":…}`（0～1）。时长参数的上限可以是 Int64 最大值，所以参数必须按原文保存，不能先转成 JavaScript 数字。
- 用上传得到的 `asset` 引用新建完整模板可以成功。读回来时，`packages` 变成 `library` 引用：带库修订、模板 ID 和模板修订。

**校验失败不说明原因**（§3 的 G31）
- 漏写 `packages` 里的包、参数越界、写了包里没有的参数，三种都返回 422 `InvalidDefinition`，消息都是“模板库操作未完成；原库保留，请按错误代码处理。”，不指出哪一项有问题。
- 用完整草稿作试样或候选时也一样，只写“完整草稿未通过模板校验。”。

**`library` 引用跟着库修订失效**
- 读回的 `library` 引用钉在当时的库修订上。个人库的任何修改（例如给别的模板改名）都会让它过期。之后拿这份定义做试样选项、候选或者 `replace`，都返回 409“模板库已改变，请重新读取。”。
- `asset` 引用不受影响，再次检查和保存都可以。

**试样**
- `template-preview-options` 返回两个 12 秒样本：`workshop-single-line-v1`、`workshop-multi-line-v1`。还返回模板能用的目标（键），以及三个材质部位的状态。
- 目标由后端按模板判断：
  - 整行模板：`line`、`project`、`branch`、`clip`、`group`；多行样本还多一个 `mark`。
  - 文本单元模板：只有 `token`。
  - 没有属性、只有逐字配方的整行模板，还多一个 `token`。
- 样本 3 秒时显示一行带注音的“模板预览”，8 秒时单行样本已经没有文字。包材质（波纹）和逐字强调（放大 2.5 倍）都看得出来。
- 一次性取一帧（建会话、取帧、关闭）要 3.6～5 秒。

**工程里应用**
- 含包材质和配方的整行模板，可以应用到行和容器节点（`includeDescendants: true`）。用到文本单元上被拒绝：“所选预设包含不适用于文字目标的属性或相对配方。”。应用后，工程预览照常出帧。
- 对同一个节点再应用一次，会替换原分配，分配 ID 不变（`includeDescendants` 不同也是同一个目标）。

**外观来源**（`resolved-style`）
- 返回解析出的完整样式、上下文（容器、节点路径、文字节点），以及 21 个属性各自的来源路径。
- 来源路径只有五种：
  - `lyricStyle`：工程样式；
  - `lyrics.branches.<来源>.styleOverride`：来源的直接覆盖；
  - `…lines.<行>.styleOverride`：行的直接覆盖；
  - `…tokens.<文本单元>.styleOverride`：文本单元的直接覆盖；
  - `presetApplications.<分配 ID>.snapshot.style`：某条分配。
- 叠加顺序：工程样式 → 工程分配 → 来源覆盖 → 来源分配 → 节点分配（从根到叶）→ 片段分配 → 行覆盖 → 行分配 → 文本单元覆盖 → 文本单元分配。
- 节点路径的最后一个是文字节点。所以分配到容器上、`includeDescendants: false` 时，对容器里的歌词文字不起作用。

**字体**
- `GET /fonts` 列出 727 个字体族，环境是 `worker-skia`。
- `fonts/inspect` 逐字返回实际用的字体、是否回退、是否缺字。
- 字体不存在时，`requestedAvailable: false`，`resolvedFamily` 是回退字体，`elements` 为空。

**`.mktpl`**
- 导出个人模板（含 3 个包）得到 12.5 KB，导出内置模板得到 579 B。内置模板在归档里的 ID 是 `exported:builtin:…`。
- 预检列出每个模板的摘要和可用性；导入时全部生成新 ID，返回新旧 ID 对照。
- 预检对象导入一次就作废，再用返回 404；库修订过期返回 409。
- **配额**（§3 的 G32）：每个客户端同时最多保留 2 个传输对象，导出和还没导入的预检都算，各保留 5 分钟。连续导出两次后，第三次导出或预检返回 429“模板传输保留配额不足”。导入会释放它的预检，导出只能等过期。

## 2. 结构调整

### 2.1 协议与客户端

- `src/protocol/templates.ts` 补完整定义：
  - `FullTemplateDefinition`、`FullTemplateStyle`；材质加 `package` 分支；
  - `TemplateEffectRecipe`、`EffectPackageReference`（`asset`／`library`／`configuration` 三种）。
  - 详情响应加 `definitionFormat`、`packageClosureDetails`，`definitionAvailability` 加 `fullAvailable`；
  - 库命令的 `create`／`replace` 加 `definitionFormat: 'full'`。
- 新文件：
  - `src/protocol/effect-packages.ts`：检查请求与响应、参数表、导出、文件、诊断；
  - `src/protocol/fonts.ts`：字体目录与检查；
  - `src/protocol/template-transfer.ts`：预检、导入、导出。
- 补充已有类型：
  - 试样：`TemplatePreviewSource` 加完整草稿；试样请求加 `sampleId`（三个取值）、`targetKey`、`materialSlot`；新增试样选项响应。
  - 外观：`resolved-style` 的响应类型。
  - 分配：目标加 `node`（`nodeId`、`includeDescendants`）和 `clips`；候选来源加 `source`。
- `MakoClient`：
  - `templates.fullDetail`，`templates.previewOptions`；
  - `templates.exportArchive`、`templates.archive`（二进制读取，沿用 `fetchBinary`）、`templates.preflightImport`、`templates.importArchive`；
  - `effectPackages.inspect`；
  - `fonts.list`、`fonts.inspect`；
  - `projects.resolvedStyle`。
  有副作用的请求沿用客户端回执。
- **参数按原文保存**：`parametersJson`、`fixedSeed`、`manifestJson`、参数的默认值和上下限都是 JSON 原文。新增纯函数模块 `model/json-text.ts`：
  - 把对象 JSON 拆成“键 → 值的原文”；
  - 改一个键只替换它的原文，其他键原样写回；
  - 数值比较按十进制原文进行（先比数量级再逐位比），不经过 `Number`。
  界面上的数字输入框也以字符串为准，不经过 `Number`。
- **协议类型继续手写**（整体设计 §10 留到 W7 评估）。理由：
  - 生成器要处理 OpenAPI 3.1 的 `oneOf`／`const` 分支和 `x-int64-string`，还要处理 1.x 留下的“已知无关字段显式 null”。生成出的类型名和现有手写类型对不上，迁移面太大；
  - 手写类型按阶段增量补，集成测试已经用冻结 OpenAPI 校验每个真实响应，类型错误能被发现。

### 2.2 样式库状态

`TemplateLibraryStore` 的草稿改为完整定义：
- **读取**：选中个人模板时读完整详情；内置模板仍然只读，“复制并编辑”走服务端 `copy`。
- **保存**：一律用 `definitionFormat: 'full'`。静态模板保存成完整定义后，读回仍是静态（没有包和配方），摘要不变。
- **包引用重定位**：个人库每次变化后，正在编辑的模板重读一次完整详情，用新的 `library` 引用替换草稿里同一包（包 ID 加修订相同）的旧引用。草稿的其他修改和撤销栈都不动。新导入、还没保存的包保持 `asset` 引用。
- **包目录**：检查结果按“包 ID + 修订”缓存。草稿里每个材质和配方都从这里取参数表和导出，用来生成控件和做本地校验。
- **本地校验**（弥补 G31）：保存、试样、试看之前先检查：
  - 引用的包都在 `packages` 里，导出存在，导出种类对（材质用 `material`，配方用 `controller` 或 `graph`）；
  - 参数没有包里没有的键，取值类型对，在上下限内，枚举值在选项里；
  - 种子是 0～2^64−1 的整数。
  有问题时就在对应控件旁写明，“保存”停用。本地查不出、后端仍然拒绝时，写“后端拒绝了这份定义（InvalidDefinition），没有说明原因。请检查效果的参数和包”。

### 2.3 编辑面板

保留 W3 的“外观”“高级”两个页签，在中间加“材质”“效果”，共四个（整体设计 §5.5.1）：
- **外观**：沿用 W3。字体和回退字体改用字体选择器（§2.5）。某个部位用了包材质时，这个部位的纯色、渐变控件换成一句“使用效果包材质 · 在“材质”页签编辑”。
- **材质**：
  - 上面三个部位按钮：未唱填充、已唱填充、描边。描边关闭时，按钮写“描边已关闭”，并给出“在外观页签打开”。
  - 下面是所选部位的材质：类型（纯色、渐变、效果包）。选效果包时，选包和包里的材质导出，再编辑参数（§2.4）。
  - 选中部位后，试样画布的材质焦点跟着切换（后端 `materialSlot`）。
- **效果**：
  - 配方列表，每项写名称、作用于、包和导出，有启用开关；可以上移、下移、删除，也可以复制一项。
  - “＋ 加效果”：先选包里的控制器或图导出，名称默认取导出名。
  - 选中一项后，下面编辑这几项：
    - 名称；
    - 作用于（整行、逐字、整个分配）；
    - 叠放层（随包、文字后面、文字上面）；
    - 读取范围（绑定的来源、整个工程、指定输入）；
    - 读取范围是“指定输入”时，填输入名，例如“翻译”；整体设计写的是只声明需要什么，不指定具体来源；
    - 固定随机种子：留空表示不固定；
    - 参数。
  - `configurationId` 只读显示：“来自效果组件 X（W8）”。
- **高级**：完整定义的 JSON，只读。另外列出包闭包：每个包的名称、版本、修订和文件清单。
- **效果包**：材质和效果页签的顶部都有“效果包 · N 个 [导入效果包…]”。
  - 展开后列出模板里的包：名称、版本、修订前 12 位、导出数。
  - 没有被材质或配方用到的包可以移除。
  - 选文件 → 上传 → 检查，然后显示包的信息和诊断。结构无效（`structureValid: false`）时不能加入。
  - 同一包 ID 已有别的修订时，问“替换为新版本”：要用到它的材质和配方都改指新修订，没有对应参数的键标出来。

### 2.4 参数控件

按参数表生成，标签用包里的 `label`，有单位就写单位：
- `number`、`integer`：数字输入。范围是有限值时加滑块；
- `duration`：按毫秒输入，内部存微秒原文；
- `boolean`：开关；
- `enum`：下拉，选项用包里的 `label`；
- `text`：文本框；
- `color`：取色器加透明度，写成 `{"r","g","b","a"}`；
- `curve`、`asset`：只读显示 JSON 原文，可以“恢复默认”。

每项右边有“恢复默认”。值等于默认值时，不写进 `parametersJson`，保持与后端示例一致的最小参数对象。

### 2.5 试样画布与字体

**试样画布**
- 详情区顶部的试样画布改用工坊样本：
  - 选模板（或草稿改动停 300 毫秒）后先取试样选项；
  - 工具栏：样本（单行／多行）、目标（后端给的键，显示成中文：整行、整个工程、来源、片段、组、标记、文本单元）、时刻滑条（0～12 秒），以及“试播”“循环”。
  - 默认是单行样本，目标取第一个，时刻 3 秒（第一句正在唱）。
- 试样画布保持一个预览会话：
  - 换模板修订或草稿时换输入，拖时刻时取帧，试播时按本地时钟连续取帧，规则同成片预览的 `PreviewController`；
  - 离开样式库时关闭会话。
- 标题“试样 · 单行样本 · 整行 · 0:03.000”，并注明“不是工程里的最终外观”。
- **缩略图**改用单行样本 3 秒、320×180：
  - 含效果的模板也有缩略图；
  - 文本单元模板的目标用 `token`；
  - 一次性取帧较慢（§0），仍然最多 2 个在途，逐张出现。

**字体**
- 字体选择器：下拉列表可以搜索，列出后端字体目录（只读一次，连接重置后重读）。目录里没有的字体照常显示，并标“后端没有这个字体”。
- “字体检查”按钮：用试样文字加上用户输入的一段文字调用 `fonts/inspect`。结果逐字列出实际字体，回退的字标黄，缺字的标红。

### 2.6 `.mktpl` 导入导出

- 样式库左栏的“⋯”菜单加“导出模板…”和“导入模板…”。
- **导出**：
  - 对话框里勾选模板。内置和我的分开勾，一次只导出一个库，最多 100 个；
  - 点“导出”后立即下载 `MakoKara-templates.mktpl`，并核对大小和 SHA-256。
- **导入**：
  1. 选文件，上传后预检，列出将导入的模板：名称、用途、是否含效果。
  2. 写明“导入后全部生成新 ID，不会覆盖已有模板”。
  3. 点“导入 N 个模板”后，选中第一个新模板。
  - 库修订过期时，重读后再确认一次。
- **配额（G32）**：遇到 429 时，写明“刚导出或预检过的归档要保留 5 分钟，请稍后再试”，并按已知的过期时间写出大约几分钟。

### 2.7 外观页

**适用规则**
- 改用后端判断：选择器打开时，对每个模板取一次试样选项（按模板修订缓存），看它的目标键里有没有当前目标的种类。种类与键的对应：

  | 目标 | 键 |
  |---|---|
  | 工程 | `project` |
  | 来源 | `branch` |
  | 行 | `line` |
  | 文本单元 | `token` |
  | 片段 | `clip` |
  | 容器或组 | `group` |
  | 标记 | `mark` |

- 取不到选项时退回 W3 的本地规则。
- 不适用时写明，例如“这个模板不能用于文本单元”。原来的“含效果，暂不支持”去掉。

**来源输入**
- 模板里有读取范围为“指定输入”的配方时，提交区列出每个输入名，各配一个来源下拉框（工程里的来源）。
- 全部选好之前，不能试看，也不能应用，并写明“这个模板需要读取：翻译”。
- 选好的映射作为 `branchInputs` 带进候选和 `apply`；“更新”沿用原分配的映射。

**编排对象**
- 目标浏览器在“歌词来源”下面加“编排对象”，按来源分组：
  - 容器和组：结构树的形状；
  - 片段：名称和句子范围；
  - 前奏提示组：下面列出它的标记。
- 选容器或组时，检查器多一个开关“包括里面的句子”，默认开；关掉时写明“只作用于容器本身，不影响里面的歌词文字”（§0）。
- 片段可以多选，同一来源的片段合成一个 `clips` 目标；其他编排对象一次只选一个。
- 时间轴上点选片段轨的片段时，目标浏览器同步选中它；外观页的时间轴加只读的片段轨。
- W3 列在工程默认下的“编排对象上的分配（只读）”去掉，改到各自的对象上。

**外观来源**
- 单选行或文本单元时，检查器“外观来源 ▸”展开后，按 W3 的属性分组列出每个属性的取值摘要和来源：
  - `lyricStyle` 写“工程样式”；
  - 直接覆盖写“来源／第 N 行／「字」的直接覆盖”；
  - 分配写“分配“模板名”（目标）”。点它就选中那个目标。
- 写明“只解析静态样式，不含动画和效果的像素”（后端 `finalPixelAppearance: false`）。
- 选的是其他种类的目标，或者选了多个时，写“选中一行或一个文本单元后显示”。

**在样式库中编辑副本**
- 单选、并且有直接分配时可用：按分配快照的模板 ID 在两个库里找原模板。
  - 找到了：服务端 `copy` 到“我的”，名称加“（副本）”，跳到样式库编辑它；
  - 找不到：停用并写明“库里已经没有这个模板”。
- 样式库顶部的返回栏写“来自 外观 · 主歌词 / 第 2 行 [保存并返回试看]”。点了先保存，回到外观页，打开选择器并选中这个模板进入试看。
- 原目标已经不存在时，要求重新选择目标。
- 返回栏只是界面状态（整体设计 R3、R6）。

### 2.8 提示组与标记的外观

按 §9 决定 2：
- 提示组和标记只作为模板的分配目标（§2.7）。
- 它们自己的直接外观（`setCountdownAppearance`、`setMarkAppearance`），在检查器里像行的直接覆盖一样只读显示。

理由：
- 整体设计 R4 规定“模板内容的编辑，包括字体、颜色、效果参数，一律去样式库改”；W3 也把直接覆盖定为只读。
- 后端解析标记外观时，会把提示组外观、标记覆盖、工程、来源和节点上的分配依次叠加。所以把模板分配到提示组（包括里面的标记）或单个标记上，就能改它们的颜色和字体。

## 3. 后端缺口

都不阻断 W7，只登记。后端已宣布收口，由用户决定是否转达。

| 编号 | 缺口 | 现状 | 前端做法 |
|---|---|---|---|
| **G31** | 完整定义校验失败不说明原因 | 下面这些情况都返回 422 `InvalidDefinition`（库命令）或“完整草稿未通过模板校验”（试样、候选），没有 `field` 路径和原因（§0）：漏写包引用、参数越界、包里没有的参数、导出种类不对 | 保存、试样、试看前先按包的参数表在本地校验（§2.2）；本地查不出时写明“后端没有说明原因”。希望响应指出出错的位置（例如 `effectRecipes[0].parametersJson.peakScale`）和原因 |
| **G32** | 模板传输对象不能提前释放 | 每个客户端最多保留 2 个导出或预检，各 5 分钟；归档下载完也不释放，没有删除接口（§0）。连续导出两次后，5 分钟内不能再导出或导入 | 导出后立即下载；429 时写明要等几分钟。希望下载完成或客户端明确放弃后释放，或者提供 `DELETE /template-transfers/{id}` |

编号已核对：W6 用到 G30；本仓库与后端仓库的文档里都没有 G31、G32。

另外两点不算缺口：
- `library` 引用随库修订失效：规范 §24.1 写明“保存造成库修订变化后，继续编辑前须重新读取 full 详情获取新引用”。前端按 §2.2 重定位。
- 外观来源不支持标记和批量读取：规范 §17.6 写明只读单个行或文本单元。

## 8. 已知限制

- **G31 未交付**（§3）：完整定义校验失败时，后端不说明原因。前端保存、试样、试看前先在本地校验（包的参数表、种子、包闭包、配方规则）；本地查不出时写“后端没有说明原因”。
- **G32 未交付**（§3）：每个客户端最多保留两个导出或预检，各 5 分钟，下载完也不释放。连续传输两次后，5 分钟内不能再导出或导入，界面写明大约还要等几分钟。
- 曲线、资源两类参数只显示 JSON 原文，可以恢复默认值，不能改（§1 不做）。作者流程、效果组件库在 W8；配方的效果组件来源原样保留，只读显示。
- 导入了还没用到的包只记在草稿里：后端要求 `packages` 恰好是材质和配方用到的包，所以这样的包不进历史、不保存，换模板或放弃修改后要重新导入。
- 含效果的模板在试样画布里取一帧要 0.4～4 秒，试播按本地时钟取帧，看起来是一帧一帧跳的；时刻最多 12 秒，更晚的时刻后端拒绝。
- 外观来源只解析静态样式（不含动画和效果画出的像素），只能看单个行或文本单元；标记、多选时不显示（规范 §17.6）。
- 提示组和标记自己的外观只读，要改就把模板分配给它们（§9 决定 2）。
- “库里有新版本”提示沿用 W3 的做法：分配不记录来源库，无法比较。
- 字体检查：后端只列出用到回退字体或缺字的元素，所以只合并序号相邻的元素，其余文字算主字体。
- 同一页第二次自动下载 `.mktpl` 会被 Chrome 的“下载多个文件”权限拦下，在浏览器里允许即可；导出页、歌词导出也是这样。
- `smoke:library`、`smoke:appearance` 的 W7 部分要用后端仓库的 `samples/ScriptEffects`；找不到时写明原因并跳过，集成测试 `full-templates` 也一样。
- 开发环境的客户端配额同 W6 §8：同一个 `pnpm dev:backend` 上连续跑十几次 smoke 后，页面会显示“连接失败，正在重试”，重启 `pnpm dev:backend` 即可。
