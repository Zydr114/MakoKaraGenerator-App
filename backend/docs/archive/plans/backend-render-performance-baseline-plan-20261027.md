# CPU/GPU短批次渲染性能基线计划（2026-10-27）

本轮记录当前后端的单帧性能和步骤耗时，不进行性能优化。用户已明确恢复性能采样，并要求不运行100帧以上的长渲染；历史暂停采样的记录不再约束本轮已授权范围。

## 基线与证据

- 生产基线固定为 `8681bc09d59fc72c11d62810940324a6a44eefd2`，产品0.106.0、合同1.39.0。
- 由Git归档生成两份独立源码：原版作为实际总耗时基线；另一份仅施加计时插桩。仓库生产 `src/` 不修改，工具与结果分步提交并推送。
- 保存原始输入、工具、插桩补丁、构建产物与环境指纹。原版和插桩版逐帧核对完整有效BGRA SHA-256；CPU与GPU之间不要求位级一致。
- 插桩数据属于带测量开销的执行体；同时记录其外层耗时相对原版的变化。不得把各父子阶段inclusive时间相加，也不把宿主提交/等待时间称为纯GPU执行时间。

## 代表负载

固定1920×1080、Final、30fps时间序列、固定字体与seed，使用仓库实际示例包：

| 场景 | 输入 |
| --- | --- |
| lyrics | 有逐字时间的歌词与静态样式 |
| csharp | WordEmphasis控制器 |
| graph | LineGlitch图效果 |
| material | CustomInk源材质 |
| particle | CursorTrail粒子与拖尾 |
| combined | 上述效果按固定顺序组合 |

这是公开示例构成的有限负载，不能替代用户真实完整工程、视频背景、音频分析、长片、其他平台或驱动矩阵。先进行少量短帧试跑，确认合法组合、实际效果贡献与插桩一致性；失败原始输出保留。

## 短批次与时间口径

- 普通歌词、C#、图效果、粒子主序列每个独立进程8帧预热、24帧计量，共32帧；五轮，CPU/GPU以及原版/插桩版交替顺序，所有渲染串行。
- 3帧试跑发现CustomInk材质及组合场景的CPU单帧约4.5～5秒。为保持每次渲染短时，这两个重负载改为4帧预热、8帧计量，共12帧，仍五轮。其计量时间范围为1.133333～1.366666秒，其他场景为1.266666～2.033333秒；跨场景不能当作完全相同时间窗口的消融实验。正式结果保留各时间戳和独立轮次中位数。
- 程序对单进程全部输出帧数设48帧硬限；独立设备检查最多另画一张4×2小表面。包括试跑在内均不达到100帧。
- 新会话创建、第一帧及释放单列；稳定帧统计不包含预热帧。默认JIT与驱动缓存保持系统实际行为，不把新进程称为驱动冷启动。
- 对有状态代表场景另用8个以内时间戳，记录直接请求晚时刻、回退、同边界与非边界重复请求。时间线内部120Hz语义求值次数与输出像素帧数分开记录。
- 计时终点是完整预乘BGRA帧返回。SHA、诊断读取、JSON写入和代表PNG在计时外执行；PNG/HTTP/视频编码不并入本轮Runtime帧指标。
- 记录逐帧wall time、托管累计分配差值、GC次数、每轮统计与跨轮中位数/P95。阶段插桩覆盖创建、prepare、脚本/粒子、绘制、surface创建、提交、内部读回/校验与最终读回。

## 完成条件

1. 两个执行体零警告构建，计时器嵌套区间及统计验证通过。
2. 同输入同设备原版/插桩版全部对应帧一致；效果对照确有贡献，诊断无Error。
3. 每轮帧预算、实际硬件证据和自建进程退出记录完整；失败目录独立保存。
4. 原始JSON/CSV、聚合统计、步骤耗时和限制落盘；结果文档引用准确源码及证据指纹。
5. 工作区生产输入无变化，无关未跟踪 `tools/backend-project-image-export-probe/` 保留；工具与文档按步骤提交、推送。

本轮只建立测量基线。优化优先级由实测结果提出，尚不实施优化。

## 实施结果

已按上述短批次完成，见[基线报告](../research/backend-render-performance-baseline-20261027.md)。正式采样共170进程、3310项目帧、170设备probe；每进程最多32个项目帧及1个4×2 probe。1616组原版/插桩帧、1688 trace、48效果贡献对照及72重复/重放对照通过。原始结果与输入/构建指纹已归档，生产源码保持不变；本轮没有实施优化。
