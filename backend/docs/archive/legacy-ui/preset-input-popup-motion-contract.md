# 具名来源下拉菜单的位置变化合同（0.49.5）

## 用户裁决与范围

2026-10-09，保持来源菜单打开后搬动／缩放窗口的隔离原生截图确认：输入已移动，旧菜单仍留在原位置。用户明确选择“接受自动收起并保留选择”。此前要求保持菜单打开的这条验收，由本合同和ADR-0184接替；这不是将旧菜单重新定位记为成功。

范围是画面区组合预设的具名歌词来源选择框。继续使用固定SukiUI7.0.1／Avalonia12.1.3的ComboBox模板、原生弹层和来源稳定ID。已选来源、待应用映射、当前工程和撤销历史保持。

## 实际行为

- 菜单打开且输入位置稳定时，普通布局更新保持菜单打开。
- 窗口实际客户区尺寸、后端报告的位置、缩放系数或输入相对窗口的矩形改变时收起菜单；祖先滚动也属于输入位置改变。
- 收起不清空来源，不提交预设应用，不产生撤销步骤。布局完成后仍保持关闭，用户再次点击才创建新菜单。
- 输入拆除时关闭旧菜单；关闭、拆除和模板重建均解除窗口／布局监听，再挂接和重新打开会跟踪新宿主。

实现为App内部`PresetInputComboBox`，StyleKey沿用ComboBox；动态来源控件明确使用该类型。只在菜单实际打开期间监听布局和窗口事件，使用公开生命周期API，不添加计时器、桌面输入循环或跨窗口资源。

## 固定版本依据与验证边界

固定提交`8eeda4f6f546165b3f72e63c9f42247abb306905`的[Popup源码](https://raw.githubusercontent.com/AvaloniaUI/Avalonia/8eeda4f6f546165b3f72e63c9f42247abb306905/src/Avalonia.Controls/Primitives/Popup.cs)仅以目标局部Bounds判断部分布局更新；祖先滚动可以改变窗口内位置而不改变该Bounds。[窗口事件源码](https://raw.githubusercontent.com/AvaloniaUI/Avalonia/8eeda4f6f546165b3f72e63c9f42247abb306905/src/Avalonia.Controls/WindowBase.cs)提供尺寸及位置通知。上述源码与本机原生截图共同决定本次收起策略，未升级固定依赖。

私人试验中的PlacementRect／PlacementTarget刷新及失效绘制未得到正确位置截图；直接窗口内宿主在当前Suki窗口找不到所需层；底层定位器访问不能成功编译。这些方案均未进入产品，不将接口调用或逻辑IsOpen断言当作屏幕定位成功。

Wayland并不保证报告全局窗口位置。本批真实验证搬成浮动、尺寸及祖先滚动变化；位置通知的处理不能推定物理拖动、多屏DPI、Windows或IME已通过。纯窗口搬动且客户区锚点不变时，仍由平台管理父子窗口位置，物理反馈另记。
