# 父级捕获与可传递合成产物

2026-10-04。接续主画布合同与 ADR-0094。此文区分已定义的合成数学与尚待用户裁决的父级捕获行为。

## 1. 本批先完成的接缝

颜色图不能单独描述「替换下层」的孩子。运行时产物保存两个独立表面：预乘前景 C、下层擦除量 E；在任意真实下层 B 上得到 `C + B × (1 − E)`。E 不等于颜色 alpha：透明输出仍可能保留已执行的替换范围。

同目标图链仍使用现行合同：历史替换蒙版取逐像素 max；最后为普通合成时，再与最终颜色 alpha 取 max。共同透明度同时缩放 C 与 E 一次。

按实际顺序叠放两个独立孩子，后者为 2：

```text
C = C2 + C1 × (1 − E2)
E = E2 + E1 × (1 − E2)
```

这是原有逐次合成的展开，不改变父图捕获选择。两个 80% 擦除的重叠孩子实际擦除 96%；不能用同目标历史 max 代替独立孩子的顺序合成。输出保持真实 Canvas 框、密度、sRGB 预乘及原始覆盖编码，资源计入共享帧账；不保存新工程字段，也不向作者公开 native 表面。

## 2. 待裁决的父级边界

以下已经询问，未答复前不实施依赖这些规则的组图 writer 或父捕获：

1. 父配方部分选择具有共同透明度的孩子时，是否允许选中／保留部分各自完成该透明度。
2. 本帧无可见孩子的真实组图是校验后不执行、失败，还是允许执行产生独立图像。
3. 父图是否继承孩子实际合成后的擦除量，即便父图将颜色改为透明。

已确认的融合不可拆分、最高层重组、无目标输入替换全部部件、仅工程／显式节点可写组保持，不再询问。未知 optional 输入、自身粒子排除及实际映射不能由这个产物接口绕过。

## 3. 实施边界

0.12.3 只增加现有 CPU 图后端可传递产物的提取、独立孩子顺序合成及真实下层应用；用现有图链与独立逐次合成作像素参照。组图调度尚未交付，不能把这一基础接口记为 R3 出口完成。正式主 Render 的原有组 alpha 路径保持；待 §2 决策后把产物接入真实父级捕获。

## 4. 代码与资源协议

- `CompiledImageGraph.CaptureCompositionPayload` 只提取存活同帧图链，最后结果须属于固定编译图；复制前景及擦除量，返回后不依赖原图结果／输入／编译图存活。
- `ComposePayloads` 按数组顺序组合独立孩子；框可不同但时间、画布、密度、透明模式必须相同，范围为实际表面的并集。不能用它替代同目标图链的 max 合同。
- `CompositePayload` 将产物应用于真实下层，框必须包含颜色及全部擦除范围，可应用一个新的共同 alpha。下层不参与前景提取或孩子合成。
- `ImageCompositionPayload` 拥有两张表面，释放幂等；输入始终借用。表面和像素密度完整计费，别名／跨帧去重，峰值预检包含旧累积产物和下一对新表面，失败回收中间合成。
- 三个固定宿主 shader 在 `CompiledImageGraph.Compile` 时创建，不新增帧内作者编译；局部图预算与会话帧预算同时生效。float32 非零下溢明确失败，不写成 alpha 零。

没有新公开脚本权限、工程字段、schema 或依赖；宿主兼容扩展升 PATCH，工程／歌词／模板 schema 保持21／15／3。精确 applicationVersion 门禁仍拒绝旧程序工程，不追加迁移。

## 5. 验证范围

新增20项正式CPU测试，结合原16项同目标图链回归共36项：在多种实际背景／密度下与原合成像素对照；两个独立透明替换的96%擦除、顺序敏感颜色、不同框及已消失的早期颜色／保留覆盖、嵌套alpha、透明旁路、产物脱离原结果和编译图、错误代次／上下文／取消／原生范围、共享及局部预算／别名／跨帧／第三个孩子失败回收。

产物使用现行BGRA8存储，实际像素对照单层允许1字节舍入、嵌套alpha允许2字节；没有引入浮点中间颜色profile。最终全量证据由 roadmap §18.61 记录。本批未改主Render的画面规则，不把独立CPU出口表述为组图人工验收或新的脚本工作区；完整native RSS测量仍待后续。
