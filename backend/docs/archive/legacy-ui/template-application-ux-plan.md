# 模板套用与歌词行编辑器体验优化方案

> 2026-09-30；**0.2.5 已实施，0.2.6 按实窗反馈调整样式页层级并获用户验收**。§1 是 0.2.4 基线调研，实施证据与视觉调整见 §10。本文细化 ADR-0050 的「模板工坊制作、歌词行编辑器套用」职责，不改变模板库格式、时间语义或旧工程断代规则。顶部波形聚焦当前行；其下只有「文字与时间」「样式选择」两个页签；样式页左侧为窄的纵向模板列表，右侧承载套用、详情和从当前效果读取模板。「全部」按模板类型作用于当前工程的全部歌词行或全部歌词元素。

## 1. 问题与现状证据

当前 `LyricLineEditorWindow.axaml` 用一个纵向 `ScrollViewer` 顺次放置行时间轴（高 188）、文字重排、元素时间和模板区。模板列表高 180，后面还有影响说明、属性展开、独立预览画布（高 160）与两排操作按钮。960×740 的默认窗口也需要滚动才能看到模板；720×560 的最小窗口更明显。用户要做的主要操作反而藏在最后。

模板区只有「行模板／元素模板」切换和一个「套用所选模板」按钮。实际目标由模板类型和当前选择隐式决定：行模板写当前行，元素模板写当前元素。`StyleTemplateApplicator.TryApply` 目前只处理一个行或元素；`EditorViewModel.TryApplyTemplate` 成功后返回空消息，窗口把空消息写进底部状态栏，所以套用确认后缺少明确的完成反馈。

`TemplateCardView` 已有 96×56 的真实渲染缩略图，足以作为选模板时的外观线索。歌词行编辑器里的第二块 `KaraokeCanvas` 会占据主要空间；模板工坊中央的实时预览则用于**制作模板**，职责不同，应保留。

当前行编辑器的 `LineTimeline.ViewAxis` 双向绑定 `EditorViewModel.ViewAxis`，与主窗口共用视口。自动聚焦当前行若继续改这个属性，会连带改变主窗口波形；现有「波形中聚焦」按钮则要用户主动寻找和点击。

## 2. 本轮体验目标

1. 顶部波形独立于页签、始终展示**当前歌词行附近**；切行就聚焦新行，用户无需寻找「波形中聚焦」。
2. 波形下方只保留两个页签：先是**「文字与时间」**，保留现有文字序列、行／元素时间和试听操作；再是**「样式选择」**，集中模板选择与套用。
3. 样式页左侧以较窄的单列纵向列表展示模板，能切换行模板／元素模板；右侧始终只有当前类型对应的**「应用到当前目标」「应用到全部」**两个套用按钮，并放置应用详情和从本行／当前元素读取模板的入口。
4. 模板卡缩略图提供大致外观；**不在歌词行编辑器放大画布预览**。模板工坊保留制作时的实时大预览，入口放在窗口顶部。
5. 套用后显示模板名、改动对象数、范围和「撤销」；无变化、失败和取消与成功明确区分。

## 3. 页面结构

窗口从上到下是固定页眉、**始终可见的当前行波形**、两个页签和固定状态区。默认打开第一个「文字与时间」页签；切行时保留用户正在看的页签，刷新当前行和元素选择。波形与两页共用同一组选中行／元素 ID。

```text
┌ 第 12 行「请照亮我前行」 [上一行][下一行] [模板工坊] [关闭] ┐
│ 波形／行轨／元素块：自动聚焦当前行，可直接拖动时间            │
├──────────────────────────────────────────────────────────────┤
│ [文字与时间] [样式选择●]                                      │
│ ┌── 左：窄模板列表 ──┐ ┌──── 右：套用与详情 ──────────────┐ │
│ │ [行模板●][元素模板] │ │ 「蓝夜」 · 将写入 4 项             │ │
│ │ ▣ 经典整行        │ │ 本行：第 12 行；全部：28 行        │ │
│ │ ▣ 蓝夜       ●    │ │ [应用到本行][应用到全部 28 行]     │ │
│ │ ▣ 其他模板        │ │ 写入属性与影响（直接展示）         │ │
│ │ （列表内部滚动）  │ │ 读取本行 读取元素 恢复行 恢复元素  │ │
│ └───────────────────┘ └────────────────────────────────────┘ │
├──────────────────────────────────────────────────────────────┤
│ 结果：已将「蓝夜」应用到本行 · 改动 1 行 [撤销]              │
└──────────────────────────────────────────────────────────────┘
```

- **固定波形**：行轨、波形、逐字块和播放头位于两个页签之上；在任一页都能选中元素和拖动其时间边沿。行时间、元素时间的现有校验不变。
- **文字与时间页**：保留当前文字序列卡片的选择、拖动重排、拆分／合并，及行／元素起止输入、清除元素时间、整行平移、试听等现有操作。只整理排列，不拆成更多页签。重排后以稳定 ID 同步顶部波形与样式页的当前元素。
- **样式选择页**：左侧约 210～240 逻辑像素宽，行／元素类型切换和单列纵向卡片列表都在这里；仅列表内部滚动。右侧自上而下是所选模板与目标、两个套用按钮、直接展示的写入属性和应用详情、同一行的两个读取与两个恢复继承入口；详情区内部可滚动，没有二级折叠菜单。窗口缩到 720×560 时，两个套用按钮和四个次要入口无需滚动仍可见。
- **固定页眉／状态区**：顶部「模板工坊」按钮打开制作窗口；返回后按模板 ID 刷新列表，保留仍存在的选择，新建模板不会自动套用。底部持续显示成功／无变化／失败及撤销。

## 4. 顶部波形始终聚焦当前行

行编辑器需要自己的 `TimeAxis` 视口状态，不再将顶部 `LineTimeline.ViewAxis` 双向绑定到主窗口的 `EditorViewModel.ViewAxis`。打开窗口、切换歌词行、行时间提交、撤销／重做改变当前行时间，以及窗口尺寸变化时，按当前行 `[startUs,endUs)` 自动适配波形视野；使用现有 `TimeAxis.ShowingRange` 的少量前后留白并限制在音频范围内。首屏聚焦要等波形控件完成测量再执行，避免宽度为零时 `FocusRange` 直接返回。主窗口波形的缩放和位置不受行编辑器影响。

用户在当前行内手动缩放或横向平移时可做精细打轴，但视口不能漂移到与当前行无关的时间段。拖动行或元素边沿**期间**保持视口稳定，避免指针下的时间坐标随每一帧跳变；拖动完成后再将新行区间校正到视野中。切到「样式选择」页也不丢失当前行聚焦。

若当前行尚无合法时间，波形区明确提示「先设置本行时间」，不假装已聚焦到整首音频；「文字与时间」页的行时间输入仍可为该行设定区间，提交后立即自动聚焦。没有选中歌词行时，波形区显示选择提示并禁用时间拖动。原「波形中聚焦」按钮可移除，因为聚焦已成为默认行为。

## 5. 应用目标由模板类型决定

默认展示行模板；左侧「行模板／元素模板」切换决定列表内容和右侧两个按钮。选中卡片后才可套用；每种类型可分别记住最近选中的模板 ID，切回时只恢复仍存在的卡片。切换行或元素时，按钮文案与目标数量即时更新。

| 当前展示 | 第一个按钮 | 第二个按钮 | 写入目标 |
|---|---|---|---|
| 行模板 | **应用到本行** | **应用到全部 N 行** | 分别写当前 `LyricLine.StyleOverride`，或当前工程 `Project.Lyrics.Lines` 的每一行（含未定时行） |
| 元素模板 | **应用到当前元素「照」** | **应用到全部 M 个元素** | 分别写当前 `LyricToken.StyleOverride`，或当前工程各行的全部元素（含未定时元素） |

未选元素时，第一个元素按钮禁用并提示选择元素，第二个「应用到全部 M 个元素」仍可用；没有任何元素时两个按钮都禁用并说明原因。目标摘要必须写明「全部 N 行」或「全部 M 个元素」，不能只写「全部」。未来若加入歌词分支，须重新定义全部范围，不默认把隐藏分支算入或排除。

模板仍按**值**应用，只写该模板勾选的属性。行模板不会清掉元素级覆盖，元素模板不写字体、排版等不受支持项。当前工程的基线样式保持独立。选择模板不写工程；只有按明确范围的按钮才提交。

## 6. 套用前后反馈

**套用前**，右侧显示模板名、当前目标及全部目标数、将写入的属性数、预计覆盖数据会变化的对象数；若行模板属性会被元素覆盖，提示被覆盖元素数。属性名、原继承来源和当前目标已有覆盖直接展示在详情区；内容较长时只滚动详情区。变化数按工程覆盖数据计算，不能冒充逐个目标的可见像素差异。左侧缩略图是**模板样式示意**，不能标成「本行最终画面」。

**本行／当前元素**：按按钮即执行一次可撤销写入；目标和影响已持续展示，不再用确认弹窗重复同样内容。**全部**：弹出确认摘要，列出模板名、全部行／元素范围、目标数、实际会变化的数量、元素覆盖保留规则；确认后一次提交。取消时工程与撤销栈不变。

**成功**：在固定状态区显示例如「已将『蓝夜』应用到本行 · 改动 1 行 · 撤销」或「已应用到全部 28 行，其中 19 行发生变化 · 撤销」。消息持续到下一次相关操作，不只闪现一下；同时刷新右侧应用详情与主窗口画面。**无变化**：显示「目标已经是这一效果，未写入工程」，不增加撤销记录。**失败**：显示具体目标及原因，保留当前选择和工程原实例，不伪装为成功。

批量动作必须是**全有或全无**：先基于同一工程快照建立全部目标并校验，再一次 `StyleBatchEditor.Apply`，一次 `Execute`，一步撤销。确认弹窗打开期间若工程或选择改变，提交前重新计算目标，必要时重新确认，不把旧下标误用到新工程。结果统计按真正改变的对象计数；即使目标数大于零而改动数为零，也按无变化处理。

## 7. 从当前效果读取模板与工坊边界

样式页右侧明确保留两条次要入口：**「从本行读取为新模板…」**和**「从当前元素读取为新模板…」**。前者取当前行实际样式的纯值快照，后者取所选元素实际样式的纯值快照；没有选中元素时，后者禁用并给出提示。这两个入口都进入模板工坊的新模板草稿，不在歌词行编辑器里直接保存模板，也不会自动套用。

「整行恢复继承」「元素恢复继承」与两条读取入口放在右侧同一行，采用较淡的次要按钮样式；各自仍只针对当前行或元素，不提供隐式的「全部恢复继承」。它们与两个主套用按钮分行排列。

工坊负责命名、编辑和保存；读取动作不携带套用目标。若在工坊中新建成功，返回样式页时可切换到对应模板类型并按新模板 ID 选中卡片，但**不会自动套用**。工坊只做模板制作／管理，中央实时预览与「保存模板／删除模板」继续保留。歌词行编辑器不把工坊变成另一个套用入口。

## 8. 实施顺序与版本

1. **状态与批量命令**：按模板类型为当前目标／全部目标建立批量预演结果；目标列表基于稳定 ID，从当前 `Project` 派生。无变化返回原实例，错误不产生半步操作。补全实际改动数与成功消息。
2. **独立波形视口**：让行编辑器顶部波形持有本地 `TimeAxis`，在行选择、行时间完成、撤销／重做和尺寸变化时聚焦当前行；拖动中不改变坐标映射，未定时行显示明确提示。保持主窗口视口不受影响。
3. **页面重排**：把固定波形放在页签上方；下方仅「文字与时间」「样式选择」两个页签。左侧模板卡为窄的单列纵向列表，右侧放两个动态套用按钮、详情和两个读取入口；移去行编辑器的大预览画布，将工坊入口提到页眉。
4. **应用反馈**：连接模板类型切换、两个动态按钮、批量确认、固定结果／撤销。工坊返回时按稳定 ID 刷新模板与选择。
5. **验证与文档**：Core／VM 测试覆盖单行、单元素、全部行、全部元素、属性继承、无变化、失败原子性和一步撤销；时间轴测试覆盖自动聚焦、拖动期间稳定、主窗口视口隔离；真实窗口检查 720×560 最小尺寸、两个页签、行切换、全部确认与结果反馈。实施时补充 ADR-0050 的「全部」目标语义，并修订原方案 §5 中「批量仅从歌词列表多选进入」及本行大预览的旧口径。

本轮保持 JSON 结构，以 **0.2.5** 交付；`project.json.applicationVersion` 随程序版本更新，0.2.4 工程按既定门禁拒绝直接打开。

## 9. 验收判据

- 波形在两个页签上方始终可见；打开或切换歌词行即聚焦当前行，行时间改变后正确校正；手动细调不漂移到其他行，主窗口波形视口不被连带改变。
- 波形下只有「文字与时间」「样式选择」两个页签；第一项包含现有文字序列、行／元素时间和试听操作。最小窗口的样式页无需滚整页即可看到左侧模板卡、右侧两个套用按钮和两个读取入口；模板工坊入口在页眉可见。
- 行模板页只出现「应用到本行／应用到全部 N 行」，元素模板页只出现「应用到当前元素『具体文字』／应用到全部 M 个元素」；无选中元素时单元素操作不可执行，全部元素操作仍可执行。
- 左侧窄列表的每张模板卡有真实缩略图；右侧有应用详情及「从本行读取为新模板」「从当前元素读取为新模板」。歌词行编辑器无独立大预览画布，模板工坊仍能实时预览编辑草稿。
- 单目标与全部目标只写对应覆盖层；未勾选属性和元素优先覆盖保留；无变化不写工程，全部套用一次撤销完整回退。
- 成功、无变化、失败、取消各显示准确结果；切行／切元素／返回工坊后不会把旧选择或旧数量用在新目标上。
- 全量构建 0 警告、0 错误，现有自动测试全通过，并由用户在真实窗口验收套用流程。

## 10. 0.2.5～0.2.6 实施与验收状态

- 顶部 `LineTimeline` 使用独立 `ViewAxis`；打开、切行、行时间修改、撤销／重做和窗口变宽时按当前行聚焦。手动平移／缩放限制在当前行邻域，行边沿拖动期间保持视口稳定。未定时行显示行时间提示并禁用波形拖动；主窗口视口不受行编辑器操作影响。
- 波形下改为「文字与时间」「样式选择」两页。文字页保留行／元素时间、文字重排、拆合、清除元素时间和试听。样式页左边单列模板卡、右边随类型变化的两个应用按钮、影响详情及从当前行／元素读取入口；移去歌词行编辑器的大画布，模板工坊入口在页眉。工坊自己的实时预览保留。
- `StyleTemplateApplicator.TryPreview` 按稳定 ID 建立当前目标或全部同类型目标，并一次交给 `StyleBatchEditor`；返回目标数、覆盖数据变化数及完整预演结果。全部范围包含未定时对象；无变化不入撤销栈，合法批量提交一步撤销，失败不留下部分写入。全部操作显示确认摘要；成功、取消、无变化、失败在固定状态区各有文案。工坊返回后按模板 ID 刷新并选中新建模板，不会自动套用。
- 首轮 720×560 实窗探针发现原布局只露出约 65 逻辑像素高的模板列表，用户指出排版不佳。已把行编辑器波形改为 128 像素的紧凑五轨布局、压缩页眉，并让影响说明局部滚动；复测同尺寸的模板列表可用高度约 180 像素，两个应用按钮和两个读取入口均处于可见区域。临时探针已移除。
- 0.2.5 实窗反馈指出「查看全部写入属性」「更多操作」两个折叠层增加了不必要的层级。0.2.6 将写入属性及影响直接放在右侧详情区，读取本行、读取元素、整行恢复继承、元素恢复继承四个淡色按钮在同一行。720×560 探针测得四个按钮宽度各约 86 逻辑像素，末按钮从 x≈278 到 x≈364，完整落在右侧面板内；临时探针已移除。
- `dotnet test MakoKaraGenerator.slnx`：**1296 项通过**。Core 测试覆盖全部行／元素含未定时目标、属性限制失败时的原子性、模板未勾选属性和元素优先覆盖保留；视图模型测试覆盖预演不写入、全部套用的一步撤销与重复套用无变化；视口测试覆盖平移限制与缩小时重适配。全量构建 0 警告、0 错误；新版实窗操作验收状态以 `roadmap.md` §18.7 最新记录为准。

**0.2.6 用户实窗验收通过**：用户在 PID 23900 的正式窗口核对直接展示的属性详情、四个同排淡色按钮，以及本行／全部套用、撤销与切行后波形聚焦，并回复「排版和操作都通过」。从当前效果进入工坊后返回的稳定 ID 选择由代码路径检查与模板工坊既有测试覆盖；本轮验收问题未单独逐项询问该分支。
