# 0.49.6 UI 交互审查

日期：2026-10-10。审查基线：`78b7a55`。状态：截图与代码审查；设计提案，未修改产品。

本轮按用户要求，以 `screenshots/0.49.6/` 的八张图片和当前界面代码为依据，不用旧设计文档为现有交互辩护。未运行原生程序，不将静态阅读写作实际操作复现，也不据此断言后端错误、数据丢失或性能问题。

用户在本轮明确：**所有外观先制作为预设，再应用到对象；允许重组工作区、入口和编辑流程。** 下文不建议在工程对象上直接修改颜色、字体或脚本参数。

新版设计见 [设计规范](ui-0496-redesign-spec.md)，可交互设计源见 [界面稿](ui-0496-prototype.html)。界面稿使用示例状态演示交互，不连接真实工程。

用户随后认可新版布局，并要求移除过多解释文字。当前设计已按 [自然引导修订](ui-0496-natural-guidance.md) 更新；以下问题记录保留，解决方式以修订后的规范为准，不以增加常驻说明作为默认解法。

## 1. 总体判断

主要问题不是功能少，而是用户每次操作前都要重新推断三件事：**我正在改哪个对象、画面展示的是哪一种结果、这个动作保存到哪里。** 大量解释文字补偿了这些缺口，却挤占了操作区。

尤其需要先解决：

1. **范围混淆。** “工程基线”“整首歌词”“所选行”“布局歌词段”出现在同一个外壳里，但不是同一种作用范围。
2. **预设制作与应用断开。** 进入工坊不一定定位到正在使用的预设；保存后也没有明确返回待应用对象的下一步。
3. **预览缺少可见身份。** 工程播放时刻、固定歌词试样、基础编排回退都以类似的中央画面出现。
4. **常用操作位置不合理。** 逐字时间和基础样式被长表单挤到下方；画布反而在大片空白中保持小尺寸。
5. **动作与反馈不成对。** “即时生效”后还有应用确认；“写入时间”之前失焦已提交；错误状态可跨任务残留。

## 2. 当前产品的最小交互模型

这是代码体现的行为，不是建议新增的数据架构。

| 用户任务 | 当前入口与实际职责 | 当前状态边界 |
|---|---|---|
| 改歌词、打轴 | 歌词与时间：来源、行、文本单元、注音、行/字时间、波形 | 修改工程；统一工程历史 |
| 制作外观 | 模板制作：内置/个人模板，静态样式、材质、效果组合 | 独立作者草稿；保存个人库；使用固定试样 |
| 配置脚本效果 | 工坊打开独立脚本窗口，导入包、选择效果、参数、来源范围、源码、验证 | 独立配置库与源码修订；保存不等于采用或验证 |
| 应用外观 | 画面与样式：工程、来源、行、字、片段、节点上的预设应用 | 将预设副本应用到工程；库后续变化不自动传播 |
| 简单布局 | 画面侧栏选择布局，当前来源全部行或连续歌词段 | 预演影响后一次应用到工程 |
| 自定义布局 | 高级编排：布局树、歌词分配、前奏、变换 | 草稿；应用后才进入工程 |
| 背景与输出 | 合成侧栏、导出对话框 | 工程参数与实际编码任务分别管理 |

不能用一个简单的“工程→来源→行→字”树穷尽全部继承。片段、节点、时刻及具体字段也影响实际来源；新界面应调用已有来源描述，而不是编造一个固定优先级。

## 3. 问题分级与证据

H：容易改错范围、误认结果或打断核心流程，优先处理。M：频繁增加寻找、理解和滚动成本。L：一致性与表达问题。这里是设计优先级，不是后端缺陷级别。

证据类型：**图+码**为图片可见且代码支持；**码**为必要调用链补充；**推断**为基于布局的可用性风险，需要后续交互验证。
