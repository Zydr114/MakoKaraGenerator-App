## 1. 目标与范围

把整个编辑器换成设计稿的紧凑 Material You，最后移除 mdui。

**做：**

1. **底座**：主题引擎（material-color-utilities）、设计令牌、Roboto Flex、Material Symbols，以及基于
   React Aria Components 的控件，加上对话框和提示条的宿主。
2. **外壳**：用顶栏页签取代导航栏；加应用设置（主题模式、主题色、色彩强度、快捷键、关于）和关于对话框；
   使用软件标志。
3. **工作区**：面板和幕后的拼接、可拖动的分栏、§7.1 的断点、共享底部区。
4. **全部页面与对话框改版**：首页、新建、恢复、保存位置、歌词、编排、外观、样式库（模板、效果组件、作者草稿）、
   工程设置、导出、导出歌词文件。
5. **歌词页行编辑区新增只读的“外观”和“显示在”**（§2.7）。
6. **冒烟脚本**改用与界面技术无关的选择器。
7. **收尾**：移除 `mdui`、`@mdui/icons`，更新整体设计稿 §3.1、§7。

**不做：**

- 不改交互流程、术语、HTTP API、浏览器静态预览协议和 500ms 控制节奏；`src/client`、`src/protocol` 不动。
- 不改渲染画面。界面主题不影响画面。
- 不改协议控制台。
- 不打包 Noto Sans CJK（每种语言每个字重就有十几 MB），用系统字体；到 Electron 打包时再评估。
- 不做 Electron 自绘标题栏；`desktop/` 的 GPU 预览原型不动。

## 2. 设计

### 2.1 依赖

| 包 | 版本 | 许可 | 用途 |
|---|---|---|---|
| `react-aria-components` | 1.22 | Apache-2.0 | 无样式的交互层 |
| `@material/material-color-utilities` | 0.4 | Apache-2.0 | 配色。改为直接依赖（现在经 mdui 间接引入 0.3.0，过渡期两版并存） |
| `@material-symbols/svg-400` | 0.48 | Apache-2.0 | 开发依赖：由脚本生成图标模块，只收用到的图标 |
| Roboto Flex 子集 | — | OFL-1.1 | 入库 `src/editor/theme/fonts/`，复用设计稿的子集和许可文本 |

不引入 `react-resizable-panels`。台前幕后的拼接靠 CSS Grid 和几个宽度变量定位内凹圆角，
自写的分隔条直接改这些变量最简单；那个库用的是 flex 布局，套上去反而要绕。设计稿 README 里的推荐届时一并改掉。
React Aria 的 Toast 在 1.22 里还是 `UNSTABLE_` 前缀，提示条自己写。

### 2.2 主题引擎

放在 `src/editor/theme/`：

- **`scheme.ts`**：纯函数。输入种子色、明暗和强度，输出全部颜色角色。
  - 强度“柔和”用 `SchemeTonalSpot`，“鲜明”用 `SchemeVibrant`。
  - M3 的标准角色直接取方案的结果。
  - 设计稿的自定义角色从方案的色调板按固定色调取值：
    - 幕后、幕后高处、幕后线、波形、已播放波形取第三色色调板；
    - 片段二取第三色色相再转 80°；
    - 对话框、输入框取中性色调板；
    - 画面选中框取主色色调板；
    - 完成、提醒用固定色相。
  - 各角色在浅色、深色下的色调写成一张表，批 1 对照设计稿截图校准。
- **`theme-store.ts`**：偏好有三项：模式（跟随系统、浅色、深色）、种子色、强度。
  - 存在 `localStorage` 的 `mako.theme`。这不是凭证，可以存。
  - 跟随系统时监听 `prefers-color-scheme`。
  - 计算结果写到 `<html>` 上，形式是 CSS 变量和 `data-mode`。
- **首帧不闪**：每次应用主题时，把算好的变量串也缓存进 `localStorage`。
  `index.html` 里的几行内联脚本在 React 启动前读这份缓存，先写上变量。
- **默认种子色**是常量 `#019BFE`，注释写明它是用 `QuantizerCelebi` 加 `Score` 从 `logo-icon.png` 取出的
  （用户 2026-11-01 选定）。设置里的“从标志取色”就是这个常量，不在运行时分析图片。
- **画布**：时间轴和画布叠加层要用 canvas 能直接用的颜色，所以引擎额外写一份 `--…-rgb` 三元组，
  替换现在读的 `--mdui-color-*`。
- **CodeMirror**：语法颜色继续分浅色、深色两套，界面色改用新变量。
- **过渡期**：mdui 还没移除时，`setColorScheme` 用同一个种子色，`setTheme` 跟着模式，混在一起的页面颜色一致。

### 2.5 外壳

按设计稿：

- **顶栏 52px（有工程时）**：
  - 左侧：标志（回首页）、工程名（点开是菜单：另存为、导出歌词文件、关闭工程、协议控制台，
    即现在“⋮”里的项目）、保存状态、页签（歌词、编排、外观）、样式库。
  - 右侧：状态胶囊、撤销、重做、工程设置、应用设置、保存、导出视频。
    状态胶囊写连接状态和渲染设备，例如“已连接，GPU”；点开是现有的渲染设备菜单，功能不变。
- **没有工程时**：标志加应用名、样式库、应用设置、关于。
- **样式库页**：撤销、重做、保存作用于模板草稿，沿用现有行为。
- **导出页**：返回编辑，加标题。
- 删除导航栏。“首页”入口改为标志；工程设置从导航栏底部移到顶栏。
- **应用设置**：右侧面板，有三个页签：
  - 外观：主题模式、主题色、色彩强度、颜色用途；
  - 快捷键：§4.5 的清单；
  - 关于：打开关于对话框。
  改动立即生效，不需要工程。
- **关于对话框**：横版标志，产品版本（后端能力信息的 `productVersion`）和前端消费的合同版本、渲染设备、
  主要第三方组件及其许可（静态清单）。
  - 许可证一行：仓库暂不添加许可证，所以要等许可证加入后再显示；
  - “源代码”链接：仓库目前是私有的，开源时再加。

### 2.6 工作区布局

- **面板**：面板之间留 8px 缝。幕后的预览板向下伸进缝里，和底部区连成一整块，接缝处补内凹圆角：
  - 歌词页是 L 形（逐字预览加时间轴）；
  - 编排页、外观页是 T 形（画布加时间轴）；
  - 样式库没有共享底部区，试样区自成一块幕后。
- **分栏可拖动（§7.2）**：
  - 范围：左栏 240～400，默认 300；右栏 300～440，默认 340；时间轴 120～320。
  - 宽度按页记在 `localStorage`，双击分隔条恢复默认。
  - 拖动时只改宽度变量，拼接处的圆角跟着走。
- **断点（§7.1）**：
  - ≥ 1440：全部常驻。
  - 1200～1439：右栏改为覆盖面板，默认打开。
  - 960～1199：左右栏都改为覆盖面板，同一时间只开一个。
  - < 960：顶部提示“请使用更宽的窗口”。
  - 栏变成覆盖面板后，拼接退化为单独的底部区。
- **高度**：最小 720。底部区至少保留播放条加 140 高的时间轴，不足时上方编辑区内部滚动。

### 2.7 各页面

已出稿的页面按设计稿（`desk-stage.html`）实施，没出稿的先补稿（§4 第 0 步）。各页的组件和交互不变，只换控件、
布局和颜色；只有一处新增：

**歌词页行编辑区的“外观”和“显示在”（只读）。**

- **外观**：所选行生效的模板名和来源（本行直接分配，或继承自哪个目标）。
  - 数据来自已在内存中的外观状态（`AppearanceStore`），算法复用外观页“当前模板”那一节。
  - 点击跳到外观页，并选中这一行。
- **显示在**：所选行所在的片段和目标容器，例如“前段（片段 1–6 句），容器：前段”。
  - 数据来自编排状态（`OrchestrationStore`）。
  - 点击跳到编排页，并选中这个片段。
- **不做**：不显示槽位序号和同屏的行。这要在前端重算调度，现有数据给不出。
- **隐藏**：工程不支持编排读取，或数据还没读到时，这一项隐藏。不为它新发请求。

### 2.8 冒烟脚本

- 新增 `scripts/ui-query.mjs`：按 ARIA 角色和可访问名称找元素，例如 `button('保存')`、`menuItem('另存为…')`、
  `dialog('新建工程')`、`field('工程名')`、`tab('编排')`、`treeItem('前段')`、`option('主歌词')`。
  这样换控件实现时选择器不用再改。改版过程中补齐缺失的 `aria-label`。
- 每批改到哪些页面，就同时改写对应冒烟脚本里的 mdui 选择器；该批结束时这些冒烟必须通过。
- `smoke:editor` 加几步主题检查：切换深色、换种子色、刷新后偏好还在。不新增冒烟命令。
- 每批用 `scripts/page-shot.mjs` 截浅色、深色两套图，与设计稿对照。截图只作检查用，不入库。

## 5. 验收

- **视觉**：每页在浅色、深色和三个种子色（标志蓝、标志紫、橙）下与设计稿一致；1440 × 900、1280 × 800、
  1024 × 768 三种窗口分别符合 §2.6 的断点。
- **功能**：交互与改版前一致，全部冒烟和集成测试通过。主题偏好刷新后保留；首帧不闪。分栏宽度按页记住。
- **键盘**：所有控件都能用键盘到达，焦点可见。快捷键（撤销重做、保存、空格播放、J 打点、方向键换单元和行、
  删除）在列表、树、输入框里的行为与改版前一致。
- **干净**：`src` 里搜不到 `mdui`；`package.json` 不再有 mdui；时间轴不再读 mdui 变量。
- **不回退**：浏览器入口、静态预览协议和 GPU 预览路径不受影响（`smoke:render` 通过）；
  200 行以上的歌词列表滚动流畅。

## 6. 风险

| 风险 | 对策 |
|---|---|
| React Aria 的列表和树自己处理方向键、空格，与全局快捷键冲突 | 全局快捷键统一按焦点所在控件判断，列表内的方向键交给控件；批 4 对照验收清单逐条测 |
| 过渡期两套控件同屏 | mdui 用同一个种子色；外壳先改，页面逐批替换，每批内一页一次换完 |
| 冒烟选择器约 240 处要改 | 改用 `ui-query.mjs` 的角色加名称查询，随页面分批改，不集中到最后 |
| material-color-utilities 的结果与稿件的 OKLCH 近似有差别 | 以库的结果为准；自定义角色的色调在批 1 对照截图校准 |
| 不同系统的中日文字体回退不同 | 字体栈列出各平台的后备字体；Electron 打包时再评估是否随附 |
| 与 GPU 共享纹理（P1～P3）并行开发，都会动预览面板 | 预览面板只改外层布局和样式，不动 `preview-controller`、`gpu-preview-controller` 的逻辑 |
