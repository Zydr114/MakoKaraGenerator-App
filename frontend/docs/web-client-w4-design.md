## 2. 结构调整

### 2.1 页面与导航

`App` 的页面加上 `orchestration`，图标用 `view-quilt`。编排页依赖当前工程，每个工程一个 `OrchestrationStore`（与外观页同样的生命周期），切换页面时保留选中的节点和来源。

### 2.2 协议与客户端（已在合同同步提交里完成）

- `src/protocol/orchestration.ts` 定义了以下类型：
  - 节点：`OrchestrationNode`、`Placement`、`ReferenceRect`、`Layout`、`SafeArea`。
  - 来源程序：`OrchestrationProgram`。
  - 读模型响应：`ProjectOrchestrationResponse`。
  - 命令及其结果：`OrchestrationCommand`、`OrchestrationCommandResult`。
- 可空字段在实际响应里都是**省略**而不是 `null`，与 OpenAPI 一致。前端类型按“可省略、也可为 null”处理。
- `MakoClient.projects.orchestration(projectSessionId, expectedRevision)`。
- 能力名：
  - 读模型：`project-sessions.orchestration.read`。
  - 命令：`project-sessions.commands.orchestration.setDefaultContainer`。
- 锚点（`Center` 等）、布局类型（`Auto`、`SlotSequence`）、动画策略（`Karaoke`、`Static`、`FollowPrimary`）都是后端 C# 枚举名的字符串。前端只给已知值配中文，未知值原样显示，不做任何推断。

### 2.3 编排模型（`model/orchestration.ts`，无 DOM）

`buildOrchestration(response)` 产出以下内容：
- `byId`：ID → 节点。
- `children`：父 ID → 子节点。顺序就是 `nodes` 数组里的顺序，读模型不单独给排序字段。
- `programs`：按 `branchId` 索引。
- `orphans`：从所有程序的根都走不到的节点。
- `role(node)`：
  - 被某个布局的 `slotIds` 引用的是**槽位**；
  - 有 `layout` 的是**歌词容器**，`Auto` 显示“自动布局”，`SlotSequence` 显示“轮换·N”；
  - 有 `contentKind` 的是**内容节点**，原样显示类型；
  - 其余是**组**。
- `displayName(node)`：
  - 有名称就用名称；
  - 没有名称时按角色命名：来源的根写“画面”，默认容器写“常规”，槽位写“槽位 N”，其余写“未命名容器”“未命名组”等；节点 ID 显示在属性区。
- `containersOf(program)`：程序根下的全部歌词容器，供默认容器选择。
- `pathOf(id)`：对象路径，例如“主歌词 / 画面 / 常规”。
- `structureSections(branches)`：结构树按来源分节，先按来源列表的顺序，再是来源列表里没有的程序，最后是“其他节点”；每个节点只出现一次。来源没有程序时那一节为空（R4）。↑↓ 按这个顺序移动。

### 2.4 编排状态（`orchestration/orchestration-store.ts`，无 DOM）

- **读取**：
  - 订阅 `session.state$`。工程修订变化后，按 `latestRevision` 读编排结构；读取期间保留上一份模型。
  - 409 不提示，等下一次刷新。
  - 后端没有开放读模型能力时，状态为 `unsupported`。
- **选中**：
  - 选中节点 ID 和选中来源都跨刷新保留；节点不存在了就回到当前来源的默认容器。
  - 默认选中当前来源的默认容器。
  - 在结构树里选中节点时，歌词分配条的来源跟着换到节点所在的来源（“其他节点”不换）；在分配条里换来源时，选中换到那个来源的默认容器。
- **`setDefaultContainer(branchId, containerId)`**：
  - 经 `session.command` 发送。
  - `changed` 时返回 `applied`，no-op 时返回 `unchanged`，被拒绝时返回 `failed`；拒绝原因由 session 显示在状态栏。

### 2.5 只涉及编排或分配的变化不重读歌词

现在的规则是：changeSet 里出现时间以外的区域，就整体重读歌词。新增一条例外：所有区域都属于 `orchestration`、`presetApplications`、`renderInputs`，并且 `lineIds` 为空时，只更新工程摘要（修订、dirty、能否撤销），不重读歌词。
- 命令回执已经带有摘要，直接用回执里的。
- 事件流带来的变化没有回执，就重读一次摘要（`projects.get`）。
- 编排页和外观页各自按修订读取自己的数据，不依赖歌词重读。

### 2.6 页面（`orchestration/OrchestrationPage.tsx`）

三栏布局加底部区，与外观页相同的骨架：
- 左栏：结构树（`StructureTree`）。
- 中栏：`PreviewPanel`，上方是模式切换。
- 右栏：属性区（`NodeInspector`）。
- 底部：歌词分配条、播放条和只读时间轴。在时间轴上点选行只改变当前行，不做多选：多选用来新建片段，要等 G19。

快捷键：空格、Ctrl／⌘+Z、Shift+Z、Y、S，与外观页相同；↑↓ 在结构树里移动选中。

### 3.1 G18 需求草案

- **场景**：
  - 用户只想套用常见布局：在编排页点“快速布局…”，选“双行居中”，范围选“主歌词全部”。对话框显示“将影响 24 句”，点“应用”后时间预览变成双行轮换；不满意就撤销。
  - 也可以先在时间轴上框选第 9～12 句，只给这几句套“单行居中”，其余句子保持原来的调度。
- **现有缺口**：
  - 后端应用层的 `BasicLayoutOperation.TryPreview`／`Recognize` 已经能预演、拆分片段、识别布局，但没有 HTTP 入口。
  - 读模型也不标出容器是否就是某个预设。
- **请求**（路由和形状由 Codex 定，以下是前端需要的信息）：
  1. **预演**（不写工程，不产生历史）。
     - 输入：精确修订、`branchId`、预设（四选一）、可选的 `lineIds`（省略表示整个来源）。
     - 输出：`AffectedLines`、`ExistingClips`、`SplitClips`、`PreservedNodes` 这几个计数，以及“已经是这个布局”的标志。
     - 不能套用时返回原因，见下文“错误”。
  2. **应用命令**，例如 `orchestration.applyBasicLayout`。
     - 输入与预演相同。
     - `BasicLayoutNames` 要求的名称（容器、各槽位、范围模式下选中段和保留段的片段名）：由前端提供中文名（如容器“双行居中”、槽位“上行／下行”），还是由后端给默认名，请 Codex 决定。
     - 回执：新容器 ID、槽位 ID（按轮换顺序）、新建或拆分出的片段 ID。整个来源模式下的新默认容器也包含在里面。
  3. **读模型**：歌词容器增加识别结果，即 `Recognize` 的四种预设之一，不是预设时为空。前端据此显示预设名或“自定义”。
- **ID 与修订**：
  - 新节点和片段的 ID 都由后端生成，回执里返回原字符串。
  - 修订是 Int64 字符串。
  - 预演与应用都要求精确修订，修订对不上返回 409。
- **历史与 no-op**：
  - 一次应用只产生一条历史，撤销后结构、默认容器、片段全部恢复。
  - 已经是这个布局时（`TryPreview` 提前返回的那种情况），返回 `changed:false`，不产生历史、不清 redo。
- **错误**：422 `commandRejected`，并带稳定的 `failureCode`：
  - `DiscontiguousRange`：前端提示“需要连续歌词段”，不会悄悄扩大范围。
  - `InvalidRange`、`SourceMissing`、`PresentationInvalid`、`RecipeConflict`、`ReferenceConflict`、`ScheduleConflict`、`ScheduleFailure`（即 `BasicLayoutErrorCode`）：前端按原因显示。
  - 失败时不修改工程。
- **验收场景**：

### 3.2 R4：后加的歌词来源没有编排程序（2026-10-17 发现）

- **现象**（合同 1.13.0，产品 0.87.0）：
  1. 新建工程后执行 `lyrics.addTranslationBranch`，`GET .../orchestration` 的 `programs` 仍然只有主歌词一项，`nodes` 也没有翻译来源的节点。

- **期望**：读模型和命令对每个歌词来源都可用。两种做法由 Codex 决定：
  - 读模型返回补齐后的默认程序，并标明是隐含的；
  - 新增来源时就把程序写进工程。
- **另一点**：后端计划 §4 写的是 422 带稳定的 `failureCode`（如 `BranchNotFound`、`OrchestrationContainerNotFound`），实际响应没有 `failureCode`。前端现在只能显示 `message`。
- **前端临时处理**：没有程序的来源，在结构树里写“这个来源还没有编排程序（后端 R4）”；歌词分配条选到它时，默认容器选择不可用。

### 3.3 R5：模板试样的来源修订与 OpenAPI 矛盾

### 10.1 后端能力核对（真实 Server，`00eaf0b` 的集成测试）

- **范围**：`selectedLineIds` 省略表示整个来源；给出时必须是非空、不重复、按来源顺序连续的行 ID。
  - 乱序或中间断开时返回 `DiscontiguousRange`；
  - 有不存在或重复的 ID 时返回 `InvalidRange`。
- **范围套用的结果**：
  - 根下新建一个轮换容器，默认容器不变；
  - 选中的几句成为一个片段，名称是 `selectedSegmentName`，目标是新容器，没有调度上下文；
  - 默认段里没选中、有时间的句子，拆成名为 `retainedSegmentName` 的片段，留在默认容器。它们带调度上下文：原段的成员、`isDefaultSegment`、前后边界；
  - 范围碰到的已有片段会被拆开。
- **回执**：`basicLayoutResult.scope` 为 `range`，`clipIds` 列出新建的片段。同一预设对同一范围再套一次是 no-op。
- **读模型**：`programs[].clips` 的每项是 `{id, name?, lineIds, containerId, scheduleContext?}`。
- **R6**：设置默认容器是一条历史，撤销、重做都对。
- **R7**：快速布局只支持独立计时、逐字动画的来源。翻译这类跟随主歌词的来源，整来源和范围都返回 `UnsupportedSource`。
- **预演不标出 no-op**：预演回执的 `changed` 总是 false。
  - 整来源模式靠读模型的 `recognizedLayoutPreset` 判断是否已经是这个布局（第二批的做法）；
  - 范围模式的读模型只识别默认容器，前端判断不了，只能等应用回执 `changed:false`。
  - 这一点登记为 G25（§3.6）：请预演明确标出“应用不会变化”。

### 10.2 时间轴：选几句、片段轨

- **只读时间轴显示分配条来源的行**，即 `linesByBranch[分配条来源]`，不再是歌词页的当前来源。在分配条里换来源，时间轴跟着换（解决 §8 的限制）。
- **选择**：编排页自己记一段选中的句子，不改歌词页的当前行。
  - 点一句：只选这一句；
  - Shift／Ctrl＋点：从上次点的那句扩展到这一句，中间的句子全选上；
  - 在行轨空白处拖动：选中与这段时间相交的句子。夹在选中句子之间的无时间句子在时间轴上点不到，一并选上；
  - 选中的句子在行轨和元素轨上高亮。
- **连续性**：按来源顺序编号。只有拖动框选能选出不连续的结果（行的时间和来源顺序不一致时）。不连续时不悄悄扩大范围，快速布局的范围选项不可用，并写明“需要连续歌词段”。
- **片段轨**：
  - 在行轨下面加一条片段轨，每个片段一个色块，横跨它第一句有时间的开始到最后一句的结束。颜色按目标容器区分，色块上写片段名；
  - 点色块选中片段；点轨道空白处只定位播放头；
  - 没有时间的片段不画色块，只在片段列表里出现；
  - 只有编排页有片段轨，歌词页和外观页的时间轴不变。
- **循环**：播放条的“循环本行”在编排页改为“循环选中”，循环选中句子的时间范围。

### 10.3 歌词分配条与片段列表

- **分配条**：默认容器后面显示“未单独分配 N 句”，即这个来源里不属于任何片段的句子。有选中的句子时显示“已选第 a～b 句”，旁边有清除按钮。
- **“片段”按钮**：可用，点一下展开或收起片段列表（在分配条下方），与片段轨联动选中。列表每项包括：
  - 容器颜色；
  - 片段名，没有名称时写“片段 N”；
  - “第 a～b 句”；
  - 目标容器名；
  - 从原来的一段拆出来的（有调度上下文）标“保留原调度”。
- **列表标题**：“片段 · N 个”，还有一个“＋ 新建片段”按钮，不可用，写明要等后端开放片段编辑（G19-B）。没有片段时写明“在时间轴上选几句再套快速布局，这几句会成为片段”。
- **选中片段**：
  - 时间轴高亮它的句子，这几句就是当前选中的句子，可以直接给它们套快速布局；
  - 结构树选中它的目标容器；
  - 属性区显示片段。
  在结构树里选节点、或在时间轴上重新选句子，就取消片段选中。
- **结构树**：容器行上标“片段·N”，表示有 N 个片段以它为目标。

### 10.4 快速布局：范围

- **对话框里的范围**是一组单选：
  - “整个来源（共 N 句）”；
  - “选中的第 a～b 句（k 句）”：没有选中的句子时不显示；选中的句子不连续时不可用，并写明原因。
  打开对话框时，有连续的选中句子就默认选后者，否则选整个来源。
- **换范围**：按新范围重新预演，只保留最新一次。
- **预演文字（范围）**：“将影响第 a～b 句（k 句）；新建‘单行居中’容器和 1 个槽位，只接这几句（新片段‘歌词段布局’）；默认容器不变，其余句子保持原来的调度。”涉及已有片段或要拆分时，附上数量。
- **no-op**：整来源模式照旧按识别出的预设判断。范围模式应用后回执 `changed:false` 时，关闭对话框，提示“已经是这个布局，没有变化”。
- **应用（范围）**：
  - 提示“已套用‘单行居中’到第 a～b 句”，可撤销；
  - 读到新修订后，选中包含范围第一句的片段，以及它的目标容器（新容器）。
- **不支持的来源**：来源的计时方式不是独立计时，或明确设成了非逐字的动画，就不能打开“快速布局…”，并写明原因：“快速布局只支持独立计时、逐字（卡拉 OK）动画的歌词来源”（翻译这类跟随主歌词的来源）。
  - 判断只用来源摘要的 `timingMode` 和读模型里明确的 `animationPolicy`；
  - `animationPolicy` 没设时不猜，交给后端，返回 `UnsupportedSource` 时显示同一段原因。

### 10.5 属性区：片段

## 11. 第四批：G19-B 片段编辑

用户 2026-10-18 的决定：核对后端新能力，按计划继续开发前端。合同 1.19.0（产品仍是 0.91.0，后端 `9dbc735`；合同冻结于 `1fc2221`，实现基线 `3ab9f92`）开放了片段的新建、改名、改目标容器、删除四条命令（规范 §13.10），回执带 `clipResult`。读片段仍只走编排读模型。部署从 `9dbc735` 的独立克隆重新发布到 `.dev/backend-dist/0.91.0`。

### 11.1 后端能力核对（真实 Server，`3843c9b` 的集成测试）

- **四条命令**：`orchestration.createClip`、`renameClip`、`setClipContainer`、`deleteClip`，都带 `branchId` 和 `clipId`，能力列表里各有一项。真实变化各产生一条历史，`changeSet` 是 `orchestration`＋`renderInputs`，要完整刷新。
- **新建**：
  - `clipId` 由前端给出，不能和已有片段重复（`ClipExists`）；
  - `lineIds` 必须按来源顺序连续（否则 `DiscontiguousRange`），不重复、都存在、都有时间（否则 `InvalidRange`）；
  - `containerId` 必须是这个来源根下的歌词容器（否则 `ContainerInvalid`），可以是默认容器；
  - `name` 可省略。
- **重叠**：每句只能属于一个片段；片段的时间跨度不能和片段外的句子、别的片段重叠。实测“这一句已在别的片段里”返回的是 `ClipScheduleConflict`，不是 `TargetConflict`（后端先查时间冲突）。所以范围快速布局之后，默认段里有时间的句子都已拆进“保留原布局的歌词段”，要给其中几句新建片段，得先删掉那个片段。
- **改名**：`name` 必须出现，`null` 清除名称；同名是 no-op，回执 `changed:false`，修订不变。
- **改目标容器**：同容器是 no-op；改到别的容器后帧变化，撤销后恢复。
- **删除**：几句回到默认容器；回执是删掉之前的片段；撤销后片段原样回来。
- **不存在的片段** 返回 `TargetStale`；改名缺 `name` 返回 400。
- **不支持的来源**：和快速布局一样，只支持独立计时、逐字动画的来源，翻译来源返回 `UnsupportedSource`。
- **成员不能改**：没有“改片段的句子”的命令。要扩大或缩小片段，只能删掉重建。

### 11.2 新建片段

- **入口**：
  - 时间轴上选了几句时，分配条的“已选第 a～b 句”旁边有“为这几句新建片段”；
  - 片段列表标题上的“＋ 新建片段”。
  两个入口打开同一个对话框。
- **对话框“新建片段”**：
  - 范围：“从第 [a] 句到第 [b] 句”，按来源顺序编号。有选中的句子时预填它们，否则预填第 1 句。
  - 目标容器：这个来源根下的全部歌词容器，写名称和角色（自动布局／轮换·N）。默认选第一个不是默认容器的容器；只有默认容器时就选它，并说明“这几句仍在默认容器显示，但单独成一段”。对话框里不能新建容器：要放进新容器，先用快速布局建一个，或等结构编辑（G20）。
  - 名称：可以不填，不填时列表里显示“片段 N”。
  - 确认按钮“创建片段”。
- **提交前就地写明不能创建的原因**（按顺序检查，第一条不满足就显示它，按钮不可用）：
  - 范围无效：起句晚于止句，或超出来源句数；
  - 第 N 句没有时间：片段只能包含有时间的句子；
  - 第 N 句已在片段“X”里：每句只能属于一个片段，先删除那个片段；
  - 第 N 句（片段外）的时间夹在这几句中间：片段的时间跨度里不能有别的句子。
  前端的判断只是提前提示，结果以后端为准。后端拒绝时，原因也写在对话框里（§11.6 的对照表），对话框不关闭。
- **成功**：关闭对话框，提示“已为第 a～b 句新建片段”，可撤销；读到新修订后选中新片段，结构树选中它的目标容器。
- **`clipId`**：`clip/` 加随机 UUID。

### 11.3 改名

- 属性区“名称”输入框：Enter 或离开输入框时提交，Esc 撤回。清空表示清除名称（显示回“片段 N”）。与原名相同就不发命令。
- 成功提示“片段已改名为‘X’”（清除时“已清除片段名称”），可撤销。

### 11.4 改目标容器

- 属性区“目标容器”下拉框，选项与新建对话框相同；旁边保留“在结构树里查看”。选别的容器就发一条命令；选当前值不发。
- 成功提示“片段‘X’已改到‘Y’”，可撤销；结构树选中新的目标容器。

### 11.5 删除

- 属性区“删除片段”。不用确认框：编排直接生效，撤销靠工程历史（整体设计 §11）。
- 成功提示“已删除片段‘X’，第 a～b 句回到默认容器”，可撤销。读到新修订后取消片段选中，选中的句子保留（就是刚才那几句），结构树选中默认容器。

### 11.6 失败与不可用

- **后端拒绝的原因**（四条命令共用）：

  | failureCode | 文字 |
  |---|---|
  | `SourceMissing` | 歌词来源已失效。 |
  | `UnsupportedSource` | 片段只支持独立计时、逐字（卡拉 OK）动画的歌词来源；翻译这类跟随主歌词的来源不能建片段。 |
  | `ClipExists` | 片段编号重复，请重试。 |
  | `TargetStale` | 这个片段或这几句已经不在了，请重新选择。 |
  | `InvalidRange` | 片段只能包含这个来源里有时间、不重复的句子。 |
  | `DiscontiguousRange` | 片段的句子必须按来源顺序连续。 |
  | `ContainerInvalid` | 目标必须是这个来源根下的歌词容器。 |
  | `ClipScheduleConflict` | 这几句的时间和别的片段或片段外的句子重叠：每句只能属于一个片段，片段的时间跨度里不能夹着别的句子。 |
  | `TargetConflict` | 结果没有通过画面结构校验，没有修改。 |

  新建写在对话框里；改名、改容器、删除写在状态栏。快速布局应用失败时，状态栏也改用快速布局自己的原因（第二批的对照表），不再显示通用文字。
- **不可用**：工程只读、后端没开放对应命令、来源不支持（与快速布局同一条判断）时，按钮和输入框不可用，并写明原因。
- **进行中**：命令进行中，四个操作和快速布局都不可用。

### 11.11 已知限制（第四批）

- **片段的句子不能改**：后端没有改片段成员的命令。扩大、缩小、拆分、合并都只能删掉重建。
- **范围快速布局之后很难再新建片段**：默认段里有时间的句子都被拆进“保留原布局的歌词段”，要给其中几句新建片段，得先删掉那个片段。对话框会写明是哪个片段。
- **对话框里不能新建容器**：目标只能选来源根下已有的歌词容器。要放进新容器，先用快速布局建一个，或等结构编辑（G20）。

- **名称离开输入框就提交**：沿用整体设计 §5.2 的提交式输入框；按 Esc 撤回。

### 12.1 后端能力核对（真实 Server，`fde4ce0` 的集成测试 `scene-editing`，以及一次只读探查）

- **八条结构命令**：
  - 原有六条：`setNode`（只改名，`null` 清除）、`reparent`、`reorderChildren`、`addSlot`、`removeNode`、`reorderSlots`；
  - 1.23.0 新增两条：`createNode`、`copySubtree`。
  - 所有业务字段都必须出现，`null` 与省略不同。真实变化各产生一条历史，`changeSet` 是 `orchestration`＋`renderInputs`；同值是 no-op。
  - 回执都带 `structureResult`；新建和复制另带 `createdNodeIds`，新根在第一个。撤销重做后身份不变。
- **新建**：
  - `kind` 是 `group`、`auto`、`slotSequence` 之一，大小写精确，不对时返回 400；
  - 父级是 `null`（画布根层，节点会落在“其他节点”里），或者一个普通组（没有布局、没有内容）。父级是歌词容器、倒计时容器时返回 `ContainerInvalid`，父级不存在时返回 `TargetStale`。来源的根就是普通组。
  - 轮换容器一次建好全部槽位（1～64 个）和默认动画，同时最多显示 `min(2, 槽位数)` 句；组和自动布局容器的 `slotCount` 必须是 `null`，否则 400。
  - 新节点的位置是中心、参考框铺满父级。
- **复制**：
  - 同父复制整棵子树，全部换新 ID，内部引用（槽位、标记）跟着换；不复制歌词、程序、默认归属、片段、前奏和预设分配。
  - 复制单个槽位或单个标记时，副本会加到原轮换容器或原提示组的最后。
  - 来源的根也能复制，副本在画布根层，不属于任何来源。
- **改父级**：
  - 后端保持世界位置不变，局部几何跟着换算（实测四角不变）；
  - 形成循环、把默认容器挪出来源的根、把来源的根挪进别的组、把槽位挪出轮换容器，都会被拒绝。
  - 普通组能挪进轮换容器（作为非槽位的子节点），但这时新建不行，前端只提供普通组和画布根层作为目标。
- **排序**：
  - `reorderChildren` 要给出该父级（`null` 是画布根层）的全部直接子节点，各一次，不完整时被拒绝，空数组返回 400；
  - `reorderSlots` 要给出全部槽位；
  - 子节点的显示顺序和槽位的轮换顺序是两回事。
- **槽位**：
  - `addSlot` 只能给轮换容器追加空槽位，`slotId` 由前端给出，重复时返回 `IdentityConflict`；
  - 轮换容器至少要有一个槽位，删最后一个会被拒绝。
- **删除**：
  - 删节点连同子树一起删；
  - 删一个标记会把它从提示组里去掉；
  - 来源的根、默认容器、片段的目标容器、前奏的提示容器（以及含有它们的子树）都不能删，后端不会隐式改绑。
- **拒绝码不具体**：除了 `TargetStale`、`IdentityConflict`、`ContainerInvalid`，其余结构问题都只返回 `PresentationInvalid`（“节点结构未通过工程校验”）。所以前端在提交前按 §12.4 自己检查，并写明不能做的原因。

### 12.2 画面结构的工具栏

结构树标题栏加一排按钮，作用于选中的节点：
- **＋ 新建…**：打开新建对话框（§12.3）；
- **复制**；
- **上移**、**下移**；
- **移到…**：打开改父级对话框；
- **删除**。

不能用时按钮不可用，悬停写明原因（§12.4）。Delete 键等同于“删除”；不能删时在状态栏写明原因（整体设计 §4）。

整体设计 §5.3 里的 ⋯／右键菜单和拖动排序本批不做，先用工具栏。

### 12.3 新建与复制

- **新建对话框“新建”**：
  - **种类**：组、自动布局容器、轮换容器。
  - **放在**：所有普通组（写对象路径），加上“画布根层（不属于任何来源）”。预填的规则：
    - 选中的节点是普通组时，预填它；
    - 否则预填它最近的普通组祖先；
    - 都没有时，预填分配条来源的根。
  - **名称**：按种类预填“新组”“新容器”“轮换”，可以改；清空表示不命名。
  - **槽位数**：只对轮换容器，1～64，默认 2；写明“同时最多显示 min(2, N) 句，之后可调”。
  - **提示**：
    - 歌词容器放在某个来源的根下，才能被选为那个来源的默认容器或片段的目标；
    - 新节点铺满父级、居中，位置以后在属性区调整。
  - 确认按钮写“新建”。
- **复制**：不需要对话框。副本名称是“原名 副本”；复制槽位时副本加到轮换的最后，复制标记时加到提示组的最后。
- **成功提示**（都可撤销）：
  - 新建：“已新建组‘X’”“已新建自动布局容器‘X’”“已新建轮换容器‘X’（N 个槽位）”；
  - 复制：“已复制‘X’”。
  读到新修订后，结构树选中新节点。

### 12.4 移动、排序、删除与提交前检查

前端的判断只是提前提示，结果以后端为准。

- **改名**：属性区顶部加“名称”输入框，与片段的名称一样，Enter 或离开输入框时提交，Esc 撤回，清空表示清除名称。成功提示“已改名为‘X’”或“已清除名称”。
- **移到…**：
  - 对话框里列出可选的目标：所有普通组（写对象路径），以及“画布根层”。以下目标不列：
    - 节点自己和自己的后代，以及当前的父级；
    - 如果子树里有某个来源的默认容器、片段的目标容器或前奏的提示容器，那个来源的根以外的组，以及画布根层也不列。
  - 写明“移动后画面上的位置不变”。
  - 不能移动的情况：
    - 来源的根（“来源的根固定在画布根层”）；
    - 槽位（“槽位只能在它的轮换里调整顺序”）；
    - 前奏标记（“标记只能留在它的提示组里”）。
- **上移、下移**：
  - 槽位按轮换顺序移动（`reorderSlots`）。结构树里，轮换容器下的槽位按轮换顺序排在前面，其余子节点在后面。
  - 其他节点在同级里移动（`reorderChildren`，提交完整的同级清单）：
    - 轮换容器下的非槽位子节点只和非槽位的兄弟交换；
    - 画布根层的节点只和其他“其他节点”交换。
  - 不能移动的情况：
    - 已在最前或最后；
    - 来源的根（“来源之间的上下层次不在这里调整”）。
  - 成功提示“已上移‘X’”“已下移‘X’”。
- **删除**：连同子树一起删，不用确认框，提示“已删除‘X’”（有子节点时加“及其中 N 个节点”），可撤销。删除后选中原来的父级。不能删的情况，写明是哪一个：
  - 来源的根；
  - 某个来源的默认容器（“先把默认容器改到别的容器”）；
  - 片段的目标容器（“有 N 个片段以它为目标容器，先删除这些片段或改目标容器”）；
  - 前奏的提示容器（“有 N 个前奏用它提示”）；
  - 子树里含有上面这些：写“子树里的‘Y’是……”；
  - 轮换的最后一个槽位（“轮换至少要有一个槽位”）；
  - 提示组的最后一个标记（“提示组至少要有一个标记”）。
- **复制**的限制只有一条：来源的根不能复制（“副本会成为不属于任何来源的节点”）。
- **工程只读、后端没开放、命令进行中**：工具栏和输入框都不可用，写明原因。

### 12.5 槽位

选中轮换容器时，属性区的“槽位”一节改成列表：
- 每行写“槽位 N”（有名称时写名称），带“上移”“下移”“删除”；
- 列表下方是“＋ 加槽位”。新槽位的 ID 是 `slot/` 加随机 UUID，名称留空，显示为“槽位 N”。

成功提示（都可撤销）：“已加槽位”“已调整槽位顺序”“已删除槽位 N”。

槽位数变了，“同时最多显示”不会跟着变：那是槽位动画的参数，第六批（G21）在属性区里可编辑。

### 12.6 失败原因

结构命令共用一张对照表，写在状态栏：

| failureCode | 文字 |
|---|---|
| `TargetStale` | 这个节点已经不在了，请重新选择。 |
| `IdentityConflict` | 编号重复，请重试。 |
| `ContainerInvalid` | 只能放在普通组下（不能放进歌词容器、槽位或内容节点）。 |
| `PresentationInvalid` | 结果没有通过画面结构校验，没有修改。 |

新建对话框失败时，原因写在对话框里，对话框不关闭。

### 12.11 已知限制（第五批）

- **后端的拒绝原因大多不具体**：除了 `TargetStale`、`IdentityConflict`、`ContainerInvalid`，结构问题都返回 `PresentationInvalid`。前端在提交前按 §12.4 检查并写明原因；漏掉的情况只能显示“结果没有通过画面结构校验，没有修改”。这不阻塞，已在联调回执里提给后端参考，暂不登记缺口。
- **没有拖动排序和右键菜单**：先用工具栏（§12.2）。上移下移一次只走一格。
- **标记的顺序不能调**：标记按提示组的顺序排在前面，“上移”“下移”不可用。前奏提示组的新建在第七批（G23）。
- **目标比后端允许的窄**：后端也允许在槽位下新建、把组挪进轮换容器，前端只提供普通组和画布根层。复制来源的根会得到不属于任何来源的副本，前端不提供。
- **槽位数变了，“同时最多显示”不跟着变**：那是槽位动画的参数，第六批（G21）接入编辑。
- **Delete 键只删节点**：选中片段时，结构树选中的是它的目标容器，按 Delete 会写明“有 N 个片段以它为目标容器”而不会删片段；删片段用属性区的“删除片段”。
- **其他不可用按钮的悬停原因**：mdui 按钮禁用后不响应指针，W4 前几批的“快速布局…”“＋ 新建片段”等按钮把原因写在按钮自己的 `title` 上，悬停看不到；这些按钮旁边都另有文字说明，本批只在新工具栏上改用外层提示。

### 13.1 后端能力核对（真实 Server，`f318645` 的集成测试 `scene-completion`）

合同同步提交 `f318645` 一次接好了协议类型和客户端：14 种新命令、回执 `leadInGenerationResult`、读模型新字段、节点模板目标，以及 `projects.linePresentation`、`projects.measureScene` 两个客户端方法。集成测试 `scene-completion` 有 10 项，在真实 Server 上逐条核对（之前的 9 个文件照常通过，合计 115 项）：

- **布局类型**（`setLayoutKind`）：
  - 自动布局改成轮换时 `slotIds` 填现有的直属普通子节点，`newSlotCount` 是要新建的个数，两者合计 1～64，新槽位的 ID 由后端生成，默认动画与新建轮换时相同；
  - 改回自动布局时槽位节点保留成普通子节点，`slotIds` 变空，`slotAnimation` 变成 `null`，安全区、最大宽度、默认位置不变；再改成轮换时可以把这些节点用回来；
  - 同类型是 no-op；数量不对（自动布局带新槽位、轮换合计为 0）返回 400；目标是普通组时返回 `ContainerInvalid`。默认容器也可以切换类型。
  - 回执 `propertiesResult: {operation: 'setLayoutKind', nodeId, changed}`。
- **进入动画**：
  - `setProjectEnterAnimation` 设工程默认，`null` 关闭；`setLineEnterAnimation` 设本句覆盖，`null` 清除后继承工程默认。五个字段都要给，时长会被规范化（`'0200000'` 读回是 `'200000'`）。
  - 单句展示读取（`line-presentation`）给出本句的局部变换、本句覆盖、实际生效的动画，以及来源 `line`／`project`／`none`。
  - 设了工程默认后，句子开头那一帧跟着变；全部清除后帧回到原样。缩放为 0 返回 400，句子不存在返回 `TargetStale`。
- **前奏自动生成**：
  - 设置有六个字段，提示组 ID 必须出现，可以是 `null`。`setLeadInGeneration` 只保存设置，不生成。
  - 预演（`previewLeadInGeneration`）修订不变，按句列出候选：开头那句和长间奏后的句子是 `New`，附上拟定的完整前奏和起止时间；其余句子 `Skipped`，原因是 `NotEligible`；已经生成过的句子是 `Preserved`。提示组为 `null` 时没有候选，诊断里有一条 `Error`。
  - 应用（`applyLeadInGeneration`）只应用 `selectedLineIds` 里的句子，前奏的 `origin` 是 `Generated`，ID 由后端按句子生成。空数组是 no-op。
  - `deleteLeadInAndExclude` 删除前奏，并把目标句写进设置的 `excludedLineIds`；之后预演，这一句是 `Skipped`，原因 `Excluded`。撤销后前奏和设置都回来。
- **标记与外观**：
  - `addMark` 加在提示组最后，新 ID 在 `leadInResult.markNodeIds` 里；
  - `setMarkText` 改字，空白返回 400；
  - `reorderMarks` 要给出完整顺序，不完整时返回 `PresentationInvalid`；
  - `spaceMarks` 按顺序均匀排开（4 个标记的 x 是 0.125、0.375、0.625、0.875，宽都是 0.25），第二次是 no-op；删除标记用 `removeNode`。
  - 标记外观覆盖与静态样式的属性修改同形，`[]` 清除，`scale` 这类不允许的属性返回 400。倒计时外观要完整六项，同值是 no-op。
  - 读模型里提示组带 `appearance` 和 `attachmentMode`，标记带 `appearanceOverride`。新建的倒计时默认就是 `CueTargetText`（跟着文字）。
- **附着方式**：
  - 改成 `FixedParent` 时，后端用真实测量把位置换算到父级（实测 x 从 0 变成约 0.447，正好是第一句文字的左缘，锚点不变）；改回 `CueTargetText` 后位置也回到原值。
  - 同方式是 no-op，回执 `propertiesResult.operation` 是 `setLeadInAttachment`。
  - 容器不是这个前奏的提示组时返回 422，但没有 `failureCode`，登记为 R8（§3.7）。
- **节点模板目标**：静态模板（如“经典整行”）可以用于编排节点，`includeDescendants` 必须给出；分配读回的目标是 `{kind: 'node', nodeId, includeDescendants}`。文本单元类模板用于节点时返回 422。
- **同帧测量**（`measureScene`）：
  - `layout` 模式用代表试样：默认容器和轮换的每个槽位各放一句代表文字（`representative: true`，`slotId` 等于它所在的槽位节点），真实句子都是 `notVisible`，前奏标记可见。
  - `time` 模式按时刻采样：4.5 秒时第一句 `measuredInk`，带 4 个角点，`parentId` 是默认容器；第三句 `notVisible`，没有角点；空的轮换容器是 `emptyReference`。两种模式的 `sampleInputFingerprint` 不同。
  - 返回的 PNG 解码后的 SHA-256 等于 `pngSha256`。测量不改修订。
  - 拒绝：`layout` 带时刻、时刻有前导零、宽超过 1280 都返回 400，修订对不上返回 409。
  - 容器和组的 `worldCorners` 是所有后代墨迹的四角，按 4 个一组排列；`fixedReference` 是固定参考框（与 G22-A 相同），`editReference` 是父级的编辑参考。每个客户端同时只能有一个测量（附着方式的切换也占这个名额），超出返回 429 `requestQuotaExceeded`。

**1.38.1 复核（2026-10-26）**：后端补齐计划 P1～P5 完成后，合同升到 1.38.1（产品 0.104.1，后端 `aef1af4`）。同步时整体替换 `docs/backend/`，协议类型只补编排相关和必须跟上的部分：
- 片段成员三条命令 `setClipMembers`、`splitClip`、`mergeClips` 与回执 `clipMembersResult`（第八批用）；外观分配目标加 `clips`。
- 注音有了片段（`segments`），`RubyAnnotation.segments` 必填；注音片段的 7 条命令先只有类型（W6 用）。
- 背景媒体 4 条命令、`audio.replaceAsset`／`audio.clear`、`project.rename`、`project.applyEdits` 的类型（W5 用）；任务种类加 `author-compilation`。
- `maxAssetBytes`／`maxAssetQuotaBytes` 可以是 `null`（部署没设上限）；上传前检查遇到 `null` 不再按大小拒绝。
- 测量可以测编辑候选（`previewId` 等三个可选字段），第六批不用。

### 13.2 属性区：位置、变换与参考框

属性区的只读列表改成输入框，提交方式与名称框相同：回车或离开时提交，值没变不发命令。

- **位置与变换**：X、Y（百分比，可以超出 0～100%，表示在父级参考框外）、锚点（六个：中心、左上、上中、右下、左中、右中）、旋转（度）、缩放（倍数，大于 0）。
- **参考框**：宽、高（相对父级的百分比，大于 0，可以超过 100%）。
- 每次提交一条 `setNodeGeometry`，带完整的位置和参考框，只改动的那一项换成新值。成功提示“已调整‘X’的位置”或“已调整‘X’的参考框”，可撤销。
- 输入不合法（不是数字、缩放或宽高不大于 0）时，输入框写明原因，不发命令。

### 13.3 属性区：内部布局

- **类型**：下拉框，有“自动布局”和“轮换”两项。
  - 改成**轮换**时打开对话框，填槽位数（1～64）。如果容器下已有直属普通子节点（比如之前从轮换改回自动布局时留下的槽位），预填为它们的个数，并写明“现有 N 个子节点会用作前 N 个槽位”；槽位数超出的部分由后端新建。发一条 `setLayoutKind`，提示“已改成轮换（N 个槽位）”。
  - 改成**自动布局**时直接提交，提示“已改成自动布局：N 个槽位留作普通子节点”，可撤销。
- **默认位置**：
  - 没有设置时显示“未设置”和“设置”按钮。点“设置”时，用节点当前的外层位置作为初值，提交一条 `setLayoutDefaultPlacement`。
  - 设置后显示 X、Y、锚点、旋转、缩放五个输入框和“清除”按钮（`placement: null`）。
- **安全区**：左、上、右、下四个百分比（0～100%，右大于左，下大于上），一次提交一条 `setLayoutSettings`，同时带上最大宽度。
- **最大宽度**：百分比，大于 0、不超过 100%。
- 前端先检查范围，不合法时写明原因，不发命令。

### 13.4 属性区：槽位动画

只对轮换容器显示，放在槽位列表下面。每改一项都提交一条 `setSlotAnimation`，带完整的十四个字段。

| 分组 | 字段 | 说明 |
|---|---|---|
| 出现时机 | 方式 `revealMode` | 按进度（`Progress`，配“进度”0～100%）、前一句开始后（`TimeAfterPreviousStart`，配“延迟”秒）、下一句开始前（`LeadBeforeNextStart`，配“提前”秒）。只显示当前方式用到的那一项 |
| 调度 | 同时最多显示 `maxVisibleLines` | 正整数。第五批已知限制里“槽位数变了这一项不跟着变”在这里解决：槽位列表下的提示改成指向这一项 |
| | 槽位已满时 `conflictPolicy` | 排队等空位、允许溢出、替换最早的、跳过 |
| | 保留到 `retentionPolicy` | 句子结束、下一句出现、立即消失 |
| 进入／退出 | 进入时长、退出时长 | 秒，非负 |
| | 进入缓动、退出缓动 | 线性、渐入、渐出、渐入渐出 |
| 姿态 | 进入起点、停留、退出终点 | 各有透明度（0～100%）、缩放（大于 0）、X 偏移、Y 偏移（像素）、旋转（度）。默认折叠 |

时间在界面上用秒，提交时换算成微秒字符串。

### 13.5 属性区：来源的动画策略

来源一节的“动画”改成下拉框：按来源角色（`null`）、卡拉 OK、静态、跟随主歌词。提交一条 `setProgramAnimationPolicy`。

已知的限制在前端先检查，选项不可用时写明原因。这些限制来自后端的画面结构校验（`PresentationValidator`），看的是**实际生效的动画**：`null` 按来源角色解释，主歌词是卡拉 OK，其他来源是静态。

- 有片段或前奏提示的来源，以及默认容器是轮换的来源，实际动画只能是卡拉 OK。静态、跟随主歌词不能选；非主歌词来源的“按来源角色”实际是静态，也不能选。
- 反过来，实际动画不是卡拉 OK 的来源：它的默认容器在“内部布局”里不能改成轮换；歌词分配条里，轮换容器也不能选作它的默认容器。两处都写明原因。（2026-10-26 冒烟时发现：默认容器是轮换时改成静态被拒绝，前端原来只检查了片段和前奏。）

其余拒绝显示“结果没有通过画面结构校验，没有修改”。

### 13.6 画布：叠加层

画布上叠一层 SVG，按同帧测量画出各元素的框：

- **容器、槽位**：画固定参考框（`fixedReference` 的四角），用虚线；
- **句子、标记**：画墨迹的四角，用实线；
- **选中的节点**：它的参考框加粗、用强调色，并画出它所有后代的墨迹。

坐标是画布坐标（1920×1080 这类），按显示尺寸缩放。

画布模式旁加一个“显示框”开关（默认开），只在本页内保持。开关只管画不画框，点选和拖动照常可用（时间预览照常测量）。

**什么时候测量**：

- 时间预览模式：暂停时播放头或修订变了，停 300 毫秒后按当前时刻测量一次。叠加层只在测量结果的修订、时刻与当前预览帧一致时显示，播放中隐藏。
- 布局参考模式：修订变了就测量。
- 每个客户端同时只能有一个测量：前一个没回来时，新的请求排在后面，只保留最新的一个。
- 测量失败时叠加层隐藏，画布下方写明原因，不影响预览：
  - 名额用完（429）：稍后自动重试一次；
  - 工程太大（413）：“画面太复杂，不能测量”；
  - Worker 不可用：“画面测量暂时不可用”。
  后端没开放测量时，开关不可用并写明原因。

测量的状态放在独立的 `SceneMeasurementController`（无 DOM，与 `PreviewController` 同样的写法），编排状态只负责选中。

### 13.7 画布：点选与拖动

- **点选**：在画布上点一下，按以下顺序选中节点：
  1. 命中某句或某个标记的墨迹：选它的父级（句子在哪个容器或槽位里，就选那个）；标记直接选它自己；
  2. 否则选包含这个点、固定参考框面积最小的容器或槽位；参考框差不多铺满画布的（面积达到画布的 90%：来源的根、铺满画布的默认容器，以及快速布局里整画布大小、只是挪了位置的槽位）不算，否则点哪里都会选中它们；
  3. 都没有时不改变选择。
  选中后，结构树和属性区跟着变。
- **拖动**：在选中节点的框内按下并拖动，框跟着移动（只移动叠加层，不重绘画面）；松手时提交一条 `setNodeGeometry`，只改 X、Y。框差不多铺满画布（同上，90%）的节点，要按在它里面的文字（后代墨迹）上才开始拖动，免得在画布任意处一拖就挪走整个来源。按下处不能拖动选中的节点时，看点选会选中的节点：能拖就直接拖它，开始拖动时选中它。
  - 换算：画布上的位移先用父级编辑参考（`editReference`）矩阵的逆变换成父级局部的位移，再除以参考的宽高，得到比例。
  - 位移小于 2 个屏幕像素时当作点选；拖动中按 Esc 取消。
  - 工程只读、后端没开放 `setNodeGeometry`、正在提交时不能拖动，光标保持默认。
  - 成功提示“已移动‘X’”，可撤销。
- 本批**不做**缩放、旋转手柄；改大小和角度用属性区。

### 13.8 画布：布局参考模式

“布局参考”按钮可用：

- 画布显示 `layout` 模式测量的 PNG，叠加层同上；
- 每个容器和槽位放一句代表文字，不看时刻；
- 时间轴、播放条照常可用，但不影响画布。

旁边的说明改成“每个容器和槽位放一句代表文字，不看时刻”。点选、拖动在两种模式下都可用。

### 13.13 已知限制（第六批）

- **没有缩放、旋转手柄**（§13.7）：改大小和角度用属性区。拖动只改 X、Y。
- **叠加层有延迟**：时间预览要等暂停后 300 毫秒再加一次测量才出现；播放中隐藏。拖动松手后，时间预览里叠加层会短暂消失，等新修订的帧和测量到达后再出现；布局参考模式会保留拖动后的位置直到新图到达。
- **测量名额**：每个客户端同时只能有一个测量；切换模式或连续编辑时只测最新的一次，名额满了（429）稍后重试一次，仍满就写明原因，等下一次编辑或移动播放头再测。
- **提前检查只覆盖已知规则**：动画与轮换的关系按后端校验补上了（§13.5）；其他被画面结构校验拒绝的情况仍只显示“结果没有通过画面结构校验，没有修改”。
- **前奏提示的标记**：叠加层和点选已经认得标记（选中它自己），前奏提示的新建和编辑在第七批（G23）。
- **开发环境**：一次会话里连续跑很多次浏览器脚本后，后端会拒绝登记新客户端（`POST /api/v1/clients` 返回 429），页面显示“连接失败，正在重试”。原因是关掉的浏览器留下的客户端租约还没到期。重启 `pnpm dev:backend` 即可，和产品代码无关。

## 14. 第七批：G23 前奏提示、G24 本句微调与进入动画

### 14.1 后端能力核对（真实 Server 0.104.1，2026-10-26 临时探查）

§13.1 的集成测试之外，这次又在真实 Server 上探查了几处界面要依赖的行为：
- **新建提示组**（`createCountdown`）：名称是 `null` 时叫“前奏提示”；三个标记的字都是“●”，均匀排在提示组里；附着方式默认是“跟着文字”（`CueTargetText`）；位置 (0, 0)、锚点右中，参考框是画布宽的 1/16、高的 1/27。
- **跟着文字时的几何**：时间预览测量里，提示组的父级是目标句（测量元素 ID `…/text/<行>`），编辑参考的原点在目标句文字的左端中点，宽高仍是画布大小。所以 (0, 0)、右中锚点表示“紧贴在文字左边”，拖动按第六批的换算照常可用。标记的编辑参考是提示组自己的框。
- **自动生成**：
  - 应用（`applyLeadInGeneration`）会把这次的设置一并存进来源（`leadInGeneration`），不用先单独保存；
  - 自动生成的前奏 ID 由后端按“来源程序＋目标句”生成（`lead-in/<程序>/<行>`），删掉后再生成还是同一个 ID；
  - 改过的自动前奏变成手工（`origin: Manual`），之后预演里是“保留”，原因 `ExistingManual`；
  - 时长改了以后，已有的自动前奏在预演里是“更新”，带新旧两份前奏。
- **后端的生成规则**（Core `LeadInGeneration`）：
  - 默认设置：开头、长间奏都勾选，间奏阈值 8 秒，提示时长 3 秒；
  - 起唱点之前的时间不够一个提示时长时是 `TooShort`（不会缩短）；和别的句子的演唱时间或别的前奏重叠时是 `TimingConflict`；
  - 已停用的前奏是“保留”（`Disabled`）；不再符合规则的自动前奏是“移除”，要用户确认；
  - 来源不是独立计时、逐字动画，或提示组不对时，没有候选，诊断里一条 `Error`。
- **单句展示**（`line-presentation`）：没有设置时三项都是 `null`，`animationSource` 是 `none`；设了工程默认后实际生效的动画就是它，来源 `project`。
- **本句偏移的几何**：句子的测量元素带 `lineId` 和编辑参考（所在容器的参考）。`offsetXRatio` 设成 0.1，文字在 1920 宽的画布上右移 192 像素，与编辑参考的宽度换算一致。
- **进入动画的默认值**（Core `LineAnimation`）：0.4 秒、渐出，起始不透明度 0、缩放 1、纵向偏移 12 像素（正值表示从下方进入）。起始不透明度 1、缩放 1、偏移 0 时看不出效果。

### 14.2 前奏提示页签与前奏轨

歌词分配条上的“前奏提示”改为可用，显示“前奏提示 · N”。它和“片段”是同一排页签，一次只展开一个；状态 `clipsOpen` 改成 `panel: 'clips' | 'leadIns'`。

- **前奏列表**：每行显示目标句（“第 N 句 · 文字开头”）、时间（开始～结束；算不出时写“没有时间”）、时长、提示组名称、来源（“手工”或“自动”）；停用的标“已停用”。按目标句的顺序排列。点选一行就选中这个前奏。
- **标题栏**：“＋ 添加前奏”和“自动生成…”两个按钮。
- **前奏轨**：时间轴在片段轨下面加一条前奏轨，每个前奏画成一段，标“▸ N 秒”，停用的画淡。点前奏轨上的一段也选中这个前奏。前奏列表和前奏轨联动，与片段相同。时间轴组件的 `bands` 推广成多条轨（`tracks`），片段轨仍在第一条。
- **选中前奏时**：时间轴高亮它的目标句，结构树选中它的提示组，属性区显示前奏（§14.3）。
- **不可用时**写明原因，按钮停用：
  - 工程只读；
  - 后端没开放；
  - 来源不是独立计时、逐字动画（与片段相同：“前奏提示只支持独立计时、逐字（卡拉 OK）动画的歌词来源……”）。

### 14.3 属性区：前奏

- **路径**：“来源 / 前奏提示 / 第 N 句”。
- **可编辑的字段**：
  - 名称（可空）；
  - 目标句（下拉框，“第 N 句 · 文字”）；
  - 提示组（下拉框，列出这个来源根下的全部提示组）；
  - 时长（秒，大于 0）；
  - 启用（开关）。
- **提交方式**：每改一项提交一条 `updateLeadIn`，带完整字段，只换改动的那一项。成功时提示“已调整前奏”（启用开关写“已停用前奏”或“已启用前奏”），可撤销。
- **只读信息**：时间（开始～结束）、来源（手工或自动）。自动生成的前奏注明“改动后变为手工，自动生成不会再改它”。
- **附着方式**（下拉框）：
  - 两种方式：“跟着目标句的文字”和“固定在父级”。发 `setLeadInAttachment`，带这个前奏和它的提示组。
  - 附着方式属于提示组，用同一个提示组的前奏都跟着变，下拉框下面写明这一点。
  - 切换时后端按真实文字位置换算，画面上不动。会占用测量名额。
- **删除**：
  - “删除前奏”发 `deleteLeadIn`，提示组保留；
  - 自动生成的前奏另有“删除并不再自动生成”，发 `deleteLeadInAndExclude`，目标句写进排除列表。
- **失败原因**（`failureCode`）：

| failureCode | 显示 |
|---|---|
| `SourceMissing` | 歌词来源已失效。 |
| `IdentityConflict` | 前奏编号重复，请重试。 |
| `TargetStale` | 这个前奏或目标句已经不在了，请重新选择。 |
| `ContainerInvalid` | 提示组必须是这个来源根下的前奏提示组。 |
| `LeadInTimeConflict` | 前奏放不下：起唱前的时间不够这么长，或和别的句子、前奏的时间重叠。缩短时长，或换一句。 |
| `SceneAttachmentReferenceUnavailable` | 目标句的文字测不到（例如没有时间或在画面外），不能切换附着方式。 |
| `PresentationInvalid` | 结果没有通过画面结构校验，没有修改。 |

### 14.4 添加前奏

点“＋ 添加前奏”，或在本句属性里点“为这一句添加前奏…”（§14.7），打开对话框。

- **目标句**：
  - 预填选中的那一句；
  - 没有选中句子时，预填第一个有时间、还没有前奏的句子；
  - 已有前奏的句子在选项里标“已有前奏”，不能选。
- **提示组**：预填这个来源根下的第一个提示组。没有提示组时显示“新建提示组”按钮：它在来源的根下新建一个有三个标记的提示组（`createCountdown`），是单独的一条历史，提示“已新建提示组‘前奏提示’”，新建后自动选中它。
- **时长**：秒，预填 3。
- **名称**：可空。
- **确认**按钮写“添加前奏”：
  - 发 `createLeadIn`，ID 是 `lead-in/` 加随机 UUID，一条历史；
  - 成功后关闭对话框，选中新前奏，提示“已为第 N 句添加前奏”，可撤销；
  - 被拒绝时按 §14.3 的表把原因写在对话框里，对话框不关。

### 14.5 自动生成

点“自动生成…”打开对话框（整体设计 §6.5）。

- **设置**：

- **候选列表**：每个目标句一行，显示“第 N 句 · 文字”、状态、原因、拟定的时间；“更新”另外写出时长从几秒变成几秒。

|---|---|---|

### 14.6 提示组与标记

- **在结构树里选中提示组时**，属性区在“位置与变换”下面加两节：

### 14.7 属性区：句子（本句微调与进入动画）

新增“句子焦点”`lineFocus`：在时间轴上点选或框选句子，或在画布上双击句子（§14.8）时为真；在结构树或画布上选节点、选片段、选前奏、清空选择时为假。属性区按这个顺序决定显示什么：

1. 选中了前奏：显示前奏（§14.3）；
2. 选中了片段：显示片段；
3. 有句子焦点、只选了一句：显示这一句；
4. 有句子焦点、选了几句：只显示范围（“已选第 3～5 句，共 3 句”），说明本句微调一次只对一句，并提供“为这几句新建片段”；
5. 其余情况显示节点。

**这一句**：
- **头部**：路径“来源 / 第 N 句”，下面是文字和时间。“显示在”写出它所在的容器：默认容器，或某个片段的目标容器。“跳到这一句”把播放头移到这一句的中间。
- **数据来源**：按（修订，来源，句子）读取单句展示（`line-presentation`）。修订变了就重读，409 时等下一次。读取中保留上一份；换了句子时先显示“正在读取……”。
- **本句微调**：
  - X 偏移、Y 偏移（所在容器参考框的百分比，可以为负）、旋转（度）、缩放（倍，大于 0）。
  - 提交一条 `setLineLocalTransform`，带完整的四项；原来没有微调时，其余三项取 0、0、0、1。成功时提示“已调整本句微调”。
  - “清除本句微调”发 `null`，没有微调时不可用。
- **进入动画**：
  - 先写明实际生效的动画和来源：“本句单独设置”“用工程默认”或“没有进入动画”。
  - “本句单独设置”开关：打开时用实际生效的动画作初值（没有时用后端默认值），发 `setLineEnterAnimation`；关掉时发 `null`，提示“已清除本句进入动画，改用工程默认”。
  - 打开后显示五个字段：时长（秒，0～10）、缓动（线性、渐入、渐出、渐入渐出）、起始不透明度（0～100%）、起始缩放（大于 0、不超过 4）、起始纵向偏移（像素，±10000，正值从下方进入）。
  - 起始不透明度 100%、缩放 1、偏移 0 时写明“这样设置看不出效果”。
- **工程默认进入动画**：
  - 一个开关和同样的五个字段，发 `setProjectEnterAnimation`；关掉时发 `null`。提示“已开启工程默认进入动画”“已关闭工程默认进入动画”“已调整工程默认进入动画”。
  - 写明“所有句子默认用它，本句可以单独覆盖”。范围视图（第 4 种情况）里也显示这一节。
- **前奏**：这一句有前奏时写出它的时长，并有“查看”（选中这个前奏）；没有时有“为这一句添加前奏…”（§14.4）。来源不支持前奏时不显示这一项。
- **不可用时**：工程只读、后端没开放时，输入框停用并写明原因。

### 14.8 画布：选中句子与拖动

- **双击句子的文字**（时间预览）：选中这一句，取得句子焦点，时间轴跟着高亮。句子属于别的来源时，分配条换到那个来源。单击仍按第六批的规则选中它所在的容器。布局参考模式里的句子是代表文字，双击不选中句子。
- **叠加层**：有句子焦点、只选了一句、这一句在当前帧可见时，用选中色画它的墨迹，不再画节点的选中框。
- **拖动**：有句子焦点时，在这一句的墨迹上按下拖动，改的是本句偏移，不是容器的位置。

### 14.13 已知限制（第七批）

- **倒计时与标记的外观**：颜色、字体，以及标记的外观覆盖，按整体设计 R2 不放在编排页，改到 W7（§14.6）。
- **前奏轨只画算得出时间的前奏**：目标句没有时间，或起唱前不够一个时长时，前奏轨上没有这一段，列表里写“没有时间”。
- **附着方式切换要测量**：后端按真实文字位置换算，会占用测量名额；目标句测不到时（没有时间、在画面外）被拒绝，并写明原因。
- **句子焦点**：
  - 本句微调一次只对一句；选了几句时只显示范围。
  - 在焦点那一句上单击不改变选择，这样双击时焦点不会先丢掉；要结束句子焦点，点别处的文字，或在结构树里选节点。
  - 布局参考模式里的代表文字不能双击选中句子。
  - 拖动只改偏移；旋转、缩放用属性区。
- **进入动画只看得到单帧**：编排页的预览是播放头时刻的静态帧，要看动画过程，得移动播放头逐帧看。
- **被拒绝的原因也写在状态栏**：对话框里的命令被拒绝时，原因除了写在对话框里，也作为工程提示写在状态栏，直到下一条提示替换它。这是 W2 以来全编辑器的行为。

## 15. 第八批：片段成员调整、拆分与合并

用户 2026-10-26 的决定见文首：第八批接片段成员调整、拆分与合并（合同 1.25.0 起开放，规范 §17.7），做完后第三～八批一起验收。协议类型（`OrchestrationClipMembersCommand`、回执 `clipMembersResult`）在合同同步时已经接好，本批做模型、状态、界面，并补一组集成测试。

### 15.1 后端能力核对（真实 Server 0.104.1，2026-10-26 临时探查）

- **三条命令**都只支持独立计时、逐字动画的来源，真实变化各一条历史，`changeSet` 是 `orchestration`＋`renderInputs`。回执 `clipMembersResult` 给出改动后的片段（拆分时两个）和被合并掉的 `removedClipIds`。
- **调整句子**（`setClipMembers`）：
  - 完整替换成员，可以向两边扩大，也可以缩小到一句；片段的身份、名称、目标容器不变。
  - 和现在相同是 no-op，修订不变。空列表是 400。
  - 不连续 `DiscontiguousRange`；和别的片段重叠 `ClipScheduleConflict`；片段不存在 `TargetStale`。
  - 片段有调度上下文（范围快速布局拆出的“保留”段，或拆分得到的两段）时，每句都必须在原段里，否则 `ScheduleContextConflict`，即使那几句不在任何片段里。手工新建的片段没有调度上下文，没有这条限制。
  - 片段的外观分配带效果配方时 `ReferenceConflict`（后端不允许隐式改变它的成员）。
- **拆分**（`splitClip`）：
  - 拆分点必须是片段里除第一句以外的句子，否则 `InvalidRange`。新片段 ID 由前端给出，重复时 `ClipExists`。
  - 拆分点之前留在原片段（保留身份），从拆分点开始进新片段。新片段的**名称与原片段相同**，目标容器也相同。
  - 原片段没有调度上下文时，拆分后两段的调度上下文都是原来的全部句子，从此只能在这一段里调整；原来有上下文时两段沿用它。所以拆开再合并后，片段多了一个调度上下文，与拆分前不完全一样。
  - 拆开后句子的槽位或显示时钟会变时 `ClipScheduleConflict`；外观分配或效果引用不能完整拆开时 `ReferenceConflict`。
- **合并**（`mergeClips`）：
  - 至少两个片段，`targetClipId` 必须在其中，否则 400。
  - 合并后保留目标片段的身份、名称和目标容器，成员按来源顺序合成。
  - 目标容器不同 `ContainerInvalid`；调度上下文不同 `ScheduleContextConflict`（后端按内容比较：句子、是否默认段、前后边界）；合并后不连续 `DiscontiguousRange`（例如中间隔着不在片段里的句子）；外观分配或效果引用冲突 `ReferenceConflict`。

### 15.2 属性区：片段的“句子”一节

片段属性区的“句子”一节（范围、时间）下面加三个操作：
- “调整句子…”（§15.3）；
- “拆分…”（§15.4），只有一句时不可用，写明“只有一句，不能拆分。”；
- “与前一个片段合并”“与后一个片段合并”（§15.5）。
不能做时按钮停用，原因写在按钮的悬停说明里，也写在这一节下面。

工程只读、后端没开放、来源不支持时，三个操作都不可用，写明原因（与片段编辑相同）。

### 15.3 调整句子

对话框“调整片段的句子”：
- 范围：“从第 [a] 句到第 [b] 句”，预填片段现在的范围，下面写句数、时间、首尾句文字，与新建片段相同。
- 片段有调度上下文时写明：“这个片段保持原段（第 x～y 句）的槽位和显示时钟，句子只能在这一段里调整。”
- **提交前的检查**（按顺序，第一条不满足就写出来，按钮不可用）：
  1. 范围无效；
  2. 和现在相同：“和现在的句子相同。”；
  3. 第 N 句没有时间；
  4. 第 N 句已在片段“X”里：“先把那个片段缩小或删除。”（不算自己）；
  5. 第 N 句不在原段里（有调度上下文时，与后端相同，每句都要在原段里）；
  6. 第 N 句（片段外）的时间夹在这几句中间。
- 确认按钮“调整”。成功后关闭对话框，提示“片段‘X’改为第 a～b 句”，可撤销；被拒绝时原因写在对话框里（§15.6）。

### 15.4 拆分

对话框“拆分片段”：
- “从哪一句开始拆出”：下拉框，选项是片段里除第一句以外的句子（“第 k 句 · 文字”）。预填播放头所在的句子（它在片段里、不是第一句时），否则预填中间那句。
- 下面写明结果：“第 a～k−1 句留在‘X’，第 k～b 句成为新片段（名称相同，目标容器相同）。拆开后两段都保持原段的槽位和显示时钟，句子只能在第 a～b 句里调整。”
- 确认按钮“拆分”：
  - 发 `splitClip`，新片段 ID 是 `clip/` 加随机 UUID；
  - 成功后关闭对话框，读到新修订后选中新片段，提示“已把片段‘X’拆成第 a～k−1 句和第 k～b 句”，可撤销；
  - 被拒绝时原因写在对话框里。

### 15.5 合并

“与前一个片段合并”“与后一个片段合并”：前一个片段是最后一句紧挨着这个片段第一句的片段，后一个同理。合并时保留**当前选中的片段**的身份、名称和目标容器（`targetClipId` 是它），一次合并两个片段；要合并更多，重复操作。

不能合并时写明原因：
- 紧挨着的句子不在片段里：“前面紧挨着的第 N 句不在片段里。”；在来源开头或末尾时写“前面没有句子。”“后面没有句子。”
- 目标容器不同：“前一个片段‘Y’在‘容器 B’里，与这个片段的目标容器不同；先把它们改到同一个容器。”
- 调度上下文不同：“两个片段来自不同的原段（调度上下文不同），不能合并。”

不用确认框：成功后提示“已把片段‘Y’合并进‘X’（第 a～b 句）”，可撤销，选中的仍是 X。失败写在状态栏。

### 15.6 失败原因

在片段命令的对照表（§11.6）上补充：

| failureCode | 显示 |
|---|---|
| `ScheduleContextConflict` | 调整句子时：“新加的句子不在这个片段的原段里：这个片段保持原段的槽位和显示时钟，只能在原段里调整。”合并时：“两个片段来自不同的原段（调度上下文不同），不能合并。” |
| `ReferenceConflict` | 调整句子时：“这个片段的外观分配带有效果配方，不能跟着改变句子：先移除这个片段的外观分配再调整。”拆分时：“这个片段的外观分配或效果引用不能完整拆开：先移除这个片段的外观分配再拆分。”合并时：“两个片段的外观分配或效果引用不同，不能合并：先让它们一致，或删掉其中一个的分配。” |
| `InvalidRange` | 拆分时：“拆分点必须是这个片段里除第一句以外的句子。”其余沿用 §11.6 |
| `ClipScheduleConflict` | 拆分时：“拆开会改变这几句的槽位或显示时钟，不能拆分。”其余沿用 §11.6 |
| `ContainerInvalid` | 合并时：“合并的片段必须在同一个目标容器里。”其余沿用 §11.6 |
| `DiscontiguousRange` | 合并时：“合并后的句子必须按来源顺序连续：两个片段之间不能隔着别的句子。”其余沿用 §11.6 |

2. 拆分：从第 3 句拆开，一条历史，变成第 2 句和第 3～4 句两个片段，名称相同，选中新片段；两段的调度上下文都是原段第 2～4 句。
3. 调度上下文：拆分后的片段想扩到第 1 句时，对话框写明“不在原段里”，按钮不可用。
4. 合并：选中第 3～4 句的片段，与前一个合并，一条历史，回到一个第 2～4 句的片段，身份是选中的那个；与没有调度上下文的片段相邻时不能合并，写明原因。
5. 撤销回到开始时的修订；`typecheck`、单元、集成、四个浏览器冒烟都通过。

### 15.11 已知限制（第八批）

- **一次合并两个**：后端一次可以合并多个片段，界面每次只合并相邻的两个，要合并更多就重复操作。拆分也只拆成两段。
- **外观分配的冲突要等后端判断**：片段的外观分配带效果配方，或两个片段的分配不同时，后端拒绝（`ReferenceConflict`）。前端不读外观分配，按钮仍可用，被拒绝后原因写在对话框或状态栏。
- **拆开再合并不能回到“没有调度上下文”**：后端拆分时给两段都记下原段，合并后保留，片段从此只能在原段里调整。要回到拆分前，只能撤销。
- **拆分后两段同名**：列表靠范围区分；两段都没改名时，合并的提示写成“已把片段‘副歌’合并进‘副歌’”。
- **检查的顺序与后端不同**：新加的句子既在别的片段里、又不在原段里时，前端按 §15.3 的顺序先写“已在片段里”，后端先报 `ScheduleContextConflict`。两边都不允许，只是原因不同。
- **只能按句号调整**：调整句子用起止句号输入，不能在片段轨上拖动片段的边缘。
