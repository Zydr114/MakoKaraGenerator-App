# CPU / Vulkan 短批次单帧性能基线（2026-10-27）

> **状态：本机固定样本短批次基线完成。** 六类负载的 CPU/GPU 总耗时、创建/首帧、阶段耗时和短序列跳转均已留档。生产源码未改动。GPU 在图、材质、组合样本上约快 2.59、2.31、1.99 倍；普通歌词、轻量脚本和粒子样本的 CPU 中位数更低。阶段数据显示中间图像读回与材质捕获是优先调查方向。

## 1. 目标与来源

本轮建立固定歌词及效果样本的直接 Runtime 单帧性能基线，并用独立插桩副本观察执行阶段；不实施性能优化。生产源码基线为 `8681bc0`，产品版本 0.106.0，API 合同版本 1.39.0；工具提交为 `3d87528`。合同版本用于标识源码背景，不表示本次运行验证了 HTTP 合同。

正式证据工作目录为 `artifacts/render-performance-20261027-final1/`。已提交 [机器可读基线](../../performance/20261027/baseline.json)、[逐帧 CSV](../../performance/20261027/frames.csv)、[阶段 CSV](../../performance/20261027/stages.csv)、[原始证据归档](../../performance/20261027/evidence.tar.gz)及[逐文件清单](../../performance/20261027/evidence-index.json)。归档包含 407 个文件，大小 1,664,659 字节，SHA-256 为 `85195e833bf04e5d44a33af1f7abb85cca103fab8e44336adb973d1cb92c3bbb`。完整源码副本、构建产物、编译缓存和代表 PNG 留在本机证据目录；归档保留逐帧原始 JSON、完整规范化诊断、trace 聚合、构建日志、环境和全部输入/产物指纹。

## 3. 采样方法

使用生产 `ProjectRenderSessionFactory`、固定样例包和确定性的逐字歌词；CPU 与 Vulkan 分别运行。基线源码和阶段插桩源码来自两份隔离副本；原版 wall 时间与插桩阶段时间分开报告。每个进程一个项目会话，项目帧上限 48，设备 probe 另计 1 个 4×2 帧。各组按短批次、独立进程执行：

| 数据组 | 场景及轮次 | 每进程项目帧 | 目的 |
| --- | --- | --- | --- |
| main | `lyrics`、`csharp`、`graph`、`particle`，各 5 轮 | 8 预热 + 24 测量 | 固定顺序窗口的基础 wall 基线 |
| heavy | `material`、`combined`，各 5 轮 | 4 预热 + 8 测量 | 材质和组合负载的较短批次 |
| seek | `csharp`、`particle`，各 3 轮 | 8 次固定请求 | 首次跳转、回退与网格／非网格重复 |
| controls | 单效果移除全部效果；组合场景分别移除四类效果 | 每进程 3 帧 | 对照固定时间下实际像素贡献 |

顺序模式从歌曲时间 1 秒开始，以 30fps 网格向前；首帧可能触发从零开始的 120Hz 时间轴重放。main 的计量窗口为 1.266666～2.033333 秒，heavy 为 1.133333～1.366666 秒。两组预热数量与时间窗口不同，跨场景不能视为同一帧集的消融比较；同场景 CPU/GPU 和原版/插桩版使用完全相同时间戳。seek 的请求序列亦不同于顺序模式，不能混入顺序稳态统计。controls 只作为效果贡献对照，不并入主性能统计。

固定工程为四行中文、逐字定时，使用 `Noto Sans CJK SC`；`WordEmphasis`、`LineGlitch`、`CustomInk` 和 `CursorTrail` 分别代表 C#、图、材质和粒子路径，组合场景同时启用。样例清单、包修订、字体匹配、目标及参数均保存于正式证据。共 170 个独立进程、3310 个项目帧和 170 个设备 probe 帧；每进程最多 32 个项目帧加 1 个 probe，最慢进程 65.648 秒。全部渲染串行执行，未运行 100 帧以上的单次渲染。controls 为 26 个进程、78 个项目帧，单独统计。

## 4. 测量口径

- 固定样本构造、包文件读取和 ProjectSnapshot 构建发生在会话计时前。会话创建计时从 CreateAsync 开始；原版 RenderAsync wall 时间包含准备帧、Skia 绘制与 BGRA 读回。会话创建和释放分别记录。
- 每个进程使用独立且初始为空的脚本编译缓存目录；会话创建包括首次脚本编译，与复用持久编译缓存不同。首帧和会话创建包含该进程正常 JIT 与资源首次访问；未清空操作系统或驱动全局缓存，不能称为驱动冷启动。
- BGRA 哈希、诊断读取与哈希、`RenderFrame.Dispose` 和代表帧 PNG 编码不在帧 wall 计时内。它们发生在批次中，仍可能影响后续请求的缓存和调度。
- managed 分配量与 GC 差值是进程级采样，可能包含其他进程内工作；不包含完整 native 或 GPU 内存分配。
- 阶段数值仅来自插桩副本。串行路径的 mean exclusive 时间在同一覆盖范围内可加；inclusive 阶段有嵌套，不能直接相加。
- Vulkan 阶段中观察到的提交、读回和宿主等待是 CPU 侧 wall 时间，不是 GPU timestamp。`device.imageReadback` 包括 Flush、同步 Submit、转为 raster、像素读取及临时对象释放，可能等待前序 GPU 工作；不能把全部时间当成纯拷贝或可直接消除的成本。CPU `graph.draw` 与 GPU 入队阶段也没有相同的 GPU 完成边界，不据它们的比值推算绘制加速比。
- `geometry.scene` 统计 GetSceneFrame；`text.shape` 只统计真实整形调用，正常布局缓存命中不会产生该 span，也不代表所有文字布局成本。
- `CustomInk` 样例使用 unmasked coverage；本轮不验证 masked region 性能。
- 诊断摘要覆盖 Runtime、图和材质诊断；随机 epoch GUID 按首次出现顺序归一化。像素及诊断哈希用于同输入对照，不代替容差分析或功能验收。

## 7. 下一步优化候选（本轮不实施）

后续源码与官方资料调研已单独记录在 [GPU 性能优化调研](backend-gpu-performance-optimization-research-20261027.md)：解释材质每帧 166 次读回的来源，按验证去重、空部件、同帧作者图共享、GPU 像素检查及受限 ROI 排序，并评估 500 ms/帧目标。该调研没有新增渲染或生产优化，不改写本报告的测量数据。

1. 优先检查源材质逐对象捕获的全画布范围与重复中间表面。工厂将画布边界交给材质程序，场景按程序边界创建对象状态；目标是研究严格像素对齐的最小必要范围、不可变产物复用及资源生命周期，必须保留图扩展、变换、反走样、采样边缘、背景输入和预算语义。源码：[工厂](../../../src/MakoKaraGenerator.Runtime.Hosting/ProjectRenderSessionFactory.cs)、[对象场景](../../../src/MakoKaraGenerator.Rendering.Skia/SkiaRenderPipeline.ImageScene.cs)、[材质捕获](../../../src/MakoKaraGenerator.Rendering.Skia/SkiaRenderPipeline.MaterialCapture.cs)。
2. 检查同一不可变图像的重复读回和预乘验证，以及空透明颜色部件的完整读回检测。优化需要保留实际像素合法性、错误归属、设备与色彩空间身份、取消及内存预算，不能直接取消验证。GPU 计时包含前序执行，实际可节省量必须在修改后用同输入再次测量。源码：[图绘制与验证](../../../src/MakoKaraGenerator.Rendering.Skia/Effects/CompiledImageGraph.Drawing.cs)、[图输入验证](../../../src/MakoKaraGenerator.Rendering.Skia/Effects/CompiledImageGraph.cs)。
3. 对轻量脚本和粒子，后续分别评估重复几何准备、出生查询、状态复制及安全检查点。任意脚本的事件、随机数、状态和粒子历史不能因性能目的被跳过；不能将现有状态会话简单改称纯函数 RenderAt(t)。源码：[时间线](../../../src/MakoKaraGenerator.Scripting/Execution/FrameSession.cs)、[粒子出生几何](../../../src/MakoKaraGenerator.Scripting/Execution/FrameEffectHost.Particles.cs)。

以上是由阶段证据和源码提出的调查方向，没有生产变更，也没有已实现收益承诺。每一项后续优化都应先保持原版像素及诊断语义，再比较同设备、同时间窗口的独立短批次。

## 8. 范围和未覆盖项

本轮为本机固定样本的直接 Runtime 短批次采样，不经过 HTTP、Worker 通信、FFmpeg 视频编码或浏览器；PNG 仅为计时外证据。它不验证完整项目、长片、跨平台、用户交互、GPU 视频编码、性能稳定性或 GPU timestamp。进程和设备 probe 证据只覆盖实际观察的进程及设备创建，不能扩展为所有运行环境的保证。

工具、基线数据和本报告分步提交至 main；不提升产品版本，不改变 API 合同，也未部署新产品。工具复现入口见 [README](../../../tools/backend-render-performance/README.md)，采样方案及重负载缩短依据见 [计划](../plans/backend-render-performance-baseline-plan-20261027.md)。
