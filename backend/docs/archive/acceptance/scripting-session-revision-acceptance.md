# R5 撤销、修订热替换与取消导出组合验收（0.26.3）

> 2026-10-05；接续后续计划第 3 批。完成证据以 roadmap §18.89 为准。本计划 R5 会话自动出口依据本表及 0.26.0～0.26.2 的证据收口；完整 SDK、R3.1、R6～R8 和最终工作区仍未交付。

## 1. 接受与撤销

工作区参数和源码先保存在草稿；源码保存生成不可变包修订，独立编译不升级任何引用。显式接受只替换选中实例的 revision，保持 ID、入口、参数、绑定、订阅、seed、启用状态及顺序，其他实例继续使用旧修订。保存工程效果通过现有 SetProjectEffectsCommand 原子提交完整包与实例，各次提交独立撤销，不合并参数和源码两步。

回归使用保存重开的 WordEmphasis／RepeatEmphasis／真实音频工程，额外保留一个使用原 Repeat 修订、独立目标和 seed 的实例。参数 scaleStep 从默认 .08 改为 .2，第三次 Repeat 从 1.16 变为 1.4；新源码显式将缩放乘以 1.5，选中实例变为 2.1。新源码只是测试中的作者修订，产品示例源码保持不变。修改草稿不会改原工程，保存修订或编译成功不自动升级引用。

普通／透明两组均逐次验证原始、参数、新源码、两次撤销、两次重做共七个状态：历史返回同一工程对象，每个状态保存重开并与真实预览及独立 Export 会话全部像素相等，起唱及音频计数不累积。未升级实例的第二句像素保持旧行为。参数不产生新 DLL；源码生成独立的第四个 Artifact，旧代次保持。旧像素会话拒绝使用新快照。

## 2. 热替换与释放

每个新快照在同一 PreviewFrameCoordinator 中建立独立正式会话，原会话先释放。七个状态建立七次并各释放一次；参数与源码切换时，通过精确 Artifact 对应的可回收加载上下文弱引用验证四个旧实例全部回收，包括音频实例和共享同一 Repeat DLL 的两个实例。关闭后当前四个上下文也回收，不以 Dispose 计数代替卸载证据。

测试观测使用既有工作区 API、正式会话工厂、AssemblyLoadContext 弱引用及受控编码器装饰器；没有增加生产测试接口、重写状态回放、跳过校验或改变作者运行语义。资源修订／Artifact 身份继续分别固定。

## 3. 取消导出与恢复

真实工程同时持有双文字、48 kHz／20 ms 音频和正式 Runtime Shader 整行图。通过正式图片、shader、图和材质门禁后，普通 MP4／ProRes4444 各在第 39 个已接收帧（1,266,666 μs，64 个音频 hop）取消；受控信号只在编码器已接管帧后发出，没有延时竞争或模拟编码。

两组都保持 OperationCanceledException；完成发布未调用，旧目标字节不变，真实临时编码文件删除，39 个帧缓冲全部释放，像素及编码会话各释放一次，四个作者上下文回收。取消前最后一帧的完整像素与重新建立的独立会话一致。使用同一固定工程／工厂和新 token 再次实际编码得到 54 帧、0 失败帧、完整音轨及可验证产物，全部上下文再次回收。

原生表面／图片／预算的取消及失败释放仍由既有 R3 Core 表面账、图执行与资源回归共同覆盖，本批实际运行整行图并消费正式资源释放路径；不把弱引用观测宣称为 native 内存性能基准。
