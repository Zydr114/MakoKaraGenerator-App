# 样式工作区交互重设计（提案）

> **历史实施文档**：本文件描述当前 0.1.0 系列的样式选择与应用流程。下一版以 [ADR-0050](../decisions/decisions.md#adr-0050模板工坊歌词行编辑器与程序版本边界) 为准，模板工坊只设计模板，歌词行编辑器选择并应用；旧样式库和旧应用入口不迁移。

> 2026-09-26；状态：**第一轮已实施**。本提案针对右侧「样式设计」和左侧歌词栏「样式选择」两套入口；
> 当前实现已合并入口、增加直接应用与批量目标选择；独立窗口最小尺寸、键盘和窗口管理器交互已完成人工验收，新增参数交互仍按路线图等待后续真机验收。
> 当前行为与已批准的数据契约仍以 [ADR-0044](../decisions/decisions.md#adr-0044样式设计面板与批量应用含可选颜色三态) 为准；本提案经用户确认后，先补 ADR，再改界面。

## 要解决的任务

用户实际要完成的动作只有四类：挑一份现成样式、调整视觉效果、把效果应用到明确的对象、管理自己保存的样式。
现在这些动作穿过两个面板，且「保存」被迫充当「应用到行／元素」的中转站：右侧草稿只能写工程基线，左侧只能套用已保存样式。
另外，下拉列表把内置预设和个人样式混在一起；个人样式保存的是**部分属性**，内置预设是**全套静态属性**，但选择时看不见这一差别。
元素目标不支持的属性目前在执行后才说明「已跳过」，用户在按下按钮前无法准确预测结果。

本设计要让用户在提交前能回答三个问题：**拿哪份效果、改哪些属性、写到哪里**。
「保存为我的样式」是整理素材，「应用」是修改工程，两者不能互相代替。

## 四种对象与权限

| 对象 | 来源与寿命 | 可以做什么 | 应用后的关系 |
|---|---|---|---|
| **内置样式** | 随应用提供；有稳定 ID；只读 | 预览、应用、复制到草稿再编辑 | 将数值写进工程；后续内置样式变化不会改动既有工程 |
| **我的样式** | 应用级 `styles.json`；跨工程；保存名称、完整静态值及要应用的属性清单 | 预览、应用、复制到草稿、明确更新／另存、重命名、删除 | 同样按值写进工程；修改或删除库项不追改已有工程 |
| **设计草稿** | 当前编辑会话；可从内置、我的、工程默认、当前行／元素或空白稿建立 | 改参数、试样、选择应用属性、直接应用、保存为我的样式 | 编辑本身不修改工程；应用后草稿继续保留 |
| **工程生效样式** | 工程基线 + 行覆盖 + 元素覆盖逐属性解析 | 查看来源、在明确层级应用或恢复继承 | 保存进工程、可撤销；局部覆盖仍优先于上层 |

**命名约束**：界面中「内置」「我的」「草稿」「工程默认」必须始终使用同一称呼。
旧 `Project.LyricStylePresetId` 只代表既有来源记录，不得在界面上暗示它是会随库变化的链接。
首轮沿用现有按值应用语义，不改 `project.json` / `lyrics.json` / `styles.json` 格式；若以后要做「更新库项后同步所有已应用对象」，那是另一个需要独立批准的数据模型需求。

## 推荐布局：一个样式工作区，一个提交区

左侧歌词栏仍负责选中行／元素和打轴；移除其中重复的「样式选择」页签，保留一条可见的当前对象样式摘要与「打开样式」入口。
右侧把「样式设计」改为**样式工作区**，内部分成「样式库」与「草稿编辑」两视图。动画保持独立页签，属性页继续只读显示实际生效值与来源。
样式工作区底部固定一块共用的**应用区**，它显示当前来源、目标、将写入的属性、不可用原因与执行结果；无需跨面板寻找第二个应用按钮。

```text
歌词栏                         画布                       右侧：样式工作区
选中：第 3 行「晚风」          已提交的工程结果           [样式库] [草稿编辑]
当前：字号来自本行／颜色来自工程                         ┌ 内置 │ 我的 ┐
[打开样式]                                              │ 样式预览卡片  │
                                                        │ 属性：颜色…  │
                                                        │ [编辑副本]   │
                                                        └───────────────┘
                                                        来源：内置 · 渐变高亮
                                                        目标：[工程默认／当前行／当前元素]
                                                        内容：未唱色、已唱色…（6 项）
                                                        提示：本行的元素覆盖仍优先
                                                        [应用到第 3 行]   结果／撤销入口
```

在 1600×1000 逻辑像素下，右栏建议 340–380 像素，预览与字段组滚动，应用区固定；在 940×640 最小窗口下，目标与主按钮纵向排列，试样可折叠，但应用摘要、错误和主按钮不能离开视野。
不引入浮动停靠或新的大型模态编辑器。

## 选择、编辑与保存

1. **挑现成样式**：样式库明确分为「内置」与「我的」，每项显示名称、简短试样、属性范围（如「全部静态属性」或「仅颜色 4 项」）。只点选卡片会更新试样和应用区，**不会替换未保存的草稿，也不会写工程**。
2. **编辑内置样式**：操作叫「基于此编辑」，把值复制到草稿；内置项始终只读。草稿顶部显示「基于内置 · 名称」，保存按钮只有「保存到我的样式…」。
3. **编辑我的样式**：操作叫「编辑副本」，草稿顶部显示「基于我的 · 名称」。参数变化只改草稿；「更新这份样式」与「另存为…」是分开的保存动作。覆盖原样式要明确点按钮；保存成功后才更新库列表。仅编辑／保存库项不会改工程。
4. **从工程取样**：在草稿视图提供「读取工程默认／当前行／当前元素」。先显示来源与作用对象；若草稿有未保存修改，替换前提示。读取生效值默认不勾选应用属性，避免无意把继承值全部固化。
5. **草稿试样**：保持现有独立渲染；标题写「草稿预览」，主画布标题写「工程预览」。改字段时即时更新试样，数值框回车／失焦提交；非法值保留输入并在字段旁报错，同时禁用应用与保存。

「保存到我的样式」还应在保存对话框里回显本次保存的属性范围；用户样式的意义是**值 + 应用属性集合**，只改名字不足以说明它将来会覆盖哪些东西。
名称冲突时保留现有确认行为，删除个人样式继续二次确认；内置项不显示编辑、重命名或删除动作。

## 应用：提交前先交代影响

应用区采用相同的步骤，无论候选来自库还是草稿：

1. **目标**：默认跟随歌词栏当前选择；明确写成「工程默认」「第 3 行」「第 3 行第 2 字」。用户可在提交前改目标，但改目标不改草稿／库选择、不移动播放头。没有选中行或元素时对应目标不可选，并给出原因。
2. **内容**：内置项默认携带全部静态属性；「我的样式」使用保存时的属性集合；草稿使用当前勾选集合。应用区列出属性名和数量，并标明「只替换这些属性，其余保持原样」。当选择「全部静态属性」时加一句「这些属性将在目标层固定，之后不再继承上层变化」。
3. **能力检查**：元素不支持字体、字号、对齐、位置、缩放等属性时，先列出不可用项并禁用原提交按钮；提供明确的「只应用元素支持的属性」操作，点击后更新摘要，再允许应用。若可用项为零，提示用户改用行目标。绝不在点击提交后悄悄跳过属性。
4. **层级提示**：工程默认的应用提示「现有行／元素覆盖仍优先」；行目标提示「本行已有元素覆盖仍优先」；元素目标提示它会覆盖本行／工程对应属性。来源列表仍可在属性页查看。
5. **提交**：按钮文字包含目标，如「应用到第 3 行」。一次提交是一条撤销记录；成功后留在当前样式和目标，反馈「已应用 6 项到第 3 行」，并提供现有工程撤销入口。无实际变化反馈「样式已一致」，不增加历史。

「恢复继承」放在**当前对象实际样式**区域，文案为「本行恢复工程默认」／「本元素恢复上层样式」；它清理覆盖，与从库应用不是同一个动作。
范围是整份覆盖还是所选属性，按钮和摘要必须逐字对应，不能用泛泛的「清除样式」。
批量目标可沿用现有 `StyleBatchEditor` 与目标清单，但入口留在应用区的「选择多行／多元素…」高级操作；普通单目标路径无需先进入批量模式。

## 四条验收任务

1. 选中一个字 → 选「我的」颜色样式 → 看清将改哪些颜色 → 应用；不会改字体，也不会经过保存草稿。
2. 选内置渐变 → 在草稿改一端颜色 → **不保存到库**也能应用到当前行；工程只在点「应用」时变化，撤销一步恢复。
3. 编辑一份「我的样式」并点「更新这份样式」→ 原先已套用的行外观不变；再点「应用到当前行」才改变该行。
4. 选全属性内置样式、目标选元素 → 应用区在提交前列出不支持的排版项；用户可显式改为只应用可用项，或改选行目标。

全量验证还要覆盖深浅主题、940×640、键盘焦点、草稿未保存切换、样式库写盘失败、撤销／重做与重新打开工程。旧即时写入路径按现有决定保留为回退实现，不因本次界面重排顺手删除。

## 依据与待确认边界

这是基于本项目操作路径作出的设计推论，不是外部产品的功能照搬：[Nielsen Norman Group 的可见状态、错误预防与减少记忆负担原则](https://www.nngroup.com/articles/ten-usability-heuristics/)支持把来源、目标、影响显示在提交区；[Microsoft 的选择模式指导](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/selection-modes)支持把批量命令与选择结果邻接，并在没有目标时禁用；[Figma 样式指南](https://help.figma.com/hc/en-us/articles/360038746534-Create-color-text-effect-and-layout-guide-styles)把样式定义为可复用的一组属性，而非仅一个名字；[Adobe InDesign 的样式库用法](https://helpx.adobe.com/indesign/desktop/format-and-style-text/text-styles/add-and-manage-text-styles-from-cc-libraries.html)把「保存到库」和「应用到对象」作为不同命令。

已确认并实施的边界：左侧「样式选择」已合并进右侧统一样式工作区；左侧只保留当前对象摘要和「打开样式」快捷入口。
第一轮实现了内置／我的双列表、草稿直接应用到工程／行／元素、个人样式更新与按行分组的批量目标选择；剩余工作是小窗口与真机键盘验收，以及后续把恢复继承进一步收进统一应用区。
