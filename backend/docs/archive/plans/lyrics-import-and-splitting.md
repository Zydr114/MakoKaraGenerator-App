# 歌词格式导入与 Token 切分方案（提案）

> **状态：部分实施（引擎侧、导入设置对话框与模态切分对话框已落地；真机验收与细节修正待做，见 ADR-0046）。** 裁决结论见 §8。
> **当前接续（0.43.9）**：普通TXT的`text.plain`保留缺失时间；新建工程必选主歌词和音频，追加歌词必须明确分支，见§9／ADR-0161。下文早期提案保留为历史来源。
> **日期**：2026-09-26
> **依据**：`development.md` §5.2/§5.4（文本元素、时间状态）、§7（导入与导出）、§8.5/§8.6（逐字打轴、字号样式）、
> §19（设计底线）、`timeline-ui.md` §4/§7、`roadmap.md` §18。
> **相关 ADR**：ADR-0020（歌词导入/导出的接口形状与"未定时元素"语义）、ADR-0022（时间语义唯一来源）。

## 0. 一句话

**"按扩展名自动识别"的骨架已经在跑**（`ILyricsImporter.CanImport(fileName, header)` + `LyricsImporterRegistry`），
但只注册了 **普通 LRC** 与 **增强 LRC** 两个导入器，且识别结果对用户不可见；
切分目前只有"选中芯片按 `S`"这一条窄路，一次只能拆一个元素、看不到时长与来源。
本提案补齐三件事：**更多格式**、**识别可见可覆盖**、**一套可解释的切分编辑器**。

## 1. 现状盘点（**已在的能力，不要重做**）

| 能力 | 位置 | 说明 |
|---|---|---|
| 导入器抽象 | `Core/Lyrics/Import/ILyricsImporter` | `Id`/`DisplayName`/`CanImport(fileName, header)`/`Import(stream, context)`；**扩展名 + 文件头嗅探已经是接口的一部分** |
| 注册表与优先级 | `LyricsImporterRegistry.CreateDefault()` | 顺序即优先级（注释已写明：**增强 LRC 必须先于普通 LRC**，因为扩展名相同）；`Find(fileName, header)` 返回首个匹配项 |
| 已实现的格式 | `EnhancedLrcImporter`、`PlainLrcImporter` | 普通 LRC（仅行级）与增强 LRC（含 `<mm:ss.xx>` 逐字）**都已支持** |
| 导入上下文 | `LyricsImportContext` | `FileName`、`MediaDurationUs`、`FallbackLineDurationUs`、`Language`——"要猜的值必须显式传入并进报告" |
| 编码处理 | `LyricsTextDecoder` | **BOM → 严格 UTF-8 → GB18030 → Latin-1 近似**；`IsFallbackDecoding` 如实汇报 ⇒ 中文 GBK 歌词已有兜底 |
| 导入报告 | `LyricsImportResult` + `LyricsImportReportFormatter` + `ImportReportText` | 已接入界面（检查器里的报告区） |
| 文本改动时的重建 | `LyricTextResplitter.Resplit` | 按文本对齐重建元素：未改动的公共前缀/后缀**保留原标识、时间与状态**；改动区间变"未定时" |
| 拆分/合并 | `EditorViewModel.SplitSelectedToken` / `MergeSelectedToken` | 按 Unicode 文本元素（grapheme）切，不按 UTF-16 char；拆分时把父区间**按元素数比例切开**，两半标 `TimingStatus.Edited` |
| 时间状态模型 | `TimingStatus` | `Missing / Imported / Estimated / Edited / Confirmed / Invalid`（其中 `Imported`、`Estimated` **都算"未确认"**） |
| 界面入口 | 工具条「导入歌词」 | 过滤 `*.lrc`、`*.elrc`、`*.txt`；导入后报告写进检查器 |

**结论**：§2 的格式扩展是"往注册表里加导入器"，§5 的切分是"给已有能力配一套界面 + 一条批量规则通路"。

## 2. 格式调研结论

### 2.1 行级（只有"这一行什么时候唱"）

| 格式 | 扩展名 | 时间写法 | 备注 |
|---|---|---|---|
| **LRC（简单）** | `.lrc` | `[mm:ss.xx]文本`（`xx` = 厘秒） | 事实标准；有 `[ti:]`/`[ar:]`/`[offset:]` 等 ID 标签（**非标准化**，各家不一）；同一行可挂多个时间戳表示重复 |
| **SRT** | `.srt` | `hh:mm:ss,mmm`，块式（序号 + 时间行 + 文本） | 剪映、YouTube 等都能导出；用户从字幕起步的主要入口 |
| **WebVTT** | `.vtt` | `hh:mm:ss.mmm` | SRT 的现代版；部分工具用 `<00:00.000>` 与 `<c>`/`<v>` 标记表达**逐字或说话人**（非标准、实现各异） |

### 2.2 逐字（有"每个字/词什么时候唱"）

| 格式 | 扩展名 | 逐字写法 | 特点与坑 |
|---|---|---|---|
| **增强 LRC（A2）** | `.lrc` / `.elrc` | 行首 `[mm:ss.xx]` + 行内 `<mm:ss.xx>` | 纯文本、人可读写、生态最广；**与普通 LRC 扩展名相同 ⇒ 必须看内容才能分辨**；结尾常出现"空时间戳"表示清屏 |
| SPL（Salt Player）/ XLRC | `.lrc` / `.spl` | 兼容增强 LRC + 翻译/罗马音/逐字 | 是增强 LRC 的**超集**，可先用"未知标签当注释并进报告"的容错方式读 |
| **ASS / SSA** | `.ass` / `.ssa` | `{\k<厘秒>}`、`\K`、`\kf`、`\ko`、`\kt` | 卡拉 OK 视频制作圈的标准；行的其余样式标签（`\pos` 等）与时间无关，可忽略但**要进报告** |
| **UltraStar** | `.txt` | 音符行 `: 起始拍 时长 音高 文本`，`-` 表示换行 | 时间单位是**拍**，需要 `#BPM`/`#GAP` 才能换成秒；自带音高（本项目不用，属**丢弃项**） |
| **TTML（Apple Music / AMLL）** | `.ttml` / `.xml` | `<span begin="…" end="…">字</span>`，头部 `itunes:timing="Word"` | 生态最活跃、表达能力最强；还有 `x-bg`（和声）、翻译/音译轨、`ttm:agent`（多歌手）——**首期只取主轨** |
| YRC / QRC / KRC | `.yrc` / `.qrc` / `.krc` | 两个家族：`[行起,行时长]音节(起,时长)文本…` 与 `[行起,行时长]音节<起,时长>文本…` | 网易云 / QQ 音乐 / 酷狗的私有格式；**QRC 与 KRC 加密**，且各带自己的元数据与压缩层 ⇒ 见 §7 |

### 2.3 明确不做的

TRC（天天动听）、KSC（KBuilder）、KAJ（Sayatoo 工程文件）等阶段性格式；图片歌词（需 OCR，非本项目目标）；
MIDI / UST / Vocaloid 工程（音高与咬字语义不同，超出"逐字时间"的范围）。

### 2.4 三条共性结论（**决定了实现方式**）

| 结论 | 对实现的影响 |
|---|---|
| 逐字信息只有两大族：**行内标记**（增强 LRC / ASS / TTML）与**音节列表**（YRC / QRC / KRC / UltraStar） | 中间表示只做一次（"行 + 音节序列 + 时间"），映射路径分两条 |
| 时间基各不相同：厘秒（LRC/ASS）、毫秒（SRT/VTT/TTML/YRC…）、拍（UltraStar） | 一律在 **Core 边界换成整数微秒**（`long`）；换算只在导入器里发生 |
| 多轨信息普遍存在（翻译、罗马音、和声、音高、多歌手） | 首期**只保主轨**，但必须把"丢弃了什么"写进导入报告（§19 不许静默丢数据） |

## 3. 识别策略：扩展名 → 候选 → 嗅探 → 打分

### 3.1 三层判定

1. **扩展名 → 候选集合**（新增 `LyricsFormatCatalog`，一份表，界面与 Core 共用）
2. **文件头/内容嗅探**（`CanImport` 已有此能力）：BOM 与编码、`[ti:`/`[ar:`、`<?xml`、`[Script Info]`、
   `#BPM`/`#GAP`、`[数字,数字]` 行头、`<mm:ss.xx>` 是否存在……
3. **打分与裁决**：特异度高的获胜（逐字 > 行级；带结构标记 > 纯文本）；
   **同分时选"信息损失更小"的那个**，并把裁决理由写进报告。

### 3.2 扩展名对照表（拟）

| 扩展名 | 候选（按优先级） |
|---|---|
| `.lrc` | 增强 LRC → SPL/XLRC（容错）→ 普通 LRC |
| `.elrc` | 增强 LRC |
| `.srt` / `.vtt` | SRT / WebVTT（含 `<00:00.000>` 逐字扩展时按逐字读，否则行级） |
| `.ass` / `.ssa` | ASS（`\k` 家族） |
| `.ttml` / `.xml` | TTML（AMLL/Apple） |
| `.txt` | UltraStar（有 `#BPM` 头）→ 普通 LRC（容错） |
| `.yrc` / `.qrc` / `.krc` | **待裁决**（§8 第 1 项） |

### 3.3 契约（与项目既有底线一致）

- **不许静默降级**：把逐字格式当行级读、或把未知标签当可见文本，都必须**在报告里说明**；
- 识别失败 → 报错并列出支持的格式（现状 `NotSupportedException`），**不猜**；
- 识别结果**对用户可见**，且**允许改选**（见 §6 批次 3）。

## 5. Token 切分：从"按 S"到"可解释的切分编辑器"

### 5.1 现状与问题

| 现状 | 问题 |
|---|---|
| 选中芯片 + `S` 拆分 / `M` 合并 | 一次一个元素；拆分点是"中间"，想切在别处只能先切再拖 |
| 芯片只显示文本，时间在 `ToolTip` 里 | 看不出每个字的时长，也看不出这个时间"是导入的还是估的" |
| 拆分把父区间按元素数**比例切开**，两半标 `TimingStatus.Edited` | **语义瑕疵**：`Estimated` 的定义正是"按字符权重分配"，标成"用户修改过"会让"估算 vs 已确认"的区分失效（§5.4 要求"仅导入/估算都算未确认"） |
| 没有"整行按规则切分" | 普通 LRC 导入后（只有行级时间）没法一键变成逐字，只能一个字一个字点 |
| `LyricTextResplitter` 只在**改文本**时触发 | 改文本能保留旧时间（很好），但没有"只改切分不改文本"的对应通路 |

### 5.2 设计原则（三条）

1. **切分与打点正交**：切分只动"边界与文本"，不动任何**已确认**的时间；改时间仍只有"拖/输入"那几条路。
2. **一切推导值必须可见、可回退**：新产生的时间要么是"未定时"，要么明确标 `Estimated` 并进报告；界面用状态点区分
   `Imported / Estimated / Edited / Confirmed`。
3. **精确操作与批量规则共用同一套命令与撤销粒度**：一次操作 = 一条命令 = 一步撤销（复用现有 `Execute` + 合并组）。

### 5.3 界面（三层，从"单点精修"到"批量规则"）

**A. 芯片层：让现状可读**
- 芯片下方显示**时长**（`ms` 或帧数，随缩放）与**状态点**（导入/估算/手改/已确认四色，来自 `Theme/Colors.axaml`）；
- 过短（< 1 帧）与过长（超过可配置阈值）用告警色描边——**只提示不改数据**；
- 元素之间的**间隙做成小分隔手柄**：单击 = 在此处拆分；拖动 = 交给时间轴改时间（两种意图靠"点/拖"区分，与标尺一致）。

**B. 「切分」页签（右侧工作区第 4 个页签，宽 340）**
```text
[样式设计] [动画] [切分] [属性]
── 字符带 ──────────────────────────
 夜│空│中│最│亮│的│星          ← 每格格 = 一个 Unicode 文本元素
 ↑ 边界手柄（点击 = 切分/合并）
── 选区与规则 ──────────────────────
 选区：第 4~6 字（3 个元素）   [合并]  [按规则切分 ▾]
 规则：混合（CJK 逐字 + 拉丁按词）/ CJK 逐字 / 拉丁按词 / 按标点 / 按空白 / 每个文本元素
── 影响预览（提交前） ──────────────
 将产生 6 个元素；其中 2 个会失去时间（标为未定时）
 应用范围：[当前行] [选中行…] [全部行]
```
- **字符带**是"科学的"核心：它把切分从"猜芯片"变成"在文本上放边界"，且**与时间无关**；
- 选区是**字符范围**（不是芯片范围），所以可以"先框几个字再合并/切分"；
- 规则与范围分开选，**提交前先看影响预览**（与样式工作区的做法一致）。

**C. 批量规则（也用于导入）**
| 规则 | 语义 |
|---|---|
| 混合（默认） | CJK 逐字 + 拉丁按词 + 标点依附前一个元素 |
| CJK 逐字 | 每个汉字/假名一个元素 |
| 拉丁按词 | 按空白与连字符分词 |
| 按标点 | 以 `，。、！？…` 等为界 |
| 按空白 | 纯空白分词 |
| 每个文本元素 | 现状 `SplitSelectedToken` 的语义（grapheme） |

**D. 键盘与时间轴联动**：`S`/`M` 保留；新增在字符带内 `←/→` 移动光标、`Enter` 在光标处切分、
`Backspace` 合并相邻；边界拖动仍在时间轴与芯片上进行（不重复两套手势）。

### 5.4 切分后时间怎么办（**需裁决，见 §8 第 2 项**）

| 方案 | 行为 | 代价 |
|---|---|---|
| **A（推荐）不动时间** | 新边界只把原元素拆成"有时间的第一个 + 未定时的其余"，或整体标为未定时 | 用户要重新打点，但不会有"看着像实测的假时间" |
| **B 按文本权重分配** | 父区间按字符数/音节数比例切开，**全部标 `Estimated`** 并进报告 | 上手快，但必须让用户看得见"这是估的" |
| 现状 | 按比例切开 + 标 `Edited` | **与 `TimingStatus` 的定义不符，建议无论如何都改** |

### 5.5 多语言

拉丁按词、CJK 逐字首期即可；**日文 mora 切分与假名对应（ruby）留到 P2**（需要假名映射表，且与"文本元素"边界不完全重合）。

## 7. 风险与不做的事

- **加密格式（QRC/KRC）**：解密属私有协议且随版本变化，维护成本高、法律边界模糊 ⇒ **建议首期不做**；
  YRC 是明文（JSON/文本），可作 P2 候选（仍需主人裁决）。
- **TTML 的复杂特性**：`x-bg` 和声、翻译轨、`ttm:agent` 多歌手首期一律**不映射**，只进报告；
  否则会牵动渲染与数据模型（那是另一条 P1 线上的事）。
- **UltraStar 的音高**：本项目不做音高 ⇒ 读取时丢弃并报告。
- **性能**：SRT/ASS 行数少；TTML 可能几 MB ⇒ 用 `XmlReader` 流式解析，禁止 `XDocument.Load` 全量驻留。
- **不做**：OCR、二进制/工程格式、MIDI 系格式、导出（本提案只承诺**导入**；导出对称性另开一批）。

---

## 8. 需要主人裁决（4 项）

1. **首期格式清单**：P0 = 增强 LRC + 普通 LRC（已有）+ **SRT + WebVTT**；P1 = **ASS/SSA + UltraStar + TTML**；
   YRC/QRC/KRC ⇒ **建议先不做**（或只读已解密的明文）。**是否照此定？**
2. **切分后的时间策略**：A 不动时间（新元素标未定时，**推荐**）/ B 按文本权重分配并标 `Estimated`（默认关）；
   另外**现状"按比例切但标 `Edited`"建议一并修正**。**选哪个？**
3. **切分编辑器位置**：右侧工作区新增「切分」页签（**推荐**，与样式工作区同构）/ 独立弹窗 / 歌词栏底部抽屉。
4. **导入时是否允许"按规则切分"**：默认关、用户显式勾选（**推荐**）/ 默认开 / 完全不做。

## 9. 验收任务（做完后按这四条点验）

1. 导入**只有行时间**的普通 LRC → 勾选"按混合规则切分" → 每行变成逐字元素，时间标为**估算/未定时**，可直接在时间轴拖动。
2. 导入**增强 LRC** → 逐字时间原样保留，报告里**没有**"估算/丢弃"字样；识别结果写着"增强 LRC（含逐字时间）"。
3. 展开一行 → 在字符带里框选"最亮的星" → 一键合并成一个元素 → **相邻元素的时间不变** → 一步撤销可回退。
4. 同一个 `.lrc` 文件，删掉所有 `<…>` 标签后再导入 → 识别结果变成"普通 LRC（仅行级时间）"，**理由写进报告**。


## 9. 0.43.9：普通TXT、必填新建与明确歌词分支

新建先选择主歌词和音频；确认格式／编码／切分后，歌词解析、音频解码和播放器准备全部成功才进入未保存工程。失败／取消不替换当前工程。追加导入不默认覆盖正在编辑的分支：必须选择已有分支或“新建歌词分支”，填写新名称和翻译／注音／其他用途。替换非空分支前提示行数及引用影响；新建与导入一次撤销，其他分支及主分支身份保持。新翻译不猜行关联，随后在歌词来源中明确设置。

新增`PlainTextImporter`（text.plain）处理没有时间标签的TXT，每个非空行成为一行歌词，Unicode字素成为文字单元。源文字和编码报告保留，时间均为Missing；音频时长不会生成假时间。TXT候选优先级为UltraStar→增强LRC→纯文本→普通LRC，实际内容嗅探继续门禁，含真实时间标签的文件仍选时间导入器。六项新增回归覆盖空白、emoji、时间缺失及原格式优先；界面、命令和原生路径证据见roadmap §18.133。

两个导入表单正文可滚动，确认／取消固定在正文之外；文件选择及设置／影响确认迟到时核对工程身份，不能写入另一工程。自动路径与真实文件选择、IME人工验收分别记录。
