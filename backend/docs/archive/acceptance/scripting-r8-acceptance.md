## 2. 本批决策

1. 两种格式各编码57秒／1710帧。副本和备份复查完整闭包与全部关键帧，避免重复六次相同长片；
   不把关键帧复查写作副本／备份也全部编码。
2. 编码器每个输入帧与独立正式 Preview 同刻、像素与诊断严格相等。
   FFmpeg完整流式解码全部帧及EOF，独立预览回退重放全部帧；不积存数百MB期望像素。
   RGB平均误差≤9、Alpha最大误差≤3，检查可见前景和透明角落。
   两份成片的完整音轨按48kHz流式解码，前57秒逐采样对照真实110Hz／0.35源信号，
   RMSE≤0.02且每秒均非静音；AAC尾部至多允许补一个1024采样帧，不只凭音轨元数据判定成功。
3. 每种格式先生成同一作者工程前14秒／420帧的可播放旧片，含起唱与真实材质／粒子。
   再加入测试专用作者Error包：在30秒Evaluate报告Error，提交900个输入帧后中止。
   作者catch不能掩盖，真实包／修订／实例／源码位置必须保留。
   之后干净工程真实写管道在12.266666秒的活动歌词／材质／粒子帧取消，
   第369个提交帧实际写入管道后中止，再以新token完成整个恢复导出。
   编码器写入方法只保证有界队列入队，回归等待真实 `FramesWritten` 达到提交数后再取消，
   分别断言369个输入帧、369个管道写入和最后时刻；不依赖后台线程恰好已排空的时序。
4. 已有可播放旧片的全部字节不变、编码器未Complete、输入帧全部释放、工厂与编码会话释放一次、
   失败工程7种Artifact／29个实际作者上下文、正常工程6种Artifact／28个上下文全部回收，
   隐藏 `.encoding.*` 文件为空共同证明失败与取消保护。
   纯资源包不会制造脚本加载上下文，释放证据来自同工程的真实C#包。
5. 自动回归默认使用临时目录；设置 `MAKOKARA_R8_EVIDENCE_ROOT` 的独立交付运行保留
   工程／副本／备份、作者模板、完整MP4／MOV和受到保护的14秒旧片、探测／报告和SHA-256。
   最终证据目录需实际存在。
6. 顺带修复透明导出报告错误记录x264的普通缺陷，PATCH升0.40.2：
   报告透明配置使用正式 `prores_ks / profile 4444 / yuva444p10le / vendor apl0`；
   实际产物仍以FFprobe读取的ProRes／yuva／Alpha与音轨为验收依据；
   报告此处是编码请求参数，探测到的ProRes像素格式可为 `yuva444p12le`，两者不混称。编码行为不改。

   两个动态列表填充后分别选中MP4与标准质量，移除提前设置的XAML索引；
   原生探针检查实际索引及非空名称。该普通UI修复仍属于本批PATCH0.40.2。
8. 真实MOV报告仍使用MP4音频规划的理由，AAC源也会误报已直接复制。仅修正报告：
   透明MOV说明实际使用 `pcm_s16le` 并令AudioCopied=false；普通MP4保留原规划。
