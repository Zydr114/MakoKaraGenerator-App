# 样式模板与歌词行编辑器临时优化方案

> 2026-09-29；状态：**0.2.0 的 A～F 功能链已接入；用户已验收歌词行编辑器。0.2.1 模板工坊交互已获用户实窗验收。0.2.2 修复未定时字的逐字误染，像素回归通过；用户已验收共享边界单边拖动、行时间轨和预览／导出对比。0.2.3 加入清除元素时间；0.2.4 修复清除后时间轴选中错位，清除、静态画面、选中状态与撤销均获实窗验收**。用户明确要求将模板制作与歌词行套用彻底分开，放弃旧样式库与旧工程格式的向后兼容；决策见 [ADR-0050](../decisions/decisions.md#adr-0050模板工坊歌词行编辑器与程序版本边界) 和 [ADR-0051](../decisions/decisions.md#adr-0051模板工坊的基线创建编辑状态与实时预览)。§1 是改造前调研，当前代码状态见 §11～15。

> 歌词行编辑器套用体验已在 0.2.5 按 [`template-application-ux-plan.md`](template-application-ux-plan.md) 改版；本文件 §2、§5 和 §11～15 保留此前设计与 0.2.4 的历史记录，当前界面与全部套用语义以新方案 §10 为准。

**一句话架构**：模板工坊负责**设计并保存行模板／元素模板**；歌词行编辑器负责**选中行或元素、选择模板并套用**。模板工坊没有工程目标、应用按钮或工程上下文。旧样式选择／应用流程在新版本中直接移除，不设置过渡回退入口。

## 1. 仓内调研：问题究竟落在哪里

本方案以改造前工作树为基线核对了模型、采样器、界面与时间轴。历史结论如下：

| 现状 | 代码证据 | 对体验的影响 |
|---|---|---|
| 样式窗口同时承担“挑选／制作”和“选择工程、行、元素目标／应用” | `StyleEditorWindow.axaml`、`StyleWorkspaceViewModel.TargetIndex/TargetLabel/Apply()`、`StyleBatchEditor.Apply()` | 用户在制作模板时必须先理解工程覆盖层级；选择器被目标状态牵着走。 |
| 行与元素已经各有 `TimeRange?` 和 `TimingStatus` | `LyricLine.cs`、`LyricToken.cs` | 数据结构无需把两者拆开；缺的是明确的行时间入口和独立编辑规则。 |
| 现有行时间由列表显示，底部时间框只编辑选中元素 | `LyricRowViewModel.cs`、`MainWindow.axaml`、`EditorViewModel.TimelineEditing.cs` | 用户看得见行区间，却无法直接精确修改它。 |
| 元素超出行时，元素编辑会扩张行区间；波形拖动也经 `ApplyBlockChanges` 扩张 | `EditorViewModel.TimelineEditing.cs` | 这让“行时间”看似独立，实际会被子元素反向改写。 |
| 相邻元素共享边界时，命中结果带 `AdjacentBlockIndex`，拖拽提交两条变更 | `TimelineInteraction.cs`、`TimelineControl.cs` | 用户抓一个色块边缘会同时改变隔壁色块。 |
| 校验器目前把越行和元素重叠报告为 Warning；导入或外部文件可保留这些数据 | `ProjectValidator.cs` | 新编辑入口需严格拒绝无效操作；旧格式工程不进入新编辑流程。 |
| 采样器按“最近一次已开始的行”选行，行结束后仍可留屏；无时间元素会按邻接边界推算进度 | `LyricSampler.cs` | 这与“行区间决定显示；区间内的空档没有逐字动画”冲突，必须改同一份采样语义。 |
| 个人样式库 `styles.json` v1 存完整静态样式和参与套用的属性清单，没有模板类型 | `SavedLyricStyle.cs`、`LyricStyleLibrary.cs` | 新模板库从零建立；不读取或迁移旧 `styles.json`。 |
| 改造前 `Directory.Build.props` 为 `VersionPrefix=0.1.0`，工程 JSON 只有各自的 `schemaVersion` | 改造前的 `Directory.Build.props`、`ProjectStore.cs` | 当时有构建版本元数据，但缺正式的版本递增规则、界面展示与工程版本检查。 |

以下界面与算法是**建议方案**。用户已明确的硬需求是：选择器只制作两类模板；歌词行编辑器负责应用和可视化重排；行与元素时间分别编辑且元素包含于行；元素按文本顺序不重叠；拖一个元素边沿不再连动相邻元素。

外部交互参照仅用于校准手势，不照搬视频剪辑的数据模型：[Adobe 的时间线教程](https://helpx.adobe.com/ph_fil/premiere-pro/how-to/trim-video-clips.html)把普通单片段裁边、会移动邻片的 Ripple 和同时改两片的 Rolling 区分为不同操作；[Rolling 工具说明](https://helpx.adobe.com/premiere/desktop/edit-projects/trim-clips/perform-rolling-edits.html)明确双边会一起被选中。由此推论，本项目“拖选中元素边沿”的默认含义应是**只改该元素**；若将来需要双边联动，应另设清楚命名的显式命令，而不能由共享边界自动触发。

## 2. 新的操作心智：制作与排演分开

### 2.1 模板工坊：只回答“要做成什么样”

独立样式窗口改成**模板工坊**。它展示只读的内置模板和可编辑的个人模板；新建个人模板必须选一份已有模板作基线。选择个人模板即进入明确标识的编辑状态，修改草稿时中央试样实时更新，用户可保存或放弃。窗口不读取当前选中行或元素，也不出现“目标”“应用到工程／行／元素”“批量目标”“恢复继承”等控件。创建、编辑和删除的具体交互以 §12 与 ADR-0051 为准。

- **行模板**：可包含行级允许的静态属性；在窗口内给出整行试样。是否把进入动画收入模板，应作为后续明确扩展；第一批先只保存静态样式。
- **元素模板**：只提供 `TokenStyleSupport` 认可的属性。试样是一整行中**一个被框出的元素**，旁边保留未改动的元素作对照；字体、字号、对齐、缩放等整行排版属性不出现在可编辑区。
- 模板保存的是**样式值 + 属性清单 + 模板类型 + 稳定 ID**；未勾选属性在套用时继续继承。编辑模板不改变任何工程。内置只读，只能作为新个人模板的基线；已保存个人模板也可作为基线。
- 模板卡显示“行／元素”“覆盖哪些属性”和缩略试样。名称允许重复时用稳定 ID 区分；搜索、收藏、最近使用仍可保留，但“最近使用”只在行编辑器实际套用后更新。
- 固定试样不依赖工程中的当前行；需要从工程取样时，行编辑器提供“把当前效果保存为模板”，打开工坊并带入**值的快照**，不带入应用目标。

工程基线样式作为渲染默认值保留，其设置入口归工程合成设置；模板工坊不承担工程默认的应用。现有动画页签的“应用到工程／行”入口不带入模板工坊；动画配置以后在独立动画界面或歌词行编辑器中设计，第一批静态模板不混入动画。

### 2.2 歌词行编辑器：只回答“这一句怎样呈现”

在歌词列表选中一行后，打开独立的**歌词行编辑器**。它不是缩小版样式窗口，而是围绕一行的排演台：

```text
┌ 第 12 行  「请照亮我前行」           [上一行] [下一行] [关闭] ┐
│ 行区间  00:12.200 ├════════════════════┤ 00:15.800      │
│          [起点] [终点] [时长]     [在波形中聚焦]           │
│                                                             │
│ 文字序列  [请] [照] [亮] [我] [前] [行]                       │
│           拖动排序 · 拆分 · 合并 · 未定时标记                 │
│                                                             │
│ 时间槽      [请──] [照──]   空档   [亮───] ...                │
│             选中元素：起点／终点／时长，波形区同步高亮        │
│                                                             │
│ 当前样式    行：蓝色粗体 · 局部覆盖 2 项                     │
│             [给整行套模板] [给选中元素套模板] [恢复继承]     │
│             套用前：将写入 4 项；现有元素覆盖仍优先          │
│                                                             │
│ [试听本行]  时间与样式诊断                         [撤销]    │
└─────────────────────────────────────────────────────────────┘
```

两种选择状态分别可见：**选中行**决定行时间和行模板目标；**选中元素**决定元素时间和元素模板目标。编辑器、歌词列表、波形轨使用同一组稳定 `LineId/TokenId` 同步选择，结构变化后不依赖旧下标指向别的元素。套用模板时才出现目标、属性差异和继承来源；模板工坊始终不出现这些概念。

建议加一个“**试听本行**”按钮：从行起点播放到行终点，并在文字序列下显示当前是“行内空档／元素演唱／行已结束”。这让时间语义可直接感知，避免只能靠反复导出判断。

### 2.3 行内重排的安全语义

文本顺序与时间顺序必须同时可解释。拖动元素只改**本行的元素排列**，新行文本由新顺序的 `Token.Text` 拼接得到；元素 ID、样式覆盖保持随元素移动。若原行文本已经与元素文本拼接结果不一致，先报告并拒绝重排，不能借此静默改写歌词。不得改 Unicode 字素内部，不得把元素拖到别的行，跨行移动另设显式操作。

- **无时间或重排后仍满足时间顺序**：直接预览并提交；行时间不变。
- **已定时元素跨过另一个已定时元素**：默认拒绝放下，显示具体冲突。提供明确的「按新顺序重新分配现有时间槽」操作，先在对照视图列出每个元素原时间与将得到的时间，用户确认后才一次性写入、标记 `Edited`；拒绝则原数据不动。
- **拆分／合并**沿用现有 Unicode 文本元素与保留来源时间的规则，但提交前经过新的包含性与无重叠校验；无法直接满足时显示冲突，不替用户缩短或平移时间。
- 每次重排、时间槽重分配、套用模板都是各自完整的一步撤销；失败不产生半步结果。

## 3. 时间契约：行是可见窗口，元素是局部演唱事件

继续使用整数微秒与半开区间。合法的已定时行 `L=[Ls,Le)` 和行内已定时元素 `Ti=[Si,Ei)` 满足：

```text
0 ≤ Ls < Le
Ls ≤ Si < Ei ≤ Le
若 i、j 是文本顺序中前后相邻的“已定时”元素：Ei ≤ Sj
```

等号允许元素无缝相接；严格小于留下真实停顿。未定时元素没有区间，不能被当作零长度色块，也不能靠渲染推算出“看起来精确”的演唱动画。**行时间并非元素时间的外接矩形**：前奏、尾音、空档可以属于行，但不属于任何元素。行没有合法时间时，先编辑或确认行时间，再给元素定时；导入的历史异常数据保留原值并显示诊断。

| 播放头时刻 | 目标画面 |
|---|---|
| `t < Ls` 或 `t ≥ Le` | 该行不显示；行间可为空画面。后续多行布局另定，不隐式延长上一行。 |
| `Ls ≤ t < Le`，未落入任何元素 | 整行可见；没有活动元素、没有逐字擦亮动画。已唱完的元素保持已唱色，未唱的保持未唱色；高亮边界静止。 |
| `Si ≤ t < Ei` | 只由该元素自己的时间驱动逐字填充；其他元素维持开始前或结束后的稳定状态。 |
| 行已切分但元素全无时间 | 整行可见，保持未唱静态外观，显示“逐字未定时”诊断；行进度不得伪装为逐字进度。 |
| 行未切分 | 整行可见，以静态行样式显示；是否提供单独的“整行淡入／淡出”由动画系统负责，不把行时间均摊给字。 |

这是对现有 `LyricSampler` “开始后留屏”和“未定时段推算进度”的有意修订。行内空档包括首字前、两字间、末字后；在 `[Ei,Sj)` 内上一字是已唱、下一字未唱，没有正在演唱的字。边界 `t=Ei=Sj` 按半开区间落入后字；`t=Le` 不属于行。预览与导出继续只调用同一个 `LyricSampler` 结果，禁止在 UI/渲染器另算一套。

建议让采样结果显式暴露 `LineVisibility` 与 `TokenPhase`（`LineOnly`、`ActiveToken`、`HoldGap`），并让 Skia 的填充规则仅使用采样器给出的稳定进度。旧 `LineProgress` 可以继续供诊断和行级动画使用，但**不能**在已切分／未定时场景退化成逐字填充。与现有“最近起点”选行规则的冲突，先在 ADR 中确定：本方案建议只在合法行区间内选行；若同时有多行区间，第一批沿用“起点较晚者优先”作为单画面策略并报告冲突，未来分支动画再处理多行显示。

## 4. 两层时间编辑与波形手势

### 4.1 独立行区间轨

在现有标尺、波形、逐字块轨之外加入**行区间细轨**，与它们共用唯一 `TimeAxis`。行区间轨显示选中行的半透明底带和两个大手柄；它的两端可拖，也可在行编辑器精确输入。逐字块仍位于独立轨道。布局与命中测试均由 `TimelineLayout` 定义，不能在控件里另算坐标。

编辑行起止**只改 `LyricLine.Time`**，不拉伸、不平移、不裁切元素。新行区间若装不下任一已定时元素，拒绝提交并显示这些元素；另外提供明确命名的「整行连同元素平移」命令，使用独立的“平移至”新起点输入，预览所有受影响时间并确认后作为单步撤销，不能复用会在失焦时提交的行起点输入。行与元素时间各自有起点、终点、时长和时间状态；数值输入回车／失焦提交，非法文本保留并报告，绝不逐键写工程。时间文本只显示毫秒时，未改动的边界必须沿用原始微秒值，不能因失焦解析而舍入。

### 4.2 单边、单对象编辑

选中一个元素后，只在该元素上显示**内侧左右手柄**。拖哪个手柄就只改该元素的起点或终点；相邻元素即使共用同一微秒也保持原值。拖动主体只平移该元素，时长不变。波形上的色块颜色仍表示各自的时间区间，选中块的手柄、边框和对应歌词芯片同步强调。

在同一 x 上有两个边界时，**选中元素优先**，不再搜索 `AdjacentBlockIndex` 并生成双块变更。未选择时，第一次点击边界只选定左／右元素（根据指针在边界哪一侧或可见的分离手柄），第二次拖动才改时间；键盘焦点也能明确选“左边元素终点”或“右边元素起点”。窄块或高缩放时手柄的命中区域可在视觉上错层，但时间 x 仍准确对齐共享 `TimeAxis`。

拖动约束为：`line.start ≤ token.start < token.end ≤ line.end` 且不穿越前后**已定时**元素。吸附产生非法候选时显示受阻原因和合法边界预览；只提交合法候选，不能悄悄挪邻居或改行区间。精确时间输入遇到重叠直接拒绝。允许把共享边界向内拉出空档；朝邻居方向拖到边界就停下，邻居不动。此规则适用于拖边、拖主体、逐帧微调、`[`/`]` 打点和精确输入，不能只在鼠标路径加限制。

## 5. 模板应用：目标在行编辑器中才出现

点击「给整行套模板」只列行模板；点击「给选中元素套模板」只列元素模板。弹层显示效果缩略图、属性差异、已有覆盖与继承来源，以及“本次将写入的属性”。选定模板后先在**本行预览**，按「套用」才写项目。`StyleBatchEditor` 与 `LyricStyleResolver` 的纯逻辑可复用，但旧样式窗口的目标状态和应用流程必须删除，不能作为第二入口继续运行。

新系统采用**按值应用**：工程保存结果数值，不依赖模板库今后是否改名或删除。行模板写 `LyricLine.StyleOverride`；元素模板写一个 `LyricToken.StyleOverride`。元素覆盖优先于行覆盖，界面明确提示“行模板的某些属性被 2 个元素覆盖”；恢复继承只清当前层选定属性。此处的批量入口限制是 0.2.0 方案的历史口径；0.2.5 改为行编辑器内直接按模板类型套用到当前目标或全部同类型目标，见 [`template-application-ux-plan.md`](template-application-ux-plan.md) §10。模板工坊始终不出现目标列表。

## 6. 断代规则与程序版本

### 6.1 旧样式和旧工程不进入新系统

新系统创建独立的应用级 `templates.json`，只存行／元素两类新模板，格式从 v1 开始。旧 `styles.json` 不读取、不迁移、不显示为“历史样式”，旧内置预设也不作为新模板的隐形来源；新内置模板重新定义。实现中删除旧样式窗口的目标选择、应用按钮、批量目标和旧样式加载链。旧 `styles.json` 文件留在磁盘上但被程序忽略，避免“放弃兼容”变成擅自删除用户文件。

这次是**有意断代**。旧工程不通过迁移器读入新模型；不提供旧采样模式、不保留旧行/元素覆盖的解释分支，也不让旧文件在一次保存后被悄悄改写成新格式。新工程从新的项目格式创建；如需复用歌词或音频，由用户走明确的导入流程，导入文本与媒体不是打开旧工程。`project.json` 与 `lyrics.json` 的 `schemaVersion` 继续表示各自的结构版本，但在此断代之后不承担旧版自动迁移。每次改结构仍需提升对应 schema、更新读写和当前版本测试；**无需为不受支持的旧版本写迁移步骤**。

### 6.2 每次完成程序修改都分配版本

改造前 `Directory.Build.props` 中的 `VersionPrefix=0.1.0` 只是构建元数据，程序没有统一展示版本，工程文件也没有程序版本字段。**0.2.0 首次落实正式版本规则，当前程序为 0.2.4**；以后纯文档修订不改变可执行程序，也不占用版本号。

- 版本采用 `MAJOR.MINOR.PATCH`，由仓库根目录 `Directory.Build.props` 的单一 `VersionPrefix` 决定；“关于”界面、启动日志、发布产物的信息版本和工程写盘都读这同一个三段值，不各写一份常量。程序集的四段 `AssemblyVersion` 可用于 .NET 绑定，但工程比较只认三段产品版本。
- **每个完成并可交付的一批程序修改至少递增一次版本**：普通修复和不改数据契约的功能递增 `PATCH`；不兼容的交互／工程结构变动在 1.0 前递增 `MINOR`，1.0 后递增 `MAJOR`。一批可以含多个提交，但交付时必须有唯一版本；只改文档、重跑测试或未交付的中间构建不占新版本。
- 提交程序改动时同步更新版本号与简短变更记录；构建后检查程序集信息版本、界面展示和新建工程中的版本一致。发布同一版本后不得把不同程序内容重新标成该版本。
- `schemaVersion` 与程序版本互不替代：前者描述 JSON 形状，结构没变时可保持不变；后者标识写入该工程的程序版本，即使只是一次程序修复也更新。

### 6.3 工程版本写盘与不一致提示

新格式的 `project.json` 根对象增加必填 `applicationVersion`，例如：

```json
{
  "applicationVersion": "0.2.4",
  "schemaVersion": 15
}
```

`15` 是 0.2.0 已实现的 project schema 版本；`lyrics.json` 仍用自己的 schema 版本，不额外复制应用版本。新建、手动保存与自动备份均写入当前程序版本。版本字符串必须是规范的三段数字；缺失、格式错误、比当前高或比当前低，一律是版本不一致。

打开工程时，`ProjectStore.Load` **先只读取 `project.json` 头部并比较版本**，在解析 `lyrics.json`、创建工作区或触发自动保存之前返回结构化“不一致”结果。界面弹窗显示“工程版本 / 当前程序版本 / 原文件未更改”，按钮为「取消打开」和「了解如何使用当前版本重新建立工程」；不提供忽略警告、自动迁移或覆盖保存。只有版本完全一致，才继续各文件 schema 与数据校验。当前已打开工程保持原样，自动恢复也不得绕过版本检查。旧工程没有 `applicationVersion` 时显示“未标注程序版本”，按不一致处理。

这一规则意味着每次版本升级后，旧版本写入的工程无法直接在新程序中打开；这是本轮选择的**无向后兼容**代价，界面和变更记录必须直说，不能让用户误以为只是一个可忽略的提醒。工程目录本身不被删除或重写。模板库与工程是两类数据：新 `templates.json` 自带独立格式版本；本节的“工程版本不一致”提示不隐式清空模板库。

| 顺序 | 交付物 | 主要位置 | 完成判据 |

## 8. 必须覆盖的验收场景

- 行 `[1.0,5.0)`，元素 `[2.0,3.0)` 与 `[4.0,4.5)`：在 1.5、3.5、4.75 秒均显示行且没有活动逐字动画；在 5.0 秒不显示该行。
- 两元素 `[1.0,2.0)`、`[2.0,3.0)`：选第二块左边沿拖到 2.4 秒，第一块终点仍为 2.0 秒并出现空档；往左拖入第一块时被拒绝。选第一块右边沿执行对称测试。
- 元素拖到行外、行边界缩入元素内、键盘微调或打点制造重叠、精确输入非法时间：都拒绝、说明目标与原因、工程引用和撤销栈不变。
- 元素未定时但行已定时：文本始终可见且未定时元素没有伪造的逐字进度；旧推算路径的变异测试必须变红。
- 把已定时元素拖过另一个已定时元素：默认无提交；明确确认时间槽重分配后，文本拼接、ID、样式和时间顺序正确，撤销一次完整回退。
- 保存／重命名／删除模板不会改工程；在行编辑器应用行模板只写行覆盖，应用元素模板只写指定元素覆盖，未勾选属性保留继承。
- 模板工坊没有任何目标或应用控件；新 `templates.json` 只接受行／元素模板，旧 `styles.json` 即使存在也不读取、不删除。
- 新工程保存 `applicationVersion`；同版本可重开，不同版本、字段缺失或格式错误均提示两个版本并取消打开，工作区和磁盘文件不变；自动恢复走相同门禁。
- 每个可交付的程序变更有唯一递增版本；程序集、“关于”界面、启动日志和新工程版本一致；纯文档修改不递增。

## 9. 非目标与设计边界

本轮不把“模板”做成工程内的实时链接，也不自动同步已应用的工程；不把行内重排扩成跨行／跨分支编排；不改变元素是 Unicode 文本元素而非 UTF-16 字符的既有契约。画布中的歌词位置、双行动画、脚本系统仍按各自计划推进，但这些后续功能应消费同一行时间与采样规则。

## 10. 与现有文档和 ADR 的关系

用户已明确确认**模板工坊设计样式、歌词行编辑器选择并应用样式、无旧样式与旧工程兼容**三项架构决定；[ADR-0050](../decisions/decisions.md#adr-0050模板工坊歌词行编辑器与程序版本边界) 取代 [ADR-0044](../decisions/decisions.md#adr-0044样式设计面板与批量应用含可选颜色三态)、[ADR-0047](../decisions/decisions.md#adr-0047样式布局与歌词分支动画系统的下一轮改造) 中与此相反的界面和迁移口径，也取代 [`timeline-ui.md`](timeline-ui.md) 的共享边界双边拖动目标。旧文档仍可作为历史查阅；0.2.0 的实际实施范围和待验收点见下一节。

已定时元素重排时，默认保留元素时间并拒绝冲突；“确认后重新分配时间槽”是一个明确的附加命令，不改变默认规则。行结束即离屏是新采样语义，不为旧工程保留另一条采样路径。

## 12. 验收后的模板工坊交互修订（0.2.1 已实施并通过人工验收）

### 12.1 目标与当前缺口

用户确认的操作模型是：软件提供**内置模板**和**用户自定义模板**；每份新模板以一份已有模板为基线；任何非内置模板都能编辑，编辑中实时预览，并能明确保存或放弃。模板工坊仍只产出模板，套用仍在歌词行编辑器完成。

0.2.0 的 `TemplateWorkshopWindow.axaml` 底部同时显示「新草稿／保存为新模板／更新我的模板／删除我的模板」，右侧 `KindBox` 允许对选中模板直接切换行／元素类型。`TemplateWorkshopViewModel.SaveNew()` 与 `UpdateSelected()` 是两个保存入口，当时没有清楚的“正在编辑／有未保存修改”状态。行模板预览缺陷已定位为 `LyricLine.Equals/GetHashCode` 漏掉 `StyleOverride` 和 `EnterAnimation`：新快照被视为与旧快照相等，属性通知未发到中央画布。0.2.1 补齐相等与哈希字段，测试先复现失败、修复后快照通知和实际像素对比通过。切换类型不再承担刷新作用。

### 12.2 界面与状态

| 区域／操作 | 修订后的行为 |
|---|---|
| 左侧列表 | 分为「内置模板」「我的模板」。列表上方放「新建模板」。模板卡右键菜单为「复制此模板」「删除此模板」；内置卡的删除项禁用或不显示。右键作用于指针所在卡片，不依赖先前选中项。 |
| 新建模板 | 打开创建对话框，要求输入名称、选择类型与基线；默认类型「行模板」、基线「经典整行」。基线可从内置或个人模板选。确认后进入**尚未保存的新模板草稿**，复制基线的样式值及属性清单，不改基线。改成元素类型时只列元素模板作基线，默认「逐字强调」；切回行类型恢复同类型选择，不静默丢弃不支持的属性。 |
| 复制此模板 | 以右键所指模板为默认基线进入同一个创建流程；预填名称和类型，确认后生成新草稿与新 ID，原模板保持不变。 |
| 查看内置模板 | 可查看属性与试样；右侧为只读，明确显示「内置模板·只读」。需要修改时使用「复制此模板」。 |
| 编辑个人模板 | 选中即进入编辑状态，右侧显示模板名称、固定类型和「正在编辑：模板名」；改动后显示「未保存修改」。既有模板的类型在编辑时不可切换；如需另一种类型，走新建并选相应类型的基线。 |
| 中央预览 | 显示**当前草稿**，有效的样式值或属性勾选变化立即重建行／元素试样；行模板始终显示整行效果，元素模板明确标出受影响元素。保存只是持久化当前草稿，不是触发预览的必要操作。输入无效时保留最后有效画面并在输入处提示，不能让旧画面伪装成已生效。 |
| 底部操作 | **只保留「保存模板」「删除模板」**。「保存模板」对新草稿创建个人模板，对已有个人模板原位更新并保留 ID；内置查看态及无有效修改时禁用。「删除模板」只对已保存的个人模板可用，使用主题中的红色警告色，先显示模板名称并确认，写盘成功后才从列表移除。 |

创建对话框中的类型选择只控制**新模板**，不会变更已有模板。右键「删除此模板」与底部删除走相同的确认与持久化路径；两个入口的可用状态保持一致。界面提示当前是「查看内置模板」「正在编辑个人模板」还是「正在编辑未保存的新模板」，保存成功后清除未保存标记。模板在工程中按值套用，编辑或删除库模板不追改已套用的歌词行。

### 12.3 实施与验收顺序

1. 先复现并修复**行模板实时预览**：选「经典整行」复制为个人模板，不切换类型，逐项改颜色、字重及属性勾选；每次有效修改后中央整行试样变化。保存后画面与持久化值一致；切换到元素模板再返回时没有额外变化。用视图模型通知与实际渲染断言覆盖这条链。
2. 收拢草稿状态与唯一保存动作：新建、个人模板编辑、保存、放弃、切换、关闭均以草稿为单位；内置只读，个人模板原位更新保留 ID，磁盘写入失败不改变已保存清单。
3. 加创建对话框与列表右键菜单；核对默认「经典整行」、类型切换后的同类基线、右键命中对象、复制 ID 独立、删除确认及警告色。把新建按钮移到列表上方，底部只保留保存和删除。
4. 在真实窗口验收：检查编辑状态与未保存提示是否醒目；行／元素样式值与勾选项均实时反映在中央；无保存离开后再次选中应恢复已保存值；保存后重启可从 `templates.json` 读回；内置始终不可更改；删除不会修改工程或误删右键菜单之外的模板。

## 13. 0.2.2 未定时元素渲染修复

按 §8 核对混合时间的画面时发现：采样器已把未定时元素标为 `ProgressSource.Unavailable`、进度为零，但 Skia 仍用“最右已唱位置”裁切整行。后续已定时元素开始演唱后，这条连续裁切区域会越过中间未定时元素，把它误染成已唱色。先新增像素测试复现：同一未定时字在行内空档与后续元素演唱时有 **1915 个像素**发生不应有的变化。

渲染器现在用各已定时元素的独立进度建立已唱区域，未定时元素不贡献区域；未唱区域取其补集。整行仍只整形一次，元素覆盖与行样式仍在相同的互补区域内绘制。新增像素断言确认未定时字保持静态、后续元素仍正常逐字演唱。`dotnet build MakoKaraGenerator.slnx` 为 **0 警告、0 错误**；`dotnet test MakoKaraGenerator.slnx --no-build` 为 **1285 项通过**。预览和导出继续消费同一 `SkiaRenderPipeline`；实际 GUI 操作与成片对比尚待人工验收。

**0.2.2 用户反馈**：共享边界单边拖动、行时间轨、预览／导出画面对比均符合预期，操作符合逻辑和计划。用户无法在演示工程人为制作未定时字：把元素时间框手动删空会被判为无效输入。因此未定时字的画面未获实窗确认；这一入口缺口由 0.2.3 解决。上段“预览和导出对比尚待人工验收”记录的是修复实施时的状态，以此反馈为准。

## 14. 0.2.3 显式清除元素时间

歌词行编辑器的元素起止框用于提交一段合法的精确时间；空白输入不代表清除。现于该区增加「清除元素时间」按钮，只有选中已定时元素时可用。点击后单独清除这个元素的区间，状态变为 `Missing`；行时间和其他元素保持原值，时间轴移去该色块，歌词字仍留在行内作静态显示。清除是一步可撤销操作；失焦时不会把旧输入重新写回。测试覆盖模型引用、时间状态、色块派生视图、撤销和保存／重开往返。实窗验收于 0.2.4 完成，见 §15。

## 15. 0.2.4 未定时元素的选中同步

清除当前选中元素的时间后，它不再有时间轴色块，但旧选中块索引仍停留在原序号；后续色块填补该序号时会被误高亮。回归测试先确认清除后得到错误索引 0，修复后统一在元素选择变化时同步对应色块索引：未定时或未选择元素为 `-1`，有时间的元素指向它自己的色块。测试还覆盖切到相邻有时间元素、再选回未定时元素，以及撤销后恢复正确色块。0.2.4 全量构建 0 警告、0 错误，1288 项测试通过；新窗口启动日志显示 0.2.4，未出现应用异常。

**0.2.4 用户实窗验收通过（2026-09-29）**：用户在 PID 349537 的窗口中确认「清除元素时间」后所选元素色块消失、相邻色块不会误高亮、预览中的未定时字保持未唱外观，撤销可恢复，并回复「全部通过」。此反馈补齐了 0.2.2 因无法人为制作未定时字而留下的实窗验收缺口。
