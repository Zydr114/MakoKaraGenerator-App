# R5 预览输出输入与取消合同（0.26.2）

> 2026-10-05，接续后续计划第 3 批。实际完成证据以 roadmap §18.88 为准；参数／源码撤销、单实例修订热替换和取消导出仍需接续，完整 R5～R8 未关闭。

## 1. 当前输入与失败门禁

每画布继续使用一个串行工作器、一个最新待请求和独立固定快照会话。输入身份包括工厂引用、快照引用、解析后的像素目标、透明模式、质量档位和布局试样行。时间推进只合并待请求，不取消当前工作，也不清除真实失败；上述输出输入改变时清除旧失败并取消旧工作，允许新输入重新尝试。

Preparing／Failed／Ready 都必须属于当前输入。取消过的工作即使忽略取消并迟到返回，或用户切换目标后又切回原值，也不得重新发布像素或错误。正常向前播放仍可发布当前已完成帧；回退不能发布较晚时刻的旧像素。

快照或工厂改变时释放原像素会话并建立独立新会话。仅输出模式／尺寸改变时保留像素会话对象，由现有共享帧会话以 InputsChanged 从固定快照重建语义状态；质量只改变绘制成本，布局试样仍遵守现有含效果时按真实时间采样的边界。

## 2. 取消与重绘

工作器 token、请求 token 及作者保留的 OperationCanceledException 均保持取消语义，不缓存为 Failed、不形成不能导出的错误。完成像素发布前再次检查工作器取消，迟到的普通异常也不覆盖新输入。同一快照／时间／输出设置换成新的请求 token 允许重试；真实非取消错误仍保持原失败门禁。

本批只修复私有预览调度，不改作者源码、公开 SDK、七阶段顺序、工程字段或会话指纹。程序升 PATCH 0.26.2，schema26／16／5、包 profile2、Shader ABI、程序集和依赖保持。

## 3. 自动验证与边界

- 原始代码的 6 项调度回归通过，新增首轮 7 项复现失败；修复后继续补齐质量档位和切换后返回原目标的迟到像素／错误，共新增 11 项调度回归。
- 保存重开的 WordEmphasis／RepeatEmphasis 与真实 48 kHz／20 ms 音频工程，在 24／30／60 FPS 下各走同一画布七次请求：普通、透明、2×、非等比尺寸、Draft、Final、返回普通。每次全部像素与独立 Export 重放会话一致，音频仍为 63 个真实 hop；只创建一个像素会话。
- 画布关闭只释放一次；两个文字包的真实可回收加载上下文经弱引用和 GC 检查均回收。没有增加宿主测试接口，也没有以调用 Dispose 的计数替代上下文回收证据。

三组真实工程验证只比较像素与正式会话，本批没有新增视频编码；已有 MP4／ProRes4444 同帧及失败保护继续在全量回归中验证。布局试样和迟到结果由受控调度回归覆盖，不宣称含效果时可使用伪造的静态行。音频 DLL、原生图／材质资源和取消导出释放的组合证据仍需接续，不以两个文字包的回收代替全部资源出口。最终 GUI／R8 人工验收保持后续。
