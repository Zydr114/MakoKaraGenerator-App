# R7 模板配方原位编辑与顺序合同（0.38.0）

本合同记录模板工坊对 `TemplateEffectRecipe` 的编辑边界。它只扩展作者工作区，不改变工程、歌词、模板 schema 或效果包 profile。

## 1. 身份与编辑模式

- 每条配方以 `RecipeId` 作为模板内稳定身份。编辑名称、参数、包修订或导出时构造同一 `RecipeId` 的替换值，保持原列表位置和 `OverlayLayer`。
- 编辑器选择已有配方后载入当前闭包中完全匹配的包、修订和导出；找不到该导出时保留配方并给出诊断，不猜测替代导出。
- 新增与原位更新是两个显式动作。编辑模式禁用“添加”，更新成功后退出编辑模式；取消或切换模板清除选中身份。

## 2. 闭包与校验

- 更新先解析规范参数 JSON，再由包定义解析导出参数，最后以完整候选配方数组调用 `StyleTemplate.Create`。
- 顺序调整只交换有序列表中的两个 `TemplateEffectRecipe`，不修改配方内容或身份；边界操作保持原列表并报告状态。
- 所有候选包仍来自当前草稿目录，正式试样与保存只使用材质和配方引用的精确闭包。任一步失败都保护旧配方、旧预览和旧保存版本。

## 3. 保存与范围

保存、复制、重开和模板套用继续使用同一配方数组与包闭包。顺序是模板语义的一部分；0.39.0 已接通行模板 `TokenFamily` 制作及显式目标更新，见[相对目标合同](../../scripting-r7-template-target-contract.md)；分享／导入 `.mktpl` 已在0.40.0接通，见[模板传输合同](../../scripting-r7-template-transfer-contract.md)；完整 R7 组合继续。

## 4. 证据

`TemplateWorkshopRecipeEditingTests` 覆盖名称／参数更新保留 `RecipeId`、顺序保存重开和无效更新保护旧预览。最终构建、全量回归与启动证据记录在 roadmap §18.102；本合同不替代用户人工验收。
